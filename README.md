颜喵是一款 Windows 桌面陪伴应用。你可以在透明宠窗直接聊天，也可以打开聊天详情，管理会话、查看记忆，让不同人设拥有各自的形象和经历。

**模型服务由你选择，数据保存在本机。** 应用不附带聊天 API Key；聊天、识图、生图等能力使用你配置的服务。本地自带的 Embedding 模型用于检索记忆，不是离线聊天模型。

> **当前状态：开发与实机测试阶段。** 下方介绍的是当前源码已接入的功能，下载包是否包含最新改动请以对应发布说明为准。真实模型兼容性、邮件投递、透明窗口和多屏体验仍需实机验证。当前支持 Windows 10/11 x64；Android、语音交互及 GPT-SoVITS 声线导入属于后续规划。

## 功能一览

### 🐾 颜文字小猫，也可以是图片伙伴

- **透明宠窗**：置顶、拖动、隐藏与恢复，记住窗口位置；“…”菜单可用滑动开关启用全屏游走，拖到左右/任务栏上沿可探头或坐趴停靠，重启保留；亮暗主题下使用描边按钮，尽量少遮挡桌面。
- **报错表情**：宠窗出现“！”错误提示或错误面板时显示超载／蔫掉的专属表情，问题解除后恢复原动作；四位图片人设和电子小猫均可在表情库修改。
- **日常互动**：点击、摸摸、喂食、拖动拎后颈，图片开心短跳、生气轻晃、切换解码后淡入，伴随饥饿、待机、无聊、睡眠与出行状态，普通点击10%概率增加1点亲密度，最高 999。
- **普通点击反应**：颜文字与图片共用开心／惊讶／害羞三种反应抽签，四位图片人设已配齐对应素材；追逐后摸摸固定开心。新图已包含在当前EXE中。
- **食物与投喂**：免费无限的 Token 小点心，五种食物统一 5 喵币／份；选好食物后随鼠标移动，点击桌宠投喂，右键或 Esc 取消，鼠标旁有半透明操作提示；支持嘴馋、咀嚼与亲密度反馈。按人设保存喜好与星标默认食物，喜好有 10% 概率额外 +1，最高 999。
- **可调的生活节奏**：默认 10 分钟无互动进入待机；无聊与睡觉共用默认 45 分钟触发时间，到点随机选择。可在“时间与桌宠”中调整；快捷聊天默认在鼠标移开、无操作3分钟后收起，有草稿或正在回复时保留，时间可调或关闭。
- **无聊主动话题**：进入无聊后，每累计5分钟有效空闲，以30%概率尝试生成；同一轮无聊最多成功发送一条，同一会话两次成功至少间隔30分钟。气泡沿用快捷聊天自动收起设置：默认鼠标移开宠窗且无操作3分钟，时间可调或关闭；有草稿、正在回复或上传时保留，正文仍在聊天记录。聊天或点击、摸摸、投喂后，重新进入无聊才开始新一轮；关闭应用期间不补抽。
- **图片自定义创作**：按人设上传透明 PNG/WebP，建立表情库并填写使用说明；也可分项填写表情要求，两列浏览卡片，在弹窗操作并逐张预览、重新生成和接受。
- **饰品与装扮**：制作、同时佩戴多件、出售饰品，调整相对桌宠的位置、大小及前后层级；可自行上传透明图片，预览后按现有档位付费；未开启生图或生图失败时，可用图标、Emoji、颜文字、符号组合兜底。

默认“电子小猫”之外，还内置四位可编辑、可删除的图片人设，每位带有初始图及三十张透明互动与情绪图：

预置形象不需要生图 Key。**人设名称不绑定同名模型服务**，你可以自由搭配；编辑或删除后，重启不会自动还原。

支持上缘放置与抛接互动：拖近屏幕上缘后，立绘靠上、按钮移到下方；快速向上甩动并松手才触发上升、下落，途中左键按住可接回拎起，未接住则落地停留3秒后底部停靠。出行时禁用抛接。四位内置人设各增加3张独立透明动作图，数据库正式扩充到v23。此部分已包含在当前EXE中，详见[抛接设计](docs/桌宠抛接与上缘布局设计.md)。

开启全屏游走且不处于待机等暂停状态时，每次有效移动有5%概率追逐鼠标。追到后露出“等摸摸”表情并显示侧边提示；点击后使用开心互动并结束，未点击则难过3秒后结束。四位内置人设具有独立等摸摸图片，上抛、下落立绘采用沿屏幕平面竖直运动的正立姿态。当前EXE等待5秒，只有确实接触可见立绘才进入等摸摸，追逐结束后默认冷却10分钟，可在“时间与桌宠”调整，不设置追逐时长上限。详见[追逐鼠标互动设计](docs/追逐鼠标互动设计.md)。

当前EXE已修正落地到坐趴时的窗口位移和透明边距校准，增强宠窗按钮边框与SVG图标，并更新GPT、Claude、Gemini的6张上抛/下落图以匹配默认头身比例。旧内置图按精确指纹更新，自定义素材保留，本机资料已完成接续。

新建人设时可选择图片模式：上传透明初始图后，可选择一次性生成30项基础表情预览，或建立占位后自己逐项上传。AI生成期间用模态进度弹窗锁住编辑，完成后由用户检查、接受或重试；需要已开启且支持参考图编辑的生图服务，可能消耗额度。手动上传分支不调用生图服务。

### 💬 两个聊天入口，同一份会话

- 宠窗底部可输入文字或添加图片，回复在头顶气泡中流式显示；聊天详情提供完整记录与可收起的会话侧栏。
- 新建人设会同时创建一个普通默认会话；主动切换人设时，若目标没有会话，也会自动创建并选中一条空白“新会话”，有会话则恢复最近使用的会话。人设页切换保留当前浏览位置；会话支持重命名、置顶、删除和绑定用户设定，人设的初始设定与当前设定可分别编辑。
- 支持中断、重说，以及达到输出长度限制后的主动“继续生成”。
- AI 回复支持 Markdown 标题、强调、列表、引用、代码块和表格；需要原样显示的内容可用 `<plain>…</plain>` 保留符号与换行；复制时去掉该包装标签。
- 上传图片让 AI 理解内容；配置生图服务后，可请 AI 画图并在聊天记录中保存展示。普通绘图不要求透明底；饰品与桌宠创作使用透明资源；结果不透明时通过本地抠图兜底，参考图编辑仍需所配置服务支持。AI 可在普通聊天中按需搜索、读取公开网页；已确认且适配的模型优先使用原生搜索，其他模型沿用独立搜索配置。提供商卡片显示已确认的联网/推理能力，未知不猜测。
- 聊天时颜文字随语境临时生成；图片模式由 AI 查询整个已启用正式表情库再按语境切换，包含用户新增表情和全部动作类别，不限于固定情绪；未有合适表情才用自然交谈。
- 按人设保存聊天背景、默认／透明／描边／毛玻璃气泡和双方文字颜色；上传背景后可拖动、缩放并确认裁剪，再保存外观。

出行时快捷聊天变为邮箱，可直接写信或打开设置中的统一邮箱；有未读回信时显示“有新信件！”。

当前版本支持：用户设定绑定与新会话默认选择集中在“绑定用户设定”，会话重命名使用列表右键菜单；背景裁剪与预览按实际聊天背景区域比例显示，裁剪后仍需保存外观。上述调整已包含在当前发布包。

### 📖 记住经历，而不只是堆积聊天记录

完整对话结束后，后台生成短期记忆，再按规则整合为带标题、可追溯来源的长期记忆。聊天结合全文与向量检索查找相关往事，用户可查看、编辑和管理记忆。

**Skill 仓库**可保存提示词资料，一份绑定多个人设，人设也可绑定多份；用于聊天、无聊主动消息、信件与游记，不执行脚本。支持按人设或未绑定分类、搜索、分页及双向跳转。普通聊天中，可请 AI 新增、修改 Skill 和调整自己的绑定；共享项默认复制为自己的版本，修改共享原文需你预览确认。

采用渐进式读取：**已绑定且标题为 `SKILL_BASE`、`AGENTS`、`SKILL_BASE.md` 或 `AGENTS.md` 的 Skill 正文会每次自动提供给 AI，名称区分大小写，不要求带文件后缀**；其余通过工具检索标题／简介，再按需读取全文。无聊主动消息、信件和游记也可按需读取自己的绑定项，后台不允许修改或调整绑定。未配置基础项时不会自动创建或编造内容。

Skill 仓库支持上传 UTF-8 `.md`：保留完整文件名（含`.md`）和原文，使用当前聊天模型解析简介后填入草稿，检查并保存后再绑定人设。解析可停止，失败时保留已读取的原文，不自动保存或覆盖同名资料。此上传入口和四种基础标题兼容已包含在当前EXE。

**聊天表情包库**：在全局设置的扩展服务创建多个收藏库，批量导入 PNG/JPEG/WebP/GIF，为图片填写介绍和多个全局标签。库可绑定多个人设，人设也可使用多个库；AI 按需查找并在聊天消息中发送，与桌宠换表情独立。管理页支持搜索、底部分页和多标签同时匹配；已发送图片不随收藏删除而消失。配套正式 v26 升级和备份兼容，详见[聊天表情包设计](docs/聊天表情与生图设计.md)。

另有独立记事本供 AI 按需记录、用户直接编辑。开启人设自调后，AI 可在必要时小幅调整当前设定；差异视图用红绿颜色和新增／删除标记展示变化。

聊天、记忆与记事本按会话保存。上下文不足时，会提示并减少**本次请求**携带的较旧内容，不因此删除历史。

### ✉️ 旅行、提醒与日常

- **出行与来信**：宠物上方实时显示已经出门时分；邮箱、出行历史、伴手礼和游记采用单列摘要卡，原位展开、收起详情。旅行途中寄信，返回时带来伴手礼与游记；三类卡片标明出发日期与目的地，可多选出行并结合关键词筛选。已启用且配置生图服务时，可为新普通伴手礼生成透明图片，开关默认开启；关闭、未配置或失败时保留文字，旧礼物不补图。删除游记不影响同次出行的信件和礼物。当前发布数据库为 v26，已包含上述功能及伴手礼独立标题。
- **提醒事项**：一次性或循环提醒，到点自动完成本次提醒并显示宠窗通知，点击“知道了”收起，最长保留一分钟。
- **邮件提醒**：通过 SMTP 同时发送邮件，支持验证码绑定、失败状态查看与重试；关闭应用期间无法实时发信，重开后汇总过期事项。
- **时间与天气**：实况每小时、气象资讯每10分钟后台更新，页面直接读缓存。展示地区、7日/24小时预报、温度趋势、体感、风、湿度、紫外线与穿衣建议；公开来源查询预警和本地台风关注路径，可查看官方原文、中气爱账号与延伸阅读，和风预警为可选兜底。重大变化时才调用聊天模型生成关怀。设置中的“日历”管理公历、农历、节日与自定义日期。详见[气象资讯设计](docs/天气预报与气象资讯设计.md)。预警、台风和详细预报已包含在当前发布包中。
- **签到与喵币**：在“全局设置 → 喵币与签到”每日签到，节日有特殊祝福和奖励；饰品、食物与小游戏共用全局钱包。“全局设置 → 喵币账单”可按收支、分类、小游戏、关键词和日期查询，支持卡片分页及收支柱状图、分类占比圆环和游戏排行。统计支持昨日、最近7天／1个月／6个月／1年与自定义范围；普通聊天也可请 AI 只读查询喵币账单。

### 💰 独立的现实账本

在 **设置 → 现实记账** 管理人民币收支，与喵币钱包分开保存。可手动记账，或明确告诉 AI“帮我记一笔现实支出，午餐 25 元”；金额性质含糊时，AI 应先询问是不是现实的钱。

- 账单记录分类、资产、简介、日期和记账者，支持搜索、筛选、排序与分页；分类和资产可以自行管理。
- 默认资产、储蓄资产、旅游资产是独立资金池，总资产自动合计；修改总额只校准默认资产，不计为收入。
- 首页展示本月收支、今日收支、近7天账单及日/月/年预算；预算卡片可直接点击编辑，不再单设预算页。底部图标导航打开账单、统计、资产、周期、分类和日历，悬停或键盘聚焦可查看说明。统计面板包含收支柱状图、分类圆环和资产排行。首页调整已包含在当前发布包。
- 周期账单在应用运行时到期自动记录；关闭期间漏掉的期次先询问，可选补记或跳过，不擅自补账。日历可叠加实际收支和未来周期计划。

这是一份本地账本，不连接银行，也不实际转账或扣款。现实财务资料只进入**全量备份**，不随人设、会话或小游戏资料包分享。本功能已包含在当前便携构建中。

### 🎮 六个自带小游戏与本地插件

扫雷和2048增加胜负反馈，扫雷提供帮助弹窗，2048使用完整方块移动与合并动效；两款正式随包插件均为1.0.2。食物商城采用主题购买弹窗，内调数量、确认或取消。这些界面改动已包含在当前EXE。

内置 **剪刀石头布、掷骰子比大小、接星星、我的家、扫雷、2048**，统一在“全局设置 → 小游戏插件”中打开和管理。存档用进度卡显示，运行历史与喵币账单可展开、分页查看。

- **扫雷**：初级 8×8／10 雷、中级 16×16／40 雷、高级 16×30／99 雷；赚钱局分别花 5／20／50 喵币，通关分别得 10／40／100 喵币。支持左键、右键标旗与问号、双击数字展开，首击安全。
- **2048**：赚钱局花 20 喵币，结束时按本局最高数字一次结算：256 得 10、512 得 25、1024 得 50、2048及以上得 200 喵币，不累加各档奖励。

扫雷与2048各自每天最多5局赚钱局，免费游玩不限次数且不扣币、不领奖；未结束的棋盘重开后恢复，不重复收取入场费。

支持安装本地 `.yanmew-game` 包，查看插件详情、停用、卸载或清除数据并重载。自带游戏不可卸载。“清除数据并重载”重置存档、自有设置和授权，保留全局余额及已发生的账单。

小游戏可申请喵币或联网权限，由用户确认；玩法、局数限制和进度由插件自行管理。当前通过本地安装包扩展，不提供内置在线插件商店。

想制作小游戏？先看[小游戏插件开发与发布教程](plugins/sdk/README.md)：从零写一个可保存进度的猜数字游戏，逐项介绍 manifest、全部11个宿主方法、喵币与联网权限、存档迁移、调试、打包及发布投稿。另有[最小模板](plugins/template/)和[自带小游戏源码](plugins/first-party/README.md)。

## 开始使用

### 1. 安装或解压

前往 [GitHub Releases](https://github.com/xianyvqiu/yanmew/releases)，以页面实际提供的附件为准；没有发布附件时，可按下方说明从源码构建。

- **安装版**：运行 `YanMew-版本号-setup.exe`，按中文向导安装，可创建桌面快捷方式。缺少 WebView2 时，安装器需要联网补装。
- **便携版**：完整解压 ZIP 到可写目录，双击 `yanwenzi.exe`。不要直接在压缩包中运行，也不要只复制 EXE；旁边的 DLL 和 `resources/` 都需要保留。

普通使用无需安装 Node.js、Rust 或 Python。便携版需要系统已安装 WebView2 Runtime。

首次启动会创建默认“电子小猫”和带一条产品介绍的初始会话。四位图片人设也会加入列表，新安装时各有一个普通默认会话；已有用户首次使用包含这些资源的新版时，会保留原来的当前人设与历史。

### 2. 配置聊天

1. 宠窗右上角 **`…` → 设置 → 提供商**，添加连接名称、Base URL 和自己的 API Key。
2. 在聊天用途配置中选择连接、填写模型名并保存，测试连接。
3. 点击宠窗底部聊天图标开始输入，或通过 **`…` → 聊天详情** 打开完整聊天界面。

通用连接可供**聊天、记忆、识图、生图**复用，各用途单独选择模型。记忆和识图可以跟随聊天；单独配置识图时，先由识图模型理解图片，再交给聊天模型回答。对应服务仍需支持所选用途的接口与能力，填写模型名称不会自动赋予它识图或生图能力。

最大输出默认 **32768 tokens**，可以在高级配置中调整；实际生效值还受服务商限制。

### 3. 按需配置可选能力

- **记忆检索**：完整分发包自带本地 `BAAI/bge-small-zh-v1.5`。也可在独立的 Embedding 配置中选择联网服务；本地模型不可用时退回全文检索，不自动上传记忆。
- **联网搜索**：默认关闭。支持 **Tavily、博查、自定义 Tavily 兼容接口**，填入自己的 Key 后开启。网页读取能否成功取决于站点和服务，不保证能打开登录页或所有网页。
- **生图与图片创作**：配置并开启生图用途。参考初始形象生成表情需要所选模型支持参考图；已适配的官方服务使用对应原生协议，其他服务需兼容图片编辑接口。图片须通过透明检测或本地抠图，先预览再接受。手动上传不需要生图服务。
- **图片模式**：“设置 → 人设”切换预置伙伴，或在“桌宠自定义创作”中为当前人设建立图片库；新开启时需要已接受的初始图及待机图。
- **邮件提醒**：“设置 → 通用”分别填写发信邮箱、收信邮箱，按页面引导获取 SMTP 授权码并完成验证码验证。常见邮箱会预填服务器配置。

联网请求的额度与费用由对应服务商计算，与游戏中的喵币无关。

## 数据与备份

**本地保存不等于所有功能离线。** 聊天、记忆生成和识图会将所需内容发送给所选模型服务；生图、搜索、天气和邮件按各自配置联网。本地 Embedding 在本机处理检索，不需要上传记忆。

- **重复打开**：同一份数据只运行一个实例，再次启动会唤出已有宠窗；不同数据目录可独立同时运行。当前便携构建已包含此规则。
- **便携版数据**：EXE 同目录的 `data/`，数据库为 `data/yanwenzi.db`。
- **安装版数据**：`%LOCALAPPDATA%\YanMew\data`，与便携版分开，不自动合并。
- **密钥**：API Key、SMTP 授权码通过 Windows DPAPI 加密保存，不随备份导出；换电脑后重新配置。
- **导出**：通用设置支持全量、人设、会话、用户设定及小游戏插件使用数据等范围。随包模型、可重建索引和小游戏程序包不进入数据备份。
- **导入**：部分资料按预览关联人设并追加会话；小游戏数据不重放历史喵币变化，权限需要重新确认。

> **全量恢复会替换全局设置、喵币钱包及账单、现实账本（资产、预算与周期）等数据。** 它与普通资料追加不同，确认前请阅读预览并备份当前内容。

升级或移动便携版前，请完全退出并保留原 `data/`。安装版升级保留个人数据；**主动卸载安装版会删除该安装版的全部个人数据**，需要保留的内容请先导出。

## 常见问题

<details>
<summary><strong>关闭聊天窗口，为什么宠物还在？怎么完全退出？</strong></summary>

关闭聊天详情、设置窗口或隐藏宠窗不等于退出。在系统托盘图标右键选择“退出”，或使用通用设置中的退出入口。

</details>

<details>
<summary><strong>能完全离线聊天吗？</strong></summary>

应用不附带本地聊天模型。内置 Embedding 只用于记忆检索；聊天需要你配置可访问的模型服务。提醒、资料管理和小游戏等不需要每次都调用聊天模型。

</details>

<details>
<summary><strong>为什么选了图片人设，却不能生成新表情？</strong></summary>

预置形象可以直接使用；生成新表情还需要开启生图用途，并选择支持参考图输入与图片输出的模型。生成结果先检查透明背景，不透明时才尝试本地抠图，成功后进入预览，由你检查接受；失败保留旧图并提示原因。

</details>

<details>
<summary><strong>为什么提醒没有立即发到邮箱？</strong></summary>

请确认已经绑定收信邮箱并开启邮件提醒，应用正在运行，SMTP 配置有效。关闭应用期间不能实时发送，重新打开后会汇总过期事项；发送失败可在通用设置查看原因。

</details>

## 本地开发

### 环境与启动

在 Windows 上准备 **Node.js 20+、npm、Rust stable（MSVC）、Visual Studio C++ 构建工具及 WebView2 Runtime**。在项目根目录执行：

```powershell
npm ci
npm run tauri dev
```

`tauri dev` 会构建自带小游戏、启动前端服务和桌面应用；`npm run dev` 只启动前端，不能代替完整桌面环境。本地 Embedding 资源的准备和校验见 [资源说明](resources/README.md)。

### 构建

```powershell
# 编译 release 程序，不组装完整分发包
npm run tauri build -- --no-bundle

# 构建并组装完整便携版：程序、模型、小游戏、运行库和许可证
./scripts/build-portable.ps1

# 构建安装向导与卸载程序
./scripts/build-installer.ps1
```

发布产物写入 `releases/构建时间/`，包含完整程序目录、分发包与 SHA-256 校验文件。刚成功编译过 release 时，两个打包脚本均可加 `-SkipBuild` 复用编译结果；打包前须准备好资源说明中列出的文件，并退出正在使用的旧程序。

安装包使用中文 NSIS 向导，可选择安装目录与桌面快捷方式；具体构建条件、安装和卸载规则见 [安装与发布设计](docs/安装与发布设计.md)。

### 技术与目录

**Tauri 2 + Rust** 承载桌面与业务服务，**React 18 + TypeScript + Vite** 构建界面，**SQLite** 持久化数据，**FTS5 + Embedding** 支持混合记忆检索。本地 Embedding 使用 ONNX Runtime，在 CPU 上运行，无需 Python 或 CUDA。

```text
src/          React 页面、组件、状态与桌面接口
src-tauri/    Rust 业务、模型服务、调度与平台适配
plugins/      小游戏 SDK、模板、第一方游戏与打包工具
db/           SQLite schema、迁移与结构检查
docs/         正式设计、接口与验收文档
resources/    随包模型、图片人设、小游戏、日历及许可声明
scripts/      可复用的构建与资源准备工具
```

本地的 `my_doc/` 仅放开发过程记录与附件，`releases/` 放发布产物，`.test-temp/` 放临时测试与资源转换材料；三者均由 Git 忽略，不作为正式文档或源码依赖。
