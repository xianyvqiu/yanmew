测试环境

建议的执行顺序

1. 第一遍：基本使用。 做 A–F、I–K、O–P 中不需要等待的项目。先确认窗口、配置、聊天、日历、小游戏和外观能用。

2. 第二遍：AI 与保存。 做 G–H、L、N、Q 以及重启项目。需要你自己的可用服务；生图、搜索等按实际配置执行，不强制为验收购买服务。

3. 第三遍：长期行为与恢复。 做 M、R–T。出行、睡眠、离线提醒等分开观察；破坏性项目只在测试副本中执行。

测试资料准备

- 建议从本次 ZIP 另行解压一份完整目录作为测试副本；路径可含中文和空格。确认该副本首次启动前没有 data 目录，才能测首次初始化。已有数据的目录不会再次播放首次教程。

- 只运行一份颜喵。切换测试目录前先从托盘退出，避免把其他副本的窗口误当成本次结果。

- 准备一张背景图、一张普通不透明图片、一张有透明区域且含可见角色的静态 PNG 或 WebP，以及另一张有明显差异的透明表情图。没有这些素材的相关项写“未测”，不要随意改文件扩展名冒充图片。

- 统一使用易辨认的测试名称：人设“测试人设甲”、用户设定“测试资料甲”、会话“验收甲 / 验收乙”。不要用真实隐私测试导出及截图。

- 修改计时、档位、价格、记忆参数前，先截图原值；测试后恢复。不得为加速验收直接改数据库、系统日期或制造超大请求。

- 下文标注 【API】 的项目需要相应服务；【长时】 可留到之后观察；【副本】 会删除或恢复数据，只在可丢弃测试副本进行。
