## F. 正常聊天、流式与中断

本组需要聊天模型。每项使用测试会话；判断保存时请同时查看宠窗与聊天详情。模型服务不可用则写“未测”，不要勾选。

- [ ] **F01【API】基本流式。** 操作：发送“用三段话介绍一下你自己”。通过标准：消息只提交一次，正文逐步显示；完成后重开窗口仍在，顺序和内容不变。
- [ ] **F02【API】宠窗快捷聊天同步。** 操作：在宠窗输入后发送，同时查看聊天详情。通过标准：头顶气泡流式显示同一条回复；详情中是同一回合，未重复调用、重复保存或漏用户消息。
- [ ] **F03【API】详情入口同步。** 操作：从详情页发送，再查看宠窗与会话记录。通过标准：仍使用当前会话，没有另建“宠窗专用”历史；切换窗口不会丢进行中的回复。
- [ ] **F04【API】发送与空输入。** 操作：尝试发送空白，再正常发一次，生成过程中重复点击发送。通过标准：空白不提交；不会并发生成重复回合；按钮状态、文字颜色可读。
- [ ] **F05【API】手动中断。** 操作：请求较长说明，收到一部分后点击停止。通过标准：停止继续追加，部分回复与用户消息保留；重开窗口可见中断状态，能正常发下一条。
- [ ] **F06【API】切换中的取消。** 操作：生成时切换会话，再切换人设。通过标准：旧请求不向新会话追加内容、表情或记忆；已保存旧消息没有跑到别处，新会话能正常聊天。
- [ ] **F07【API】连接故障恢复。** 操作：用测试连接填错模型名发一次，随后改回并重新测试。通过标准：显示具体失败，用户消息和历史没有丢失；修复后能继续，不把连接错误当作睡眠或饥饿。
- [ ] **F08【API】普通内容兼容。** 操作：要求输出中文、英文、列表、一段代码及几个颜文字。通过标准：排版能读，正常颜文字没有被错误检测当作乱码截断；记录区不会撑宽整窗。
- [ ] **F09【API】首次标题。** 操作：在新会话先中断一次，再正常完成一次。通过标准：中断不触发自动标题；首次完整回复后按规则生成标题，手动命名不会被反复覆盖。
- [ ] **F10【API，条件项】输出长度停止。** 操作：仅在愿意测试且模型支持时，临时降低测试用途最大输出，再请求长回答。通过标准：若明确以长度限制停止，显示原因与“继续生成”；主动继续追加同一回合，不复制用户消息。不要为了本项生成数万字，结束后恢复参数。未触发长度停止则记未测。
- [ ] **F11【API，条件项】异常停止反馈。** 操作：正常测试中若遇到长时间无进展、持续重复或乱码，记录现象及停止提示。通过标准：可手动停止，已生成内容保留；系统检测触发时有可理解原因，后续能继续使用。本项没有自然触发就写未测，不要求故意诱导模型死循环。
