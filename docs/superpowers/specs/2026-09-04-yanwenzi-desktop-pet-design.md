# 颜喵 YanMew 设计文档

- 日期：2026-09-04
- 状态：已确认，待进入实现
- 平台：仅 Windows
- 技术栈：Tauri 2（Rust 核心）+ React + TypeScript 前端
- 应用名：颜喵 YanMew

## 1. 目标

做一个常驻 Windows 桌面的颜文字桌宠“颜喵 YanMew”：透明、置顶、可拖动的可爱小窗口，形象全部用颜文字。它能根据用户设置的人设做出不同表情和动作，能与用户聊天、维护会话记忆、创建提醒，并感知时间、地点、天气。

## 2. 功能需求

### 2.1 窗口与外观
- 主宠窗：透明、无边框、置顶；默认位于屏幕右下角（320×240）；可拖动到任意位置，位置会被记住并在下次启动恢复。
- 透明空白区域鼠标点击穿透，只让颜文字本身可交互。
- 聊天窗：独立、轻量、贴近气泡风格的窗口，可拖动、可关闭。
- 设置窗：常规窗口，承载所有配置。
- 记忆小窗：独立小窗，从聊天窗打开，只显示当前会话记忆。
- 系统托盘图标：快速打开设置、退出应用。
- 应用图标：使用用户提供的 `cat_icon.png`（已转为 `src-tauri/icons/icon.png`），用于窗口、任务栏、托盘与便携版 zip。

### 2.2 设置
- API 提供商：可添加多个，每项包含名称、base URL（自定义接口时）、API Key、模型名。
- 聊天当前提供商：可设置一个为当前启用，可随时切换。
- 记忆整合提供商：可单独指定；未指定时默认跟随聊天当前提供商。
- 提供商“测试连接”按钮。
- 人设：可保存多个人设（prompt），可切换当前人设。
- 天气 API Key：可填写和风天气 API Key（可选，加密存储），用于 Open-Meteo 失败时的兜底。
- 时间参数：饥饿、无聊、多久没互动进入睡觉、空闲气泡触发时长，全部可配置。
- 开机自启：可配置，默认关闭。

### 2.3 宠物活动与表情
- 活动：点击互动、移动（拖动）、饿、吃东西、无聊、睡觉、说话、思考中、休眠（错误）。
- 表情库：
  - 创建人设后自动生成一次分类表情库；设置页也提供“生成表情库”按钮手动重新生成。
  - 分类：开心、惊讶、害羞、饿、困、无聊、思考、点击等；不同活动取对应标签，点击在点击类表情中随机。
- 每次说话（聊天回复）由 AI 实时重新生成表情，说话前先切换，不取表情库。

### 2.4 互动方式
- 左键单击：随机点击互动。
- 右键：菜单（聊天、喂食、摸摸、设置、退出等）。
- 退出：关闭整个应用，包括所有窗口、托盘与后台任务。

### 2.5 聊天
- 点击聊天按钮打开轻量聊天窗。
- 回复为流式输出；AI 说话前先切换表情。
- 聊天记录持久化，可在设置中查看。
- 支持新建会话；可查看、切换、继续、删除历史会话。
- 会话按人设隔离：切换人设后历史会话列表随之切换。
- 会话标题：首次发送后由 AI 自动生成，用户可重命名。

### 2.6 空闲气泡
- 长时间没互动时，AI 生成一条消息气泡；触发时长用户可配置。
- 上下文选择：当前会话 → 该人设最近会话 → 人设 + 环境。

### 2.7 错误与休眠
- 无 token、无法连接 API 等异常时进入休眠状态。
- 出现错误显示红色感叹号；点击后显示中文错误提示。
- 后台记忆整合失败：进入休眠 + 红色感叹号；记忆小窗手动操作失败仅在小窗提示。

### 2.8 环境感知
- 时间：由系统提供。
- 地点：Windows 系统定位自动获取，处理定位权限。
- 天气：优先 Open-Meteo（免费、按经纬度）；失败时用和风天气免费版兜底。和风需要在设置中填写 API Key（DPAPI 加密存储），未填写且 Open-Meteo 失败时显示“天气不可用”。

### 2.9 提醒
- 来源：聊天中让 AI 提取并创建；设置中手动创建。
- 类型：一次性、重复（每天/每周/每月，循环规则可配置）；创建时可选类型和循环方式。
- 到点时应用开着：每次到点调用 AI 用人设语气润色成一句气泡，可标记完成；润色失败时回退到原始内容。
- 到点时应用未开：一次性提醒在下次打开时询问“补提醒还是标过期”；重复提醒只补最近一次错过的，其余自动跳过。
- 状态：未完成、完成、已过期。
- 仅到点提醒，不做提前提醒。
- 用户可手动编辑提醒的时间、详情、状态。

### 2.10 v1 不做
- 联网搜索（留待后续迭代）。

## 3. 技术架构

- 桌面壳：Tauri 2（Rust 核心）+ React + TypeScript 前端。
- Rust 核心模块：配置存储、API 提供商管理、人设管理、表情库管理、AI 客户端、宠物状态机、提醒调度、天气与定位服务、会话/记忆/记事本存储。
- 聊天 AI 与记忆整合 AI 拆成两个独立模块。
- 本地数据：SQLite，建库脚本为 `db/schema.sql`，运行库为 `data/yanwenzi.db`。
- 安全：API Key 使用 Windows DPAPI 加密存储。

## 4. 数据模型

完整结构见 `db/schema.sql`。表如下：

- `providers`：id、name、base_url、api_key_encrypted、model、is_active（聊天）、memory_is_active（记忆，为空跟随聊天）。
- `personas`：id、name、prompt、is_active、expressions（分类表情库 JSON）。
- `sessions`：id、persona_id、title、created_at、updated_at、summary_cursor。
- `messages`：id、session_id、role、content、expression、created_at。
- `settings`：key、value（键值对，见 schema 注释）。
- `short_memories`：id、session_id、content、created_at。
- `long_memories`：id、session_id、content、created_at。
- `notebooks`：session_id（主键，一个会话一个记事本）、content、updated_at。
- `reminders`：id、kind、schedule、content、status、fire_at、source、created_at。

删除会话时级联删除该会话的消息、短期记忆、长期记忆、记事本；删除人设时级联删除其所有会话、消息、记忆与记事本（数据库级 `ON DELETE CASCADE`）。

## 5. AI 引擎

- Provider 抽象统一流式协议：官方 OpenAI 与自定义 OpenAI 兼容接口共用一套流式客户端。
- 聊天 AI：使用聊天当前提供商；回复分两步——先决定本次说话表情，再流式输出正文。
- 记忆整合 AI：独立模块，使用记忆专用提供商（默认跟随聊天提供商）。
- 记事本：通过 function calling 调用 `read_notebook` / `update_notebook`；工具调用轮数可配置（默认 3）。
- 空闲气泡：按上下文选择规则生成。
- 错误处理：无 key、连不上、限流等统一进入休眠状态，展示红色感叹号与中文错误。

## 6. 宠物状态机

- 状态：正常、饿、无聊、睡觉、吃东西、说话、思考中、休眠。
- 饥饿按“上次喂食时间”计时；无聊/睡觉按最近互动时间计时；喂食、摸摸、点击分别更新对应计时。
- 饿、无聊状态可弹一条气泡（如“好饿…”“好无聊…”）。
- 表情：点击类随机取点击标签；饿/无聊/睡觉取对应标签；说话用实时生成表情。

## 7. 记忆与记事本（会话级）

### 7.1 隔离范围
- 记事本、短期记忆、长期记忆均按会话隔离。

### 7.2 AI 上下文组装（顺序）
系统提示词 → 其他提示词（时间/地点/天气 + 工具说明 + 当前记忆参数）→ 人设 → 全部长期记忆 → 尚未整合的短期记忆 → 最近 30 条消息原文。

### 7.3 记事本
- AI 通过 function calling 调用 `read_notebook` / `update_notebook`。
- `update_notebook` 用结构化操作：追加 / 替换某段 / 删除某段 + 内容；段落按空行分隔、从 1 开始编号，用 `section_index` 定位。
- AI 自己决定是否读写；每次回复最多调用工具的轮数用户可配置，默认 3。
- 记事本长度上限用户可配置，默认 4000 字；超限时提示 AI 删除/精简。
- 用户可在记忆小窗查看并手动编辑记事本。

### 7.4 记忆生成（后台异步，回复完成后检查）
- 最近 30 条之外的旧消息，按连续 10 条一组生成 1 条短期记忆；用 `summary_cursor` 避免重复生成。
- 满 10 条短期记忆 → AI 整合成 1 条长期记忆，然后删除那 10 条短期记忆。
- 长期记忆不设自动上限，全部进上下文。
- 记忆内容为中性事实记录，不带人设语气。
- 后台整合若无可用 API 或调用失败：立即进入休眠 + 红色感叹号。

### 7.5 记忆管理小窗
- 独立小窗，从聊天窗打开，自动跟随聊天窗当前会话。
- 显示短期记忆、长期记忆、记事本。
- 单条短期/长期记忆可手动编辑、删除；不支持手动新建，不支持 AI 重写。
- 长期记忆：选中连续几条 → AI 合并 → 弹窗预览（可手动改）→ 确认后才替换。
- 手动合并失败：仅在小窗提示，不触发休眠。

### 7.6 记忆参数（均可在记忆管理中配置）
- 短期记忆字数范围（中文汉字）。
- 长期记忆字数范围（中文汉字）。
- 手动合并字数范围（中文汉字）。
- 工具调用轮数（默认 3）。
- 记事本长度上限（默认 4000 字）。
- AI 按参数撰写记忆，不硬截断。

## 8. 会话与消息操作

### 8.1 会话
- 删除会话：级联删除该会话的消息、短期记忆、长期记忆、记事本。
- 会话标题：首次发送消息后由 AI 自动生成；用户可在聊天窗或历史中重命名。
- 删除人设：级联删除该人设下的所有会话、消息、短期记忆、长期记忆、记事本。

### 8.2 消息操作（聊天窗）
- 每条消息气泡下提供三个按钮：删除、编辑、重说。
- 删除：只删除该条消息，后续消息保留。
- 编辑：只修改文本，不触发重新生成；用户消息和 AI 消息都可编辑。
- 重说：仅当最后一条消息是 AI 回复时可用；重新生成 AI 对“最后一条用户消息”的回复，并覆盖原 AI 回复。删除最后一条后，若新的最后一条是 AI 回复，则它可重说。

## 9. 提醒系统

- 创建：AI 从聊天提取结构化提醒；设置内手动创建。
- 类型：一次性、重复（每天/每周/每月，循环规则可配置）。
- 触发：应用运行中每次到点调用 AI 用人设语气润色成一句气泡；润色失败时回退到原始内容；可标记完成。
- 关闭期间到期：一次性提醒在下次打开时询问补提醒或标过期；重复提醒只补最近一次错过的，其余自动跳过。
- 状态流转：未完成 → 完成；未完成且已过触发时间 → 已过期。
- 仅到点提醒；用户可手动编辑时间、详情、状态。

## 10. 天气与定位

- 定位：Windows 系统定位（需处理系统位置权限，失败时提示）。
- 天气：Open-Meteo 优先，失败时用和风天气免费版兜底；和风 API Key 在设置中配置（DPAPI 加密存储），未配置且 Open-Meteo 失败时显示“天气不可用”。
- 时间/地点/天气在相关时注入 AI 上下文。

## 11. 应用名、默认人设与开机自启

- 应用名与窗口标题使用 **颜喵 YanMew**；`tauri.conf.json` 的 `productName` 与 `identifier` 更新为 `颜喵 YanMew` 与 `com.yanmew.pet`。
- 首次启动且无人设/未配置时，自动使用内置默认人设 **喵喵桌宠**，并在界面提醒用户去设置。
- 开机自启：使用 Tauri autostart 插件，默认关闭。

## 12. 发布与存储位置

- 发布形态：Windows 便携版 zip，解压即用。
- 代码：`src/`、`src-tauri/`。
- 建库脚本：`db/schema.sql`。
- 运行数据库：应用目录下 `data/yanwenzi.db`（与可执行文件同目录，首次启动自动创建）。
