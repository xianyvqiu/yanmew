# 颜喵 YanMew 设计文档

- 日期：2026-09-08
- 状态：已确认，待进入实现
- 平台：仅 Windows
- 技术栈：Tauri 2（Rust 核心）+ React + TypeScript 前端
- 应用名：颜喵 YanMew

## 1. 目标

做一个常驻 Windows 桌面的颜文字桌宠“颜喵 YanMew”：透明、置顶、可拖动的可爱小窗口，形象全部用颜文字。它能根据用户设置的人设做出不同表情和动作，能与用户聊天、维护会话记忆、创建提醒，感知时间、地点、天气，并按会话进行旅行、写信、伴手礼、亲密度与饰品养成；数据支持备份、导入导出和跨设备迁移。

## 2. 功能需求

### 2.1 窗口与外观

- 主宠窗：透明、无边框、置顶；默认位于屏幕右下角（320×240）；可拖动到任意位置，位置会被记住并在下次启动恢复。
- 透明空白区域鼠标点击穿透，只让颜文字本身和可交互控件接收鼠标事件。
- 桌宠形象分两层：基础颜文字 + 头顶饰品层；饰品默认隐藏，佩戴后显示。基础颜文字颜色按人设绑定，饰品层不跟随该颜色。
- 气泡显示在桌宠上方；聊天/写信、显示/隐藏宠窗、设置、红色感叹号等控件并排在桌宠右上角。
- 隐藏宠窗后，桌面上只保留一个“显示宠窗”按钮。
- 聊天窗：独立、轻量、贴近气泡风格的窗口，可拖动、可关闭；支持按人设设置背景图、透明度和模糊度，聊天窗内也能修改背景。
- 设置窗：常规窗口，左侧分“全局设置”和“桌宠与内容”两组。
- 记忆小窗：独立小窗，从聊天窗打开，只显示当前会话记忆。
- 系统托盘图标：快速打开设置、退出应用。
- 应用图标：使用用户提供的 `cat_icon.png`（已转为 `src-tauri/icons/icon.png`），用于窗口、任务栏、托盘与便携版 zip。

### 2.2 设置

设置窗左侧分两组：**全局设置** 和 **桌宠与内容**。会话与聊天记录不在设置窗，统一放在聊天窗。

**全局设置**

- API 提供商：可添加多个，每项包含名称、base URL（自定义接口时）、API Key、模型名；可测试连接。
- 聊天当前提供商：可设置一个为当前启用，可随时切换。
- 记忆整合提供商：可单独指定；未指定时默认跟随聊天当前提供商。
- 人设：可保存多个人设、切换当前人设；包含当前人设、初始设定、本体颜色、自调开关、聊天窗背景和表情库查看。
- 用户设定：可保存多个用户自己的背景/设定；每个仅含名称和内容；会话可选绑定一个，未绑定则为空。
- 提醒：手动创建、查看、编辑、标记完成/过期。
- 时间与天气：和风天气 API Key、定位状态、天气来源。
- 通用：开机自启、版本信息、退出应用、导入与导出。

**桌宠与内容**

- 桌宠状态：当前会话亲密度、全局喵币、每日签到、石头剪刀布。
- 时间与桌宠：饥饿触发时长、无聊触发时长、睡眠时长范围、空闲气泡触发时长。
- 记忆：短期/长期/手动合并字数范围、记事本工具每次 AI 调用轮数、记事本长度上限。
- 出行：邮箱、伴手礼、出行历史；不显示会话选择。
- 饰品：当前会话饰品管理、佩戴/卸载/卖出/删除。

### 2.3 桌宠活动与表情

- 活动：点击互动、移动（拖动）、饿、吃东西、无聊、睡觉、说话、思考中（仅聊天/工具调用）、休眠（错误）。
- 表情库：
  - 创建人设后自动生成一次分类表情库；设置页也提供“生成表情库”按钮手动重新生成。
  - 分类：点击（开心/惊讶/害羞）、饿、吃东西、困、无聊、思考；不同活动取对应标签，点击在点击分类的开心/惊讶/害羞中随机。
- 每次说话（聊天回复）由 AI 实时重新生成表情，说话前先切换，不取表情库；表情使用所属人设的本体颜色。
- 出门中：主宠窗不显示“出门中表情”，只显示文字“`{当前人设名}出门啦`”；聊天按钮变为“写信”。
- 记忆整合在后台运行，不触发“思考中”表情。

### 2.4 互动方式

- 左键单击：随机点击互动。
- 右键：菜单（聊天、喂食、摸摸、桌宠状态、饰品、设置、退出等）。
- 主宠窗右上角并排控件：聊天/写信、显示/隐藏宠窗、设置；错误时显示红色感叹号。
- 隐藏宠窗后，桌面上只保留一个“显示宠窗”按钮。
- 出门中时点击、摸摸、喂食不增加亲密度，只弹“它出门啦”之类气泡。
- 退出：关闭整个应用，包括所有窗口、托盘与后台任务。

### 2.5 聊天

- 点击聊天按钮打开轻量聊天窗。
- 回复为流式输出；AI 说话前先切换表情。
- 流式回复期间发送按钮变为“暂停”，点击可中断当前 AI 回复。
- 聊天记录、历史会话、新建会话、切换会话和重命名都在聊天窗内完成，不放在设置窗。
- 会话按人设隔离：切换人设后历史会话列表随之切换。
- 会话可绑定一个用户设定；未绑定则为空，可在聊天窗修改绑定。
- 聊天窗背景可在聊天窗内修改，也可在人设设置中修改。
- 若当前会话的 AI 正在出门，聊天窗只显示写信入口，不展示聊天会话；主宠窗聊天按钮变为“写信”。

### 2.6 空闲气泡

- 长时间没互动时，AI 生成一条消息气泡；触发时长在“时间与桌宠”中配置。
- 上下文选择是代码层固定规则：当前会话 → 该人设最近会话 → 人设 + 环境；前端不提供选择或查看。

### 2.7 错误与休眠

- 无 token、无法连接 API 等主流程异常时进入休眠状态。
- 出现错误显示红色感叹号；点击后显示中文错误提示。
- 休眠状态下 AI 不主动说话，所有依赖 AI 的操作（聊天、写信、生成表情、人设自调等）不可用。
- 后台记忆整合失败：显示红色感叹号并提示，但不阻塞聊天、不进入休眠；主流程 API 不可用时才休眠。
- 记忆小窗手动合并失败仅在小窗提示；旅行总结生成失败不影响旅行返回结果。

### 2.8 环境感知

- 时间：由系统提供。
- 地点：Windows 系统定位自动获取，处理定位权限。
- 天气：优先 Open-Meteo（免费、按经纬度）；失败时用和风天气免费版兜底。和风需要在设置中填写 API Key（DPAPI 加密存储），未填写且 Open-Meteo 失败时显示“天气不可用”。

### 2.9 提醒

- 位置：全局设置 > 提醒；来源：聊天中让 AI 提取并创建，或用户手动创建。
- 类型：一次性、重复（每天/每周/每月，循环规则可配置）；创建时可选类型和循环方式。
- 到点时应用开着：每次到点调用 AI 用人设语气润色成一句气泡，可标记完成；润色失败时回退到原始内容。
- 到点时应用未开：一次性提醒在下次打开时询问“补提醒还是标过期”；重复提醒只补最近一次错过的，其余自动跳过。
- 状态：未完成、完成、已过期。
- 仅到点提醒，不做提前提醒。
- 用户可手动编辑提醒的时间、详情、状态。

### 2.10 人设自调

- 每个人设单独开关，默认开启。
- 聊天回复完成后，AI 按需判断是否需要调整，不是每轮都调用；调整通过 function call 直接改写当前人设文本。
- 调整约束：只做小幅、有意义的调整，保持原人设核心；v1 不保存修改历史。
- 调整成功后在桌宠弹气泡提示，设置页人设卡片显示“最近 AI 调整过”。
- 用户可手动编辑当前人设；可点击“保存为初始设定”更新初始设定；可点击“从初始设定恢复”并在确认后覆盖当前人设。

### 2.11 亲密度与喵币

- 亲密度按会话绑定，删除会话一并删除。
- 亲密度初始为 0；聊天完成一轮 +1，点击、摸摸、喂食各 +1。
- 解锁档位默认：10 / 50 / 150 / 300，设置里可改。
- 喵币为全局用户级，删除会话不影响。
- 喵币初始为 0。
- 每日签到：本地时间每天 0 点刷新，每次随机获得 1–10 喵币。
- 石头剪刀布：用户选择剪刀/石头/布，系统随机出；赢 +5、输 -4、平局 0；开始前余额必须 ≥ 4；每天最多 20 次。
- 喵币目前只用于制作饰品；卖出饰品固定获得 10 喵币。

### 2.12 饰品

- 饰品按会话绑定，删除会话一并删除。
- v1 只做 1 个头顶装饰槽，允许“少量 emoji + 颜文字/符号”，前端限制长度和字符集。
- AI 在达到亲密度解锁档位后可发起制作请求；10/50/150 档各限 1 次，300 档后不限。
- 制作费用默认：20 / 50 / 120 / 300 喵币；300 档后每次固定 300，设置里可改。
- 用户确认“给你买”且余额足够时扣款制作；余额不足点“没有钱了”则暂不制作。
- 用户拒绝后，AI 至少间隔 1 小时，或下次启动应用后，才能再次请求。
- AI 制作的饰品可以选择佩戴或不佩戴；用户可手动穿戴、卸载、删除未佩戴饰品，删除不可恢复；未佩戴饰品可卖出，固定获得 10 喵币。
- 每件饰品都有 AI 按人设口吻写的简介。
- 设置 > 桌宠与内容 > 饰品 管理；右键菜单提供“饰品”快捷入口。

### 2.13 旅行、写信与伴手礼

- 旅行、信件、伴手礼均按会话绑定，删除会话一并删除。
- 出行状态只有：在家、出门中。
- 出行触发：仅应用开启且桌宠空闲时；距离上次回来累计在线 4–24 小时随机触发，出行时长 1–3 小时。
- 触发时先弹气泡，再进入出门中状态；主宠窗只显示文字“`{当前人设名}出门啦`”，聊天按钮变为“写信”。
- AI 出门期间，主宠窗和聊天窗不展示聊天会话，只提供写信入口。
- 出门期间：AI 发 1 封途中信，返回时生成 1 封回来信；AI 生成的信件内容应包含可爱颜文字。用户可写多封信，每封都会回信，回信延迟默认 10–30 分钟随机。
- 写信界面提供“跳转邮箱”按钮，可打开邮箱管理。
- 回信机制：每封信只能回复一次；已回复的信不能再回。
- 应用关闭时：
  - 旅行间隔只累计应用开启时间；关闭期间不新触发旅行。
  - 若 AI 已出门，下次启动按真实时间差判断：若已到返回时间，则标记为已回来、带回伴手礼并补生成 1 封回来信；若未到返回时间，则继续出门。
- 每次旅行回来带 1 件伴手礼；其中 10% 概率是可佩戴饰品，90% 概率是普通文字礼物。
- 可佩戴饰品免费获得，进入饰品管理；普通文字礼物进入伴手礼管理。
- 文字伴手礼必须包含 AI 按当前人设口吻写的备注。
- 回来后 AI 用记忆整合 provider 生成 1 条短期记忆，总结出行时间、时长、做了什么、写了什么信、带了什么回来；应用关闭期间返回则下次启动后台补生成。
- 设置 > 桌宠与内容 > 出行 下管理邮箱与伴手礼；该页面不显示会话选择，数据默认跟随最近使用的会话。
- 邮箱：查看、收藏、删除、回信。
- 伴手礼：文字礼物列表，支持查看、收藏、删除；不做背包、数量、容量或使用机制。

### 2.14 导入、导出与迁移

- 导入导出放在“全局设置 > 通用 > 导入与导出”。
- 支持五级导出：
  - 全量备份：导出除 API Key 密文外的全部业务数据，以及 `data/chat_background/` 下被引用的背景图片。
  - 人设资料包（分享用）：只导出指定人设的名称、当前人设文本、初始设定文本、本体颜色、自调开关、聊天窗背景设置与背景图、表情库；不导出会话、聊天记录、记忆、记事本、旅行、信件、伴手礼、饰品、亲密度和喵币。
  - 人设完整包（迁移用）：导出指定人设、其所有会话，以及这些会话的消息、记忆、记事本、饰品、旅行、信件、伴手礼和引用的背景图。
  - 会话包：导出指定会话及其消息、记忆、记事本、饰品、旅行、信件、伴手礼。
  - 用户设定包：导出指定用户设定；也可选择同时导出绑定它的会话。
- 文件格式：`.yanmew-backup.zip`，内含 `manifest.json`、`data.json` 和 `files/` 目录；Rust 层负责打包与校验。
- 导入策略：默认按“新建副本”导入并重新生成内部 ID。人设资料包（分享用）只允许新建副本，名称冲突时自动重命名；其他备份包可选择“覆盖同名项”，覆盖前必须二次确认。
- 安全：API Key 和和风天气 API Key 是 Windows DPAPI 机器绑定数据，不导出明文或密文；导入后在对应设置中重新填写。
- 导入导出失败、文件损坏、版本不兼容时，前端显示中文错误，不写入半成品数据。
- 便携版数据目录 `data/` 可直接整目录复制，作为更简单的冷备份方式。

### 2.15 v1 不做

- 联网搜索（留待后续迭代）。
- 图片素材型饰品/旅行礼物（v1 全部使用文字与颜文字）。

## 3. 技术架构

- 桌面壳：Tauri 2（Rust 核心）+ React + TypeScript 前端。
- Rust 核心模块：配置存储、API 提供商管理、人设管理、用户设定、表情库管理、AI 客户端、桌宠状态机、提醒调度、天气与定位服务、会话/记忆/记事本存储、喵币、饰品、旅行、邮箱、伴手礼、导入导出。
- 聊天 AI 与记忆整合 AI 拆成两个独立模块。
- 本地数据：SQLite，建库脚本为 `db/schema.sql`，运行库为 `data/yanwenzi.db`。
- 安全：API Key 使用 Windows DPAPI 加密存储。
- 流式聊天：聊天 AI 先返回表情决策，再以 SSE/增量事件流式输出正文；前端可发送中断命令。

## 4. 数据模型

完整结构见 `db/schema.sql`。表如下：

- `providers`：id、name、base_url、api_key_encrypted、model、is_active（聊天）、memory_is_active（记忆专用；为 0 时跟随聊天）。
- `personas`：id、name、prompt（当前人设）、initial_prompt（初始设定）、self_evolve_enabled、last_evolved_at、color（本体颜色）、chat_bg_file、chat_bg_opacity、chat_bg_blur、is_active、expressions（分类表情库 JSON）。
- `user_profiles`：id、name、content、created_at、updated_at。
- `sessions`：id、persona_id、user_profile_id、title、created_at、updated_at、summary_cursor、intimacy、last_return_at、active_seconds_since_return、next_travel_after_seconds。
- `messages`：id、session_id、role、content、expression、created_at。
- `settings`：key、value（键值对，见 schema 注释）。
- `short_memories`：id、session_id、content、source_type、source_ref_id、created_at。
- `long_memories`：id、session_id、content、created_at。
- `notebooks`：session_id（主键，一个会话一个记事本）、content、updated_at。
- `reminders`：id、kind、schedule、content、status、fire_at、source、created_at。
- `user_state`：id（固定为 1）、coins、updated_at。
- `currency_ledger`：id、delta、reason、ref_id、created_at。
- `accessories`：id、session_id、name、display_text、description、cost、source、travel_id、is_worn、created_at。
- `travels`：id、session_id、status、started_at、planned_return_at、actual_return_at、created_at。
- `letters`：id、session_id、travel_id、sender、content、reply_to_id、is_favorite、is_read、created_at。
- `souvenirs`：id、session_id、travel_id、content、note、is_favorite、created_at。

删除会话时级联删除该会话的消息、短期记忆、长期记忆、记事本、饰品、旅行、信件、伴手礼；删除人设时级联删除其所有会话及会话级数据（数据库级 `ON DELETE CASCADE`）；删除用户设定时保留会话，仅把会话的 `user_profile_id` 置空。喵币与账单是全局用户级数据，不随会话或人设删除。

## 5. AI 引擎

- 聊天 AI：使用聊天当前提供商；回复分两步——先决定本次说话表情，再流式输出正文；流式期间支持中断。
- 记忆整合 AI：独立后台模块，使用记忆专用提供商（默认跟随聊天提供商）；不注入人设、不显示思考中表情、不阻塞聊天。
- 记事本：通过 function calling 调用 `read_notebook` / `update_notebook`；“记事本工具每次 AI 调用轮数”可配置（默认 3）。
- 人设自调：聊天回复后由聊天 AI 按需判断是否调用人设修改工具，不是每轮都调用。
- 上下文组装顺序：系统提示词 → 时间/地点/天气 + 工具说明 + 记忆参数 → 用户设定（如绑定）→ 人设 → 全部长期记忆 → 尚未整合的短期记忆 → 最近 30 条消息原文。
- 旅行相关生成：途中信、回信使用当前会话人设、记忆与记事本，AI 生成的信件内容应包含可爱颜文字；旅行总结由记忆整合 AI 生成。
- 空闲气泡：按代码层固定上下文规则生成。
- 错误处理：无 key、连不上、限流等主流程异常统一进入休眠状态，展示红色感叹号与中文错误。

## 6. 桌宠状态机

- 状态：正常、饿、无聊、睡觉、吃东西、说话、思考中、休眠；出行使用独立的“出门中/在家”状态。
- 饥饿按“上次喂食时间”计时；无聊/睡觉按最近互动时间计时；喂食、摸摸、点击分别更新对应计时。
- 睡觉不是用户唤醒时，睡眠时长从“睡眠最短/最长分钟数”随机取，默认 60–120 分钟。
- 饿、无聊状态可弹一条气泡（如“好饿…”“好无聊…”）。
- 表情：点击类随机取点击分类中的开心/惊讶/害羞；饿取“饿”，吃东西取“吃东西”，睡觉取“困”，无聊取“无聊”，思考取“思考”；说话用实时生成表情。
- 出门中：主宠窗只显示文字“`{当前人设名}出门啦`”，聊天按钮变为“写信”，点击/摸摸/喂食不增加亲密度。

## 7. 记忆与记事本（会话级）

### 7.1 隔离范围

- 记事本、短期记忆、长期记忆均按会话隔离。

### 7.2 AI 上下文组装（顺序）

系统提示词 → 其他提示词（时间/地点/天气 + 工具说明 + 当前记忆参数）→ 用户设定（如绑定）→ 人设 → 全部长期记忆 → 尚未整合的短期记忆 → 最近 30 条消息原文。

### 7.3 记事本

- AI 通过 function calling 调用 `read_notebook` / `update_notebook`。
- `update_notebook` 用结构化操作：追加 / 替换某段 / 删除某段 + 内容；段落按空行分隔、从 1 开始编号，用 `section_index` 定位。
- AI 自己决定是否读写；“记事本工具每次 AI 调用轮数”用户可配置，默认 3。
- 记事本长度上限用户可配置，默认 4000 字；超限时提示 AI 删除/精简。
- 用户可在记忆小窗查看并手动编辑记事本。

### 7.4 记忆生成（后台异步，回复完成后检查）

- 记忆整合与聊天 AI 分模块运行，使用记忆专用 provider（默认跟随聊天），不看人设、不显示思考中表情、不阻塞聊天。
- 最近 30 条之外的旧消息，按连续 10 条一组生成 1 条短期记忆；用 `summary_cursor` 避免重复生成。
- 满 10 条短期记忆 → AI 整合成 1 条长期记忆，然后删除那 10 条短期记忆。
- 长期记忆不设自动上限，全部进上下文。
- 记忆内容为中性事实记录，不带人设语气。
- 旅行返回后额外生成 1 条短期记忆，来源标记为 `travel`，参与后续短期记忆合并。
- 后台整合失败仅显示错误提示，不进入休眠、不阻塞聊天；主流程 API 不可用时才进入休眠。

### 7.5 记忆管理小窗

- 独立小窗，从聊天窗打开，自动跟随聊天窗当前会话。
- 显示短期记忆、长期记忆、记事本。
- 单条短期/长期记忆可手动编辑、删除；不支持手动新建，不支持 AI 重写。
- 长期记忆：选中连续几条 → AI 合并 → 弹窗预览（可手动改）→ 确认后才替换。
- 手动合并失败：仅在小窗提示，不触发休眠。

### 7.6 记忆参数（均可在记忆管理中配置）

- 短期记忆字数范围（中文汉字）。
- 长期记忆字数范围（中文汉字）。
- 手动合并字数范围（中文汉字）。
- 记事本工具每次 AI 调用轮数（默认 3）。
- 记事本长度上限（默认 4000 字）。
- AI 按参数撰写记忆，不硬截断。

## 8. 会话与消息操作

### 8.1 会话

- 会话归属一个人设，可绑定一个用户设定；删除用户设定时保留会话并把该会话的用户设定置空为“未绑定”。
- 删除会话：级联删除该会话的消息、短期记忆、长期记忆、记事本、饰品、旅行、信件、伴手礼。
- 会话标题：首次发送消息后由 AI 自动生成；用户可在聊天窗重命名。
- 删除人设：级联删除该人设下的所有会话，以及这些会话的全部会话级数据。

### 8.2 消息操作（聊天窗）

- 每条消息气泡下提供三个按钮：删除、编辑、重说。
- 删除：只删除该条消息，后续消息保留。
- 编辑：只修改文本，不触发重新生成；用户消息和 AI 消息都可编辑。
- 重说：仅当最后一条消息是 AI 回复时可用；重新生成 AI 对“最后一条用户消息”的回复，并覆盖原 AI 回复。删除最后一条后，若新的最后一条是 AI 回复，则它可重说。

## 9. 提醒系统

- 创建：AI 从聊天提取结构化提醒；全局设置 > 提醒中手动创建。
- 类型：一次性、重复（每天/每周/每月，循环规则可配置）。
- 触发：应用运行中每次到点调用 AI 用人设语气润色成一句气泡；润色失败时回退到原始内容；可标记完成。
- 关闭期间到期：一次性提醒在下次打开时询问补提醒或标过期；重复提醒只补最近一次错过的，其余自动跳过。
- 状态流转：未完成 → 完成；未完成且已过触发时间 → 已过期。
- 仅到点提醒；用户可手动编辑时间、详情、状态。

## 10. 天气与定位

- 定位：Windows 系统定位（需处理系统位置权限，失败时提示）。
- 天气：Open-Meteo 优先，失败时用和风天气免费版兜底；和风 API Key 在设置中配置（DPAPI 加密存储），未配置且 Open-Meteo 失败时显示“天气不可用”。
- 时间/地点/天气在相关时注入 AI 上下文。

## 11. 应用名、默认人设与开机自启

- 应用名与窗口标题使用 **颜喵 YanMew**；`tauri.conf.json` 的 `productName` 与 `identifier` 更新为 `颜喵 YanMew` 与 `com.yanmew.pet`。
- 首次启动且无人设/未配置时，自动使用内置默认人设 **喵喵桌宠**，并在界面提醒用户去设置。
- 开机自启：使用 Tauri autostart 插件，默认关闭。

## 12. 发布与存储位置

- 发布形态：Windows 便携版 zip，解压即用。
- 代码：`src/`、`src-tauri/`。
- 建库脚本：`db/schema.sql`。
- 运行数据库：应用目录下 `data/yanwenzi.db`（与可执行文件同目录，首次启动自动创建）。
- 聊天窗背景图片：应用目录下 `data/chat_background/`，数据库只保存相对文件名和设置值。
- 导入导出文件：默认导出到用户选择的目录，文件名 `颜喵YanMew-<时间戳>.yanmew-backup.zip`。

## 13. 里程碑建议

1. 桌面壳与透明置顶可拖动窗口、托盘、隐藏/显示宠窗。
2. 设置页：全局设置（提供商、人设、用户设定、提醒、时间与天气、通用）与桌宠内容（桌宠状态、时间与桌宠、记忆、出行、饰品）。
3. AI 引擎与流式聊天（含暂停中断）、表情库生成、function calling 记事本、人设自调。
4. 桌宠状态机与活动（含喂食计时、睡眠时长、饿/无聊气泡、隐藏宠窗）。
5. 聊天窗会话列表、消息操作与历史记录（会话记录不在设置窗）。
6. 记忆与记事本（短期/长期/整合/记忆小窗，含旅行总结）。
7. 亲密度、喵币与饰品（含饰品卖出）。
8. 旅行、写信、伴手礼与旅行总结。
9. 提醒系统。
10. 天气与定位。
11. 导入、导出与数据迁移。
