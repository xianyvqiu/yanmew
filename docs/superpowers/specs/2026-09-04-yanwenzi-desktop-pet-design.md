# 颜喵 YanMew 设计文档

- 日期：2026-09-19
- 状态：已确认方案按实现计划推进
- 持久化规则：见 `docs/数据库与持久化设计.md`；结构以 `db/schema.sql` 为唯一来源。
- 平台：首版 Windows；架构预留未来 Android 复用，移动端另行实施
- 技术栈：Tauri 2（Rust 核心）+ React + TypeScript 前端
- 应用名：颜喵 YanMew

## 1. 目标

做一个常驻 Windows 桌面的颜文字桌宠“颜喵 YanMew”：透明、置顶、可拖动的可爱小窗口，形象全部用颜文字。它能根据用户设置的人设做出不同表情和动作，能与用户聊天、维护会话记忆、创建提醒，感知时间、地点、天气，并按会话进行旅行、写信、伴手礼、亲密度与饰品养成；数据支持备份、导入导出和跨设备迁移。

## 2. 功能需求

以下功能与窗口交互以 Windows 首版为验收范围。未来 Android 共享聊天、记忆、旅行、钱包、插件协议与数据规则，系统能力经平台适配接入；手机悬浮服务、通知、页面导航和模型资源在后续专项验证。本次不增加 iOS 或跨设备实时同步承诺。架构分工见[项目架构与代码职责](../../项目架构与代码职责.md)。

### 2.1 窗口与外观

- 主宠窗：透明、无边框、置顶；默认位于屏幕右下角（320×240）；可拖动到任意位置，位置会被记住并在下次启动恢复。
- 透明空白区域鼠标点击穿透，只让颜文字本身和可交互控件接收鼠标事件。
- 桌宠形象分两层：基础颜文字 + 头顶饰品层；饰品默认隐藏，佩戴后显示。基础颜文字颜色按人设绑定，饰品层不跟随该颜色。
- 气泡显示在桌宠上方；聊天/写信、显示/隐藏宠窗、设置、红色感叹号等控件并排在桌宠右上角。
- 隐藏宠窗后，桌面上只保留一个“显示宠窗”按钮。
- 聊天窗：独立、轻量、贴近气泡风格的窗口，可拖动、可关闭；支持按人设设置背景图、透明度和模糊度，聊天窗内也能修改背景。
- 设置窗：常规窗口，左侧分“全局设置”和“桌宠与内容”两组。
- 主程序内置亮色和暗色两套主题；可选跟随 Windows、固定亮色或固定暗色，默认跟随系统。主题即时作用于主程序窗口，小游戏插件保持自己的独立视觉。
- 记忆小窗：独立小窗，从聊天窗打开，只显示当前会话记忆。
- 除固定画布的主宠窗外，聊天窗、设置窗、记忆窗、写信窗和出行窗均允许拖动与缩放，并按容器宽度响应式重排。同类窗口只保留一个实例，重复点击入口时聚焦已有窗口；关闭按钮只关闭该窗口。切换人设或会话后，所有已打开的会话级窗口立即刷新并丢弃旧上下文结果。
- 系统托盘图标：快速打开设置、退出应用。
- 应用图标：使用用户提供的 `cat_icon.png`（已转为 `src-tauri/icons/icon.png`），用于窗口、任务栏、托盘与便携版 zip。

### 2.2 设置

设置窗左侧分两组：**全局设置** 和 **桌宠与内容**。会话与聊天记录不在设置窗，统一放在聊天窗。

**全局设置**

- API 提供商：可添加多个，每项包含名称、base URL（自定义接口时）、API Key、模型名；可测试连接。没有提供商时显示“暂无提供商，请先新增”。
- 聊天当前提供商：可设置一个为当前启用，可随时切换。
- 记忆整合提供商：可单独指定；未指定时默认跟随聊天当前提供商。
- 正被聊天或记忆整合使用的提供商不允许删除，必须先切换；其他提供商删除前二次确认。当前联网 Embedding 项同样必须先切换，内置本地 Embedding 项永远不可删除。
- Embedding 模型：独立模块，默认启用随便携版打包的本地 `BAAI/bge-small-zh-v1.5`；也可配置并切换到用户自己的 OpenAI-compatible 联网 Embedding API。
- 人设：可新建、保存和切换多个人设；包含当前人设、初始设定、本体颜色、自调开关、当前与初始的累计差异、聊天窗背景和表情库查看。差异视图以绿色“新增”和红色删除线“删除”共同表达变化，不能只靠颜色；系统默认人设“喵喵桌宠”不可删除，删除其他人设前明确列出级联数据，删除当前人设后切回默认人设。
- 用户设定：可保存多个用户自己的背景/设定；每个仅含名称和内容；会话可选绑定一个，未绑定则为空。
- 提醒：手动创建、查看、编辑、标记完成/过期。
- 时间与天气：和风天气 API Host 与 API Key、定位状态、天气来源与观测时间。
- 记忆：短期记忆字数范围（默认 `12–100` 字）、长期记忆字数范围（默认 `150–250` 字）、每条长期记忆使用的短期记忆数量 `k`（默认 20）、最近消息原文数量（默认 30）、最近长期记忆数量 `m`（默认 30）、旅行游记字数范围（默认 `250–350` 字）、单次回复的工具调用轮数上限与记事本长度上限。
- 通用：主题模式（跟随系统/亮色/暗色）、开机自启、版本信息、退出应用、导入与导出。主题是可随全量备份迁移的全局设置，不与人设或会话绑定。

**桌宠与内容**

- 桌宠状态：当前会话亲密度、全局喵币、每日签到（含节日彩蛋）。
- 游戏中心与插件管理：独立入口，展示随包和本地安装插件；石头剪刀布从这里启动。
- 小游戏插件的界面主题由插件自行决定，不跟随主程序亮色/暗色主题；宿主不向插件传递主题模式或颜色变量。
- 时间与桌宠：饥饿触发时长、无聊触发时长、无互动入睡时长（默认 45 分钟，可修改）、睡眠时长范围，以及四档亲密度阈值与饰品制作价格表单。
- 出行：邮箱、伴手礼、旅行游记、出行历史；不显示会话选择。
- 饰品：当前会话饰品管理、佩戴/卸载/卖出/删除。
- 节日：系统节日（母表，只读）与当前会话节日子表；不显示会话选择，数据跟随当前会话。

### 2.3 桌宠活动与表情

- 活动：点击互动、拖动、桌面游走、饿、吃东西、无聊（可概率主动说话）、睡觉、说话、思考中（仅聊天/工具调用）、休眠（错误）。
- 表情库：
  - 创建人设后自动生成一次分类表情库；设置页也提供“生成表情库”按钮手动重新生成。
  - 分类：点击（开心/惊讶/害羞）、饿、吃东西、困、无聊、思考；不同活动取对应标签，点击在点击分类的开心/惊讶/害羞中随机。
- 每次说话（聊天回复）由 AI 实时重新生成表情，说话前先切换，不取表情库；表情使用所属人设的本体颜色。
- 出门中：主宠窗不显示“出门中表情”，只显示文字“`{当前人设名}出门啦`”；聊天按钮变为“写信”。
- 记忆整合在后台运行，不触发“思考中”表情。

#### 无聊与睡眠的随机分支

- 饥饿、无聊计时和睡眠状态按会话保存，切换时恢复目标会话自己的状态。饥饿和无聊只累计当前会话的有效运行时间，关闭、系统暂停和非当前会话期间不补累计；上次喂食、互动时刻仅作事实记录，不用于计算离线增量。
- 已开始睡眠持久化 UTC 结束时刻，关闭应用或切换会话后仍按真实时间自然经过；恢复时未到期继续睡，到期醒来并开始新的无互动周期。提供商连接错误单独管理，不随会话切换清除。

- `bored_minutes` 与 `sleep_idle_minutes` 默认均为 45 分钟，保留用户可修改的设置；两个条件同时首次满足时按各 50% 随机选择无聊或睡眠。不增加概率设置项。
- 每段无互动周期只决定一次分支，不每个定时 tick 重抽，不在无聊与睡眠间来回跳动。若用户把两项设为不同时间，则先到阈值的有效分支进入；本周期不因另一个阈值随后到达而再次抽取或强行切换。
- 仅在允许进入空闲状态时判定，不覆盖聊天、出门或休眠状态。互动重新开始无互动计时；睡眠结束时开始新的计时周期，避免醒来立即再次入睡。
- 选择无聊不等于立即发送主动消息，主动消息仍遵守现有概率、冷却和同一段无聊最多一条的限制；选择睡眠则只在入睡时抽取一次睡眠持续时间。

### 2.4 互动方式

- 左键单击：随机点击互动。
- 右键：菜单（聊天、喂食、摸摸、桌宠状态、饰品、设置、退出等）。
- 主宠窗右上角并排控件：聊天/写信、显示/隐藏宠窗、设置；错误时显示红色感叹号。
- 隐藏宠窗后，桌面上只保留一个“显示宠窗”按钮。
- 出门中时点击、摸摸、喂食不增加亲密度，只弹“它出门啦”之类气泡。
- 退出：关闭整个应用，包括所有窗口、托盘与后台任务。

### 2.5 聊天

- 点击聊天按钮打开轻量聊天窗。
- 回复为流式输出；AI 说话前先切换表情。
- 流式回复期间发送按钮变为“暂停”，点击可中断当前 AI 回复。
- 聊天记录、历史会话、新建会话、切换会话和重命名都在聊天窗内完成，不放在设置窗。
- 会话按人设隔离：切换人设后历史会话列表随之切换。
- 会话可绑定一个用户设定；未绑定则为空，可在聊天窗修改绑定。
- 聊天窗背景可在聊天窗内修改，也可在人设设置中修改。
- 若当前会话的 AI 正在出门，聊天窗显示状态与写信入口，不展示消息区，并保留切换其他会话入口（切换即取消本次旅行）；主宠窗聊天按钮变为“写信”。

### 2.6 无聊主动消息

- 桌宠进入“无聊”状态后，按概率主动发一条消息气泡；不再使用“空闲气泡”与独立的空闲气泡触发时长设置。
- 是否触发由代码层概率决定，同一段无聊状态与冷却时间内最多发一条，避免刷屏。
- 上下文是代码层固定规则：只使用当前会话的人设、用户设定、记忆、记事本、旅行标题、环境和当天节日；没有当前会话时不触发，不回退到该人设的其他会话。前端不提供选择或查看。
- 与日常聊天共用人设、用户设定、记忆、环境和当天节日母子表上下文；仅触发指令不同，不伪造用户消息。由独立后台任务执行，不阻塞聊天；休眠、出门中、隐藏宠窗或正在聊天时不触发。

### 2.7 错误与休眠

- 无 token、无法连接 API 等主流程异常时进入休眠状态；普通计时循环不能自行解除休眠。
- 用户可点击“刷新”尝试恢复；配置有效提供商或当前聊天提供商测试连接成功也可恢复。恢复失败继续显示错误，不自动重发旧消息。
- 出现错误显示红色感叹号；点击后显示中文错误提示。
- 休眠状态下 AI 不主动说话，所有依赖 AI 的操作（聊天、写信、生成表情、人设自调等）不可用。
- 后台记忆整合失败：显示红色感叹号并提示，但不阻塞聊天、不进入休眠；主流程 API 不可用时才休眠。
- 记忆小窗重新生成或重新整合失败仅在小窗提示；旅行游记生成失败不影响旅行返回结果，并保留 pending 等待重试。

### 2.8 环境感知

- 时间：由系统提供。
- 地点：Windows 系统定位自动获取，处理定位权限。
- 天气：优先 Open-Meteo（免费、按经纬度）；失败时用和风天气免费版兜底。和风需要在设置中填写控制台分配的 API Host 和 API Key（Key 由 DPAPI 加密存储），未填写且 Open-Meteo 失败时显示“天气不可用”。

### 2.9 提醒

- 循环提醒跟随电脑当前时区；不存在的月度日期和夏令时当地时刻跳过，同一时刻重复时只在第一次提醒。一次性提醒按已保存的绝对时间触发。
- 位置：全局设置 > 提醒；来源：聊天中让 AI 提取并创建，或用户手动创建。
- 类型：一次性、重复（每天/每周/每月，循环规则可配置）；创建时可选类型和循环方式。
- 到点时应用开着：每次到点调用 AI 用人设语气润色成独立提醒气泡，可标记完成；润色失败时固定回退为“`{提醒名}事件提醒：{提醒详情}{提醒时间}`”。提醒气泡与聊天气泡使用不同样式。
- 到点时应用未开：下次启动由后端根据持久化时间补记全部过期的一次性提醒；每个循环提醒无论错过多少次只保留一条离线过期记录。下次启动统一提示“`你离开这段时间，{提醒名称1-n}过期了！`”，并记录该汇总已经展示，避免重复弹出。
- 每次触发记录的状态：未完成、完成、已过期。重复提醒点击“完成”仅完成本次，规则继续生效；永久停止只能删除提醒。
- 原定到期时间、过期记录和汇总展示状态必须持久化；用户可在提醒页面手动修改每次触发记录的状态。
- 仅到点提醒，不做提前提醒。
- 用户可手动编辑提醒的时间、详情、状态。

### 2.10 人设自调

- 每个人设单独开关，默认开启。
- 聊天回复完成后，AI 按需判断是否需要调整，不是每轮都调用；调整通过 function call 直接改写当前人设文本。
- 调整约束：只做小幅、有意义的调整，保持原人设核心；v1 不保存修改历史。
- 调整成功后在桌宠弹气泡提示，设置页人设卡片显示“最近 AI 调整过”。
- 设置页可以比较当前 `prompt` 与 `initial_prompt`：新增内容用绿色背景和“新增”标记，删除内容用红色背景、删除线和“删除”标记，未变化内容正常显示；提供行内与左右两种对比方式，窄屏使用行内或上下布局。颜色不是唯一提示，文字标记需要支持辅助技术。
- 该视图表示当前人设相对初始设定的累计差异，包含 AI 自调和用户手动编辑，不能表示每一次 AI 自调的独立历史。比较在前端本地完成，不调用 AI，也不新增差异存储表。
- 用户可手动编辑当前人设；可点击“保存为初始设定”更新初始设定；可点击“从初始设定恢复”并在确认后覆盖当前人设。

### 2.11 亲密度与喵币

- 亲密度按会话绑定，删除会话一并删除。
- 亲密度初始为 0，固定上限 999；聊天完成一轮、点击、摸摸、喂食各 +1，实际新值为 `min(旧值 + 1, 999)`。满值后互动与聊天照常完成，不再增加亲密度；上限不作为可修改设置。四个解锁档位须严格递增且均在 1–999 内。
- 解锁档位默认：10 / 50 / 150 / 300，设置里可改。
- 喵币为全局用户级，删除会话不影响。
- 喵币初始为 0。
- 每日签到：本地时间每天 0 点刷新，无节日时随机获得 1–10 喵币；当天命中节日时固定 10 喵币并直接展示节日祝福词（见 2.15）。
- 每日签到是颜喵应用唯一的全局签到，属于桌宠状态，不属于小游戏或插件协议；插件不能新增另一套应用签到、修改签到状态或写入签到类型流水。
- 石头剪刀布是标准第一方插件，源码位于主仓库并随便携版提供；用户选择剪刀/石头/布，系统随机出，每天最多 20 次。取得喵币权限后赢 +5、输 -4、平局 0，开始前余额必须 ≥ 4；拒绝权限时按纯玩模式运行，不增减喵币，也不要求最低余额。
- 所有小游戏插件均为应用全局数据，不绑定人设或会话。插件可申请联网权限，manifest 必须预先声明 HTTPS 来源，安装或更新时由用户按来源授权，宿主只代发已授权来源的请求。
- 第一版实现版本化插件协议、受限插件宿主、本地 `.yanmew-game` 安装、插件游戏局和钱包服务。石头剪刀布与用户安装的插件使用同一套 manifest、宿主 API、存档和结算边界，不提供绕过插件系统的专用实现。
- 所有小游戏插件都可申请 `wallet.modify`。本地插件在安装时、随包插件在首次打开时明确展示并由用户决定；允许后插件通过 `wallet.changeCoins()` 增减喵币，主程序在同一事务更新余额并记录插件 ID、插件版本、游戏局 ID、数量和原因。拒绝后插件仍可纯玩。
- 第一版不显示“官方收录”或其他推荐徽标。小游戏插件不提供 `ai.generate()`，也不能读取聊天、记忆、记事本、模型配置或 API Key。完整规则见 `docs/小游戏插件生态设计.md`。
- 主程序内喵币用于制作饰品；获授权的小游戏插件也可按玩法增减喵币。卖出饰品固定获得 10 喵币。

### 2.12 饰品

- 饰品按会话绑定，删除会话一并删除。
- v1 只做 1 个头顶装饰槽，允许“少量 emoji + 颜文字/符号”，前端限制长度和字符集。
- AI 在达到亲密度解锁档位后可发起制作请求；10/50/150 档各限 1 次，300 档后不限。
- 制作费用默认：20 / 50 / 120 / 300 喵币；300 档后每次固定 300，设置里可改。
- 用户确认“给你买”且余额足够时，在同一事务中扣款、写流水、写饰品和标记会话档位已使用；卖出或删除饰品、修改阈值/价格不恢复档位资格；余额不足点“没有钱了”则暂不制作。
- 用户拒绝后，AI 至少间隔 1 小时，或下次启动应用后，才能再次请求。
- AI 制作的饰品可以选择佩戴或不佩戴；用户可手动穿戴、卸载、删除未佩戴饰品，删除不可恢复；未佩戴饰品可卖出，固定获得 10 喵币。
- 每件饰品都有 AI 按人设口吻写的简介。
- 设置 > 桌宠与内容 > 饰品 管理；右键菜单提供“饰品”快捷入口。

### 2.13 旅行、写信与伴手礼

- 旅行、信件、伴手礼均按会话绑定，删除会话一并删除。
- 出行状态只有：在家、出门中。
- 出行触发：创建会话、正常返回或取消旅行后，从用户可配置的范围抽取一次剩余有效在线时间并持久化，默认 2–4 小时；仅当前会话、应用开启、在家且桌宠空闲时递减，其他会话和应用关闭期间暂停，切回后继续。倒计时到期后出行 1–3 小时。
- 旅行倒计时与无聊/睡眠的无互动计时相互独立：互动会重置无聊/睡眠周期，但只暂停旅行倒计时，不重抽已经保存的旅行等待时间。
- 触发时先弹气泡，再进入出门中状态；主宠窗只显示文字“`{当前人设名}出门啦`”，聊天按钮变为“写信”。
- AI 出门期间主宠窗显示写信入口；聊天窗隐藏消息区，保留写信和切换其他会话入口，切换会取消本次旅行。
- 出门期间：AI 发 1 封途中信，返回时生成 1 封回来信；AI 生成的信件内容应包含可爱颜文字。用户可写多封信，回信延迟默认 10–30 分钟随机并保存到期时间；只在旅行仍进行时生成，返回或切换会话即取消待回信。
- 写信界面提供“跳转邮箱”按钮，可打开邮箱管理。
- 回信机制：每封信只能回复一次；删除回复不恢复资格。旅行返回后不能写信或回信，取消尚未完成的回信。
- 切换会话或人设时，尚未出发的会话暂停并保留剩余倒计时；已经出发的旅行和待回信直接取消，不生成回来信、礼物或总结，已存在记录保留。取消事务为该会话抽取下一轮完整倒计时并暂停，旅行历史显示“已取消”；重新启用该会话后继续递减已保存的剩余时间。
- 应用关闭时：
  - 旅行间隔只累计当前会话在家空闲的应用运行时间；关闭期间不新触发旅行。
  - 若 AI 已出门，下次启动按真实时间差判断：若已到返回时间，则标记为已回来、带回伴手礼并补生成 1 封回来信；若未到返回时间，则继续出门。
- 每次正常旅行回来带 1 件伴手礼；其中 10% 概率是可佩戴饰品，90% 概率是普通文字礼物。
- 可佩戴饰品免费获得，进入饰品管理；普通文字礼物进入伴手礼管理。
- 文字伴手礼必须包含 AI 按当前人设口吻写的备注。
- 正常返回后 AI 用对应人设口吻生成 1 篇独立旅行游记，详细总结出行时间、时长、做了什么、往返信件和实际带回结果；它不属于短期或长期记忆，也不参与记忆整合。应用关闭期间返回则下次启动后台补生成。
- 旅行游记标题必须用一句话极精炼概括什么时候去了哪里、做了什么、有什么伴手礼、去了多久。当前会话最近 5 篇只把标题放入上下文，AI 可通过只读工具列出、查找和读取当前会话的历史游记。
- 设置 > 桌宠与内容 > 出行 下管理邮箱、伴手礼与旅行游记；该页面不显示会话选择，数据跟随当前会话。
- 邮箱：查看、收藏、删除；仅旅行仍在进行时允许写信/回信。正常返回的信件、礼物和游记分别记录完成状态，失败可重试，已生成结果不得重复补发。
- 伴手礼：文字礼物列表，支持查看、收藏、删除；不做背包、数量、容量或使用机制。

出行记录保存固定目的地、活动时间线与实际礼物快照，供信件和游记共用；快照不随展示子项删除，具体字段见数据库设计第 6.1 节。

游记、信件、伴手礼和旅行饰品分别通过 `travel_id` 关联 `travels` 出行记录，是并列子项。游记允许编辑与单独删除，不提供 AI 重新生成。删除游记不删除出行记录或其他子项，且保留 `journal_state=done`，防止后台补回。

### 2.14 导入、导出与迁移

- 导入导出放在“全局设置 > 通用 > 导入与导出”。
- 支持六类导出：全量备份、人设资料包、人设完整包、会话包、用户设定包、插件使用数据包。
- 全量备份包含全部非密钥业务数据及全局配置、聊天/记忆/Embedding 提供商非密钥配置、钱包和账单、小游戏插件登记与逐作用域权限、插件设置与私有存档、游戏局、提醒与触发记录，以及被引用背景图；内置节日母表不导出，由目标端生成，石头剪刀布程序包由目标应用随包提供。用户自行安装的 `.yanmew-game` 程序包不进入备份，恢复后由用户重新安装。
- 插件登记随备份保存名称、插件 ID、作者、原版本、包校验值，以及 manifest 中的 GitHub 仓库、项目主页、Release 页面和声明的联网 origin。恢复时缺少程序包的插件仍在游戏中心显示其保留数据、来源链接和原授权；用户从浏览器重新下载并安装相同插件 ID 后，经兼容检查重新关联设置和存档，新增联网 origin 仍需重新授权。
- 插件使用数据包保存所选插件的登记快照、来源链接、权限申请、设置和私有存档，不保存插件程序包、游戏局、插件账单或钱包余额。独立导入时覆盖用户确认的插件设置与存档，不重放历史喵币变化；喵币权限和所有联网 origin 都恢复为待确认，用户重新授权前不可调用。
- 人设资料包只含人设定义、初始设定、颜色、自调开关、背景和表情库；不含会话或私密数据。
- 人设完整包含所属全部会话级数据与引用的用户设定；会话包含该会话全部会话级数据、所属人设定义、绑定用户设定及背景；用户设定包可附带绑定会话及其人设定义，保证引用完整。
- 会话级数据包括聊天回合、消息、短期记忆、带标题的长期记忆及来源关联、记事本、亲密度、饰品档位标记、节日子表、旅行任务状态、旅行游记、信件回复状态、饰品与伴手礼。全文索引和向量是可重建数据，不进入导出包；人设资料包、人设完整包、会话包和用户设定包不携带或修改任何插件登记、授权、设置、存档、游戏局与插件账单，插件数据只由全量包或插件使用数据包处理。
- 格式统一为 `.yanmew-backup.zip`，内部仅使用 `manifest.json`、`data.json` 和 `files/`；版本、清单、ID 映射与校验规则见数据库与持久化设计第 12 节。
- 默认新建副本并重建 ID，名称冲突自动重命名；人设资料包只允许新建副本。其他包覆盖同名项时必须明确选定类型和父级范围内的目标，二次确认；不凭名称自动覆盖多条。
- 全量导入用备份替换全局喵币、账单、设置、提醒、提供商非密钥配置，以及小游戏插件登记、授权、设置、存档和游戏局；全局数据不累加、不随人设复制，确认摘要明确提示替换范围。
- API Key / 和风天气密钥均不导出。新导入聊天、记忆及联网 Embedding 提供商密钥为空；部分包不改目标全局密钥，全量替换后重新填写。内置本地模型文件随目标应用提供，不写入备份；导入完成后重建长期记忆全文索引和向量。
- 导入前校验文件、版本、字段与关联；文件暂存和数据库事务保证失败不写入半成品。后台任务暂停到事务提交，取消任务不恢复。
- `data/` 整目录复制仅作为应用关闭后的冷备份方式。

### 2.15 节日与签到彩蛋

- 节日数据分两张表：系统级内置的节日母表（`festival_catalog`）与会话级的节日子表（`session_festivals`）。
- 母表由项目内置静态数据在首次启动时写入，写入时就直接按内置农历表算好当年的公历月日，不联网、不调用任何日历接口、失败不进休眠。
- 母表节日分三类（`calendar_type`）：公历节日（solar）、农历节日（lunar）、节气（solar_term，清明与冬至）。
- year 记录本年公历年份，不是生日出生年；日期按内置小型日历表判断。公历月日不变，只更新 year；农历和节气按目标公历年查表更新，年初腊月不能误用同号农历年。
- 启动、跨年或系统日期变化时更新 year 和换算日期，行不删除，子表关联不断。本年无对应日期就不命中，清除失效的农历换算值，不沿用旧值或挪动日期。
- 除夕按“腊月最后一天”处理，农历日是廿九还是三十每年由内置农历表推出，不写死固定日期。
- 内置农历/节气数据表覆盖 1950–2100 年；系统日期超出该范围时只跳过农历与节气节日，公历节日照常，不报错、不进休眠。
- 子表在母表之外，允许 AI 与用户新增生日、纪念日、自定义日子；AI 可通过工具增删改查子表，不需要的行可由 AI 删除。
- 子表也可在设置中查看并手动新增、编辑、删除；AI 写入时必须自行填写非空祝福词，用户手动维护同样必填；母表只读。
- 签到彩蛋：当天命中母表或子表中任一节日时固定获得 10 喵币，并直接展示该节日记录的祝福词，不调用 AI。
- 当天同时命中母表与子表时，祝福词合并展示，喵币仍为 10，不叠加。
- 当天没有命中任何节日时，签到保持原有的随机 1–10 喵币。
- 纪念性节日（如清明）使用纪念向祝福词，不出现“快乐”。
- 当天是节日时，注入 AI 上下文的日期信息中包含节日名称与是否为纪念性节日。
- 子表与母表一起参与签到彩蛋、日常聊天和无聊主动消息上下文。

### 2.16 v1 不做

- 联网搜索（留待后续迭代）。
- 颜喵直接访问 GitHub、自动检查 Release 更新、应用内在线插件目录、“官方收录”徽标、独立插件网站和 `yanmew://` 一键安装；v1 支持本地插件包安装，但不在应用内联网找插件。
- 图片素材型饰品/旅行礼物（v1 全部使用文字与颜文字）。
- 节日放假安排与调休信息（不接日历接口，节日彩蛋完全离线）。

## 3. 技术架构

- 桌面壳：Tauri 2（Rust 核心）+ React + TypeScript 前端。
- Rust 核心模块：配置存储、API 与 Embedding 提供商管理、本地 Embedding 推理、长期记忆混合检索、人设管理、用户设定、表情库管理、AI 客户端、桌宠状态机（含桌面游走）、提醒调度、天气与定位服务、会话/记忆/记事本存储、喵币、小游戏插件宿主、饰品、旅行、邮箱、伴手礼、节日与内置农历表、导入导出。
- 聊天 AI 与记忆整合 AI 拆成两个独立模块。
- 本地数据：SQLite，建库脚本为 `db/schema.sql`，运行库为 `data/yanwenzi.db`。
- 安全：API Key 使用 Windows DPAPI 加密存储。
- 流式聊天：聊天 AI 先返回表情决策，再以 SSE/增量事件流式输出正文；前端可发送中断命令。

## 4. 数据模型

当前完整 V1 结构见 `db/schema.sql`，事务和恢复规则见 `docs/数据库与持久化设计.md`。小游戏插件表从初始化阶段就存在；阶段 13 只接入插件业务，不另建一套表。表如下：

- `providers`：id、name、base_url、api_key_encrypted、model、is_active（聊天）、memory_is_active（全表无启用项时跟随聊天）。
- `embedding_providers`：id、name、kind（local/online）、base_url、api_key_encrypted、model、is_builtin、is_active；默认本地模型由种子逻辑写入。
- `personas`：id、name、prompt（当前人设）、initial_prompt（初始设定）、self_evolve_enabled、last_evolved_at、color（本体颜色）、chat_bg_file、chat_bg_opacity、chat_bg_blur、is_active、is_builtin、expressions（分类表情库 JSON）；内置默认人设以 `is_builtin` 保护。
- `user_profiles`：id、name、content、created_at、updated_at。
- `sessions`：id、persona_id、user_profile_id、title、created_at、updated_at、memory_revision、craft_tier_1_used、craft_tier_2_used、craft_tier_3_used、intimacy、last_return_at、travel_trigger_remaining_seconds。旅行只持久化剩余有效在线秒数，不同时保存累计值和随机阈值。
- `chat_rounds`：id、session_id、status、created_at、completed_at；完整回合、待回复回合和中断回合的主记录。
- `messages`：id、session_id、round_id、role、content、expression、created_at；主动消息的 round_id 为空。
- `settings`：key、value（键值对，见 schema 注释）。
- `short_memories`：id、session_id、round_id、content、integration_state、created_at、updated_at；每个完整回合一条，整合后仍保留。
- `long_memories`：id、session_id、title、content、source_count、activated_by_round_id、created_at、updated_at；实际覆盖边界由 `long_memory_sources` 最大 `source_order` 推导。
- `long_memories_fts`：长期记忆标题和正文的 SQLite FTS5 `trigram` 可重建全文索引。
- `long_memory_embeddings`：long_memory_id、session_id、model_key、dimensions、vector、content_hash、updated_at；当前 Embedding 模型的可重建向量索引。
- `long_memory_sources`：long_memory_id、short_memory_id、source_order；保存每条长期记忆的固定短期来源。
- `notebooks`：session_id（主键，一个会话一个记事本）、content、updated_at。
- `reminders`：id、name、kind、schedule、content、status、fire_at、source、created_at。
- `reminder_occurrences`：id、reminder_id、scheduled_at、status、delivery_state、completed_at、created_at；每次提醒的持久化状态，离线过期项使用 missed 展示状态参与一次汇总。
- `user_state`：id（固定为 1）、coins、updated_at。
- `game_plugins`：插件 ID、名称、简介、作者、安装版本、API/存储版本、来源类型、相对包路径、包校验值、GitHub 仓库、项目主页、Release 页面、manifest 声明的联网来源、是否随包提供、程序包状态、启用状态及安装/更新时间。
- `game_permissions`：插件 ID、权限名、权限作用域、待确认/允许/拒绝状态、决定时间和对应插件版本；`network.fetch` 的作用域保存单个 HTTPS 来源。
- `game_plugin_settings`：插件 ID、设置键、JSON 值和更新时间。键由 manifest `settings_schema` 声明，常见为音效开关、音量、难度、操作确认和减少动画；无覆盖行时使用 manifest 默认值。
- `game_plugin_data`：插件 ID、数据键、JSON 值、存储版本和更新时间；仅为插件全局私有存档。常见键为进度、总统计、最高纪录、解锁项、教程状态和可恢复局面，不能保存并冒充钱包或权限事实。
- `game_runs`：游戏局 ID、插件 ID/名称/版本快照、钱包授权快照、状态、结果、JSON 明细、累计喵币变化和时间；不保存人设或会话 ID。明细可包含 schema 版本、模式、选择/得分、结果和耗时。
- `currency_ledger`：id、delta、reason、ref_id、game_run_id、plugin_id、plugin_version、plugin_display_reason、wallet_request_id、created_at；插件钱包统一写 `plugin_game`。
- `accessories`：id、session_id、name、display_text、description、cost、source、travel_id、is_worn、created_at。
- `travels`：id、session_id、status、started_at、planned_return_at、actual_return_at、cancelled_at、midway_letter_at、midway_letter_state、return_letter_state、gift_state、journal_state、gift_kind、facts_state、destination、activities_json、facts_version、facts_ready_at、gift_snapshot_json、created_at。
- `travel_journals`：id、session_id、travel_id、title、content、created_at、updated_at；每次正常返回的旅行最多一篇。
- `letters`：id、session_id、travel_id、sender、content、reply_to_id、has_been_replied、reply_due_at、reply_state、letter_kind、is_favorite、is_read、created_at。
- `souvenirs`：id、session_id、travel_id、content、note、is_favorite、created_at。
- `festival_catalog`：id、code、name、year、calendar_type、solar_month、solar_day、lunar_month、lunar_day、is_leap_month、solar_term、blessing、is_memorial、note（系统级内置节日母表，只读）。
- `session_festivals`：id、session_id、festival_id、kind、name、year、calendar_type、solar_month、solar_day、lunar_month、lunar_day、is_leap_month、blessing、note、source、created_at、updated_at（会话级节日子表）。

删除会话时级联删除该会话的聊天回合、消息、短期记忆、长期记忆及来源关联、记事本、节日子表、饰品、旅行、旅行游记、信件和伴手礼。删除非内置人设时级联删除其所有会话及会话级数据（数据库级 `ON DELETE CASCADE`），内置默认人设禁止删除；删除用户设定时保留会话，仅把会话的 `user_profile_id` 置空。小游戏插件、插件授权、设置、存档、游戏局、喵币和账单均为全局数据，不随会话或人设删除；历史游戏局和账单也不随插件卸载删除。节日母表是系统内置数据，不随任何业务数据删除。

## 5. AI 引擎

- 聊天 AI：使用聊天当前提供商；回复分两步——先决定本次说话表情，再流式输出正文；流式期间支持中断。
- 记忆整合 AI：独立后台模块，使用记忆专用提供商（默认跟随聊天提供商）；不注入人设、不显示思考中表情、不阻塞聊天。
- Embedding：默认使用随便携版打包的本地 `BAAI/bge-small-zh-v1.5`；用户可切换联网 OpenAI-compatible `/embeddings`。联网失败时本次降级为 FTS5，不让聊天进入休眠。
- 记事本：通过 function calling 调用 `read_notebook` / `update_notebook`；“单次回复的工具调用轮数上限”可配置（默认 3）。
- 人设自调：聊天回复后由聊天 AI 按需判断是否调用人设修改工具，不是每轮都调用。
- 上下文只使用当前会话数据。最近消息原文数量由全局设置控制，默认 30；尚未整合且原消息已离开最近原文范围的短期记忆可进入上下文。最近 `m` 条长期记忆直接进入，更早的长期记忆由 FTS5 与 Embedding 混合 RAG 按需选取，`m` 默认 30。
- 日常聊天与无聊主动消息共用当前会话的人设、用户设定、记忆、最近 5 篇旅行游记标题、记事本、环境和当天节日上下文；区别只在触发方式。游记正文由只读工具按需查询。
- 旅行相关生成：途中信、回信使用当前会话人设、记忆、最近 5 篇旅行游记标题与记事本，AI 生成的信件内容应包含可爱颜文字；旅行游记使用对应人设口吻生成。
- 无聊主动消息：处于无聊状态时按代码层概率与固定上下文规则生成。
- 错误处理：无 key、连不上、限流等主流程异常统一进入休眠状态，展示红色感叹号与中文错误。

## 6. 桌宠状态机

- 状态：正常、饿、无聊、睡觉、吃东西、说话、思考中、休眠；出行使用独立的“出门中/在家”状态。
- 饥饿与无聊/睡觉分别读取当前会话保存的有效运行累计；上次喂食和互动时刻只作记录，不计算离线增量。喂食清零饥饿及无互动累计，摸摸和点击只清零无互动累计；合法互动同时结束睡眠，亲密度变化与互动状态同事务保存。
- 进入睡眠时，从“睡眠最短/最长分钟数”随机确定一次持续时长，默认 60–120 分钟，到时自动唤醒；无互动入睡阈值 sleep_idle_minutes 默认 45 分钟，与无聊默认阈值相同，到点随机选择无聊或睡眠，允许用户在全局设置修改；不使用睡眠最长值代替入睡阈值。
- 饿、无聊状态可弹一条气泡（如“好饿…”“好无聊…”）。
- 无聊状态按概率由独立后台任务主动发一条消息气泡，上下文规则与聊天上下文一致；休眠或出门中不触发。
- 桌面游走：只移动固定宠窗画布内的颜文字及随附饰品、气泡；不自动移动整个窗口。鼠标进入画布附近时可在画布范围内靠近；前台窗口避让仅在画布内有可用位置时进行；用户拖动、点击、打开聊天、睡觉、出门中或隐藏宠窗时立即暂停。
- 表情：点击类随机取点击分类中的开心/惊讶/害羞；饿取“饿”，吃东西取“吃东西”，睡觉取“困”，无聊取“无聊”，思考取“思考”；说话用实时生成表情。
- 出门中：主宠窗只显示文字“`{当前人设名}出门啦`”，聊天按钮变为“写信”，点击/摸摸/喂食不增加亲密度。

## 7. 记忆与记事本（会话级）

### 7.1 隔离范围

- 回合、消息、记事本、短期记忆、长期记忆、旅行与旅行游记均按会话隔离。

### 7.2 AI 上下文组装（顺序）

主请求组装前，程序先在当前会话内对最近 `m` 条以外的长期记忆执行 FTS5 + Embedding 混合 RAG；检索结果完成融合、去重、阈值和预算筛选后才进入初始 `messages`。初始 `messages` 顺序为：系统提示词 → 其他提示词（时间/地点/天气/当天节日 + 工具说明 + 当前记忆参数）→ 用户设定（如绑定）→ 人设 → 当前会话记事本 → 最近 `m` 条长期记忆 → 混合 RAG 命中的较旧长期记忆 → 尚未整合且未与最近原文重复的短期记忆 → 最近 5 篇旅行游记标题 → 最近消息原文 → 本次用户消息。最近原文数量和 `m` 分别由全局设置控制，默认都为 30；同一条长期记忆和本次用户消息只出现一次。

主请求除 `messages` 外，还在 `tools` 字段携带当前场景已实现且获准使用的工具定义。AI 调用工具后，assistant 工具调用消息与对应 tool 结果作为不可拆分的一组追加到同一轮上下文，再调用聊天模型继续生成；所有工具轮次复用发起请求时固定的当前人设、会话、上下文版本、请求 ID 和取消信号，并受 `tool_call_rounds` 与上下文预算限制。未实现或当前状态不可用的工具不得注册空实现。

上下文总量超过模型容量时，自动减少本次携带的较旧内容并提示；数据库记录和用户设置不变。具体裁减顺序、输出预留与无法进一步裁减时的处理见《记忆与旅行游记设计》第 6.2 节。

每次请求在当前会话内使用 SQLite FTS5 标题/正文检索和 Embedding 语义相似度两路召回，合并去重后受相关阈值、数量上限和上下文预算控制。普通聊天与快速回忆的正文主模型只调用一次；独立颜文字生成请求不计入这个表述。使用联网 Embedding 时会额外调用一次向量接口，本地默认模型没有网络请求。现有上下文仍不足时，AI 可调用 `search_long_memories`、`open_long_memory`、`open_long_memory_sources`、`open_chat_round`，逐层读取长期记忆、来源短期记忆和原始聊天回合；每轮工具调用会增加一次聊天模型往返。

### 7.3 记事本

- AI 通过 function calling 调用 `read_notebook` / `update_notebook`。
- `update_notebook` 用结构化操作：追加 / 替换某段 / 删除某段 + 内容；段落按空行分隔、从 1 开始编号，用 `section_index` 定位。
- AI 自己决定是否读写；“单次回复的工具调用轮数上限”用户可配置，默认 3。
- 记事本 AI 维护建议上限用户可配置，默认 4000 字。它不是数据库硬限制：不截断、不拒绝或丢弃超限内容；工具向 AI提供限制值、当前字数、剩余字数和超限状态，接近或超过时要求 AI 合并重复内容、精简旧段落，并在后续修改中优先恢复到范围内。用户手动编辑和导入的超限内容保持完整。
- 用户可在记忆小窗查看并手动编辑记事本。

### 7.4 记忆生成（后台异步，回复完成后检查）

- 记忆整合与聊天 AI 分模块运行，使用记忆专用 provider（默认跟随聊天），不看人设、不显示思考中表情、不阻塞聊天。
- 一轮完整对话由一条用户消息和一条正常完成的 AI 回复组成，使用 `chat_rounds` 绑定；每轮生成且只生成一条短期记忆。中断回复和主动消息不生成短期记忆。
- **短期记忆和长期记忆是中性事实记录，不使用人设口吻，不需要任何氛围总结或主观评价，必须只是如同剧本一样的叙事描述。**
- 短期记忆有“尚未整合/已经整合”状态；整合后不删除，永久保留来源回合。
- 全局设置中的 `k` 默认 20。当出现第 `k+1` 条尚未整合短期记忆时，AI 使用它之前连续的 `k` 条生成长期记忆；触发的第 `k+1` 条继续保持尚未整合。修改 `k` 只影响后续尚未整合数据。
- 长期记忆保存实际来源数量和触发整合的第 `k+1` 轮回合 ID；按顺序排列的短期记忆 ID 保存于来源关联表。覆盖到的第 `k` 轮 AI 消息由最后一条来源的回合推导，不重复保存。正常整合不删除旧长期记忆。
- 长期记忆的简短标题与正文在同一次请求中生成，均遵守中性事实记录要求。标题和正文共同参与全文与语义检索。
- 旅行正常返回后生成独立的 `travel_journals`，不写短期记忆，不参与长期整合。
- 后台整合失败仅显示错误提示，不进入休眠、不阻塞聊天；主流程 API 不可用时才进入休眠。

### 7.5 记忆管理小窗

- 独立小窗，从聊天窗打开，自动跟随聊天窗当前会话。
- 显示短期记忆、长期记忆、记事本。
- 短期记忆显示来源回合和整合状态；长期记忆显示简短标题、正文、短期来源、由来源末轮推导的覆盖消息与触发回合。
- 短期和长期记忆不可手动新建或删除，可以手动编辑。
- 短期记忆提供“重新生成”，长期记忆提供“重新整合”；均使用原有来源，长期记忆同时重新生成标题和正文，弹出可编辑预览，用户确认后覆盖原记录且 ID 不变。
- 编辑或重新生成已整合短期记忆不自动改写长期记忆，界面提示用户按需重新整合相关长期记忆。
- 取消选择多条长期记忆合并。长期记忆永久保存，不自动删除、再次合并或压缩；上下文数量通过最近 `m` 条与混合 RAG 控制。

### 7.6 记忆参数（均可在全局设置中配置）

- 短期记忆字数范围（中文汉字），默认 `12–100`。
- 长期记忆字数范围（中文汉字），默认 `150–250`。
- 每条长期记忆使用的短期记忆数量 `k`，默认 20。
- 最近消息原文数量，默认 30。
- 最近长期记忆数量 `m`，默认 30。
- 旅行游记字数范围（中文汉字），默认 `250–350`。
- 单次回复的工具调用轮数上限（默认 3，统一约束记事本、深层回忆等工具）。
- 记事本 AI 维护建议上限（默认 4000 字，软限制）。
- AI 按参数撰写记忆，不硬截断。

## 8. 会话与消息操作

### 8.1 会话

- 会话归属一个人设，可绑定一个用户设定；删除用户设定时保留会话并把该会话的用户设定置空为“未绑定”。
- 删除会话：级联删除该会话的聊天回合、消息、短期记忆、长期记忆及来源关联、记事本、节日子表、饰品、旅行、旅行游记、信件和伴手礼；全局小游戏插件、插件授权、设置、存档、游戏局、喵币和账单不受影响。
- 会话标题：首次发送消息后由 AI 自动生成；用户可在聊天窗重命名。
- 删除人设：系统默认人设不可删除；其他人设删除前展示级联范围，确认后删除其所有会话及会话级数据。删除当前人设后切回默认人设并刷新所有会话级窗口。

### 8.2 消息操作（聊天窗）

- 编辑：用户与 AI 历史消息均可修改，只改变原文，不自动修改或删除记忆；需要同步时由用户手动编辑或重新生成记忆。
- 删除：只允许从底部删除。最后一个完整回合在 AI 消息下显示“删除本轮”，同时删除该轮两条消息、回合和短期记忆；若该轮触发过长期记忆，则删除该长期记忆并把其来源短期记忆恢复为尚未整合。底部只有待回复用户消息时只删除该消息和未完整回合。
- 底部为中断回合时，允许将用户消息、部分 AI 回复和回合记录一起删除；底部为主动消息时，只删除该条消息。两者都不修改已有记忆，也不能越过实际底部删除更早回合。
- 重说：最后一个完整回合可用；排除旧 AI 回复后重新生成，成功后原位更新 AI 回复和本轮短期记忆。如果该短期记忆参与了长期记忆，则同步更新受影响长期记忆。失败/中断保留旧结果，不重复增加亲密度或重放已提交工具。
- 发送消息由 Rust 保存一次，组装最近消息后不再次追加当前消息；前端不重复写库。中断保留已收到正文一次，无正文不插空消息。

## 9. 提醒系统

- 创建：AI 从聊天提取结构化提醒；全局设置 > 提醒中手动创建。
- 类型：一次性、重复（每天/每周/每月，循环规则可配置）；月度选定日期不存在的月份跳过。
- 触发：先事务保存每次触发记录并推进下一次时间，再在应用运行中调用 AI 用人设语气润色成独立提醒气泡；失败使用固定默认提醒词“`{提醒名}事件提醒：{提醒详情}{提醒时间}`”；可标记完成。
- 关闭期间到期：下次启动时补记全部过期的一次性提醒；每个重复规则只保存最近一次错过的离线过期记录，其余自动跳过。下次启动统一汇总提醒名称，后端记录汇总已展示。
- 状态流转按每次触发记录管理：用户可在提醒页面手动改为未完成、完成或已过期；重复规则仍继续，永久停止只能删除提醒。
- 仅到点提醒；时间与循环规则编辑影响未来触发，本次完成/过期操作触发记录；永久停止重复提醒只能删除规则。

## 10. 天气与定位

- 定位：Windows 系统定位（需处理系统位置权限，失败时提示）。
- 天气：Open-Meteo 优先，失败时用和风天气免费版兜底；和风 API Host 与 API Key 在设置中配置（Key 由 DPAPI 加密存储），未配置且 Open-Meteo 失败时显示“天气不可用”。
- 时间/地点/天气在相关时注入 AI 上下文。
- 天气快照包含实际坐标、定位时间、观测时间、来源及可空温度；不由经纬度猜测城市。运行期缓存接收超过 30 分钟或观测超过 60 分钟即过期，刷新失败区分缓存与不可用，旧观测不能当作当前事实。缓存可重建、不进备份；天气配置和加密 Key 持久化。聊天读取快照，不同步等待天气刷新。

## 11. 应用名、默认人设与开机自启

- 应用名与窗口标题使用 **颜喵 YanMew**；`tauri.conf.json` 的 `productName` 与 `identifier` 更新为 `颜喵 YanMew` 与 `com.yanmew.pet`。
- 首次启动时幂等保证内置默认人设 **喵喵桌宠** 存在；它不可删除。首次启动且没有其他配置时自动设为当前人设，并在界面提醒用户去设置。
- 开机自启：使用 Tauri autostart 插件，默认关闭。

## 12. 发布与存储位置

- 发布形态：Windows 便携版 zip，解压即用。
- 代码：`src/`、`src-tauri/`。
- 小游戏：主仓库 `plugins/first-party/` 保存项目维护者发布的插件；`plugins/bundled-games.json` 指定随便携版提供的插件，第一版包含石头剪刀布。
- 建库脚本：`db/schema.sql`。
- 运行数据库：可执行文件所在目录的 `data/yanwenzi.db`（位于 data 子目录，首次启动自动创建）。
- 聊天窗背景图片：应用目录下 `data/chat_background/`，数据库只保存相对文件名和设置值。
- 导入导出文件：默认导出到用户选择的目录，文件名 `颜喵YanMew-<时间戳>.yanmew-backup.zip`。

## 13. 功能覆盖清单

8. 旅行、写信、伴手礼与旅行游记。
9. 提醒系统。

11. 导入、导出与数据迁移。
12. 节日母表与节日子表、内置农历与节气数据表、签到彩蛋。
13. 桌面游走与无聊主动消息。
14. 小游戏插件宿主、本地插件安装，以及随便携版提供的石头剪刀布第一方插件。
15. 后续版本：独立社区小游戏仓库、GitHub Release 自动安装与更新、推荐目录、独立轻量插件网站和一键唤起颜喵。
16. 后续版本：按人设绑定的本地唤醒词、流式 ASR、两个内置声线、兼容 TTS 模型导入、联网 ASR/TTS、导入别人已经制作完成的 GPT-SoVITS 声线，以及再后续的本地音色克隆。GPT-SoVITS 导入只安装并运行现成权重，不在颜喵内训练。该扩展不进入首版，完整规则见 `docs/语音扩展设计.md`。
