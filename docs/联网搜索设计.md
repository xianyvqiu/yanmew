# 普通聊天联网搜索设计

## 一、使用范围

联网搜索是普通聊天工具，不是后台生活模拟或记忆生成服务。全局开关默认关闭；用户配置并启用后，AI 只在需要最新资料、核实信息或用户要求搜索时调用。不得为了普通寒暄每轮搜索。普通聊天和最后完整回合重说允许只读搜索；主动消息、旅行、信件、记忆生成、人设自调后台任务均不开放。长度续写继续遵守现有不开放工具的规则。

复用已有有限工具循环、请求取消、会话上下文校验及上下文预算，不另建 Agent 框架。不额外调用一次 AI 判断是否搜索，由正文模型按需选择工具。

## 二、全局配置与持久化

“设置 → 提供商”增加独立的“联网搜索”模块，与聊天、记忆和 Embedding 配置分别管理。支持新增、编辑、测试、切换及删除配置，列表显示服务类型、名称、接口地址、是否保存 Key 和当前项；页面提供联网搜索开关。没有配置时显示“暂无搜索服务，请先新增”。当前项不能删除，先切换其他项；关闭开关不删除配置。

服务类型包括 Tavily、博查及“自定义（Tavily 兼容）”，三种选项均已接通。Tavily 默认地址为 `https://api.tavily.com`，博查为 `https://api.bocha.cn`。用户使用自己的 Key；程序不内置共享 Key，不需要颜喵服务器。测试连接会实际发送一条简短搜索，可能消耗服务额度，界面需事先说明。服务费用和免费额度以服务商网站为准，不写死价格。

复用 `settings`，不增加表、列或数据库版本。`web_search_config` 保存版本化 JSON：`version` 为配置格式版本 1；`revision` 为配置变化版本；`nextId` 为下一个配置 ID；`enabled` 为开关；`activeId` 为当前配置 ID 或 null；`providers` 为配置数组，各项包含 `id`、`name`、`kind`、`baseUrl`。`kind` 枚举为 `tavily`、`bocha`、`custom`；custom 明确采用 Tavily 兼容协议。未登记配置等于关闭、空列表。

每项 Key 独立保存为 `web_search_provider_<id>_api_key_encrypted`，使用现有 `SecretProtector` 加密；界面仅返回 `hasApiKey`。编辑留空表示保留，清除密钥是独立操作。配置和密文在同一 SQLite 事务中保存。更换服务类型或地址时不能误把旧 Key 发往新地址，必须重新填写 Key 或清除。

配置变化递增自己的 `revision`，不改变聊天会话的上下文版本、不修改历史消息。每个搜索请求取得配置快照，联网前后均校验搜索配置版本；过期结果不得再进入模型。本轮搜索失败通过工具结果说明，普通聊天仍可继续。

全量备份可保存搜索配置元数据，但所有搜索 Key 均排除，包括密文。导入后搜索默认关闭，重新填写 Key 并测试后由用户启用。人设包、会话包和插件包不改变全局搜索配置。

## 三、搜索服务适配

### Tavily

使用 Bearer Key，`POST /search`；基础参数为 `query`、`search_depth: basic`、`max_results: 5`、`include_answer: false`、`include_raw_content: false`、`include_published_date: true`、`auto_parameters: false`。按需传入 `topic` 和 `time_range`。读取 `results` 的标题、URL、摘要和发布时间，不使用服务商生成的答案冒充搜索证据。

需要正文时，`open_web_page` 使用同一连接和 Key 调用 `POST /extract`，一次提交一个已授权公开 URL，参数为 `urls: [url]`、`extract_depth: basic`、`format: markdown`、`include_images: false`、`include_favicon: false`。不附带用户消息、完整查询上下文或隐私资料；不自动升级 advanced、不为了普通搜索预取所有正文。免费 Key 同样支持正文提取，搜索和提取消耗账户服务额度；实际免费额度及计费以官网为准，客户端不区分免费/付费 Key、不代开付费计划。

只接受 `results` 中与请求 URL 对应且非空的 `raw_content`；HTTP 200 也须检查失败项，`failed_results` 命中时返回 `WEB_PAGE_UNAVAILABLE`，不能回退到摘要却标注为已读正文。额度/认证/网络错误沿用分类，不回传可能含凭据的原始报错。正文仍最多向模型返回 6000 个 Unicode 字符，超过时 `truncated=true` 并明确已截短；不声称取得完整全文。同一回合已成功读取的网址复用结果，新的调用 ID 也不重复消耗提取额度；新回合重新按需读取。失败不自动反复重试或切换其他服务。

### 自定义（Tavily 兼容）

用户填写自己的 API 根地址和 Key，无默认地址。不支持任意协议：请求必须兼容 Tavily `POST /search`、Bearer 认证、搜索参数和 `results` 响应结构；仅替换 API 根地址。例：根地址 `https://search.example.com/api` 对应 `/api/search`。正常聊天模型的 `/chat/completions` 不能直接充当搜索接口。正文统一本地读取，不要求自定义服务实现 `/extract`。更换类型或根地址须重新填写或清除 Key。

### 博查

使用 Bearer Key，`POST /v1/web-search`；参数为 `query`、`summary: true`、`count: 5`、`freshness`。时间筛选由无筛选、日、周、月、年映射为 `noLimit`、`oneDay`、`oneWeek`、`oneMonth`、`oneYear`。读取 `data.webPages.value` 中的 `name`、`url`、`summary`（缺失时用 `snippet`）、`datePublished`。同时检查 HTTP 状态、服务声明的错误及返回格式。博查没有与 Tavily 同名的 `topic` 参数，按查询词和时间过滤，不宣称已严格筛选新闻。

博查和自定义服务由颜喵本地读取公开网页正文，不要求服务实现提取接口。不打开浏览器、不登录、不执行脚本；通过 `scraper` 解析 HTML，优先 main/article，回退 body，排除脚本、样式和导航。每跳 DNS 结果必须全部为公开 IP，固定结果发起请求，禁用系统代理和自动重定向；最多三次重定向、30 秒总超时、1 MiB 内容限制，UTF-8 HTML/纯文本正文最多返回 6000 字符，明确 truncated。Tavily 正文由服务商抓取，不由颜喵本机解析页面或控制其 DNS/重定向；客户端仍校验 URL 协议、凭据及明显本机/内网地址，API 请求沿用 30 秒总超时、1 MiB 响应限制和取消机制。

Tavily 的正文提取接口是 `POST /extract`，返回 `raw_content`；博查搜索 API 的摘要不等于读取了网页正文，禁止用摘要冒充正文。

协议依据：[Tavily Search](https://docs.tavily.com/documentation/api-reference/endpoint/search)、[Tavily Extract](https://docs.tavily.com/documentation/api-reference/endpoint/extract)、[博查官方搜索集成](https://github.com/bocha-ai/dsh-web-search-bocha)。

## 四、聊天工具与外部资料边界

`search_web` 接收搜索词及可选的新闻类型、时间范围，默认返回最多五项标题、URL、简短摘要、发布时间及查询时间。`open_web_page` 用于需要正文时进一步读取；它不得接受任意本地路径、文件 URL、内网地址或带账号密码的 URL。搜索时只发送必要检索词，不自动上传完整聊天、人设、记事本或记忆。

允许读取的网址只来自本轮 `search_web` 结果，或当前用户消息中明确写出的 HTTP(S) 链接。后端从 `PreparedReply.messages` 的当前 user 原文提取并规范化链接，去除片段与句末标点、保留有效查询参数和成对括号，校验协议/凭据/明显私有地址；不从历史消息、人设、记忆、AI 回复或网页正文中扩展授权。用户直接给网址时无需先搜索。正常聊天和重说复用该范围；主动消息、续写及后台任务仍无网页工具。

提示词要求需要正文时实际调用工具，不能未尝试就声称仅能读摘要；读取失败、仅有摘要或正文截短时如实说明。补充来源时区分“搜索来源（摘要）”与“网页来源（已读取正文）”，已读页面不再归为摘要，截短页面加“正文已截短”；正文已有的来源链接不重复附加。

工具结果是外部证据，不能修改系统规则、授权其他工具或指挥读取密钥。正文模型必须区分搜索摘要、实际读取的正文和读取失败。回答涉及联网证据时附可核对的来源链接；不得把网页中的事件写成桌宠亲身经历。发布时间和抓取时间分别表示，不混为一谈。

每次网络请求有超时和响应大小限制，不无限重试或自动切换其他服务；请求取消、上下文切换和退出复用现有机制。数据库锁在联网前释放。错误只返回安全的中文原因和错误类型，不返回请求头、Key 或可能包含密钥的原始响应。

聊天界面显示“正在搜索”或“正在读取网页”的本轮状态；完成、取消、失败后收起。检索结果进入现有上下文预算，不无限添加全文。搜索结果不单独自动保存为记忆，聊天消息及其来源说明继续按现有回合规则保存。

## 五、定向验收

验收实际配置持久化及 Key 不外泄、Tavily/博查请求和错误解析、Tavily 单页提取/HTTP 200 单项失败/空正文/额度不足/正文截短、当前消息链接直读/越界网址拒绝/同页复用、开关关闭及非普通聊天拒绝、取消和配置变更后的过期结果、结果大小和 URL 限制，以及聊天来源的摘要/正文区分。覆盖真实普通聊天工具循环传入当前消息，不只测孤立解析函数。不为此重复全量测试。真实服务需要用户自己的 Key，未提供时用本地协议夹具验证，不宣称已通过真实额度或网页质量验收。


## 宠窗互动与挂件图层（增量Q，v19）

已确认且适配的当前聊天模型可优先使用原生搜索，不需要独立搜索Key；没有原生适配时沿用外部服务开关。能力依据精确官方端点/模型文档或显式元数据，不猜代理能力。保留正常模型推理协议，推理内容不显示不持久化；原生搜索失败不自动重试付费请求，来源、取消和配置校验见完整设计。完整行为、接口边界、测试与实机待验项见[宠窗互动与挂件图层设计](宠窗互动与挂件图层设计.md)。
