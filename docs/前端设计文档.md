# 颜喵 YanMew 前端设计文档

- 日期：2026-09-19
- 类型：前端界面与交互设计
- 状态：已确认方案已同步
- 说明：本文描述窗口结构、页面内容和交互；颜色、字体、圆角、阴影、组件状态和动效的统一规范见[前端美化风格设计](前端美化风格设计.md)，保存与恢复规则见 `docs/数据库与持久化设计.md`。

## 1. 设计目标与原则

- 首版面向 Windows，视觉上像桌面小宠物；共享页面预留未来 Android 适配，具体移动端导航后续专项设计。
- 主宠窗保持小、透明、无边框、置顶；聊天窗轻气泡风；设置窗使用圆角卡片，但整体仍要轻。
- 主程序内置亮色与暗色两套主题；用户可以跟随 Windows、固定亮色或固定暗色。主题只作用于颜喵主程序界面，小游戏插件保持自己的视觉。
- 颜文字是核心视觉元素，字体要大、清晰；状态优先用颜文字和短气泡表达。
- 桌宠本体颜色按人设绑定，只影响基础颜文字；饰品层、气泡、窗口背景不跟随该颜色。
- 主流程与后台错误可用红色感叹号查看中文详情；表单校验、记忆预览和插件局部失败在对应界面提示。只有主聊天提供商不可用等主流程故障进入休眠，不将所有错误映射成休眠。
- v1支持AI生成的透明图片饰品，保留图标、Emoji、颜文字或符号组合兜底；桌宠本体仍为颜文字，普通旅行伴手礼仍是文字。生图统一由用户在提供商模块配置并开启，关闭或失败不影响图标/Emoji/颜文字饰品。
- 除固定画布的主宠窗外，聊天窗、设置窗、记忆窗、写信窗、出行窗等主要窗口均采用响应式设计，允许用户拖动和缩放。
- 文案使用简体中文；代码、路径、配置键保持原文。

## 2. 窗口与页面结构

本节窗口结构描述 Windows 首版。业务内容按架构文档放入 `pages/*Page.tsx`，`windows/*Window.tsx` 负责桌面外壳；共享页面不直接调用窗口创建、拖动、关闭或托盘 API。打开聊天/记忆/出行等使用语义导航，未来 Android 以同一应用内页面承载，不复制多窗口行为。

页面按容器宽度响应式展示，移动端还须处理触摸、软键盘、安全区和系统返回；窗口缩小不等于完成 Android 适配。平台能力由后端返回，缺少悬浮权限不影响应用内聊天和设置；托盘、开机自启等入口仅在实际支持的平台出现。Android 页面不会自动启用悬浮或后台麦克风。

### 2.1 二级窗口通用规则

当前实现：`chat`、`settings` 两个窗口已接入，分别由宠窗聊天/设置按钮和托盘设置入口打开。聊天窗提供会话新建、切换、改名、删除、历史分页及发送/流式/暂停；设置窗已开放主题、聊天/记忆提供商、人设基础管理和提醒管理。两级导航中其他页面明确标记未开放，游戏中心与插件管理分别开放入口。

默认逻辑尺寸：聊天 800×640、设置 960×700，最小 360×420；创建时按主显示器工作区及 DPI 缩小初始/最小尺寸以适配可用空间。二级窗口采用普通系统标题栏，宠窗不受影响。布局小于 520px 时设置导航换成顶部选择器，主体独立滚动。

- 聊天窗、设置窗、记忆窗、写信窗和出行窗使用普通可拖动窗口，允许用户从窗口边缘调整大小；内容随窗口宽高响应式重排。
- 同一种二级窗口只保留一个实例。重复点击入口时不创建新窗口，而是显示、聚焦并置于前台；需要切换内容时复用现有窗口并刷新上下文。
- 窗口右上角关闭按钮关闭该窗口，不退出应用；退出应用只能通过主宠窗右键菜单、托盘菜单或设置中的“退出应用”。
- 切换当前人设或当前会话后，所有已打开且依赖会话的窗口立即刷新；旧流式事件、旧加载结果和旧表单提交不得写入或显示到新上下文。
- 宽屏优先使用侧栏 + 内容区或多列卡片；窗口变窄时改为单列、折叠侧栏或顶部选择器。表单标签、输入框和按钮允许换行，不使用横向滚动承载主要内容。
- 列表、消息区和正文区使用各自的纵向滚动容器；固定标题栏、主要操作按钮和当前上下文标识不得被滚动内容挤出窗口。
- 在 Windows 100%–200% DPI 和最小窗口尺寸下，文字、按钮、确认框均应完整可见；弹窗不得超出当前显示器可用区域。
- 主宠窗继续使用 `320×240` 固定桌宠画布规则，可拖动位置；它不套用普通内容窗口的响应式布局。

## 3. 主宠窗

### 3.1 画布

- 默认大小：`320×240`。
- 默认位置：当前显示器工作区右下角，避开任务栏；用户拖动后记住物理坐标，下次启动按真实窗口尺寸恢复，允许副屏负坐标。原显示器移除或位置越界时放回可见工作区，临时校正不覆盖保存的位置。
- 拖动位置在后台节流保存，结束和退出前补存；不通过网页 CSS、颜文字内部移动或人设/会话切换修改窗口位置。缩放和托盘恢复检查可见区域，最小化时不强行回位。保存失败使用现有局部错误提示，不改变聊天或提供商状态。
- 窗口透明、无边框、置顶。
- 透明空白区域鼠标点击穿透，只让颜文字本体和可交互控件接收鼠标事件。
- 隐藏宠窗后，窗口缩小为只保留“显示宠窗”按钮；点击该按钮恢复完整宠窗。
- 固定宠窗内只移动颜文字及其饰品、气泡，不自动移动窗口；仅在画布有可用位置时避开前台窗口，鼠标靠近画布时可在范围内靠近。拖动、点击、聊天、睡觉、出门中、隐藏宠窗时暂停。

### 3.2 主宠窗布局

```text
┌────────────────────────────────┐
│ 右上角：[聊天/写信] [隐藏宠窗] [设置] [!] │
│                                 │
│   ┌─────────────────────┐       │
│   │ 气泡：饿/无聊/说话…  │       │
│   └─────────────────────┘       │
│           [饰品层]              │
│         ฅ^・ﻌ・^ฅ               │
│                                 │
└────────────────────────────────┘
```

- 基础颜文字：使用当前会话所属人设的 `color` 渲染。
- 饰品层：佩戴饰品时显示在头顶；未佩戴则隐藏。
- 气泡：位于桌宠上方，按类型显示。饥饿/无聊普通状态提示显示 8 秒后自动收起；提醒保留到点击“完成”或“收起”；提供商错误由既有错误入口展示。
- 聊天/写信按钮：
  - 正常状态显示“聊天”。
  - 当前会话 AI 出门中时显示“写信”。
- 隐藏宠窗按钮：隐藏后只留下一个“显示宠窗”按钮。
- 设置按钮：打开设置窗。
- 红色感叹号：出错或休眠时显示，点击弹出中文错误气泡；休眠错误气泡提供“刷新”恢复入口，设置与测试连接始终可用。

### 3.3 主宠窗状态

- 正常：基础颜文字 + 当前人设颜色。
- 饿：显示对应表情或气泡，例如“好饿…”；颜色仍使用人设颜色。
- 无聊：显示无聊表情，并可能按概率主动发一条消息气泡。
- 普通饥饿/无聊状态气泡：进入状态时显示一次“好饿…”或“好无聊…”，8 秒后收起，不调用 AI、不写入聊天或记忆。到点提醒及离线提醒汇总优先，普通提示直接略过、不排队补弹。隐藏宠窗、拖动、菜单或错误层遮挡时撤下，恢复后不重放；喂食、聊天、睡眠、出门或切换上下文也撤下旧提示。无聊主动消息已由 Task 11.3 接通，生成与状态提示分开处理。
- 无聊主动消息气泡：后台先将正文保存到当前会话，前端再展示 20 秒，提供“查看聊天”入口，打开或聚焦已有聊天窗。到点提醒及离线提醒汇总优先；隐藏、拖动或提醒遮挡时撤下，不排队补弹，正文仍可在聊天历史查看。此功能已由 Task 11.3 接通；普通状态提示不调用 AI。
- 睡觉：显示睡觉表情；睡眠计时结束后自动唤醒，用户点击/摸摸/喂食也可唤醒。
- 吃东西：喂食后短暂显示吃东西表情。
- 说话：AI 开始回复前先切换说话表情，再显示流式气泡。
- 思考中：仅在聊天工具调用或说话前显示；记忆整合后台任务不显示思考中表情。
- 出门中：不显示出门中表情，只显示文字“`{当前人设名}出门啦`”；聊天按钮变为“写信”。
- 休眠：显示红色感叹号，不主动说话；AI 相关操作不可用。

### 3.4 左键与右键

- 左键单击：在家时随机触发点击类表情，并给当前会话亲密度 +1；出门中只弹“它出门啦”，不增加亲密度。
- 右键菜单：

```text
┌────────────┐
│ 聊天        │
│ 喂食        │
│ 摸摸        │
│ 桌宠状态    │
│ 饰品        │
│ 设置        │
│ 退出        │
└────────────┘
```

- 出门中时，“喂食”“摸摸”置灰；点击桌宠、喂食或摸摸都只弹“它出门啦”，不增加亲密度，也不改变饥饿等状态。
- 喂食、摸摸成功时更新亲密度和桌宠状态。
- 退出关闭整个应用，包括所有窗口、托盘和后台任务。

- 右键菜单：


## 5. 聊天窗

当前实现：聊天页已提供会话管理、分页记录、发送与暂停；输入区按亮暗主题在底部停靠。Enter 发送、Shift+Enter 换行，输入法组合期间 Enter 不发送。流式片段明确显示“尚未保存”，终态后使用后端消息替换；错误保留中文提示与草稿。回执前事件暂存，重复或旧上下文事件丢弃，序号缺口和窗口聚焦通过后台快照恢复。记忆入口已开放记事本、生成状态及 9.7 短期/长期正文管理；背景图片和消息编辑/删除/重说均已接通。

### 5.2 顶部与会话列表

- 标题：`颜喵 YanMew`。
- 新建会话按钮：创建当前人设下的新会话，创建时可选择绑定用户设定，也可留空。
- 记忆按钮：打开当前会话的记忆小窗。
- 背景按钮：在聊天窗内直接修改当前人设的聊天窗背景。
- 会话列表按人设隔离；切换当前人设后，历史会话列表同步切换。
- 首个完整回复保存为 `completed` 回合后，原标题仍为“新会话”时由 AI 使用会话首条用户消息生成 1–12 个字符的简短中文标题，只接受结构化 JSON `{title}`。手动改名取消标题任务，迟到结果不覆盖用户名称；中断或长度停止的聊天不触发标题，标题请求取消、空结果、长度停止或失败时保留“新会话”，不影响已保存聊天。
- 会话可切换、继续、删除；删除需要二次确认。确认框明确说明不可恢复，以及会话级聊天、记忆及来源、记事本、出行与旅行游记、节日、饰品、信件和伴手礼会被删除；全局喵币钱包、账单、提醒、小游戏插件、授权、设置、存档和运行记录不受影响。删除当前会话后切到同一人设最近更新的剩余会话，最后一项删除后进入无会话状态，不自动创建。切换会话/人设时取消原会话旅行及待回信，不生成返回结果；有进行中旅行时在切换操作旁说明该后果。
- 切换或删除当前会话前中断其流式请求，提交后递增 `contextRevision` 并通过 `window_context_changed` 刷新所有会话级窗口，前端不把旧事件显示到新上下文。删除非当前会话不递增版本、不影响当前聊天或记忆，仅通过 `configuration_changed` 刷新列表。
- 当前删除确认使用原生 `dialog`，绑定打开时的 `personaId/sessionId/contextRevision` 与目标会话快照；上下文改变则取消旧确认。失败保留弹窗和中文错误，忙碌时禁止重复提交、取消和 Escape；成功后重读后端权威状态。取消在左、危险确认在右，长说明内部滚动且按钮固定可见。
- 会话可修改绑定的用户设定；会话选项显示“用户设定：未绑定/名称”。新会话选择器默认未绑定，当前会话表单可修改或解除绑定，回复进行中也可提交，由后端先中断再保存。失败保留选择，切换会话清除旧绑定草稿；资料删除后列表与选择器同步变为未绑定。

### 5.3 消息区

- 用户消息靠右，AI 消息靠左。
- AI 回复为流式输出；AI 说话前先切换桌宠表情。
- 用户和 AI 的历史消息都提供 `编辑`：只修改消息原文，不自动修改或删除短期记忆、长期记忆和旅行游记；需要同步时由用户进入记忆小窗操作。
- 最底部是完整回合时提供 `删除本轮`：按钮显示在该轮 AI 回复下方，删除时同时删除本轮用户消息、AI 回复、对应短期记忆，并按触发关系回退长期记忆。
- 如果最底部只有一条尚未得到正常回复的用户消息，该消息提供 `删除`，删除未完整回合。
- 最底部是中断回合且已有部分 AI 正文时，在该回复下提供 `删除本轮`，同时删除用户消息、部分 AI 回复及回合记录；中断回合不生成记忆，此操作不修改已有记忆。
- 最底部是主动消息（`round_id=NULL`）时提供 `删除`，只删除该条消息，不删除前面的回合或修改已有记忆。不能越过底部主动消息删除更早回合。
- `重说` 只在最后一个完整回合的 AI 回复上显示；成功后原位更新 AI 回复与本轮短期记忆，如果该短期记忆参与了长期记忆，则同步重新生成受影响长期记忆；失败或中断保留旧结果。

- 用户可从汇总提示进入提醒页面，逐项把触发记录改为“未完成”“完成”或“已过期”。汇总是否已经展示由后端保存，避免每次启动重复弹出；未处理记录继续保留在提醒页面。

### 7.6 时间与天气

- 打开页面只读取配置和运行期缓存，不请求定位或联网。用户点击刷新后才申请 Windows 定位并查询天气；刷新期间可取消，离开页面或关闭设置窗时取消该页面正在进行的刷新。
- 定位状态区分尚未定位、已定位、权限拒绝与定位失败；位置展示实测经纬度，不推断城市。刷新失败且有历史结果时继续展示原位置，错误说明属于本次刷新。
- 天气来源：Open-Meteo / 和风天气 / 不可用；展示天气描述、温度、观测时间及获取时间，时间跟随电脑当前时区。缺失温度显示暂无，不显示为 0℃。
- 结果分为可用、缓存、已过期、不可用。刷新失败但仍在有效期内为缓存；接收超过 30 分钟、观测超过 60 分钟或时间回拨才为已过期。缓存与过期结果均保留来源和时间，不作为刚刚取得的结果。
- 和风天气配置包含控制台分配的 API Host 与 API Key，可选；Host 校验合法 HTTPS 主机，不含接口路径、账号和查询参数。Key 保存后不展示明文，留空保留，替换和清除是不同操作；保存失败保留草稿，成功后清空密钥输入。
- Host/Key 两项齐备才启用和风兜底。Open-Meteo 始终优先，普通刷新成功不代表已经验证和风连接；不提供虚假的“和风已连接”提示。保存配置后清空旧天气缓存，用户可再次主动刷新。
- 保存与刷新互斥。切换人设或会话后按 `contextRevision` 重新读取，仅接收当前版本结果；聚焦及页面内时效检查只读取本地缓存，不自动定位，不覆盖未保存的配置草稿。

### 7.9 游戏中心与插件管理

实施边界：13.4–13.5 后端及 src/api.ts 的 gamePluginsApi 已接通，本页与真实小游戏从 13.6 才实施。历史列表展示一次打开到关闭的运行记录，不把打开次数当成玩法局数；石头剪刀布每日 20 局由插件自己的存档统计。

安装页先选文件、预览，再展示 manifest、旧版本、迁移需要和逐项权限，让用户确认或取消。取消/关闭调用 cancelInstall；确认只传 token 与 choices。升级提示将关闭该插件窗口，保留存档，执行开发者迁移；失败显示原因，可重新打开旧版，不推荐清空存档。

游戏中心是“桌宠与内容”下的独立导航入口，不嵌在桌宠状态页面。顶部显示全局喵币余额，下面按响应式卡片展示随应用提供和用户安装的小游戏插件。

- 石头剪刀布是随便携版提供的第一方插件，从游戏中心启动，与本地安装插件使用相同的宿主、运行记录和钱包接口。
- 石头剪刀布规则：用户选择剪刀/石头/布，系统随机出拳；授权喵币权限时赢 `+5`、输 `-4`、平局 `0`，开始前余额必须 `≥ 4`，每天最多 `20` 次；拒绝喵币权限时可纯玩，不检查最低余额，也不修改喵币。

- 第一版展示随应用提供和用户从本地安装的插件，支持从 `.yanmew-game` 安装、启用、停用、更新、卸载、存档处理和权限管理，并提供“备份插件数据”“导入插件数据”入口。
- 石头剪刀布标记为“随应用提供”，允许停用和清除私有存档，不允许永久卸载；应用升级时随颜喵一起更新。
- 本地插件申请“修改喵币”时，安装确认页单独展示该权限及“可以增加或扣除全局喵币”的说明；随包插件在第一次打开时显示同等权限确认。用户允许或拒绝；剪刀石头布、骰子、接星星拒绝后可纯玩，我的家要求允许钱包才能玩。
- 用户可以在游戏管理页撤销喵币权限。插件更新增加新权限时必须再次确认，不能静默沿用旧授权。
- 小游戏插件全部是应用全局数据，不绑定人设或会话；切换、删除人设或会话不会切换或删除插件、设置、存档、运行记录和授权。
- 插件可以申请联网权限。安装或更新确认页按 HTTPS 来源逐项显示，用户可分别允许或拒绝；拒绝联网不阻止安装，但依赖联网的玩法可能不可用。
- 每个插件显示名称、作者、版本、来源、源码链接、全局存档状态、喵币权限、联网来源及其授权状态。第一版不显示“官方收录”或其他推荐徽标。
- 插件设置区读取 manifest `settings_schema` 自动生成开关、数字输入、文本输入或枚举选择控件，显示标题、说明和默认值；数据库只保存用户覆盖值。插件运行时从 `game.getContext().settings` 读取默认值与覆盖值合并后的只读对象。
- 插件数据区显示存档键数量、总大小、最近更新时间，并可在展开的技术信息中列出 `progress.main`、`stats.overall`、`records.high_scores` 等键名；默认不直接展开可能包含私人内容或插件服务凭据的原始 JSON。清除存档与清除设置分开确认。
- 历史运行记录列表显示插件名称/版本、开始与结束时间、`running/completed/cancelled/error` 状态、结果、喵币变化和插件提供的明细摘要；它不从当前插件存档反推历史结果，卸载插件后仍可查看。
- 从备份恢复但尚未重新安装的插件显示“缺少插件包”卡片：列出插件名称、插件 ID、原版本、作者、保留的设置/存档状态，以及可用的 GitHub 仓库或 Release 页面。
- 缺包卡片提供“打开来源页面”“从本地重新安装”和“删除保留数据”；打开链接使用系统默认浏览器，不由颜喵直接连接 GitHub API 或自动下载。
- 来源链接缺失时显示“未提供来源链接”，保留插件 ID、作者和原版本，方便用户自行查找。重新安装的插件 ID 与备份一致且兼容检查通过后，恢复原设置与存档。
- 第一版不直接连接 GitHub。以后社区仓库启用后，用户先在浏览器下载，再从本地安装；GitHub 自动安装、插件网站和 `yanmew://install?...` 放到后续版本。
- 小游戏不显示或申请 AI 出题、AI 解说能力，插件协议不提供 `ai.generate()`。
- 小游戏插件拥有独立视觉，不跟随颜喵亮色/暗色主题，也不从宿主读取主题模式或颜色变量。
- 完整协议与版本范围见 `docs/小游戏插件生态设计.md`。

### 7.10 时间与桌宠

- 饥饿触发时长 `hungry_minutes`，默认 `120` 分钟。
- 无聊触发时长 `bored_minutes`，默认 `45` 分钟。
- 无互动入睡分钟数 `sleep_idle_minutes`，默认 `45`，允许用户修改，保存时校验正整数。
- 睡眠最短/最长分钟数，默认 `60–120` 分钟，表示每次睡眠持续时间，与入睡触发时间分开设置。
- 出行最短/最长有效在线时间，默认 `2–4` 小时，允许用户修改；两项均为正数且最短值不得大于最长值。修改只影响以后新抽取的旅行倒计时，不重抽当前会话已经保存的剩余时间。
- 亲密度与饰品制作规则使用四行联动表单：
  - 档位 1：亲密度默认 `10`，制作价格默认 `20` 喵币。
  - 档位 2：亲密度默认 `50`，制作价格默认 `50` 喵币。
  - 档位 3：亲密度默认 `150`，制作价格默认 `120` 喵币。
  - 档位 4：亲密度默认 `300`，制作价格默认 `300` 喵币；达到该档位后重复制作继续使用该价格。
- 亲密度档位必须是 1–999 内严格递增的整数，价格必须为非负整数；校验失败时在对应输入框下显示中文原因并禁止保存。
- 页面提供“恢复默认值”和“保存”按钮；计时设置用于后续状态判定，亲密度/价格设置影响后续解锁与报价。保存不恢复已使用档位，也不退补历史喵币。
- 全部数值可编辑并保存。
- 当前页面已接入 15 项配置：饥饿/无聊/睡眠 5 项、出行间隔 2 项、四档亲密度/价格 8 项。仅保存本页实际改动的字段，不覆盖主题或记忆设置；读取失败时提供重试，保存失败保留草稿。
- “恢复默认值”从 Rust 读取默认值后只填入本页草稿，点击保存后生效；不直接修改数据库。出行与饰品玩法尚未接通时明确提示配置供后续使用，不将配置保存等同于玩法可用。
- 无聊主动消息的触发概率与上下文由代码层决定，不在此页面展示或选择。

无聊/睡眠实现与验收统一遵守产品规格“无聊与睡眠的随机分支”：默认同时到 45 分钟时各 50% 二选一，每段空闲只抽一次；不同阈值先到先进入，互动或睡眠结束开启下一周期。测试使用固定随机源分别覆盖两个分支，不能只等待真实随机结果。

旅行倒计时与无聊/睡眠计时分开显示和保存：互动会重置无聊/睡眠计时，但只暂停旅行倒计时；非当前会话保留剩余旅行秒数，切回后继续。界面不得使用一个“下次事件倒计时”混合表达旅行与无聊。

### 7.11 记忆（全局设置）

当前已开放 11 项配置的读取、校验、保存和默认值草稿恢复。设置全局生效，记忆内容仍按会话隔离；记事本工具、短期自动生成和 k+1 长期整合已接通，完整聊天上下文与混合 RAG 已接通，正文管理已在 9.7 接入；配置保存本身不等于已生成或整合记忆。保存只提交本页改动项，失败保留草稿；默认值统一读取 Rust 的 `get_settings_defaults`，不在前端复制默认常量。

- 短期记忆字数范围，默认 `12–100` 字。
- 长期记忆字数范围，默认 `150–250` 字。
- 每条长期记忆使用的短期记忆数量 `k`，默认 `20`；修改后只影响尚未整合的短期记忆。
- 进入上下文的最近消息原文数量，默认 `30`。

## 10. 错误、空态与加载

### 10.1 错误

- 主宠窗显示红色 `!` 感叹号。
- 点击感叹号弹出中文错误气泡。
- 错误类型包括：无 Token、连接失败、限流、后台记忆整合失败、导入导出失败等。
- 休眠状态下 AI 不主动说话，普通 AI 操作不可用；“刷新”、设置、测试连接仍可用。刷新恢复尝试、配置有效提供商或当前聊天提供商测试成功可恢复；失败保留错误。
- 后台短期/长期记忆失败在当前会话宠窗红色感叹号中列出，提供“查看记忆”进入记忆窗使用已有重试入口；修复成功移除对应提示，不阻塞聊天。主错误提供“刷新”，刷新时禁用重复点击，失败保留中文错误，成功清除连接错误。两类错误同时存在时分别提供入口，不互相清除。
- `usePetMemoryErrors` 先订阅 `memory-generation-changed` 再读取，焦点补查；结果校验会话和查询代次，切换上下文立即隐藏旧错误，不新增轮询或前端错误存储。查询失败在本地显示中文说明，不改变桌宠健康状态。
- 恢复中的配置/健康版本变化返回 `CONTEXT_CHANGED` 时，只重新读取 `get_pet_activity`，不展示旧连接失败，不自动重发聊天。后台记忆、Embedding、导入导出错误均不进入休眠；导入错误由通用备份页显示，不进入桌宠休眠。

### 10.2 空态

- 未配置提供商：聊天窗提示“请先在设置中添加 API 提供商”。

- 无信件：邮箱显示“还没有信件”。
- 无伴手礼：伴手礼显示“还没有收到伴手礼”。
- 无饰品：饰品管理显示“还没有饰品”。
- 无节日：我的节日列表显示“还没有添加节日”。

### 10.3 加载

- 流式回复：AI 气泡持续追加文字，不显示全局 loading。
- 流式回复期间发送按钮显示“暂停”。
- 生成表情库：按钮显示“生成中…”。
- 测试连接：按钮显示“测试中…”。
- 记忆重新生成/重新整合：对应按钮显示“生成中…”或“整合中…”。
- 出行事实和礼物快照由后端保存；旅行游记在其准备完成后后台生成，不要求信件或礼物展示行仍存在。删除展示项不清除出行事实，也不自动补回该项。

## 12. 关键交互流程

### 12.1 正常聊天

1. 用户点击主宠窗“聊天”。
2. 打开聊天窗，选择或新建会话。
3. 用户输入并发送。
4. AI 先切换表情，再流式输出回复。
5. 流式期间发送按钮变为“暂停”，点击可中断。
6. Rust 保存完整回复后唤醒既有记忆任务，并尝试提交本轮按需提出的人设候选；没有候选不额外请求 AI 判断。人设失败不撤销回复，初始设定保留。记事本工具仍在聊天工具循环中独立提交。

### 12.2 AI 出门

1. 满足在线时间和空闲条件后，主宠窗弹出“我出去玩啦”。
2. 主宠窗只显示“`{当前人设名}出门啦`”，不展示出门中表情。
3. 聊天按钮变成“写信”，聊天窗只显示写信入口。
4. 用户写信后等待 `10–30` 分钟随机回信。
5. 正常返回后先确保出行事实完整，生成伴手礼并保存实际快照，再据此生成回来信与游记；展示项被删除不清除事实、不触发重复发放。

### 12.3 制作饰品

1. 聊天AI按尚未使用的最低已解锁档位准备name、非空display_text和人设口吻description，工具只提交准备请求，不扣币、不自动佩戴；不新增聊天AI的生图工具。
2. 后台检查全局提供商生图开关/当前项/Key，有效时通过独立生图服务尝试一次，普通聊天回复不等待图片完成；预览准备中禁“给你买”，取消始终可用。未开启/未配置直接准备图标/Emoji/颜文字预览。
3. 图片成功校验时预览在透明槽中显示图片；图片失败/超时/不透明则预览图标、Emoji、颜文字或符号组合，并显示“图片未生成，当前预览将以图标、Emoji、颜文字或符号组合显示”及原因。不要显示白底、棋盘格或破图图标，不自动反复调用接口。
4. 最终预览就绪后显示当前会话、饰品名称/外观/简介、喵币价格及本次图像状态。用户点“给你买”才提交previewId；客户端不提交image_file、价格、余额或档位作为权威值。
5. 后端复验上下文、预览、档位、报价和余额，同一事务扣币、流水、饰品与档位标记；图片先已发布。确认前图片丢失必须回到图标/Emoji/颜文字预览重新确认；失败保留可用预览或说明已失效，不重复扣费。
6. 关闭制作界面/取消/切换会话丢弃未确认预览，迟到生图结果不保存；购买完成后支持佩戴/卸载/卖出/删除。图片文件日后丢失时仅回退display_text，不重新调用付费接口。

头顶图片随颜文字锚点移动，不改变文字排版或本体颜色。默认槽宽不超过颜文字实际宽度、高不超过基础字号的1.2倍，等比contain；与颜文字上沿保持约4CSS像素间距，画布不足时先缩小，不遮脸/裁图。亮暗主题不重绘图片；局部内容边界及原生命中区须覆盖饰品，保持原透明窗修复和拖动逻辑。管理列表图片加载失败显示图标、Emoji、颜文字或符号组合及局部说明。

### 12.4 从聊天创建提醒

1. 用户在聊天中要求提醒。
2. AI 通过 function calling 创建结构化提醒。
3. 设置 > 全局设置 > 提醒中出现该提醒，可手动编辑时间、详情、状态。

### 12.5 导入与导出

1. 用户打开设置 > 全局设置 > 通用 > 导入与导出。
2. 选择导出范围，Rust 打包 zip 并保存到用户选择的位置。
3. 用户换机或备份后，在目标机器选择导入文件。
4. 前端显示人设归属及将追加的会话，用户确认关联既有人设或新建人设；现有会话保留。全量包另行明确提示全局数据替换，插件包另行提示指定设置与存档恢复。
5. Rust 校验并导入；完成后提示重新填写 API Key / 和风天气 API Key。
6. 若选择插件使用数据包，则只恢复用户确认的插件设置与存档；缺少插件包时在游戏中心保留来源卡片。钱包和联网权限改为待确认，当前喵币、运行记录和账单保持不变。

### 12.6 签到彩蛋

1. 用户点击“每日签到”。
2. Rust 查当天是否命中母表或子表节日。
3. 命中：固定发放 `10` 喵币，直接展示节日记录里的祝福词，不调用 AI。
4. 同时命中母表和子表：合并祝福词，喵币仍为 `10`。
5. 未命中：随机发放 `1–10` 喵币。
6. 当天是节日时，聊天上下文的日期信息包含节日名称。

### 12.7 无聊主动消息与桌面游走

Task 11.5 已接通画布内游走：颜文字与气泡共享位移，顶部操作按钮固定。每 5 秒最多选择一次不超过 12 CSS 像素的位移，约 600ms 完成；前端每步更新现有原生命中区域。按住桌宠立即停下，打开聊天窗、拖动、隐藏、菜单/错误遮挡、睡眠、出门、休眠或系统减少动态效果时保持静止。气泡/颜文字尺寸变化后重新检查边界，跨会话与旧布局目标丢弃。位置偏移是临时显示状态，不作为会话数据或备份内容。

主动消息已接通：`PetConversationBubbles` 仅消费提交后的 `proactive-message`，校验人设、会话及上下文版本，显示 20 秒并提供“查看聊天”。提醒到来、隐藏和拖动会卸载并丢弃气泡，恢复时不回放。聊天历史保持可读；重复事件不延长显示。普通状态提示仍显示 8 秒。真实桌面及 DPI 体验待人工验收，游走已由 Task 11.5 接通，规则见本节。

1. 无互动达到配置阈值后按随机分支规则决定状态；只有选中无聊才进入主动消息流程，睡眠分支不请求主动消息。
2. 进入无聊后，每累计 5 分钟有效空闲时间抽签一次，命中概率 30%；同一段无聊最多成功发送一条，同一会话两次成功发送至少间隔 30 分钟。失败或取消只在下一次符合条件的抽签时再尝试。抽签由后端决定，前端不维护另一份计时。
3. 独立后台任务只用当前会话的人设、用户设定、消息、短期与长期记忆、记事本、最近 `5` 篇旅行游记标题、环境和当天节日；没有当前会话时不触发，不回退到其他会话。休眠、出门中、隐藏宠窗、拖动或正在聊天时不触发。正文先保存再展示 20 秒气泡，并提供“查看聊天”；提醒优先，隐藏、拖动或提醒遮挡时不补弹，历史正文保留。
4. 只在固定画布内移动颜文字及饰品、气泡；不移动整个窗口。日常聊天与主动消息共用含当天节日母子表的上下文。
5. 用户拖动、点击、打开聊天、睡觉、出门中、隐藏宠窗时立即暂停游走。

### 12.8 到点提醒与离线过期汇总

1. 后端先保存本次提醒触发记录，再向前端发送提醒事件。
2. 应用正在运行时，前端显示独立提醒气泡；AI 润色成功时显示润色结果，失败时显示默认提醒词。
3. 用户点击“完成”只更新本次触发记录；也可进入提醒页面手动改为未完成、完成或已过期。
4. 应用启动时，后端返回离线期间全部过期的一次性提醒，以及每个循环提醒最多一条汇总项。
5. 前端显示“你离开这段时间，{提醒名称1-n}过期了！”，并提供“查看提醒”入口。
6. 后端记录本次汇总已经展示，避免下次启动重复弹出；用户没有修改状态的记录仍保留在提醒页面。

## 13. 前端与 Rust 接口约定

- 所有数据通过 Tauri command 获取或提交。
- AI 流式输出通过 Tauri event 推送到前端；前端可调用中断命令停止当前回复。
- 前端不直接读写 SQLite，不直接调用 AI 提供商。
- API Key 只在设置表单输入，前端不展示已保存的明文 Key。
- 前端按错误类别处理：主流程故障显示全局错误状态，字段校验与局部操作失败留在对应窗口；错误显示不等于切换桌宠到休眠。
- 前端只展示当前会话的出行、信件、伴手礼、饰品、节日子表和记忆数据。
- 所有删除操作使用确认弹窗；删除会话、人设、饰品等不可恢复操作需要二次确认。

完整的请求时序、恢复要求与行为用例见[实施接口与验收约定](实施接口与验收约定.md)。

上下文自动缩减后，聊天窗显示非阻断提示：“本次上下文过长，已减少部分较旧内容；历史消息和记忆仍完整保留。”不修改用户配置的原文条数或 m 值；最低必要内容仍超限时明确提示无法发送，不循环重试。

### 13.1 通用返回与并发规则

- 饰品管理、伴手礼、会话固定日期以及插件运行历史/账单保留各自已展开的分页深度。聚焦、事件和手动刷新从首页重读已展开范围，不能只读取第一页而收起旧记录；是否还有下一页以最后一页条数判断。切换会话或插件重置其分页深度，此状态只在页面运行期保存，不写数据库。
- 插件管理清空选择或切换插件时使旧详情及分页请求失效，清空旧详情和确认状态；旧响应不能重新显示原插件的权限、存档操作或历史。刷新与追加分页采用同一查询代次，失效结果不追加，列表按记录 ID 去重。
- Tauri command 统一返回成功数据或结构化错误。错误至少包含稳定的 `code` 和中文 `message`；表单字段错误可附带 `field`，前端不得通过解析错误字符串判断业务类型。
- 会话级请求必须携带 `personaId`、`sessionId` 和当前 `contextRevision`。前端收到结果时再次核对；上下文已切换则丢弃旧结果。
- 聊天流式事件必须携带 `requestId`、`sessionId`、`roundId`、事件序号和事件类型。前端只接收当前请求且序号更新的事件，防止旧回复串入新会话。
- 新建、编辑、删除和钱包变化由 Rust 在事务中完成，前端成功后重新读取权威状态，不自行推算数据库最终结果。
- 会影响多个窗口的数据变化由 Rust 广播领域事件；已打开窗口按事件携带的 revision 刷新，避免各窗口各自维护不同副本。

### 13.2 窗口与上下文接口

- `focus_or_create_window`：按窗口类型显示并聚焦已有窗口，不重复创建；可携带当前人设或会话上下文。
- `window_context_changed` 事件：当前人设或会话变化后广播，聊天窗、记忆窗、出行窗、饰品页和节日页同步刷新。
- `get_current_context`：窗口恢复或首次加载时读取当前人设、当前会话和 context revision。
- 二级窗口关闭只销毁对应前端窗口，不调用应用退出；`exit_app` 仅由明确的退出入口调用。

### 13.3 桌宠状态接口

- `get_pet_activity`：读取后端权威快照；包含 `personaId`、可空 `sessionId`、`contextRevision`、`revision`、`activity`、`expression`、可空 `intimacy`、`sleepUntil`、`error`、`canInteract`、`canWander`。
- `activity` 枚举：`normal`、`hungry`、`bored`、`sleeping`、`eating`、`interacting`、`thinking`、`speaking`、`away`、`dormant`；仅表示展示状态，不替代数据库睡眠分支或出行状态。
- `interact_pet`：`input` 携带 `personaId/sessionId/contextRevision/action`，`action` 为 `click/stroke/feed`；后端校验当前上下文与出门状态，事务保存互动及封顶为 999 的亲密度，返回完整快照。前端不传奖励数量。
- `set_pet_dragging`：接收 `dragging` 布尔值，拖动结束或失败必须恢复 false。隐藏操作复用 `set_pet_hidden`。
- `refresh_pet_provider`：测试当前聊天提供商；成功恢复故障状态，失败保留可读错误，不改会话计时记录。
- `pet-activity-changed`：携带提交后的完整快照，旧 `revision` 不覆盖新状态。`pet-activity-error`：状态读取或保存失败的局部错误，不伪装成 AI 故障休眠。
- 订阅事件后主动读取一次快照。点击颜文字互动；右键菜单提供喂食、摸摸和 `亲密度 n / 999`，满值标注“已达上限”但仍可操作。无会话时提示创建会话，出门时禁用互动；菜单随隐藏或上下文变化关闭。

### 13.4 会话与消息接口

- `list_sessions`：接收当前 `personaId/contextRevision`，只列出该人设会话，并返回 `isCurrent`、标题、绑定用户设定、亲密度、记忆版本及创建/更新时间。
- `create_session`：为当前人设创建标题为“新会话”的会话并切为当前会话；后端先结算旧会话计时，按既有规则取消旧会话已开始旅行和待回信，提交后广播 `window_context_changed`。
- `set_active_session`：接收目标 `sessionId` 和调用前上下文；目标必须属于当前人设。重复选择当前会话不增加 context revision，实际切换取消旧聊天请求并恢复目标会话桌宠状态。
- `rename_session`：标题去除首尾空白后须为 1–100 个字符；只修改归属当前人设的目标会话。复用已有命令和会话列表入口，手动改名取消目标标题任务。
- `delete_session`：携带当前 `personaId/sessionId/contextRevision` 和目标会话 ID，返回 `{currentSessionId: string | null, contextRevision: number}`。删除当前会话才取消当前请求、回退到同人设最近更新项并递增版本；没有剩余项时返回 null。非当前删除保留当前会话、聊天、记忆和版本，仅广播 `configuration_changed`；当前删除广播 `window_context_changed`。删除范围及确认交互见 5.2，该功能没有新增数据库结构。

- `list_messages`：只读取当前会话，按消息 ID 正序分页；`afterId` 是上一页最后消息 ID，`limit` 为 1–200，默认 100，返回 `nextAfterId`。主动消息的 `roundId` 为 null。

### 13.6 提醒接口与事件

- `list_reminders`、`create_reminder`、`update_reminder`、`delete_reminder`：管理提醒规则。
- `list_reminder_occurrences`、`update_reminder_occurrence_status`：查看并手动修改每次触发记录的状态。
- `get_missed_reminder_summary`：按 `afterId` 分页返回未展示过期记录，每页最多 200 条，返回 `occurrences/nextAfterId/text`；读取所有页后按提醒 ID 去重组成汇总名称。一次性全部包含，循环提醒每次启动补偿只新建最近一次错过的记录；之前尚未展示的记录仍须一起确认，不因名称去重而遗漏 ID。
- `ack_missed_reminder_summary`：前端实际展示汇总后，携带本次 occurrence ID 列表确认已展示；重试幂等，不改变提醒完成状态。
- `complete_reminder_occurrence`：只完成指定 occurrence；一次性提醒同步更新规则状态，重复规则继续调度。
- 已实现的规则保存输入为 `{name, content, schedule, fireAt}`；循环提醒 `fireAt=null`、传版本 1 的 schedule，一次性 `schedule=null`、传未来时间。修改已触发的一次性提醒文字时可保留 `fireAt=null`。规则列表支持 `afterId/limit`，取不足一页即结束；触发记录列表返回 `nextAfterId`。ID 均为字符串。
- `reminders-changed` 通知页面重新查询数据库，`reminder-error` 独立报告提醒调度故障；启动不能只监听事件，必须主动读 queued 和 missed。实际展示 queued 后用 `acknowledge_reminder_occurrences(ids, deliveryState="queued")` 确认，missed 使用专用汇总确认接口；每批最多 200 个 ID，只改展示状态。
- 当前已接入上述后端命令与 `reminderApi`；提醒管理页面与页面内离线汇总已实现。宠窗气泡与启动离线汇总已接入；后台AI润色已接入，失败保持默认词。
- 气泡复用 `reminders-changed` 提示重查和 queued/missed 恢复查询，不额外引入重复投递事件。`get_reminder_occurrence(id)` 用于刷新已展示但尚未收起的当前气泡，其他窗口完成或删除后同步撤下。后台润色完成前及失败时使用固定默认文案。

### 13.9 响应式实现约定

- 页面组件使用容器实际宽度决定布局，不只依据显示器分辨率；用户拖动窗口边缘时应即时重排。
- 宽度不足时，设置左侧导航折叠为顶部选择器或抽屉；卡片网格降为单列；表单操作按钮换行并保持主要按钮可见。
- 组件不得写死只适用于默认窗口宽度的绝对定位。主宠窗颜文字、饰品和气泡可继续使用受控画布坐标。
- 对话框最大宽高受当前窗口可用区域限制，正文过长时内部滚动；确认与取消按钮保持可见。

### 会话固定日期页面与后端契约（18.3/18.4已接通）

母表为只读内置节日；子表只编辑当前会话自己的固定公历/农历日期（生日、纪念日、自定义日子），不提供复制母表、选择母表关联或填写出生年份的表单。使用festivalsApi与SessionFestivalInput/Record。名称、祝福词必填，日期/历法/闰月明确，备注可空。年度没有日期显示“本年无对应日期”；出现两次则均展示occurrences，不只显示首次缓存。编辑/删除提交旧revisionToken，冲突提示重新读取并保留草稿；所有修改携带当前context，切换时清理旧会话草稿与记录。festivals-changed中null会话表示日期整体刷新。

### 节日管理与签到页面交付（18.4）

实际组件为components/settings/FestivalPanel.tsx，由pages/SettingsPage.tsx的“节日”入口展示，并非新窗口。沿用亮暗主题Token、卡片、表单与确认dialog，字段网格按可用宽度自动换列，长祝福和备注换行、保留正文换行，列表不固定高度。
