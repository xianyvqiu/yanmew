# 颜喵 YanMew 前端设计文档

- 日期：2026-09-19
- 类型：前端界面与交互设计
- 状态：已确认方案已同步
- 说明：本文描述窗口结构、页面内容和交互；颜色、字体、圆角、阴影、组件状态和动效的统一规范见[前端美化风格设计](前端美化风格设计.md)，保存与恢复规则见 `docs/数据库与持久化设计.md`。

## 1. 设计目标与原则

- 首版面向 Windows，视觉上像桌面小宠物；共享页面预留未来 Android 适配，具体移动端导航后续专项设计。
- 主宠窗保持小、透明、无边框、置顶；聊天窗轻气泡风；设置窗使用圆角卡片，但整体仍要轻。
- 主程序内置亮色与暗色两套主题；用户可以跟随 Windows、固定亮色或固定暗色。主题只作用于颜喵主程序界面，小游戏插件保持自己的视觉。
- 颜文字是核心视觉元素，字体要大、清晰；状态优先用颜文字和短气泡表达。
- 桌宠本体颜色按人设绑定，只影响基础颜文字；饰品层、气泡、窗口背景不跟随该颜色。
- 主流程与后台错误可用红色感叹号查看中文详情；表单校验、记忆预览和插件局部失败在对应界面提示。只有主聊天提供商不可用等主流程故障进入休眠，不将所有错误映射成休眠。
- v1 不引入图片素材型饰品、旅行礼物或桌宠形象；饰品和礼物全部用文字、颜文字或 emoji 表达。
- 除固定画布的主宠窗外，聊天窗、设置窗、记忆窗、写信窗、出行窗等主要窗口均采用响应式设计，允许用户拖动和缩放。
- 文案使用简体中文；代码、路径、配置键保持原文。

## 2. 窗口与页面结构

本节窗口结构描述 Windows 首版。业务内容按架构文档放入 `pages/*Page.tsx`，`windows/*Window.tsx` 负责桌面外壳；共享页面不直接调用窗口创建、拖动、关闭或托盘 API。打开聊天/记忆/出行等使用语义导航，未来 Android 以同一应用内页面承载，不复制多窗口行为。

页面按容器宽度响应式展示，移动端还须处理触摸、软键盘、安全区和系统返回；窗口缩小不等于完成 Android 适配。平台能力由后端返回，缺少悬浮权限不影响应用内聊天和设置；托盘、开机自启等入口仅在实际支持的平台出现。Android 页面不会自动启用悬浮或后台麦克风。

### 2.1 二级窗口通用规则

当前实现：`chat`、`settings` 两个窗口已接入，分别由宠窗聊天/设置按钮和托盘设置入口打开。聊天窗提供会话新建、切换、改名、历史分页及发送/流式/暂停；设置窗已开放主题、聊天/记忆提供商、人设基础管理和提醒管理。两级导航中其他页面明确标记未开放，游戏中心与插件管理分别保留入口。

默认逻辑尺寸：聊天 800×640、设置 960×700，最小 360×420；创建时按主显示器工作区及 DPI 缩小初始/最小尺寸以适配可用空间。二级窗口采用普通系统标题栏，宠窗不受影响。布局小于 520px 时设置导航换成顶部选择器，主体独立滚动。

- 聊天窗、设置窗、记忆窗、写信窗和出行窗使用普通可拖动窗口，允许用户从窗口边缘调整大小；内容随窗口宽高响应式重排。
- 同一种二级窗口只保留一个实例。重复点击入口时不创建新窗口，而是显示、聚焦并置于前台；需要切换内容时复用现有窗口并刷新上下文。
- 窗口右上角关闭按钮关闭该窗口，不退出应用；退出应用只能通过主宠窗右键菜单、托盘菜单或设置中的“退出应用”。
- 切换当前人设或当前会话后，所有已打开且依赖会话的窗口立即刷新；旧流式事件、旧加载结果和旧表单提交不得写入或显示到新上下文。
- 宽屏优先使用侧栏 + 内容区或多列卡片；窗口变窄时改为单列、折叠侧栏或顶部选择器。表单标签、输入框和按钮允许换行，不使用横向滚动承载主要内容。
- 列表、消息区和正文区使用各自的纵向滚动容器；固定标题栏、主要操作按钮和当前上下文标识不得被滚动内容挤出窗口。
- 在 Windows 100%–200% DPI 和最小窗口尺寸下，文字、按钮、确认框均应完整可见；弹窗不得超出当前显示器可用区域。
- 主宠窗继续使用 `320×240` 固定桌宠画布规则，可拖动位置；它不套用普通内容窗口的响应式布局。

## 3. 主宠窗

### 3.1 画布

- 默认大小：`320×240`。
- 默认位置：屏幕右下角；用户拖动后记住位置，下次启动恢复。
- 窗口透明、无边框、置顶。
- 透明空白区域鼠标点击穿透，只让颜文字本体和可交互控件接收鼠标事件。
- 隐藏宠窗后，窗口缩小为只保留“显示宠窗”按钮；点击该按钮恢复完整宠窗。
- 固定宠窗内只移动颜文字及其饰品、气泡，不自动移动窗口；仅在画布有可用位置时避开前台窗口，鼠标靠近画布时可在范围内靠近。拖动、点击、聊天、睡觉、出门中、隐藏宠窗时暂停。

### 3.2 主宠窗布局

```text
┌────────────────────────────────┐
│ 右上角：[聊天/写信] [隐藏宠窗] [设置] [!] │
│                                 │
│   ┌─────────────────────┐       │
│   │ 气泡：饿/无聊/说话…  │       │
│   └─────────────────────┘       │
│           [饰品层]              │
│         ฅ^・ﻌ・^ฅ               │
│                                 │
└────────────────────────────────┘
```

- 基础颜文字：使用当前会话所属人设的 `color` 渲染。
- 饰品层：佩戴饰品时显示在头顶；未佩戴则隐藏。
- 气泡：位于桌宠上方，临时显示 AI 说话、活动提示、错误信息，自动消失。
- 聊天/写信按钮：
  - 正常状态显示“聊天”。
  - 当前会话 AI 出门中时显示“写信”。
- 隐藏宠窗按钮：隐藏后只留下一个“显示宠窗”按钮。
- 设置按钮：打开设置窗。
- 红色感叹号：出错或休眠时显示，点击弹出中文错误气泡；休眠错误气泡提供“刷新”恢复入口，设置与测试连接始终可用。

### 3.3 主宠窗状态

- 正常：基础颜文字 + 当前人设颜色。
- 饿：显示对应表情或气泡，例如“好饿…”；颜色仍使用人设颜色。
- 无聊：显示无聊表情，并可能按概率主动发一条消息气泡。
- 睡觉：显示睡觉表情；睡眠计时结束后自动唤醒，用户点击/摸摸/喂食也可唤醒。
- 吃东西：喂食后短暂显示吃东西表情。
- 说话：AI 开始回复前先切换说话表情，再显示流式气泡。
- 思考中：仅在聊天工具调用或说话前显示；记忆整合后台任务不显示思考中表情。
- 出门中：不显示出门中表情，只显示文字“`{当前人设名}出门啦`”；聊天按钮变为“写信”。
- 休眠：显示红色感叹号，不主动说话；AI 相关操作不可用。

### 3.4 左键与右键

- 左键单击：在家时随机触发点击类表情，并给当前会话亲密度 +1；出门中只弹“它出门啦”，不增加亲密度。
- 右键菜单：

```text
┌────────────┐
│ 聊天        │
│ 喂食        │
│ 摸摸        │
│ 桌宠状态    │
│ 饰品        │
│ 设置        │
│ 退出        │
└────────────┘
```

- 出门中时，“喂食”“摸摸”置灰；点击桌宠、喂食或摸摸都只弹“它出门啦”，不增加亲密度，也不改变饥饿等状态。
- 喂食、摸摸成功时更新亲密度和桌宠状态。
- 退出关闭整个应用，包括所有窗口、托盘和后台任务。

## 4. 系统托盘

- 托盘图标使用应用图标。
- 左键单击托盘图标：显示或聚焦主宠窗。
- 右键菜单：

```text
┌────────────┐
│ 显示宠窗    │
│ 设置        │
│ 退出        │
└────────────┘
```

- “退出”与主宠窗右键退出行为一致，关闭整个应用。

## 5. 聊天窗

当前实现：聊天页已提供会话管理、分页记录、发送与暂停；输入区按亮暗主题在底部停靠。Enter 发送、Shift+Enter 换行，输入法组合期间 Enter 不发送。流式片段明确显示“尚未保存”，终态后使用后端消息替换；错误保留中文提示与草稿。回执前事件暂存，重复或旧上下文事件丢弃，序号缺口和窗口聚焦通过后台快照恢复。背景图片、记忆入口和消息编辑/删除/重说按后续阶段接入。

### 5.1 聊天窗布局

```text
┌──────────────────────────────────┐
│ 颜喵 YanMew    [新建] [记忆] [背景] │
│ ┌──────────────────────────────┐ │
│ │ 会话列表                      │ │
│ │ ○ 会话A  ⋯ [重命名] [删除]   │ │
│ │ ○ 会话B  ⋯ [重命名] [删除]   │ │
│ └──────────────────────────────┘ │
│ ┌──────────────────────────────┐ │
│ │ 消息气泡区                    │ │
│ │ 用户消息靠右                  │ │
│ │ AI 消息靠左                   │ │
│ │ [删除] [编辑] [重说]          │ │
│ └──────────────────────────────┘ │
│ ┌──────────────────────────────┐ │
│ │ 输入框               [发送/暂停]│ │
│ └──────────────────────────────┘ │
└──────────────────────────────────┘
```

### 5.2 顶部与会话列表

- 标题：`颜喵 YanMew`。
- 新建会话按钮：创建当前人设下的新会话，创建时可选择绑定用户设定，也可留空。
- 记忆按钮：打开当前会话的记忆小窗。
- 背景按钮：在聊天窗内直接修改当前人设的聊天窗背景。
- 会话列表按人设隔离；切换当前人设后，历史会话列表同步切换。
- 会话标题由 AI 自动生成，用户可重命名。
- 会话可切换、继续、删除；删除需要二次确认。确认框明确说明会话级聊天、记忆、旅行、节日、饰品、信件和伴手礼会被删除；全局小游戏插件、插件设置、插件存档、游戏局与喵币账单不受影响。切换会话/人设时取消原会话旅行及待回信，不生成返回结果；有进行中旅行时在切换操作旁说明该后果。
- 切换/删除会话前中断流式请求，前端不把旧请求事件显示到新会话。
- 会话可修改绑定的用户设定；绑定项在会话行右侧显示“用户设定：未绑定/名称”。

### 5.3 消息区

- 用户消息靠右，AI 消息靠左。
- AI 回复为流式输出；AI 说话前先切换桌宠表情。
- 用户和 AI 的历史消息都提供 `编辑`：只修改消息原文，不自动修改或删除短期记忆、长期记忆和旅行游记；需要同步时由用户进入记忆小窗操作。
- 最底部是完整回合时提供 `删除本轮`：按钮显示在该轮 AI 回复下方，删除时同时删除本轮用户消息、AI 回复、对应短期记忆，并按触发关系回退长期记忆。
- 如果最底部只有一条尚未得到正常回复的用户消息，该消息提供 `删除`，删除未完整回合。
- 最底部是中断回合且已有部分 AI 正文时，在该回复下提供 `删除本轮`，同时删除用户消息、部分 AI 回复及回合记录；中断回合不生成记忆，此操作不修改已有记忆。
- 最底部是主动消息（`round_id=NULL`）时提供 `删除`，只删除该条消息，不删除前面的回合或修改已有记忆。不能越过底部主动消息删除更早回合。
- `重说` 只在最后一个完整回合的 AI 回复上显示；成功后原位更新 AI 回复与本轮短期记忆，如果该短期记忆参与了长期记忆，则同步重新生成受影响长期记忆；失败或中断保留旧结果。

### 5.4 输入区

- 支持多行文本输入。
- 后端确认用户消息已持久化并返回请求回执后清空输入框；校验失败或提交失败保留输入，防止丢失未发送正文。
- 流式回复期间，发送按钮变为“暂停”；点击后中断当前 AI 回复。
- 暂停后输入框恢复可用，已收到正文保存一次，无正文不插空消息；中断不增加完整聊天轮次亲密度。已提交工具操作不回滚。消息统一由 Rust 保存。

### 5.5 出门中状态

- 当前会话 AI 出门中时，聊天窗不展示会话列表和消息区，只显示一个简洁状态面板。
- 出门状态面板保留切换其他会话的入口，并说明切换将取消本次旅行和待回信。
- 状态面板文案：`{当前人设名}出门啦`，并提供“写信”按钮和“跳转邮箱”按钮。
- 主宠窗聊天按钮同步变为“写信”。

### 5.6 聊天窗背景

- 聊天窗背景按人设隔离，切换人设后跟随切换。
- 背景层位于消息气泡、会话列表和输入框下方。
- 背景效果由三部分组成：
  - 背景图片：`jpg / png / webp`，单张最大 `10MB`。
  - 透明度：`0–100%`。
  - 模糊度：`0–40px`。
- 未设置背景图时使用默认纯色背景。
- 设置入口：
  - 聊天窗顶部“背景”按钮。
  - 设置 > 全局设置 > 人设 > 对应人设卡片 > 聊天窗背景。
- 上传、预览、透明度滑块、模糊度滑块、恢复默认。

## 6. 写信界面

### 6.1 打开方式

- 主宠窗出门中时点击“写信”。
- 旅行进行中，在设置 > 桌宠与内容 > 出行 > 邮箱点击“写信”；返回后入口置灰。
- 回复某封 AI 来信时，复用写信界面并带上回复目标。

### 6.2 写信界面布局

```text
┌──────────────────────────────────┐
│ 写信给：当前会话 AI              │
│ 当前人设：人设名                 │
│                                  │
│ ┌──────────────────────────────┐ │
│ │ 写信正文                     │ │
│ │                              │ │
│ │                              │ │
│ └──────────────────────────────┘ │
│                                  │
│ [取消] [跳转邮箱]        [发送]   │
└──────────────────────────────────┘
```

### 6.3 写信规则

- 出门中时可连续写多封。
- 旅行仍在进行且信件未取消时，每封用户来信按计划获得 AI 回信；返回或切换会话后取消待回信。
- 回信延迟默认 `10–30` 分钟随机。
- 已回复的信不能再回，删除回复也不恢复资格；旅行返回后禁止写信和回信，邮箱中相应按钮置灰。
- 写信和回信使用当前会话人设、记忆和记事本；AI 生成的信件内容应包含可爱颜文字。
- “跳转邮箱”按钮打开当前会话邮箱管理。

### 7.2 提供商

已确认待接入的高级设置：最大输出默认 `32768 tokens`，可修改为正整数；上下文容量默认自动，允许手动覆盖但不要求填写。显示能力来源、配置最大输出与实际生效值；自动识别不到时明确显示“未知”，不显示虚假的固定容量。服务商上限或本次剩余容量较小时说明生效值降低原因，不修改用户已保存的设置。token 不等于字数，推理模型可能把思考计入额度。

聊天长度终止时，在原回复下显示“已达到本次输出上限”和“继续生成”；仅当前会话最后一轮且仍符合后端资格时可用。点击后原位追加正文，按钮进入忙碌态，可暂停；不增加一条用户“继续”消息，不自动续写。异常重复、乱码、超时及普通暂停显示各自停止原因，不误显示长度继续入口。所有资格由后端返回，刷新后从持久化状态恢复。容量缩减提示只说明本次减少较旧内容，不暗示历史被删除。详细规则见《记忆与旅行游记设计》6.2、6.4、6.5；上述新能力尚未实现。

当前实现：聊天与记忆提供商的新增、编辑、测试、选择和删除已接入；桌面导航与窄窗选择器均可进入提供商页。Embedding 仅显示“尚未开放”，实际本地模型与联网配置待 Task 9.5；不把规划默认项展示成已经可运行。

### 7.5 提醒

当前实现：设置中的提醒管理已开放，规则与触发记录分区展示；规则可新增/编辑/删除，触发记录可筛选、分页加载、完成本次或手动调整状态。删除规则确认时说明同时删除全部触发记录。页面订阅提醒变化并在聚焦时补查，后台错误独立展示，不改变提供商状态。

页面内离线汇总读完所有分页后按提醒 ID 去重名称，“知道了”只确认本次看到的全部记录，分批最多 200 条；未点击确认不会消耗待展示记录。queued 记录有独立“确认已看到”，同样不改变完成状态。宠窗已接入到点气泡和启动离线汇总，实际可见后自动确认投递；AI 润色仍未接入，当前使用固定默认文案。

- 循环提醒时间跟随电脑当前时区；月度不存在日期和夏令时不存在时刻跳过，重复时刻只提醒第一次。一次性输入由前端转换为带时区 RFC3339，后端保存绝对时间；切换时区后显示为当前当地时间，但触发瞬间不变。
- 提醒列表显示：提醒名、提醒详情、类型、状态、触发时间、来源。
- 支持新增、编辑、删除。
- 类型：
  - 一次性
  - 每天
  - 每周
  - 每月
- 提醒规则和每次触发记录的状态都在提醒页面可见；用户可以手动修改某次提醒状态：
  - 未完成
  - 完成
  - 已过期
- 编辑项：时间、详情、循环规则影响未来触发；完成/过期操作本次触发记录。重复提醒“完成”仅完成本次，继续下一次；永久停止只能删除提醒。
- 显示本次原定时间与下一次触发时间；离线期间错过的记录标为“已过期”，并由启动汇总统一告知，用户可在提醒页面手动调整状态。
- 到点时使用独立的提醒气泡，视觉上与聊天气泡区分：包含提醒图标、提醒名、详情、原定时间和“完成”按钮，不伪装成 AI 聊天消息。
- 到点时宠窗隐藏则自动恢复并显示提醒；气泡不自动消失，保留到点击“完成”或“收起”。“收起”只关闭提示、不修改完成状态；“查看提醒”打开或聚焦已有设置窗的提醒页。用户在本次提示后再次手动隐藏时，不因同一条记录反复恢复，新的到期记录仍可恢复宠窗。
- 多条通知按队列展示，先恢复 queued 到点提醒再显示 missed 离线汇总。汇总以宠窗内非模态局部卡片呈现，不用全窗口不透明遮罩，不修改 Windows 边框或窗口尺寸。长内容在卡片内滚动，操作按钮固定可见。
- 提醒到点后可让 AI 按当前人设润色气泡文案；AI 调用失败时直接回退为：`{提醒名}事件提醒：{提醒详情}{提醒时间}`。
- 应用关闭期间不执行提醒任务；下次启动时，后端根据已保存的到期时间补记离线过期触发记录，再用汇总提示告诉用户：`你离开这段时间，{提醒名称1-n}过期了！`；所有过期的一次性提醒都列出，同一个循环提醒无论错过多少次只汇总一次。
- 用户可从汇总提示进入提醒页面，逐项把触发记录改为“未完成”“完成”或“已过期”。汇总是否已经展示由后端保存，避免每次启动重复弹出；未处理记录继续保留在提醒页面。

### 7.6 时间与天气

- 打开页面只读取配置和运行期缓存，不请求定位或联网。用户点击刷新后才申请 Windows 定位并查询天气；刷新期间可取消，离开页面或关闭设置窗时取消该页面正在进行的刷新。
- 定位状态区分尚未定位、已定位、权限拒绝与定位失败；位置展示实测经纬度，不推断城市。刷新失败且有历史结果时继续展示原位置，错误说明属于本次刷新。
- 天气来源：Open-Meteo / 和风天气 / 不可用；展示天气描述、温度、观测时间及获取时间，时间跟随电脑当前时区。缺失温度显示暂无，不显示为 0℃。
- 结果分为可用、缓存、已过期、不可用。刷新失败但仍在有效期内为缓存；接收超过 30 分钟、观测超过 60 分钟或时间回拨才为已过期。缓存与过期结果均保留来源和时间，不作为刚刚取得的结果。
- 和风天气配置包含控制台分配的 API Host 与 API Key，可选；Host 校验合法 HTTPS 主机，不含接口路径、账号和查询参数。Key 保存后不展示明文，留空保留，替换和清除是不同操作；保存失败保留草稿，成功后清空密钥输入。
- Host/Key 两项齐备才启用和风兜底。Open-Meteo 始终优先，普通刷新成功不代表已经验证和风连接；不提供虚假的“和风已连接”提示。保存配置后清空旧天气缓存，用户可再次主动刷新。
- 保存与刷新互斥。切换人设或会话后按 `contextRevision` 重新读取，仅接收当前版本结果；聚焦及页面内时效检查只读取本地缓存，不自动定位，不覆盖未保存的配置草稿。

### 7.9 游戏中心与插件管理

游戏中心是“桌宠与内容”下的独立导航入口，不嵌在桌宠状态页面。顶部显示全局喵币余额，下面按响应式卡片展示随应用提供和用户安装的小游戏插件。

- 石头剪刀布规则：用户选择剪刀/石头/布，系统随机出拳；授权喵币权限时赢 `+5`、输 `-4`、平局 `0`，开始前余额必须 `≥ 4`，每天最多 `20` 次；拒绝喵币权限时可纯玩，不检查最低余额，也不修改喵币。

- 第一版展示随应用提供和用户从本地安装的插件，支持从 `.yanmew-game` 安装、启用、停用、更新、卸载、存档处理和权限管理，并提供“备份插件数据”“导入插件数据”入口。
- 石头剪刀布标记为“随应用提供”，允许停用和清除私有存档，不允许永久卸载；应用升级时随颜喵一起更新。
- 本地插件申请“修改喵币”时，安装确认页单独展示该权限及“可以增加或扣除全局喵币”的说明；随包插件在第一次打开时显示同等权限确认。用户允许或拒绝，拒绝后仍可纯玩。

- 小游戏插件全部是应用全局数据，不绑定人设或会话；切换、删除人设或会话不会切换或删除插件、设置、存档、游戏局和授权。
- 插件可以申请联网权限。安装或更新确认页按 HTTPS 来源逐项显示，用户可分别允许或拒绝；拒绝联网不阻止安装，但依赖联网的玩法可能不可用。
- 每个插件显示名称、作者、版本、来源、源码链接、全局存档状态、喵币权限、联网来源及其授权状态。第一版不显示“官方收录”或其他推荐徽标。
- 插件设置区读取 manifest `settings_schema` 自动生成开关、数字输入、文本输入或枚举选择控件，显示标题、说明和默认值；数据库只保存用户覆盖值。插件运行时从 `game.getContext().settings` 读取默认值与覆盖值合并后的只读对象。
- 插件数据区显示存档键数量、总大小、最近更新时间，并可在展开的技术信息中列出 `progress.main`、`stats.overall`、`records.high_scores` 等键名；默认不直接展开可能包含私人内容或插件服务凭据的原始 JSON。清除存档与清除设置分开确认。
- 历史游戏局列表显示插件名称/版本、开始与结束时间、`running/completed/cancelled/error` 状态、结果、喵币变化和插件提供的明细摘要；它不从当前插件存档反推历史结果，卸载插件后仍可查看。
- 从备份恢复但尚未重新安装的插件显示“缺少插件包”卡片：列出插件名称、插件 ID、原版本、作者、保留的设置/存档状态，以及可用的 GitHub 仓库或 Release 页面。
- 缺包卡片提供“打开来源页面”“从本地重新安装”和“删除保留数据”；打开链接使用系统默认浏览器，不由颜喵直接连接 GitHub API 或自动下载。
- 来源链接缺失时显示“未提供来源链接”，保留插件 ID、作者和原版本，方便用户自行查找。重新安装的插件 ID 与备份一致且兼容检查通过后，恢复原设置与存档。
- 第一版不直接连接 GitHub。以后社区仓库启用后，用户先在浏览器下载，再从本地安装；GitHub 自动安装、插件网站和 `yanmew://install?...` 放到后续版本。
- 小游戏不显示或申请 AI 出题、AI 解说能力，插件协议不提供 `ai.generate()`。
- 小游戏插件拥有独立视觉，不跟随颜喵亮色/暗色主题，也不从宿主读取主题模式或颜色变量。
- 完整协议与版本范围见 `docs/小游戏插件生态设计.md`。

### 7.10 时间与桌宠

- 饥饿触发时长 `hungry_minutes`，默认 `120` 分钟。
- 无聊触发时长 `bored_minutes`，默认 `45` 分钟。
- 无互动入睡分钟数 `sleep_idle_minutes`，默认 `45`，允许用户修改，保存时校验正整数。
- 睡眠最短/最长分钟数，默认 `60–120` 分钟，表示每次睡眠持续时间，与入睡触发时间分开设置。
- 出行最短/最长有效在线时间，默认 `2–4` 小时，允许用户修改；两项均为正数且最短值不得大于最长值。修改只影响以后新抽取的旅行倒计时，不重抽当前会话已经保存的剩余时间。
- 亲密度与饰品制作规则使用四行联动表单：
  - 档位 1：亲密度默认 `10`，制作价格默认 `20` 喵币。
  - 档位 2：亲密度默认 `50`，制作价格默认 `50` 喵币。
  - 档位 3：亲密度默认 `150`，制作价格默认 `120` 喵币。
  - 档位 4：亲密度默认 `300`，制作价格默认 `300` 喵币；达到该档位后重复制作继续使用该价格。
- 亲密度档位必须是 1–999 内严格递增的整数，价格必须为非负整数；校验失败时在对应输入框下显示中文原因并禁止保存。
- 页面提供“恢复默认值”和“保存”按钮；计时设置用于后续状态判定，亲密度/价格设置影响后续解锁与报价。保存不恢复已使用档位，也不退补历史喵币。
- 全部数值可编辑并保存。
- 当前页面已接入 15 项配置：饥饿/无聊/睡眠 5 项、出行间隔 2 项、四档亲密度/价格 8 项。仅保存本页实际改动的字段，不覆盖主题或记忆设置；读取失败时提供重试，保存失败保留草稿。
- “恢复默认值”从 Rust 读取默认值后只填入本页草稿，点击保存后生效；不直接修改数据库。出行与饰品玩法尚未接通时明确提示配置供后续使用，不将配置保存等同于玩法可用。
- 无聊主动消息的触发概率与上下文由代码层决定，不在此页面展示或选择。

无聊/睡眠实现与验收统一遵守产品规格“无聊与睡眠的随机分支”：默认同时到 45 分钟时各 50% 二选一，每段空闲只抽一次；不同阈值先到先进入，互动或睡眠结束开启下一周期。测试使用固定随机源分别覆盖两个分支，不能只等待真实随机结果。

旅行倒计时与无聊/睡眠计时分开显示和保存：互动会重置无聊/睡眠计时，但只暂停旅行倒计时；非当前会话保留剩余旅行秒数，切回后继续。界面不得使用一个“下次事件倒计时”混合表达旅行与无聊。

### 7.11 记忆（全局设置）

当前已开放 11 项配置的读取、校验、保存和默认值草稿恢复。设置全局生效，记忆内容仍按会话隔离；记事本工具与短期记忆自动生成已接通，页面明确说明长期整合和 RAG 尚未接入，不把配置保存描述为已生成或整合记忆。保存只提交本页改动项，失败保留草稿；默认值统一读取 Rust 的 `get_settings_defaults`，不在前端复制默认常量。

- 短期记忆字数范围，默认 `12–100` 字。
- 长期记忆字数范围，默认 `150–250` 字。
- 每条长期记忆使用的短期记忆数量 `k`，默认 `20`；修改后只影响尚未整合的短期记忆。
- 进入上下文的最近消息原文数量，默认 `30`。
- 直接进入上下文的最近长期记忆数量 `m`，默认 `30`；该值与最近消息原文数量独立。
- 旅行游记字数范围，默认 `250–350` 字。
- 单次 AI 回复的工具调用轮数上限 `tool_call_rounds`，默认 `3`，统一约束记事本、深层回忆等工具。
- 记事本 AI 维护建议上限，默认 `4000` 字。设置项和记事本窗口均明确标注为软限制；窗口显示“当前字数 / 建议上限”，超限仍允许完整保存并提示“AI 将在后续整理”，不截断正文。
- 所有字数单位为中文汉字个数。
- 所有全局设置控件的键名、默认值、校验和缺省行为以《数据库与持久化设计》第 2.7 节的 `settings` 完整键清单为准；前端不得用标签文字临时拼接数据库键，也不得直接调用任意键值写入接口。

### 7.12 出行

- 出行页不显示会话选择器，数据跟随当前会话；只有当前会话在家空闲时累计出行时间。
- 显示当前出行状态：在家 / 出门中。
- 显示最近旅行历史，历史状态区分出门中、已返回和已取消；取消不显示虚构返回礼物或游记。
- 三个标签页：邮箱、伴手礼、旅行游记。
- 邮箱、伴手礼和旅行游记都按当前会话加载。

### 7.13 饰品

- 当前会话饰品列表。
- 每项显示：
  - 饰品名称
  - 头顶显示文字/emoji/颜文字
  - AI 按人设口吻写的简介
  - 来源：制作 / 旅行带回
  - 是否佩戴
- 操作：
  - 佩戴
  - 卸载
  - 卖出未佩戴饰品，固定获得 `10` 喵币
  - 删除未佩戴饰品
- 删除后不可恢复；卖出和删除都需要二次确认。
- AI 发起制作请求时，在主宠窗弹出确认气泡/卡片：
  - `给你买`
  - `没有钱了`
- 余额足够才可完成制作。

### 7.14 节日

- 页面分“系统节日”和“我的节日”两部分。
- 系统节日（母表）：只读列表，显示节日名、历法类型（公历/农历/节气）、公历月日、农历月日、祝福词、是否纪念性节日。
- 我的节日（当前会话子表）：显示名称、类型（节日/生日/纪念日/自定义）、历法类型、公历月日、农历月日、祝福词、备注、来源。
- 支持手动新增、编辑、删除；农历日期可选择“闰月”，祝福词必填。year 记录本年，日期按内置小型日历判断，本年无对应日期则不触发。
- 页面不显示会话选择器，数据跟随当前会话，与出行页一致。
- 页面提示：农历与节气日期每年自动查内置表更新，无需手动维护。
- 母表只读，不提供编辑入口。

### 7.15 导入与导出

- 入口：全局设置 > 通用 > 导入与导出。
- 导出类型：
  - 全量备份
  - 人设资料包（分享用）
  - 人设完整包（迁移用）
  - 指定会话
  - 指定用户设定（可选择同时导出绑定它的会话）
  - 插件使用数据包（从游戏中心与插件管理选择要备份的插件）
- 导出时弹窗选择保存位置和导出范围。
- 导入时选择 `.yanmew-backup.zip`，先显示文件摘要：
  - 类型、导出时间、包含的人设/会话/用户设定/文件数量。
  - 人设资料包只包含人设定义、聊天窗背景和表情库，不包含会话与私密数据。
- 导入模式：
  - 新建副本（默认）
  - 人设资料包只允许新建副本，名称冲突时自动重命名
  - 其他备份包可选覆盖同名项（二次确认）
- 全量导入摘要明确显示：备份将替换全局喵币、账单、设置、提醒与提供商非密钥配置，不累加余额；部分包不修改这些全局数据。
- 全量备份与恢复同时显示小游戏插件登记、权限、设置、私有存档和游戏局；同时保存 manifest 中的 GitHub 仓库、项目主页和 Release 页面。石头剪刀布程序包由目标便携版提供，用户另装的 `.yanmew-game` 程序包不进入备份，恢复后由用户自行重新下载并安装。
- 插件使用数据包只包含插件登记快照、来源链接、权限申请、设置和私有存档，不包含程序包、游戏局、插件账单或钱包余额。导入摘要逐个列出将被覆盖的插件设置和存档，并明确显示“不会改变当前喵币，也不会重放历史喵币变化”。
- 独立导入插件数据后，喵币权限和每个联网 origin 都显示“待确认”；插件再次请求对应能力时由用户允许或拒绝，确认前宿主拒绝调用。
- 导入摘要单独列出“需要重新安装的插件”；导入完成后可直接进入游戏中心查看缺包数据卡片和来源链接。插件尚未安装时，其设置与存档可见但不可运行。
- 覆盖同名项列出对象类型、父级和目标供明确选择，不自动覆盖多个同名对象。
- 导入完成显示成功摘要；仅对需要配置的密钥提示重新填写，部分包不清除目标现有密钥。
- 长期记忆全文索引和向量不从备份导入；导入提交后显示“正在重建长期记忆检索索引”，该过程不阻塞已导入数据的查看。
- 导入文件损坏、版本不兼容、结构异常时显示中文错误，不写入半成品数据。

## 8. 记忆小窗

```text
┌────────────────────────────────┐
│ 当前会话记忆                    │
│ ┌────────────────────────────┐ │
│ │ 短期记忆                   │ │
│ │ - 记忆1 [编辑] [重新生成]  │ │
│ └────────────────────────────┘ │
│ ┌────────────────────────────┐ │
│ │ 长期记忆                   │ │
│ │ - 记忆A [编辑] [重新整合]  │ │
│ └────────────────────────────┘ │
│ ┌────────────────────────────┐ │
│ │ 记事本                     │ │
│ │ [大段文本，可编辑]         │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

- 从聊天窗打开，自动跟随聊天窗当前会话。
- Task 9.2 已开放聊天窗“查看记事本”入口，复用单实例 memory 小窗；Task 9.3 增加短期生成状态，短期/长期记忆正文管理面板在 Task 9.7 接入。窗口可缩放，跟随亮暗主题，关闭只关闭本窗口。
- 当前短期生成状态区显示已生成数量、待生成完整回合数量及“正在生成”；失败显示安全中文错误和有限重试/暂停说明，聊天记录仍完整保留。存在缺失回合时提供“重试待生成记忆”，本会话正在生成时禁用按钮，重试不覆盖已有记忆。状态读取失败独立提供“重新读取状态”；切换会话更新统计，后台变化和窗口聚焦时补查，旧上下文响应不刷新新会话。
- 记事本支持全文编辑和保存，显示当前 Unicode 字数、建议上限与超限提示；不设截断输入限制，清空正文也可保存。读取失败可重试，保存成功显示反馈；后台更新不覆盖未保存草稿，旧快照冲突时保留草稿并提供明确的重新加载按钮。聚焦时补查最新数据，人设或会话切换时读取目标会话。
- 短期记忆按聊天回合展示来源回合与“尚未整合/已经整合”状态；长期记忆卡片优先显示简短标题，展开后显示正文、来源短期记忆、由来源末轮推导的覆盖消息和触发回合。
- **短期记忆和长期记忆是中性事实记录，不使用人设口吻，不需要任何氛围总结或主观评价，必须只是如同剧本一样的叙事描述。**
- 短期记忆和长期记忆都不支持手动新建或删除，只支持手动编辑；长期记忆的标题和正文均可编辑。
- 短期记忆提供“重新生成”，使用绑定回合原文生成；长期记忆提供“重新整合”，只使用其原有短期记忆来源，并同时生成标题和正文。生成后先弹出可编辑预览，用户确认才覆盖原记录，ID 不变。
- 编辑或重新生成已整合短期记忆时提示：现有长期记忆不会自动变化，可按需重新整合相关长期记忆。
- 不提供“选择多条长期记忆合并”。长期记忆正常保存时不自动删除、再次合并或压缩，进入上下文的数量由最近 `m` 条与混合 RAG 控制。
- 长期记忆编辑或重新整合成功后，全文索引同步更新，旧向量失效并在后台补建；向量尚未补建时仍可使用标题与正文进行关键词检索。
- 旅行游记不出现在记忆小窗，统一在出行管理中查看。

## 9. 出行管理

### 9.1 邮箱

- 邮箱列表显示：发送方、信件摘要、时间、是否已读、是否收藏。
- 支持查看、收藏、删除、回信。
- 已回复的信不能再回，删除回复也不恢复资格；旅行结束后写信与回信均不可用，待回信显示已取消。
- 写信入口可打开写信界面；写信界面提供“跳转邮箱”。

### 9.2 伴手礼

- 只保存普通文字礼物。
- 每项显示文字礼物内容和 AI 按人设口吻写的备注。
- 支持查看、收藏、删除。
- 不做背包、数量、容量或使用机制。
- 旅行带回的可佩戴饰品进入“饰品管理”，不进入伴手礼。

### 9.3 出行历史

```text
┌────────────────────────────────┐
│ 出行历史                      │
│ ┌────────────────────────────┐ │
│ │ 出发时间：2026-09-08 14:00 │ │
│ │ 返回时间：2026-09-08 16:20 │ │
│ │ 带回：普通文字礼物          │ │
│ └────────────────────────────┘ │
└────────────────────────────────┘
```

- 展示最近旅行记录。
- 可查看出发时间、计划返回时间、实际返回时间和带回结果。
- 正常返回的旅行显示游记标题，点击可查看完整正文；游记标题与正文允许手动编辑，提供带确认弹窗的“删除游记”，不提供 AI 重新生成。删除确认说明仅删除游记正文，出行事实仍保留；删除后刷新列表及上下文标题，出行记录、信件和伴手礼仍保留；已删除游记不会自动补生成。
- 游记标题用一句话极精炼概括什么时候去了哪里、做了什么、有什么伴手礼、去了多久；正文使用对应人设口吻，比短期记忆更详细地总结整次旅行。
- 当前会话最近 `5` 篇游记标题会进入日常聊天、无聊主动消息和旅行信件上下文；正文不直接注入，AI 可通过只读工具列出、查找和读取当前会话的历史游记。

## 10. 错误、空态与加载

### 10.1 错误

- 主宠窗显示红色 `!` 感叹号。
- 点击感叹号弹出中文错误气泡。
- 错误类型包括：无 Token、连接失败、限流、后台记忆整合失败、导入导出失败等。
- 休眠状态下 AI 不主动说话，普通 AI 操作不可用；“刷新”、设置、测试连接仍可用。刷新恢复尝试、配置有效提供商或当前聊天提供商测试成功可恢复；失败保留错误。
- 后台记忆整合失败、导入导出失败只提示，不进入休眠；主流程 API 不可用时才进入休眠。

### 10.2 空态

- 未配置提供商：聊天窗提示“请先在设置中添加 API 提供商”。
- 未配置人设：使用默认“喵喵桌宠”，设置页提示用户配置。
- 无会话：聊天窗显示“新建一个会话开始聊天”。

## 12. 关键交互流程

### 12.1 正常聊天

1. 用户点击主宠窗“聊天”。
2. 打开聊天窗，选择或新建会话。
3. 用户输入并发送。
4. AI 先切换表情，再流式输出回复。
5. 流式期间发送按钮变为“暂停”，点击可中断。
6. Rust 保存回复后后台检查记忆整合与人设自调；记事本工具在聊天工具循环中执行。

### 12.2 AI 出门

1. 满足在线时间和空闲条件后，主宠窗弹出“我出去玩啦”。
2. 主宠窗只显示“`{当前人设名}出门啦`”，不展示出门中表情。
3. 聊天按钮变成“写信”，聊天窗只显示写信入口。
4. 用户写信后等待 `10–30` 分钟随机回信。
5. 正常返回后先确保出行事实完整，生成伴手礼并保存实际快照，再据此生成回来信与游记；展示项被删除不清除事实、不触发重复发放。

### 12.3 制作饰品

1. AI 达到亲密度档位后准备饰品名称、显示内容和简介，后端校验后发起制作请求。
2. 主宠窗展示待制作内容和价格，并弹出确认：`给你买` / `没有钱了`。
3. 用户确认后，后端重新校验请求所属会话、档位和余额，在同一事务中扣币、写账单、保存已准备好的饰品并标记档位使用状态；生成或校验失败时不扣币。
4. 饰品进入饰品管理，用户可佩戴、卸载、卖出或删除。

### 12.4 从聊天创建提醒

1. 用户在聊天中要求提醒。
2. AI 通过 function calling 创建结构化提醒。
3. 设置 > 全局设置 > 提醒中出现该提醒，可手动编辑时间、详情、状态。

### 12.5 导入与导出

1. 用户打开设置 > 全局设置 > 通用 > 导入与导出。
2. 选择导出范围，Rust 打包 zip 并保存到用户选择的位置。
3. 用户换机或备份后，在目标机器选择导入文件。
4. 前端显示摘要，用户选择“新建副本”或“覆盖同名项”。
5. Rust 校验并导入；完成后提示重新填写 API Key / 和风天气 API Key。
6. 若选择插件使用数据包，则只恢复用户确认的插件设置与存档；缺少插件包时在游戏中心保留来源卡片。钱包和联网权限改为待确认，当前喵币、游戏局和账单保持不变。

### 12.6 签到彩蛋

1. 用户点击“每日签到”。
2. Rust 查当天是否命中母表或子表节日。
3. 命中：固定发放 `10` 喵币，直接展示节日记录里的祝福词，不调用 AI。
4. 同时命中母表和子表：合并祝福词，喵币仍为 `10`。
5. 未命中：随机发放 `1–10` 喵币。
6. 当天是节日时，聊天上下文的日期信息包含节日名称。

### 12.7 无聊主动消息与桌面游走

1. 无互动达到配置阈值后按随机分支规则决定状态；只有选中无聊才进入主动消息流程，睡眠分支不请求主动消息。
2. 后台任务按概率只用当前会话的人设、用户设定、消息、短期与长期记忆、记事本、最近 `5` 篇旅行游记标题、环境和当天节日生成一条气泡；没有当前会话时不触发，不回退到其他会话。
3. 休眠、出门中、隐藏宠窗或正在聊天时不触发。
4. 只在固定画布内移动颜文字及饰品、气泡；不移动整个窗口。日常聊天与主动消息共用含当天节日母子表的上下文。
5. 用户拖动、点击、打开聊天、睡觉、出门中、隐藏宠窗时立即暂停游走。

### 12.8 到点提醒与离线过期汇总

1. 后端先保存本次提醒触发记录，再向前端发送提醒事件。
2. 应用正在运行时，前端显示独立提醒气泡；AI 润色成功时显示润色结果，失败时显示默认提醒词。
3. 用户点击“完成”只更新本次触发记录；也可进入提醒页面手动改为未完成、完成或已过期。
4. 应用启动时，后端返回离线期间全部过期的一次性提醒，以及每个循环提醒最多一条汇总项。
5. 前端显示“你离开这段时间，{提醒名称1-n}过期了！”，并提供“查看提醒”入口。
6. 后端记录本次汇总已经展示，避免下次启动重复弹出；用户没有修改状态的记录仍保留在提醒页面。

## 13. 前端与 Rust 接口约定

- 所有数据通过 Tauri command 获取或提交。
- AI 流式输出通过 Tauri event 推送到前端；前端可调用中断命令停止当前回复。
- 前端不直接读写 SQLite，不直接调用 AI 提供商。
- API Key 只在设置表单输入，前端不展示已保存的明文 Key。
- 前端按错误类别处理：主流程故障显示全局错误状态，字段校验与局部操作失败留在对应窗口；错误显示不等于切换桌宠到休眠。
- 前端只展示当前会话的出行、信件、伴手礼、饰品、节日子表和记忆数据。
- 所有删除操作使用确认弹窗；删除会话、人设、饰品等不可恢复操作需要二次确认。

完整的请求时序、恢复要求与行为用例见[实施接口与验收约定](实施接口与验收约定.md)。

上下文自动缩减后，聊天窗显示非阻断提示：“本次上下文过长，已减少部分较旧内容；历史消息和记忆仍完整保留。”不修改用户配置的原文条数或 m 值；最低必要内容仍超限时明确提示无法发送，不循环重试。

### 13.1 通用返回与并发规则

- Tauri command 统一返回成功数据或结构化错误。错误至少包含稳定的 `code` 和中文 `message`；表单字段错误可附带 `field`，前端不得通过解析错误字符串判断业务类型。
- 会话级请求必须携带 `personaId`、`sessionId` 和当前 `contextRevision`。前端收到结果时再次核对；上下文已切换则丢弃旧结果。
- 聊天流式事件必须携带 `requestId`、`sessionId`、`roundId`、事件序号和事件类型。前端只接收当前请求且序号更新的事件，防止旧回复串入新会话。
- 新建、编辑、删除和钱包变化由 Rust 在事务中完成，前端成功后重新读取权威状态，不自行推算数据库最终结果。
- 会影响多个窗口的数据变化由 Rust 广播领域事件；已打开窗口按事件携带的 revision 刷新，避免各窗口各自维护不同副本。

### 13.2 窗口与上下文接口

- `focus_or_create_window`：按窗口类型显示并聚焦已有窗口，不重复创建；可携带当前人设或会话上下文。
- `window_context_changed` 事件：当前人设或会话变化后广播，聊天窗、记忆窗、出行窗、饰品页和节日页同步刷新。
- `get_current_context`：窗口恢复或首次加载时读取当前人设、当前会话和 context revision。
- 二级窗口关闭只销毁对应前端窗口，不调用应用退出；`exit_app` 仅由明确的退出入口调用。

### 13.3 桌宠状态接口

- `get_pet_activity`：读取后端权威快照；包含 `personaId`、可空 `sessionId`、`contextRevision`、`revision`、`activity`、`expression`、可空 `intimacy`、`sleepUntil`、`error`、`canInteract`、`canWander`。
- `activity` 枚举：`normal`、`hungry`、`bored`、`sleeping`、`eating`、`interacting`、`thinking`、`speaking`、`away`、`dormant`；仅表示展示状态，不替代数据库睡眠分支或出行状态。
- `interact_pet`：`input` 携带 `personaId/sessionId/contextRevision/action`，`action` 为 `click/stroke/feed`；后端校验当前上下文与出门状态，事务保存互动及封顶为 999 的亲密度，返回完整快照。前端不传奖励数量。
- `set_pet_dragging`：接收 `dragging` 布尔值，拖动结束或失败必须恢复 false。隐藏操作复用 `set_pet_hidden`。
- `refresh_pet_provider`：测试当前聊天提供商；成功恢复故障状态，失败保留可读错误，不改会话计时记录。
- `pet-activity-changed`：携带提交后的完整快照，旧 `revision` 不覆盖新状态。`pet-activity-error`：状态读取或保存失败的局部错误，不伪装成 AI 故障休眠。
- 订阅事件后主动读取一次快照。点击颜文字互动；右键菜单提供喂食、摸摸和 `亲密度 n / 999`，满值标注“已达上限”但仍可操作。无会话时提示创建会话，出门时禁用互动；菜单随隐藏或上下文变化关闭。

### 13.4 会话与消息接口

- `list_sessions`：接收当前 `personaId/contextRevision`，只列出该人设会话，并返回 `isCurrent`、标题、绑定用户设定、亲密度、记忆版本及创建/更新时间。
- `create_session`：为当前人设创建标题为“新会话”的会话并切为当前会话；后端先结算旧会话计时，按既有规则取消旧会话已开始旅行和待回信，提交后广播 `window_context_changed`。
- `set_active_session`：接收目标 `sessionId` 和调用前上下文；目标必须属于当前人设。重复选择当前会话不增加 context revision，实际切换取消旧聊天请求并恢复目标会话桌宠状态。
- `rename_session`：标题去除首尾空白后须为 1–100 个字符；只修改归属当前人设的目标会话。本接口已具备，阶段 10 再接入会话列表 UI 与首次回复 AI 标题生成。
- `list_messages`：只读取当前会话，按消息 ID 正序分页；`afterId` 是上一页最后消息 ID，`limit` 为 1–200，默认 100，返回 `nextAfterId`。主动消息的 `roundId` 为 null。
- pending 回合建立、completed/interrupted 终态和主动消息写入是 Rust 内部业务 API，不注册前端命令。聊天窗口只能走后续聊天总协调，不能自己保存 AI 消息或伪造完整回合。
- 应用启动时将遗留 pending 回合收束为 interrupted，保留已有用户消息和部分已落盘内容，不自动重发。

### 13.5 设置管理接口

- 提供商：`list_providers`、`create_provider`、`update_provider`、`delete_provider`、`test_provider_connection`、`set_active_chat_provider`、`set_memory_provider`。
- Embedding：`list_embedding_providers`、`create_embedding_provider`、`update_embedding_provider`、`delete_embedding_provider`、`test_embedding_provider`、`set_active_embedding_provider`。
- 人设：`list_personas`、`create_persona`、`update_persona`、`delete_persona`、`set_active_persona`、`save_persona_initial_prompt`、`restore_persona_initial_prompt`。差异计算使用详情中已有的 `prompt` 与 `initial_prompt`，不增加后端差异接口。
- 表情库：`generate_expressions` 和 `cancel_expression_generation` 接收人设 `id`；成功返回完整分类库，取消和失败保留旧库。新建人设后台生成失败时监听 `expression_generation_failed`，按 `personaId` 展示对应错误；成功或配置保存后的 `configuration_changed` 通知界面重新读取权威数据，不携带密钥。
- 删除接口由 Rust 判断默认人设、当前使用状态和级联范围；前端只根据返回的错误码显示“不可删除”或高风险确认，不绕过后端保护。
- `get_settings` / `save_settings`：复用全局配置读写，时间与桌宠页只提交其 15 项字段中的改动项，Rust 再校验范围和组合并事务保存；`get_settings_defaults` 只读 Rust 默认值，供恢复草稿使用，不写库。

### 13.6 提醒接口与事件

- `list_reminders`、`create_reminder`、`update_reminder`、`delete_reminder`：管理提醒规则。
- `list_reminder_occurrences`、`update_reminder_occurrence_status`：查看并手动修改每次触发记录的状态。
- `get_missed_reminder_summary`：按 `afterId` 分页返回未展示过期记录，每页最多 200 条，返回 `occurrences/nextAfterId/text`；读取所有页后按提醒 ID 去重组成汇总名称。一次性全部包含，循环提醒每次启动补偿只新建最近一次错过的记录；之前尚未展示的记录仍须一起确认，不因名称去重而遗漏 ID。
- `ack_missed_reminder_summary`：前端实际展示汇总后，携带本次 occurrence ID 列表确认已展示；重试幂等，不改变提醒完成状态。
- `complete_reminder_occurrence`：只完成指定 occurrence；一次性提醒同步更新规则状态，重复规则继续调度。
- 已实现的规则保存输入为 `{name, content, schedule, fireAt}`；循环提醒 `fireAt=null`、传版本 1 的 schedule，一次性 `schedule=null`、传未来时间。修改已触发的一次性提醒文字时可保留 `fireAt=null`。规则列表支持 `afterId/limit`，取不足一页即结束；触发记录列表返回 `nextAfterId`。ID 均为字符串。
- `reminders-changed` 通知页面重新查询数据库，`reminder-error` 独立报告提醒调度故障；启动不能只监听事件，必须主动读 queued 和 missed。实际展示 queued 后用 `acknowledge_reminder_occurrences(ids, deliveryState="queued")` 确认，missed 使用专用汇总确认接口；每批最多 200 个 ID，只改展示状态。
- 当前已接入上述后端命令与 `reminderApi`；提醒管理页面与页面内离线汇总已实现。宠窗气泡与启动离线汇总已接入；AI 润色仍待后续接入。
- 气泡复用 `reminders-changed` 提示重查和 queued/missed 恢复查询，不额外引入重复投递事件。`get_reminder_occurrence(id)` 用于刷新已展示但尚未收起的当前气泡，其他窗口完成或删除后同步撤下。AI 润色接入前使用固定默认文案。

### 13.7 游戏中心与插件接口

- `list_game_plugins`、`install_game_plugin`、`update_game_plugin`、`set_game_plugin_enabled`、`uninstall_game_plugin`：管理插件包。
- `get_game_plugin_permissions`、`set_game_plugin_permission`：按权限名和 `permission_scope` 读取、修改权限；新增权限或联网来源时必须返回待确认状态，前端显示权限确认框。
- `export_game_plugin_data`、`import_game_plugin_data`：导出或导入插件使用数据包；导入结果返回被覆盖的设置/存档、缺包插件和待确认权限，不能返回或修改钱包、账单与游戏局。
- `network.fetch` 通过宿主代发已授权 HTTPS 来源的请求；前端和插件 WebView 都不能绕过权限直接访问未授权来源。
- `start_game_run`、`finish_game_run`、`cancel_game_run`：管理游戏局；钱包变化只能由插件宿主统一调用 Rust 钱包服务。
- `wallet_changed` 与 `game_plugin_changed` 事件使桌宠状态、游戏中心和账单视图刷新；前端不直接修改余额显示。

### 13.8 出行与游记接口

- `list_travels`：按当前会话列出出行记录，包括已返回、出门中及已取消；不能把“无游记”当作“无出行”。
- `list_travel_journals` / `get_travel_journal`：只返回当前会话仍存在的游记。
- `update_travel_journal`：携带 journalId、travelId、会话上下文、标题、正文与原内容快照；目标已删除或快照已变更时拒绝覆盖。
- `delete_travel_journal`：确认后提交目标与会话上下文；只删除游记，返回目标 ID 与所属会话，事务提交后通知相关窗口刷新。客户端不能请求重置 journal_state。
- 删除成功后关闭已打开的该游记详情，刷新标题列表；失败保留页面。后台只读工具复用同一归属检查。

### 13.9 响应式实现约定

- 页面组件使用容器实际宽度决定布局，不只依据显示器分辨率；用户拖动窗口边缘时应即时重排。
- 宽度不足时，设置左侧导航折叠为顶部选择器或抽屉；卡片网格降为单列；表单操作按钮换行并保持主要按钮可见。
- 组件不得写死只适用于默认窗口宽度的绝对定位。主宠窗颜文字、饰品和气泡可继续使用受控画布坐标。
- 对话框最大宽高受当前窗口可用区域限制，正文过长时内部滚动；确认与取消按钮保持可见。

## 14. 后续语音扩展（首版不实现）

语音功能不进入当前首版页面和阶段 0–18。实施后在“设置 > 全局设置”增加“语音”模块，管理语音组件、麦克风与扬声器、本地和联网 ASR/TTS、模型与声线以及全局快捷键；每个人设卡片增加独立的唤醒词、声线、语速、音量、自动发送、句末静音、无输入自动结束时间和朗读范围设置。

- 第一次启用语音时使用向导完成组件安装、麦克风测试、当前人设唤醒词与声线绑定。
- 只监听当前人设的唤醒词；切换人设或聊天会话会结束现有语音会话，取消旧字幕与未播放音频。切换人设时同步切换关键词，同一人设下切换会话不改变唤醒词。
- 聊天输入区增加麦克风按钮、监听状态、可替换的 partial 字幕和 final 确认区。自动发送关闭时，final 文字进入普通输入框供用户修改。
- 点击麦克风、按全局快捷键或说当前人设唤醒词均可开始。唤醒睡觉中的桌宠；出门中的当前会话仍只允许写信。
- 默认只朗读语音会话回复。键盘聊天、无聊主动消息和提醒的朗读开关按人设独立设置，默认关闭。
- 语音资源页显示两个内置声线，并支持安装 `.yanmew-voice` 兼容模型包；后续增加“导入 GPT-SoVITS 声线”向导，要求选择受支持的 GPT 权重、SoVITS 权重、参考音频、准确参考文字和语言，校验并试听成功后才允许绑定人设。该入口不提供模型训练。第二阶段再增加应用内参考音频处理、试听确认和克隆声线管理。
- 常驻麦克风默认关闭，启用时在宠窗、聊天窗或托盘持续显示可见状态，并提供立即关闭入口。

完整交互、状态、模型包与错误处理规则见 `docs/语音扩展设计.md`。
