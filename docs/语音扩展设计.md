# 颜喵 YanMew 语音扩展设计

> 当前实现基线（2026-11-09）：源码及备份v26，最新正式包20261109-143800为v26。本文中的阶段版本仅说明引入历史；实际交付范围与默认值见[当前实现与版本范围](当前实现与版本范围.md)。


- 日期：2026-09-19
- 状态：产品规则已确认，属于首版完成后的扩展设计
- 实施边界：不属于当前阶段 0–18，不修改当前 `db/schema.sql`，开始开发前另行确定模型、许可证、资源预算、schema 版本与迁移方案

## 1. 目标与范围

语音扩展让用户通过当前人设自己的唤醒词、聊天窗麦克风按钮或全局快捷键开始语音会话，在本地实时看到识别文字，并继续使用已有聊天、会话、记忆、RAG、工具与消息回合规则。AI 回复可以使用绑定到该人设的声线朗读。

扩展分为两个阶段：

1. 第一阶段：本地唤醒词、本地流式 ASR、实时字幕、两个内置声线、兼容 TTS 模型导入、联网 ASR/TTS 提供商和按人设绑定的语音设置。
2. 后续适配：导入别人已经制作完成的 GPT-SoVITS 声线，包括现成 GPT 权重、SoVITS 权重、参考音频、准确参考文字和语言；只提供安装、校验、试听和推理，不在颜喵内训练 GPT-SoVITS 模型。该适配可以独立于应用内克隆功能交付。
3. 第二阶段：本地零样本音色克隆、参考音频处理、试听确认、克隆声线档案和独立声线包导入导出。

第一阶段不实现声纹识别、用户插话打断、任意格式模型直接导入或训练新的音色克隆模型。后续 GPT-SoVITS 导入也不等于接受任意项目目录或在应用内训练；只接受明确字段和文件完整的受支持版本。WebRTC APM、AEC 和更强语音增强等到需要在 AI 播放期间继续收音时再评估。

## 2. 已确认的产品规则

- 每个人设绑定一套独立语音设置，底层 ASR、KWS、VAD、TTS 模型与联网提供商是全局资源，可被多个人设复用。
- 只监听当前人设启用的唤醒词。切换当前人设时结束现有语音会话，并原子切换 KWS 关键词集合；唤醒词不自动切换人设。
- 用户只输入普通唤醒词文字。后端负责规范化、转为模型 token 或拼音、校验支持范围和生成 KWS 配置；这些细节不要求用户填写。
- 第一次启用语音时，安装或检查语音组件，选择麦克风，测试输入，并要求为当前人设至少填写一个唤醒词。之后可在“设置 > 语音”和人设语音设置中修改。
- 唤醒词、聊天窗麦克风按钮和可配置全局快捷键都能开始语音会话。
- 默认在检测到句末静音后自动发送；用户可以关闭自动发送，改为在最终文字出现后确认发送。
- 语音唤醒会结束桌宠的睡觉状态。
- 当前会话出门中时不能发起普通语音聊天，界面沿用现有规则进入写信；本地结束语音、关闭麦克风等控制命令仍可用。
- 默认只在语音会话中朗读 AI 回复。键盘聊天、无聊主动消息和提醒默认只显示文字；用户可在人设语音设置中分别开启朗读。
- AI 播放期间第一阶段暂停麦克风识别和 KWS，不接受插话；播放结束并经过短暂冷却后恢复当前语音会话监听。

## 3. 总体架构

平台边界遵守《项目架构与代码职责》：Windows 语音先落地，采集/播放、麦克风权限、热键、密钥和资源路径经平台适配；会话状态、转写提交和人设绑定逻辑共享。未来 Android 不照搬桌面全局快捷键与常驻唤醒，必须另行验证后台麦克风限制、ARM64 运行库、模型内存和耗电。Windows 能导入的 GPT-SoVITS 声线不自动等于 Android 能推理；不支持时显示不可用，不静默上传声音或切换联网服务。本文 `data/models/voice/` 在 Android 对应受管私有模型目录，逻辑层不写死 Windows 路径或 DPAPI。

语音采集与推理放在 Rust 后端，React 只负责设置、状态、字幕、确认和错误展示。候选本地推理核心为 `sherpa-onnx`，但业务层通过接口隔离具体引擎，避免数据库和前端直接依赖某个模型实现。

```text
麦克风 / 点击 / 快捷键
        │
        ▼
Rust 音频采集与统一重采样
        │
        ├─ SLEEP：当前人设 KWS
        │
        └─ 语音会话：VAD + Streaming ASR
                         │
                         ├─ partial → 实时替换字幕
                         └─ final   → 本地命令路由
                                          │
                              ┌───────────┴───────────┐
                              ▼                       ▼
                         结束语音等命令           现有聊天发送流程
                                                      │
                                       会话 / 记忆 / RAG / 工具 / LLM
                                                      │
                                               TTS 分句与播放队列
                                                      │
                                               冷却后继续监听
```

麦克风识别输入总线统一为 `16kHz / mono / f32`；TTS 输出按声线模型原生采样率生成，由播放层转换为设备格式，不强制降到 16kHz。麦克风原始格式只在采集层转换一次，KWS、VAD 和 ASR 共享标准化音频；只有模型接口或导出确实需要时才转成 PCM16。

Rust 后端建议按职责拆分：

```text
src-tauri/src/voice/
├─ audio_capture.rs
├─ audio_resampler.rs
├─ audio_playback.rs
├─ ring_buffer.rs
├─ wake_word.rs
├─ vad.rs
├─ streaming_asr.rs
├─ command_router.rs
├─ tts.rs
├─ tts_chunker.rs
├─ model_manager.rs
├─ session_manager.rs
└─ state.rs
```

音频回调只写入有界 ring buffer，不执行模型推理、数据库操作或前端事件等待。KWS/VAD/ASR、AI 网络请求、TTS 生成和播放使用独立工作线程或异步任务，通过有界事件通道通信。

## 4. 语音状态与生命周期

主状态使用：

- `DISABLED`：语音功能关闭，麦克风完全释放。
- `MODEL_MISSING`：语音已配置但本地组件缺失或损坏。
- `SLEEP`：只运行当前人设 KWS；若关闭唤醒词则不持续占用麦克风。
- `LISTENING`：VAD 与流式 ASR 并行工作，持续产生 partial/final。
- `PROCESSING`：最终文字已提交，等待或接收 AI 流式回复。
- `SPEAKING`：TTS 队列正在生成或播放。
- `ERROR`：权限、设备、模型或运行时错误，保留进入语音设置和重试入口。

语音 SLEEP 仅表示等待唤醒词，不等于桌宠正在睡觉或因错误进入 Dormant。语音唤醒桌宠时同时重置其无互动计时，避免立即重新进入睡眠。

从 final 被接受进入 PROCESSING 起暂停 ASR/KWS，直至 LLM 流已结束、全部 TTS 块处理完毕且播放队列为空，再经过冷却恢复 LISTENING；不能在两个音频块之间的短暂停顿误恢复监听。手动确认发送时先停止本段识别，等待发送或丢弃，不重复提交同一 final。

`llm_streaming`、`tts_generating` 和 `tts_playing` 是独立活动标记，因为 AI 生成与 TTS 播放可能重叠，不能用一个互斥枚举表达全部并发状态。

用户主动结束、说出严格匹配的结束指令、切换人设或聊天会话、禁用语音、麦克风权限撤销或长时间无语音输入时结束语音会话并返回 `SLEEP` 或 `DISABLED`。结束指令只在规范化后整句匹配，避免普通聊天中包含“挂了”等词时误退出。

每次语音会话固定绑定启动时的人设、聊天会话与上下文版本。切换或删除绑定对象时取消识别任务与未播放音频，旧 partial、final 和迟到结果不得进入新会话；同一人设下切换聊天会话不改变其唤醒词配置。重新唤醒后才建立绑定新上下文的语音会话。

## 5. 唤醒词与首次配置

- 一个人设可以保存多个唤醒词，至少一个、数量上限在实施时根据 KWS 性能测试确定。
- 用户看到并编辑的始终是原始文字；数据库保留原始文字，派生 token、拼音和阈值配置可重建。
- 保存唤醒词时先做空白、重复、长度和模型字符集校验，再由后端转换成当前 KWS 模型要求的表示。
- 用户可以逐条试听测试；设置页显示最近测试是否命中，而不要求用户理解 boosting score 或 trigger threshold。
- 切换 KWS 模型后重新生成所有人设的派生关键词索引。无法转换的唤醒词保留原文并标为不可用，不能静默删除。
- 始终提供点击麦克风和快捷键作为 KWS 失败、环境嘈杂或用户不希望持续监听时的替代入口。

## 6. VAD、流式 ASR 与发送

- VAD 判断是否正在讲话，Streaming ASR 持续生成识别内容，二者并行运行。
- `VoiceSessionManager` 是唯一有权确认本轮结束并提交消息的模块；VAD 和 ASR 不得各自发送，避免重复消息。
- 句末静音时间保存为配置项，不把 `800ms` 固化为永久规则。默认值在真实中文停顿、远近场麦克风和噪音环境测试后确定。
- UI 使用 `committedText + partialText`。新的 partial 替换旧 partial，final 才追加到 committed 并清空 partial，不能把每次中间结果都追加。
- 自动发送关闭时，final 进入聊天输入区，用户可以修改、发送或丢弃；自动发送开启时，final 通过现有 Rust 聊天命令保存一次。
- 只有最终发送成功的语音文本成为用户消息。partial、被丢弃的 final 和本地结束指令不进入消息、回合或记忆。
- 语音消息与键盘消息使用同一聊天流程；以后可给 `messages` 增加 `input_mode=typed/voice` 作为展示和诊断元数据，但不改变记忆规则。

## 7. TTS、内置声线与模型导入

### 7.1 两个内置声线

- 语音组件默认提供两个内置声线；具体声线在许可证、中文效果、模型体积和 Windows CPU 性能验收后确定。
- 优先从一个明确允许使用、转换和再分发的中英多声线模型中选择两个 speaker，以减少模型体积；具体模型不在设计阶段写死。
- 两个声线随可选语音组件安装，不强制塞入基础便携版。未安装语音组件不影响文字聊天及其他首版功能。

### 7.2 用户导入 TTS 模型

用户导入版本化 `.yanmew-voice` 包，不承诺任意 `.onnx`、`.pth`、`.ckpt` 或某个开源项目目录可以直接使用。第一阶段只接受颜喵已实现适配器的 `sherpa-onnx` 兼容模型类型；以后新增转换工具或引擎适配器。

包至少包含：

```text
manifest.json
models/
LICENSE
NOTICE（如适用）
preview.wav（可选）
```

manifest 至少声明 `format_version`、稳定模型 ID、名称、作者、版本、引擎类型、支持语言、采样率、模型文件与校验值、speaker 列表、来源地址、许可证标识和颜喵语音接口版本。安装先解压到临时目录，检查路径越界、大小、哈希、manifest、模型文件和运行兼容性，通过后再原子登记；失败不破坏旧模型。

### 7.3 导入已制作完成的 GPT-SoVITS 声线

颜喵后续提供 GPT-SoVITS 引擎适配器，支持导入别人已经制作完成、可以用于推理的声线。它属于“导入已有声线”，不属于应用内训练或自动制作模型。

提供两种入口：

1. 安装符合颜喵协议的 `.yanmew-voice` 包。包内已经包含 manifest、GPT 权重、SoVITS 权重、参考资料、许可证与校验值。
2. 使用“导入 GPT-SoVITS 声线”向导，分别选择受支持版本的 GPT 权重、SoVITS 权重、至少一组参考音频、与音频准确对应的参考文字和参考语言。颜喵校验后复制到受管目录并生成内部 manifest，用户不必手工制作包。

第一版 GPT-SoVITS 适配器不自动扫描或直接运行完整 GPT-SoVITS 项目目录，也不猜测缺失的参考文字、语言、模型版本或配置。导入向导必须明确显示缺失项和不兼容原因。

GPT-SoVITS 包或向导生成的 manifest 除通用字段外，还必须记录：

- `engine = gpt_sovits` 和适配器协议版本；
- GPT 权重与 SoVITS 权重各自的文件、版本、大小和哈希；
- 推理所需配置、语言能力、采样率及兼容运行时范围；
- 每组参考音频的文件、准确参考文字、参考语言和可选用途标签；
- 原作者、来源地址、模型及参考声音的许可说明。

导入完成后先用固定试听句验证运行，成功后才登记为可绑定声线。运行时缺文件、权重不匹配、参考资料无效或适配器不兼容时，保留安装记录并标记不可用，不自动改绑人设。卸载声线只删除颜喵受管目录中的副本，不删除用户选择的原始文件。

### 7.4 联网 TTS

- 预留联网 ASR/TTS 提供商，API Key 使用 Windows DPAPI 加密。
- 本地和联网提供商通过相同业务接口输出 final 文本或音频块；切换提供商不改变聊天、消息和记忆逻辑。
- 联网 TTS 或本地 TTS 失败时保留完整文字回复，提示本次朗读失败，不回滚已经保存的 AI 消息。

### 7.5 朗读策略

LLM 流式正文由 `TTSChunker` 按句号、问号、感叹号、分号、换行和最大长度切块。完整块进入有序队列；已播放内容、待播放内容和当前生成块分别管理，避免重复朗读。用户停止语音会话时取消未播放队列，已经保存的文字回复不删除。

## 8. 第二阶段：本地音色克隆

- 第一版语音扩展不训练模型，使用支持中文的零样本克隆引擎，例如实施时验证通过的 ZipVoice 类模型。
- 创建克隆声线时，用户导入或录制一段单人、清晰、无明显背景音乐的参考音频，并填写与音频准确对应的文字。
- 可使用本地 ASR 预填参考文字，但保存前必须由用户确认；参考音频和文字不一致时提示可能降低效果。
- 创建后先生成固定试听句，用户确认满意才保存为声线档案并允许绑定人设。
- 声线档案保存名称、基础克隆模型 ID/版本、参考音频相对路径、参考文字、采样率、可选缓存特征和创建时间。
- 创建时要求用户确认参考声音属于本人或已获得允许。删除克隆声线时同时删除参考音频与派生缓存；已保存的聊天文本不受影响。

## 9. 设置与界面

语音扩展实施后，在“设置 > 全局设置”增加“语音”模块：

- 语音总开关、组件状态、安装、修复和卸载。
- 麦克风、扬声器、音量电平与测试。
- 本地 ASR/KWS/VAD 模型和联网 ASR 提供商。
- 本地 TTS 模型、联网 TTS 提供商、两个内置声线、导入与卸载。
- 可配置全局快捷键。
- 已安装声线列表；后续增加“导入 GPT-SoVITS 声线”，第二阶段增加“创建克隆声线”和独立声线包导入导出。

每个人设卡片增加“语音设置”：

- 启用该人设语音。
- 唤醒词列表与逐条测试。
- 绑定声线。
- 语速、音量以及模型支持时的音高。
- 是否自动发送、句末静音时间和无输入自动结束时间。
- 是否朗读语音会话回复。
- 是否朗读键盘聊天回复。
- 是否朗读无聊主动消息。
- 是否朗读提醒。

首次启用向导依次完成组件安装、麦克风授权和测试、当前人设唤醒词、声线试听与绑定。未完成时可以退出向导，语音保持关闭，不影响应用其他功能。

## 10. 持久化草案

语音扩展开发前再把以下逻辑结构落实到 `db/schema.sql` 和版本化迁移；当前首版 schema 不提前加入空表：

- `voice_models`：全局本地模型登记，包含 kind、engine、model_key、version、languages、relative_path、checksum、license、source_url、is_builtin、status；GPT-SoVITS 的两个权重和运行配置由受版本控制的 manifest 描述，数据库保存其整体安装身份和状态。
- `voice_providers`：联网 ASR/TTS 提供商，包含 kind、base_url、model、加密密钥、启用状态与最近测试结果。
- `voice_profiles`：可绑定声线，区分 builtin/imported/cloned/online，关联模型或提供商，保存 engine、speaker ID、显示名称和资源状态；导入的 GPT-SoVITS 声线属于 `imported`，`engine` 为 `gpt_sovits`。
- `voice_profile_references`：一条声线的零到多组参考资料，包含 `voice_profile_id`、相对音频路径、准确参考文字、语言、用途顺序、哈希和启用状态。GPT-SoVITS 导入至少需要一组；内置固定 speaker 或联网声线可以没有本地参考资料。
- `persona_voice_settings`：以 `persona_id` 唯一绑定启用状态、voice_profile_id、语速、音量、自动发送、句末静音时间、无输入自动结束时间和四类朗读开关。
- `persona_wake_words`：按人设保存原始唤醒词、规范化值、启用状态和派生索引版本；同一人设内规范化值唯一。
- `messages.input_mode`：可选的 typed/voice 元数据；只在扩展开发时通过迁移加入。

底层麦克风设备 ID 属于本机易失配置，单独保存并在设备消失时回退系统默认，不能作为跨设备稳定标识。

## 11. 文件、备份与便携边界

```text
data/models/voice/
├─ runtime/
├─ asr/
├─ kws/
├─ vad/
├─ tts/
│  └─ <model_id>/
│     ├─ manifest.json
│     └─ models/
└─ profiles/
   └─ <voice_profile_id>/
      ├─ references/
      │  └─ <reference_id>.wav
      └─ cache/
```

- 模型文件、运行库、导入包展开内容、克隆参考音频和派生缓存不进入普通全量备份。
- 全量备份保留非密钥语音设置、人设唤醒词、模型稳定 ID 和声线绑定元数据；联网提供商密钥仍不导出。
- 导入后若目标机器缺少对应模型或声线资源，保留配置但标记不可用，提示重新安装、重新导入或重新创建，不能自动改绑其他声音。
- 已导入的 GPT-SoVITS 权重、参考音频和运行时文件不进入普通全量备份；普通全量备份只保留稳定模型/声线 ID、绑定和来源元数据，恢复后提示重新导入对应声线包。
- 第二阶段可以提供独立 `.yanmew-voice-profile` 声线包。它与普通全量备份分开，导出时再次确认其中可能包含参考声音和可再分发的模型文件。
- 卸载某个模型前检查引用它的人设和克隆声线；用户确认后解除运行可用性，但不静默删除人设的原始配置。

## 12. 隐私、许可与错误处理

- 常驻麦克风默认关闭，首次启用明确说明本地持续监听；托盘、宠窗或聊天窗始终提供可见麦克风状态与立即关闭入口。
- 默认不保存日常麦克风原始音频。只有用户明确创建克隆声线时保存选定参考音频。
- 本地识别不上传音频；使用联网 ASR/TTS 时在设置和首次启用时明确显示会向所选提供商发送音频或文字。
- 运行引擎的开源许可证与模型权重许可证分别记录。随颜喵提供或由项目下载的模型必须明确允许目标用途和再分发；不能仅因推理引擎采用 Apache-2.0 就推定模型也可随包发布。
- 第三方导入包显示作者、来源和许可证；缺少 manifest、许可证声明或哈希不一致时拒绝作为标准包安装。
- 麦克风权限、设备断开、模型损坏、推理失败和播放失败统一显示中文错误。语音扩展故障不让文字聊天进入休眠；聊天 AI 本身不可用时仍按现有休眠规则处理。

## 13. 实施前验收门槛

开始开发语音扩展前必须完成：

1. 选定并记录 ASR、KWS、VAD、两个内置声线及候选克隆模型的来源、许可证、大小、哈希和再分发依据；GPT-SoVITS 适配另行锁定受支持版本、运行方式和资源预算。
2. 在 Windows CPU 设备测试实时率、内存、首个 partial 延迟、首句 TTS 延迟、长期 KWS 占用与误唤醒率。
3. 用普通话停顿、远近场、风扇噪音、扬声器播放和多个唤醒词录音建立离线测试集。
4. 确定 `.yanmew-voice`、GPT-SoVITS 导入向导、独立声线包和联网提供商的版本化协议。
5. 确定数据库 schema 版本、旧库迁移、备份兼容和模型缺失恢复流程。

详细实施计划在首版完成、模型与许可验收通过后单独编写，不追加到当前阶段 0–18 中。
