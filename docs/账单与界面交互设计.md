# 全局账单、统计面板与窗口交互

日期：2026-10-20。全项目数据库为v19；本模块仍复用既有喵币流水，无结构变更。20261020-160457已包含账单统计基础功能；20261020-173045已包含主页、明细和数据面板分层，旧v19资料已接续并核对。

## 1. 账单入口与数据范围

设置的“桌宠与内容”分组提供“账单”。它读取全局 `currency_ledger`，与当前人设、会话无关；不创建第二份账本，不回填或重放历史喵币变化。当前余额来自 `user_state`，属于现在的钱包余额，不是筛选时段的期末余额。

列表以卡片展示，每页12条。支持分类、收支、小游戏、关键词、日期和时间排序。分类沿用数据库的六个原因：签到、节日奖励、食物购买、饰品制作、饰品卖出、小游戏。收支按单笔 `delta` 正负判断；零变动只计笔数，不增加收入或支出。关键词按分类中文名称、历史游戏名/ID、历史说明、带符号的原始整数金额进行字面包含查询，不作为 SQL 模式或表达式执行。

每张卡片显示来源、时间、变动金额和收支语义；展开后显示账单编号、分类、游戏版本/ID或历史饰品编号。饰品可能已删除，不能因此隐藏账单，也不能假定当前饰品的内容就是历史内容。游戏名来自 `game_runs` 历史快照，不要求当前插件仍已安装。

查询期间保留上次成功内容并标注正在更新，旧结果暂时不可交互；失败保留旧结果并提示重试。连续切换条件时，过期请求不得覆盖新查询。钱包变更或窗口重新获得焦点时刷新；快捷日期同时按当前电脑日期重新计算。

## 2. 日期与金额口径

- 全部时间：查询完整账单；显示已有匹配流水覆盖的日期。
- 昨日：当前电脑日期的前一天。
- 最近7天：今天及之前6个本地日。
- 最近1个月、6个月、1年：从今天向前推1/6/12个日历月，目标月不存在该日时取月末，再加一天作为开始日；截止今天。例如2026-10-20的最近1个月为2026-09-21至2026-10-20，2024-03-31的最近1个月为2024-03-01至2024-03-31。
- 自定义：开始、结束日期都必须填写，开始不得晚于结束；两端本地日期均包含。不限制为固定天数，也不截断用户的历史。
- 账单储存的UTC时间投影为电脑当前时区的日期。Rust利用现有时间索引先读取放宽一天的UTC候选，再逐条判断本地日期；不把每天假设为固定24小时。
- 收入为正数流水之和；支出为负数绝对值之和；净变化为收入减支出；笔数包含零变动。全部是实际记账结果，不从游戏文案反推输赢金额，也不统计未提交或失败的操作。
- 后端以 `i128` 累加 `i64` 流水，并以十进制字符串跨IPC传递。前端金额显示、分类汇总比较使用 `BigInt`；只有SVG坐标和百分比使用近似浮点比例，不用它记账。

## 3. 统计面板

主页只显示当前钱包余额及“账单明细”“账单数据面板”两个模块入口，不展开流水、查询表单或图表。明细页显示记录与分页，不重复数据面板的四张统计摘要；统计摘要、趋势、占比及排行只在数据面板展示。筛选工具默认收起，点击“筛选账单”后显示完整条件，收起保留输入；两个模块显示当前日期范围。视图可返回主页，明细与数据面板之间保留已应用筛选、页码和列表滚动位置。分类或小游戏图表跳转会把相应条件应用到第一页。统计只覆盖当前全部筛选条件，不能只累计当前页12条。

顶部显示当前余额、区间收入、区间支出和区间净变化，另标明匹配笔数。当前余额明确独立于历史统计区间。

收支趋势使用零轴上下柱状图：收入向上，支出向下，轴标签、悬停信息和键盘焦点说明同时提供金额及方向。区间长度不超过31天按日、32–180天按周、181–730天按月，更长按年。周从周一开始。补齐没有交易的时段；首尾桶只累计所选日期内的记录，界面说明这个规则。

收入和支出分别绘制分类圆环，不能把正负金额混成同一占比。图例显示名称、金额、百分比，可直接跳转对应账单。没有对应收支时显示空状态，不绘制虚假比例。

下方列出分类金额/笔数，以及按收入加支出的总额倒序排列的小游戏排行，并同时显示各游戏收入、支出与净变化。小游戏纯玩不产生流水，不进入这个排行。所有统计都是喵币，不是模型API费用。

图表使用现有 React、SVG、CSS，不新增图表依赖。沿用主题语义色，收入和支出同时用方向、文字与颜色区分。宽屏双列圆环、窄屏单列；页面纵向滚动，不产生横向滚动条。

## 4. 只读接口与持久化

命令 `query_currency_ledger(input)` 仅向受信任的设置窗口开放，在阻塞工作线程中读取数据库。小游戏、AI工具和宠窗不能通过它查询全部账单。

输入为 `start/end`（可空的YYYY-MM-DD）、`direction`（all/income/expense）、`reason`（空或现有六种原因）、`pluginId`（空或历史ID）、`search`、`ascending`、从1开始的 `page`。每页固定12条，时间相同按ID同方向排序。

返回 `entries`、`summary`、`balance`、`page/totalPages`、`categories`、`games`、`plugins`、`timeline`、`bucket`、`rangeStart/rangeEnd`。统计与列表来自同一次候选扫描；服务逐条读取，只保留当前页、分类和日期桶，不把全部历史正文传给前端。超出末页时前端回到最新末页并重新读取。

复用 `currency_ledger`、`game_runs`、`user_state` 及现有 `created_at` 索引，无新表、列、索引、迁移或持久化筛选字段。备份继续保存原始账单，不保存可计算的图表结果。

## 5. 自带小游戏窗口

四个窗口仍统一默认800×600，最小320×240，可手动缩放。内部纸卡不再维持独立固定尺寸或 `resize:both` 把手，而是随原生窗口铺开，保留8px留白，窄窗4px。外观颜色和游戏数值、玩法、进度、概率均沿用各自实现，不套主程序主题。

常规页面和“我的家”当前子页面可纵向滚动；必要的游戏区域、卡片与控制不压缩成不可阅读的小字。接星星使用实际场地尺寸和现有坐标换算，不使用非等比CSS缩放。第三方插件页面不注入这份样式。

共享样式在 `plugins/first-party/shared/window.css`，构建时复制到各游戏 `ui/window.css`。各HTML显式引用；随包资源重新pack/validate。四个manifest程序版本升级为1.0.1，`storage_version`仍为1，走现有随包升级流程保留存档和授权；不清空或复制用户数据。

## 6. 动效边界

设置页切换采用约200ms淡入和5px位移，`MotionRegion`操作现有DOM，不使用React key重建页面。卡片、详情标题、展开内容和菜单采用短暂入场过渡；普通按钮按背景、文字、描边即时变化及短位移/透明度反馈，不持续弹跳。聊天侧栏直接完成布局，使用内容淡入衔接。

原生HTML dialog使用透明度、轻微位移及离散display/overlay过渡，新版WebView2支持开合动效，旧版正常打开和关闭。宠窗菜单只增加透明度入场，不加底色、不改透明规则和停靠定位。

柱子从零轴展开，更新时平滑变化；圆环淡入，比例数值即时更新。不会给流式消息逐字播放入场动画，不对所有属性应用 `transition:all`，不为动画等待网络或延迟业务操作。

遵循系统 `prefers-reduced-motion`，CSS关闭持续动画、缩短过渡，Web Animations也不启动。高频页面保持正文清楚，不加入文字模糊滤镜。

## 7. 验收范围

定向验证账单收支、零变动、金额精度、日期端点、分页/筛选、过期响应、失败保留、图表跳转和设置页回归。浏览器检查四游戏默认/最小/放大尺寸，以及账单亮暗主题和宽窄布局。安装后的原生WebView2、系统DPI和实际用户存档升级仍需新版EXE实机确认；本增量不自动构建安装包。
