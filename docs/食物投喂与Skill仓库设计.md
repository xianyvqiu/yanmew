# 食物投喂、互动特效与 Skill 仓库设计

日期：2026-10-20。
状态：当前数据库v19，食品与Skill表由015引入。20261020-160457发布包已包含食品与Skill仓库、Skill聊天工具、按人设筛选、共享原文确认及菜单避让；本机旧资料已正式升级并核对保留，见[发布记录](发布记录-20261020-160457.md)。原生跨屏/DPI、食物跟随及真实模型遵守Skill仍须实机验收。范围为单宠窗投喂、食物仓库/商城、角色表情及Skill仓库，多宠窗与群聊不开发。

## 1. 已确认的产品规则

- 基础食物为立体画风的 token，免费且无限。它是虚拟食物，不是模型 token 额度、API 余额或喵币，不能兑换这些资源。
- 五种喜好食物统一每份 5 喵币，使用全局钱包购买。GPT 喜欢云朵奶油小蛋糕；Claude 喜欢红茶；Gemini 喜欢猫猫头饼干；DeepSeek 喜欢白饭；电子小猫喜欢小鱼干。
- 喜好食物与普通食物的反馈表情不同。每次成功投喂喜好食物，有 10% 概率随机额外增加 1 点亲密度。
- 现有一次合法投喂基础奖励为 1 点，继续沿用；普通食物通常 +1，喜好食物 90% +1、10% +2。所有结果仍受 999 上限约束，奖励归当前会话，不把会话亲密度改成人设或全局数值。
- 点击投喂先选择拥有的食物，选中后食物随鼠标移动，再点击桌宠才真正投喂。选择弹窗可用星标设为该人设的默认食物；未设置默认使用 token。
- 增加嘴馋/等待投喂表情，颜文字和图片模式均支持。进食图片不画食物，食物由独立透明素材呈现。
- 按各自 base 图及不同人设重新设计后生成的基础互动图，避免同质化；base 原图保持。
- 设置增加 Skill 仓库：标题/简介卡片、搜索、分页、新增、编辑、删除；详情可查看绑定人设。Skill 与人设多对多，人设详情也能查看绑定项并跳转。

## 2. 食物界面与数值特效

设置增加“食物”入口，内含“仓库”“商城”两个页签，不建两套重复管理页。复用现有卡片浏览器、弹窗、搜索和分页；允许按名称及相关时间排序。仓库时间指最近库存变化，商城时间指目录上架时间，不伪造购买时间。

仓库固定展示免费无限 token，其他卡片展示食物图片、名字、当前数量；零库存付费食物可在商城查看，但不出现在投喂选择弹窗。商城展示价格与购买数量，提交前显示总价，余额不足明确提示。不自动补货、不提供本次未要求的出售、抽奖或制作食物功能。

投喂弹窗默认项优先显示。星标仅保存默认偏好，不立即投喂或购买；点击食物卡片才拿起食物。默认付费食物耗尽时，这次选择回退 token，保留用户的默认偏好，补货后重新可选；不自动花币。切换人设使用目标人设自己的默认项。

亲密度特效位于桌宠附近，喵币特效位于发生操作的窗口余额区域，沿用主题粉/紫强调色。显示实际差值，扣款显示负数，收入显示正数；不为同一次事件在多个窗口重复庆祝。999 时仍可投喂，表达吃到了，但不显示虚假的 +1/+2；998 命中额外奖励时只显示实际 +1，可另作喜好神态反馈。动画不阻塞聊天和后续界面操作，不把余额计数交给前端计算。

视觉时序建议：食物靠近嘴部后缩小淡出，咀嚼姿态短时保持，亲密度小标上浮淡出。具体时长、粒子数量和尺寸由视觉实现定向验证，不新建长期计时系统。优先使用 CSS 与既有透明 PNG，不为此引入动画库。

## 3. 投喂状态与事务

运行态使用 idle → choosing → holding → submitting → feedback → idle。选择、食物跟随位置和嘴馋是瞬时状态，不存数据库；退出程序不在下次启动时恢复“鼠标拿着食物”。

- choosing：只读取库存，不扣除；关闭弹窗回 idle。
- holding：绑定拿起时的人设、会话和 contextRevision；桌宠展示嘴馋，喜好食物使用不同反馈。Esc、取消、切换人设/会话、隐藏宠窗、进入不允许投喂的状态或关闭应用时取消；不扣粮。
- submitting：点击桌宠命中区域后提交唯一 actionId；禁用重复提交，不同时触发普通点击奖励或拖动。后端再次验证上下文、当前状态和库存。不能因前端已选择食物而跳过检查。
- feedback：只有事务成功才显示食物消失、咀嚼及数值特效。响应丢失时查询同一 actionId，不重抽奖励、不再次扣粮；不能用新的 actionId 自动重试。

付费投喂在同一事务中扣 1 个库存、复用 pet_store 的合法互动和饥饿重置、计算亲密度、保存成功回执。免费 token 不写负库存或“无限数量”，但其状态更新和奖励也必须走同一入口。旧直接 Feed 命令改为复用该服务或要求完成选择后的请求，不能保留第二个可绕过库存的入口；普通点击/摸摸奖励保持原有规则。

喜好判断依据持久化的 foodId，不根据 AI 文本或可改名字猜测。使用现有后端随机源从 0–99 均匀取值，值小于 10 触发额外 1 点；仅喜好食物执行该判断。不按累计十次保底，不因切换主题或重放动画再抽取。随机结果与实际增量随成功回执保存；事务失败没有食物和亲密度部分落库。

购买事务重新读取目录价格，核对前端展示的报价版本/单价；价格变更返回重新确认，不静默改价扣款。校验购买数量、整数乘法溢出和余额，复用 currency 的同事务接口扣币、写流水、加库存及购买回执。余额或库存失败整体回滚。不要在外层事务里调用另一个自带事务的钱包入口。

投喂可用状态沿用现有规则，不额外改变睡眠唤醒、出行或提供商休眠行为。瞬时嘴馋不能盖住睡眠、出行、错误和提醒等已有高优先级展示；开始持有时暂停自主游走，避免点击目标自行移开，结束后恢复原资格。

## 4. 鼠标食物显示与素材

Windows 平台适配负责跨桌面跟随：独立透明、无边框、不抢焦点、鼠标穿透的轻量显示层，只绘制食物。复用现有屏幕鼠标采样与缩放转换，不扩大主宠窗的鼠标拦截区域；只有主宠窗内桌宠命中才提交投喂。点击其他应用不得被拦截或误投喂，窗口隐藏/取消后立即撤掉显示层。跨屏、负坐标和不同 DPI 用定向实机验证。

新图为真实透明底，风格统一为柔和立体小物：token 是可辨认的立体 token 小块/点心，与喵币图标区分；云朵奶油蛋糕、红茶、猫猫头饼干、白饭和小鱼干均是独立食物图。显示尺寸随现有宠物缩放调整，图片资源随包，投喂不调用付费生图服务。

新增表情分类为 craving（拿起普通食物等待投喂）、craving_favorite（拿起喜好食物）、eating_favorite（喜好进食）；既有 eating 作为普通咀嚼。缺喜好分类时回退普通分类，再回到已有安全默认图，不导致功能不可用。颜文字库增加对应分类，复用已有生成和校验流程；拿起食物时读取已保存表达，不每次额外调用 AI。

四位图片人设按 base 保持脸、服装、发色、眼睛、角/耳朵/尾巴及统一透明画布：GPT 自信克制、嘴硬但期待；Claude 优雅理性、细微满足；Gemini 俏皮灵动、动作更明显；DeepSeek 悠闲可爱、满足而不敷衍。嘴馋不画手持食物，普通/喜好咀嚼都不能画饭碗、糕点、杯子或其他食物；红茶对应品尝/吞咽神态，仍使用同一进食阶段。hungry 表示尚未拿到食物的饥饿，craving 表示用户正在拿食物，两者不同。

重新生成仅针对衍生互动图，逐张预览确认。新安装使用新资源；已有用户数据不得被资源升级静默覆盖，已有用户可继续通过自定义创作的上传/生成/接受流程主动替换，不增加自动替换入口。已删角色不复活，自定义 base 不冒充原预置角色重新匹配。预置身份不能用可编辑的显示名识别。

## 5. Skill 仓库与上下文

Skill 是用户编写的提示词资料，不是小游戏插件、脚本、命令或工具权限。字段为标题、简介、正文；使用现有列表搜索、分页和时间排序组件，点击卡片进入详情，可修改并查看绑定人设。人设详情展示绑定 Skill 的标题/简介并跳转。绑定和解绑只改关联；删除 Skill 需明确告知会解除全部绑定，不删除人设；删除人设只删其关系，不删除共享 Skill。

用户在仓库手动编辑共享Skill会影响全部绑定人设的后续请求，保存前显示绑定范围。AI普通修改仅影响自己：独占则原位保存，共享则复制到仓库、解绑自己的旧项并绑定新项，其他人设及原文保持。仅在用户明确要求改共享原文时，AI可暂存预览；聊天详情/宠窗展示原文、拟修改内容及受影响人设，用户点击“确认修改共享原文”后才保存，取消不写库。请求开始时读取一致的绑定及正文快照，正在生成的回复保持原快照；保存不重写历史、记忆或人设初始设定，也不另开模型判断请求。

仓库增加“全部／未绑定／各人设”筛选；未绑定指没有任何人设关联。先筛选，再搜索、排序与分页；切换分类回到第一页。仓库和人设详情订阅skills-changed，更新绑定和卡片，不覆盖正在编辑的草稿。

### 5.1 当前人设Skill工具

只对普通聊天开放list_skills、get_skill、create_skill、update_skill、set_skill_binding、preview_shared_skill_update。默认只列自身绑定，也可查询仓库标题简介并读取具体正文；不返回其他人设设定。新增/修改/绑定必须有用户明确要求，不自动把日常聊天或事实写成Skill。工具没有persona_id参数，目标由可信请求上下文固定；不能绑定/解绑他人，没有全库删除或确认共享原文的模型工具。修改/绑定前先get_skill，保存核对读取版本，取消及作用域失效不落库；重复写调用ID返回原回执而不重复创建。

共享修改预览只在进程内保存，绑定当前人设、会话、contextRevision及原文/绑定快照；确认时重新校验完整快照，原文或绑定改变则拒绝保存。切换上下文、重启后旧预览无效，重新生成；预览不进数据库或备份。确认命令仅可信main/chat界面可调用。重说保留只读工具，禁止Skill写操作；续写及无聊主动消息不开放Skill工具，信件、游记和内部任务也不开放，只沿用其已确定的Skill注入范围。新正文和绑定从后续请求生效。

### 5.2 喜好设定与菜单

新安装的五位初始人设设定明确各自喜好食物；已有用户修改的设定不覆盖。四位图片预置的身份匹配同时兼容旧设定与含食物的新设定，仍检查初始图，不按显示名识别。聊天读取保存的favorite_food_id对应名称，用户改喜好后以当前配置为准，不代表已经拥有或投喂；设置为暂无喜好时不沿用旧喜好。右键投喂/摸摸/饰品以紧凑按钮排列，自由位置按实测身体上边界留8px间隔显示，左右停靠放内侧，底部放上方；限制高度并可滚动，不能覆盖身体。

已绑定 Skill 完整、按稳定顺序注入，不做 RAG、不让 AI 再自行下载或执行 Skill。优先级为应用协议/工具权限 > 当前人设 > 用户绑定的 Skill；遇到相互矛盾的多个 Skill，不允许依靠其声明扩大权限。首次实现固定按绑定时间及 ID 排序，不增加未经要求的复杂优先级编辑器。

Skill 内容属于固定请求资料，不能悄悄截掉一半规则。复用现有上下文预算，先裁剪可移除旧历史；仍放不下时明确报告并允许用户缩减或解绑，不发送残缺规则。标题/简介用于列表；正文进入模型，不拿简介替代正文。更新正文不能触发记忆索引重建。

已确认并实现的生效范围：正常聊天、重说/继续所继承的聊天上下文，以及无聊主动消息、信件、旅行游记。严格格式的记忆生成、标题、表情选择与连接测试不盲目注入用户 Skill，避免破坏 JSON 等输出协议。禁止实现者自行扩展成全局每种模型请求都加入。

## 6. 数据库结构与现有复用（当前v17）

当前正式结构版本为v17，015_foods_and_skills.sql是v14→15的历史升级；016/017仅扩充停靠及行走分类。db/schema.sql与迁移同步，新库一次建立全结构；旧库由既有流程在升级前生成一致性备份，失败回滚。015增加下列六表，并重建currency_ledger/pet_artworks以扩充CHECK，保留原记录、外键、索引和自增序列，不修改旧迁移。本轮Skill工具、筛选、确认及回合显示全部复用现有结构，不新增迁移。

1. food_catalog（全局食物目录）：id TEXT 主键，稳定食品代码；name TEXT 显示名；asset_key TEXT 随包资源键而非任意路径；is_unlimited INTEGER，0/1；price INTEGER，非负整数喵币；revision INTEGER，报价修订；created_at/updated_at TEXT UTC。token 固定无限且价格 0，付费食品数量有限且价格大于 0。token 固定 0，五种付费食品固定 5；目录由程序初始化，备份不能改写价格。
2. food_inventory（全局库存）：food_id TEXT 主键兼外键 → food_catalog.id，ON DELETE RESTRICT；quantity INTEGER 非负；updated_at TEXT。只存有限食品；无限食品不能出现库存行，由写服务验证。空库存可保留 0 行，不伪造无限数量。
3. persona_food_settings（人设偏好）：persona_id INTEGER 主键兼外键 → personas.id，CASCADE；default_food_id TEXT 非空外键 → food_catalog.id，RESTRICT，默认 token；favorite_food_id TEXT 可空外键 → food_catalog.id，RESTRICT；updated_at TEXT。没有配置的普通人设默认 token、无已知喜好；用户可在人设详情修改喜好或设为暂无喜好；选项为五种付费食品。默认食物独立，由投喂弹窗星标保存。预置人设按稳定身份初始化，不按名字猜测。
4. food_actions（购买/投喂成功回执）：action_id TEXT 主键，由宿主为一次操作生成；kind TEXT 枚举 purchase/feed；food_id TEXT 外键 → food_catalog.id，RESTRICT；quantity INTEGER 正整数，feed 固定 1；persona_id/session_id 可空外键，删除后 SET NULL；food_name TEXT 和 target_name TEXT 快照；unit_price INTEGER 非负；ledger_id INTEGER 可空外键 → currency_ledger.id，RESTRICT，非空时唯一；favorite_bonus INTEGER 0/1（本次是否抽中）；intimacy_delta INTEGER 0–2（封顶后的实际增加）；created_at TEXT。purchase 有扣币流水，不加亲密度；feed 无扣币流水，消费已有库存。只存已提交操作，不建持久化鼠标/pending 动画状态；同一 actionId 的参数不同必须拒绝，重试返回原回执。用户删除人设后保留购买/消费事实，不恢复库存。
5. skills（全局共享资料）：id INTEGER 主键；title/summary/body TEXT，标题与正文非空，简介可空；revision INTEGER 非负，防止并发编辑覆盖；created_at/updated_at TEXT UTC。文档内容不是可执行代码。
6. persona_skills（多对多）：persona_id INTEGER 外键 → personas.id，CASCADE；skill_id INTEGER 外键 → skills.id，CASCADE；created_at TEXT 绑定时间；PRIMARY KEY(persona_id,skill_id)，防止重复绑定；skill_id 另加索引用于反查绑定人设。

currency_ledger 复用现有表，reason 的 CHECK 需正式增加 food_purchase，并同步 Rust 枚举、账单展示与导入导出校验；ref_id 不混用为食物 ID，购买详细信息由 food_actions.ledger_id 关联。不得把食物购买伪装成插件游戏或饰品制作。成功投喂在唯一 Immediate 事务中调用 pet_store::interact_in_transaction 获得普通奖励，再在同一事务计算喜好额外奖励和封顶，最后保存回执；不使用双事务补奖。

表情分类扩展需同步 pet_artworks.category CHECK、颜文字 JSON 校验和两种模式的分类选择。现有饥饿计时/会话亲密度/全局钱包继续保留，不新增重复计时字段、第二份余额或第二份亲密度。

## 7. 备份与恢复边界

全量备份应包含库存、食物偏好、操作回执、Skill 和绑定；食品定义与随包图片作为版本化程序资源，备份记录引用与必要名称快照，不能让导入包任意改写商城价格。全量恢复的钱包、库存、购买流水、回执一起恢复，不能仅恢复金币却丢库存或重复重放购买。

人设及携带人设的资料包包含该人设食物偏好、绑定 Skill 正文和关系，不携带全局库存/钱包。跨设备导入不得直接按整数 ID 或标题认定 Skill 是同一份；优先仅复用经比对内容完全一致的现有资料，否则创建新项并重映射，不覆盖目标同名 Skill。复用已有目标人设时沿用现有“保留目标资料”规则，不擅自把备份偏好与 Skill 追加给它。

旧包缺新表时使用空库存、token默认和空Skill，不凭空赠送付费食品。当前备份schemaVersion=17，接受v6–16旧包；Skill复制及新绑定仍由既有skills/persona_skills白名单导出恢复，未确认预览不进入备份。检索索引不用于保存Skill，食物动画不进入备份。

## 8. 已实现的代码职责与接口

- `src-tauri/src/foods.rs`：程序目录种子、库存、偏好、购买和投喂事务、成功回执、保存的表情选择；复用 `currency`、`pet_store`、既有随机源和999上限。
- `skills.rs`：资料、修订冲突、多对多绑定和上下文文本；`chat/context.rs` 在固定上下文加入绑定快照，信件/主动消息复用；`travel_journals/generation.rs` 独立加入同一快照。修改 Skill 仅影响后续请求，不使已开始的游记任务失效。
- `companion_commands.rs`：可信宿主 IPC。`list_foods()` 返回 `id,name,unlimited,price,quantity,revision,createdAt,updatedAt`，时间分别用于上架/库存排序；`get_food_preferences(personaId)` 返回 `defaultFoodId,favoriteFoodId`；`save_food_preferences(personaId,defaultFoodId,favoriteFoodId,field)` 只更新 field 对应的一项，避免另一项被旧快照覆盖。
- `buy_food(actionId,foodId,quantity,quote)` 与 `feed_food(actionId,foodId,personaId,sessionId,contextRevision)` 返回 `actionId,kind,foodId,quantity,personaId,sessionId,favoriteBonus,intimacyDelta,coinDelta,replayed`。quote 是展示时的目录 revision；服务端重算价格、库存、奖励。`get_food_action(actionId)` 查询原回执；同一 actionId 不同载荷拒绝。
- `list_skills()` 返回资料及绑定人设，`save_skill({id,revision,title,summary,body})` 创建或按修订保存，`delete_skill(id,revision)` 删除并级联解除关系；`bind_skill(skillId,personaId,enabled)` 幂等绑定/解绑。标题/正文去首尾空白后非空，简介可空；不设未经确认的字数截断。卡片搜索、分页和排序沿用前端组件，不谎称后端分页。
- Settings 窗口可以购买、编辑喜好和管理 Skill；Main 宠窗可以读投喂资料、修改默认食物、投喂、查询回执。`get_food_expression(personaId,favorite)` 返回已保存的图片/颜文字，不调用模型。小游戏和食物光标页无食品/Skill业务访问权。
- `food_cursor.rs`：仅主宠窗可调用 `set_food_cursor(foodId|null)`；独立190×102逻辑像素透明无框、穿透、不获取焦点的窗口，25ms采样系统鼠标位置，偏移12物理像素，支持负坐标。右键或Esc全局撤掉并通知宠窗。取消/隐藏/切换/退出销毁显示层，不写数据。
- `FoodPanel`：仓库/商城卡片，搜索、分页、按名称及相关时间排序；购买回执确认后才更新反馈，刷新失败明确提示已成功，不诱导重复购买。`FoodPicker` 只列 token 和正库存，星标与拿起是独立按钮。
- `useFoodFeeding`：持有/取消/提交及上下文隔离；`PetWindow` 只在宠物命中时投喂，不同时触发普通点击，持有时暂停游走。食物缩小淡出与咀嚼分离，咀嚼保持3秒；数值特效显示已提交的实际变化。
- `SkillPanel` 与 `PersonaCompanionSettings`：可编辑卡片与双向详情导航；一份 Skill 可绑定多个角色，一个角色可绑定多份。删除 Skill 不删除人设，删除人设不删除共享资料。
