# 颜喵 YanMew 小游戏插件生态设计

> 当前实现基线（2026-11-09）：源码及备份v26，最新正式包20261109-143800为v26。本文中的阶段版本仅说明引入历史；实际交付范围与默认值见[当前实现与版本范围](当前实现与版本范围.md)。


- 日期：2026-09-19
- 状态：已接通数据服务、安装/宿主及六个自带小游戏；扫雷、2048及我的家互动钓鱼1.0.4均已包含在正式包20261029-094243；原生窗口与真实游玩体验仍需验收
- 范围：小游戏插件协议、仓库分工、便携版内置插件、喵币权限、本地安装与后续 GitHub 分发

## 1. 已确认的产品规则

- 所有小游戏都使用同一套插件协议，包括随颜喵发布的石头剪刀布；主程序不为石头剪刀布保留一套绕过插件宿主的专用实现。
- 颜喵主仓库保存项目维护者自己发布的小游戏、插件 SDK、插件模板和构建工具。
- 剪刀石头布、掷骰子比大小、接星星、我的家均为主仓库第一方插件，随便携版一起提供。
- 第三方小游戏以后进入单独的社区小游戏仓库。社区仓库当前只保留规划，不在本阶段创建。
- 社区仓库启用后，作者通过 Pull Request 提交小游戏；审查和自动检查通过后合并，由用户从 GitHub 手动下载插件包。
- 第一版不做“官方收录”徽标、应用内在线目录、自动连接 GitHub、独立插件网站或网页一键安装。
- 所有插件都可以申请“修改喵币”权限。用户允许后，插件通过 `wallet.changeCoins()` 增减喵币；用户拒绝后不允许修改喵币；剪刀石头布、骰子、接星星可纯玩，我的家必须授权钱包才能玩。
- 主程序负责喵币事务、非负余额校验、请求去重和账单记录。插件不能直接访问 SQLite。
- 颜喵原有的每日签到是应用级全局功能，不属于小游戏插件。插件不能创建第二套应用签到、修改全局签到状态或写入签到类型流水。
- 插件协议不提供 `ai.generate()` 或其他 AI 出题、解说能力，也不能读取聊天、记忆、记事本、模型配置或 API Key。

## 2. 仓库分工

平台边界：首版发布和验收面向 Windows。插件协议、设置/存档、运行记录与钱包服务可供未来 Android 复用；宿主通过平台适配创建受限 WebView，并将可信实例映射到插件身份，不能依赖插件自行声明 Windows 窗口标签。Android 文件选择、包安装、触摸操作、直接网络阻断与桥接隔离完成专项验收后，才能声明兼容对应插件包。当前不为移动端改动权限规则、不取消第三方插件机制，也不把“能显示网页”等同于“插件安全兼容”。未来主界面和原生悬浮层共用一个 Rust 钱包入口，不分别结算。

### 2.1 颜喵主仓库

主仓库负责主程序和项目维护者发布的小游戏，规划目录如下：

```text
yanwenzi/
├─ src/                                  # React 主程序前端
├─ src-tauri/                            # Rust 核心与插件宿主
├─ plugins/
│  ├─ sdk/                               # 宿主接口类型、开发辅助工具
│  ├─ template/                          # 新小游戏模板
│  ├─ build/                             # 校验和打包脚本
│  ├─ bundled-games.json                 # 随便携版发布的插件清单
│  └─ first-party/
│     ├─ rock-paper-scissors/            # 剪刀石头布
│     ├─ dice/                           # 掷骰子比大小
│     ├─ star-catcher/                   # 接星星
│     ├─ my-home/                        # 我的家
│     └─ shared/                         # 第一方存档与钱包衔接
├─ db/
└─ docs/
```

规则：

- `plugins/first-party/` 只保存项目维护者自己发布的小游戏。
- 第一方和第三方插件使用同一 manifest、宿主 API、存档格式和喵币权限接口。
- 是否随便携版打包由主仓库的 `bundled-games.json` 决定，不能由插件在自己的 manifest 中自行声明。
- 四个自带游戏列入 `bundled-games.json`。以后新增的第一方小游戏可以选择随应用打包，或只在主仓库 Release 中提供下载。
- 主程序发布流程只自动打包清单中列出的插件，避免所有第一方游戏都无条件增加便携版体积。

### 2.2 社区小游戏仓库

社区仓库以后单独建立，暂定职责和目录如下：

```text
yanmew-community-games/
├─ games/
│  └─ <plugin-id>/
│     ├─ manifest.json
│     ├─ src/
│     ├─ locales/
│     ├─ icon.svg
│     └─ README.md
├─ validation/                           # 自动检查规则
├─ build/                                # 统一打包脚本
├─ CONTRIBUTING.md                       # 投稿与审查说明
└─ README.md                             # 游戏列表与下载说明
```

规则：

- 第三方作者向 `games/<plugin-id>/` 提交 Pull Request；一个 PR 只新增或更新一个小游戏。
- 作者提交源码、manifest、图标、说明和必要素材，不能只提交无法审查来源的成品包。
- 自动检查通过后再进行人工审查；合并表示允许它进入社区仓库供用户下载，不在颜喵界面授予“官方”身份。
- 社区仓库使用统一构建流程生成 `.yanmew-game`，避免每个作者使用不同打包规则。
- 推荐按 `<plugin-id>/v<version>` 创建 tag 或 Release，并生成 `<plugin-id>-<version>.yanmew-game`。
- 社区仓库未创建前，不在主仓库接收第三方小游戏代码，防止主程序 PR、Issue、CI 和第三方游戏更新混在一起。

## 3. 第一版范围

第一版实现可工作的插件基础，而不是把石头剪刀布伪装成普通内置页面：

- 版本化插件 manifest。
- 插件包校验、安装、启用、停用和卸载。
- 受限插件 WebView 与宿主桥接。
- 插件私有设置和存档。
- 运行记录创建、完成和战绩记录。
- `wallet.modify` 权限与 `wallet.changeCoins()`。
- 按 manifest 中 HTTPS origin 逐项授权的 `network.fetch()` 宿主代理。
- 从本地 `.yanmew-game` 文件安装插件。
- 四个自带小游戏的构建、随包分发、首次注册和运行。

第一版不实现：

- 在应用内请求 GitHub API、浏览仓库或检查 Release 更新。
- 应用内在线插件目录和“官方收录”徽标。
- 独立插件网站。
- `yanmew://install?...` 网页一键安装。
- 社区仓库的实际创建和运营。

用户将来可以从浏览器打开社区仓库，手动下载 `.yanmew-game`，再使用第一版已经具备的“从本地安装”能力导入颜喵；因此社区仓库上线不要求立即修改颜喵的联网功能。

## 4. 石头剪刀布插件

### 4.1 源码与构建

- 源码位置：`plugins/first-party/rock-paper-scissors/`。
- 插件 ID 固定为 `com.yanmew.game.rock-paper-scissors`，发布后不修改。
- 游戏界面、用户出拳、系统随机出拳、胜负判断和结果展示都在插件边界内完成。
- 实际出拳由 `game.random()` 提供；最后一局的选择和结果保存在私有存档，喵币结算明细同时作为账单 details 保存，不要求用一条窗口运行记录保存每一局。
- 构建流程先按普通插件生成 `.yanmew-game`，再由便携版打包流程把同一个包放入应用资源。不能维护“开发版内置代码”和“外部插件包”两份实现。

### 4.2 便携版首次启动

1. 主程序读取随包插件清单并校验石头剪刀布插件资源。
2. `game_plugins` 没有该插件时，登记当前内置版本；已经登记时按版本规则更新。
3. 内置插件显示“随应用提供”，不显示“官方收录”。
4. 内置插件的程序文件不能在游戏管理页永久卸载，因为应用资源中始终存在；用户可以停用插件并清除它的私有存档。
5. 应用升级携带新版本时，先完成兼容检查和插件数据迁移，再切换登记版本；失败时保留可运行旧版本，或禁用并显示具体错误。

### 4.3 喵币权限与纯玩模式

石头剪刀布需要申请 `wallet.modify`，但作为随包插件没有普通安装确认页。因此第一次打开游戏时显示权限确认：

- 每天最多 20 局，无论是否授权喵币都执行同一次数限制。
- 允许：使用原定规则结算，胜利 `+5`、失败 `-4`、平局 `0`，开始前余额至少 4。
- 拒绝：进入纯玩模式，胜负仍正常记录，但本局不增加或扣除喵币，也不受“余额至少 4”的限制。
- 稍后修改：用户可在游戏管理页开启或撤销权限；新增授权只影响之后开始的运行记录，撤销则立即阻止尚未提交的钱包请求。

运行打开时保存钱包授权快照；每个玩法局另外锁定自己的喵币/纯玩模式，揭晓与结算期间不能切换。撤权立即拒绝新钱包请求，已经提交的账单不回滚；未确认的结算不伪装成功。剪刀石头布与骰子在动画开始前提交结果，接星星开始扣费、完成发奖。

### 4.4 四个自带游戏及存档契约（Task 13.6）

四个游戏的固定 ID、数值、源码职责和资源构建见 [第一方游戏说明](../plugins/first-party/README.md)。所有游戏使用同一个全局钱包，不赠送原型初始 30/100 币；我的家熟练度是私有成长值。原型 HTML 主体与样式保留，脚本拆成宿主 CSP 允许的外部文件。无 AI、无联网、无宿主主题注入。四窗统一默认 800×600，可手动缩放，保持原型纸卡的原有缩放能力。

每个插件通过 `state.main` 保存 `{version:1, progress, pending}`。前三个 progress 保存 `day/usedToday/walletMode/lastRound`，接星星另有 `activeRound`；我的家保存 `affinity/inventory/farm/fishing/barn`，不保存喵币余额。日期采用当前本地 `YYYY-MM-DD`，次数在开始前落盘，各插件互不共享额度。接星星旧 activeRound 重开记为放弃，不返还入场费，不发未完成奖励。

pending 保存原钱包请求及结算后 progress。先写旧进度与 pending，再提交宿主钱包，最后写新进度并清除 pending；中断重开先核对原 request_id/game_run_id。已有账单补存进度而不再次结算；旧运行未提交请求由宿主拒绝，保留旧进度。未知结果保留请求并禁止新动作，不生成新请求 ID 尝试同一操作。此衔接只占用既有私有 JSON 存档，不增加数据库表或 SDK 命令。

我的家的菜品按既有菜谱标价售卖；所有关闭确认弹窗的路径移除旧回调，宰杀重新检查动物数量。购买、种植、收获、钓鱼、升级、制作、送出与出售均从同一串行动作入口保存，钱包及进度确认后才显示成功动画。田地每日奖励和蛋奶收取只改自己的日标记，不操作全局签到。

## 5. 插件包与 manifest

插件包扩展名为 `.yanmew-game`，必需根目录 manifest 和其指定入口；图标、语言包及其他资源按需提供。推荐结构：

```text
example.yanmew-game
├─ manifest.json
├─ ui/
│  ├─ index.html
│  └─ assets/
├─ locales/
│  └─ zh-CN.json
└─ icon.svg
```

manifest 的稳定字段：

- `id`：全局稳定插件 ID，建议使用反向域名格式。
- `name`、`description`、`author`：用户可见信息。
- `version`：插件版本。
- `api_version`：所需宿主协议版本。
- `entry`：插件入口页面。
- `permissions`：申请的权限列表，例如 `wallet.modify`、`network.fetch`。
- `network_origins`：申请联网时必填的 HTTPS origin 列表，格式为协议、主机和可选端口，不接受路径、通配符、用户名或密码。
- `settings_schema`：插件设置项定义。
- `storage_version`：插件私有数据结构版本。
- `homepage`：可选的项目主页。
- `repository`：源码仓库地址；通过主仓库或以后社区仓库分发的插件必须填写 GitHub 仓库地址，本地开发或私人插件可以留空。
- `release_page`：可选的 GitHub Release 或其他人工下载页面。颜喵只保存和展示该链接，不在第一版中自动下载插件包。
- `migration`：可选的包内 JavaScript ES module 相对路径；改变存档或不兼容设置结构时，由插件开发者导出 `migrate(snapshot, targetVersion)`。

manifest 中的权限声明只是申请，不代表用户已经授权。`bundled`、审查状态或未来目录展示状态由分发仓库和主程序决定，不接受插件自报。

## 6. 插件宿主

插件运行在独立的受限 WebView 中，通过带版本号的桥接访问主程序。插件不能取得数据库连接、任意文件路径、系统命令或 Tauri 全部命令。

小游戏插件的视觉与颜喵主程序主题相互独立。亮色、暗色或跟随系统只影响主程序窗口；宿主不向插件注入主题 CSS、不发送主题变化事件，插件作者自行决定游戏界面的颜色与样式。

第一版宿主接口：

运行记录口径：`game_runs` 是一次打开到关闭的宿主运行，不是游戏的一局，也不是长期游戏进度。重复点击入口聚焦已有窗口，不新建运行。关闭窗口或退出颜喵将 running 标为 cancelled；重启将崩溃残留 running 标为 error，已完成记录不改变。长期游戏下一次打开读取原存档继续，同时创建新的运行记录。插件自行维护局次、角色、养成等结构，不要求调用 `game.start()`。

- `game.ready()`：通知宿主插件已经准备完成。
- `game.getContext()`：取得语言、运行记录 ID、插件版本、打开时的钱包授权快照 `walletPermissionGranted`、当前授权摘要，以及 manifest 默认值与用户覆盖值合并后的只读插件 `settings` 对象；打开时快照与当前授权都允许才可发起新的钱包请求。不包含人设、会话、颜喵主题、主程序全局设置或颜色变量。
- `game.random()`：取得宿主生成的随机数。
- `game.complete(outcome, details)`：可选，标记本次运行正常完成并保存结果和明细；相同结果重复完成幂等，不同结果拒绝。之后不能提交新的钱包操作，私有存档仍可读写；关闭不清空存档。连续游戏通常保持 running 到窗口关闭。
- `storage.get(key)`、`storage.set(key, value)`、`storage.delete(key)`：访问当前插件自己的 `data_key → JSON value` 命名空间存档。
- `wallet.getBalance()`：读取全局喵币余额。
- `wallet.changeCoins(request)`：在获得 `wallet.modify` 授权时申请喵币变化。
- `network.fetch(request)`：在指定 HTTPS origin 获得 `network.fetch` 授权后，由宿主代发受限网络请求。
- `game.close()`：请求关闭小游戏窗口。

钱包接口只产生插件游戏类型账单，不允许插件伪装成每日签到、节日签到、饰品制作或饰品卖出等主程序业务来源。

协议明确不提供 `ai.generate()`。如果以后出现必须使用 AI 的独立玩法，再作为新权限和新协议版本重新讨论。

## 7. 安装与权限

### 7.1 本地插件安装

1. 用户选择 `.yanmew-game`。
2. 主程序校验包结构、manifest、路径、文件类型、解压大小和 `api_version`。
3. 安装页显示名称、作者、版本、来源、全局存档说明、申请权限和逐项联网来源。
4. “可修改喵币”必须单独说明插件可以增加或扣除全局余额。
5. 用户允许或拒绝每项可选权限后完成安装；拒绝 `wallet.modify` 不影响安装。
6. 新版本先写入临时目录并校验，再发布到全新版本目录；数据库事务中完成使用数据变更及当前版本指向，提交前保留旧版本目录。不得把 SQLite 提交与文件移动声称为同一个原子操作；文件先发布、后提交引用及崩溃清理遵守数据库设计第 12 节。失败继续使用旧版本。

插件更新没有增加权限时可以沿用已有授权；新增权限必须重新确认。用户可以随时在游戏管理页撤销权限。

### 7.1.1 更新与存档迁移

这里的更新指开发者发布新版插件、用户安装新包；不是颜喵把第三方存档自行猜测为新结构。随包插件升级使用相同规则。

1. 同一版本同一包重复安装可幂等处理；拒绝版本降级、存储版本降级和同版本不同内容。
2. 存储版本不变且新设置仍兼容时沿用数据；不兼容设置也属于结构变更，作者必须提高 `storage_version`。
3. 存储版本提高且存在设置/存档时，要求作者提供迁移模块。输入是 `{storage_version, settings, data}` 的副本，第二参数是目标存储版本；输出完整同形快照。跨版本升级由作者逐级或直接转换，不能要求用户先装齐中间版本。
4. 升级前关闭该插件运行窗口。迁移使用独立隐藏 WebView，无游戏 SDK、钱包、联网或存储写入；仅可取得输入及返回结果。原库、旧包不在执行时修改。
5. 15 秒内完成并通过键名、JSON、容量、目标版本和新设置校验后，发布新文件，并将登记、权限及转换后的完整数据同事务提交。返回时省略的键在成功提交后删除。
6. 事务前重新比较原版本、包校验值及真实数据快照；任何并发变化拒绝覆盖。缺少模块、异常、超时、非法结果或提交失败均保留旧插件与存档，不自动清空。升级失败后用户可重新打开旧版。
7. 新文件发布而数据库尚未提交时崩溃，启动按登记引用清理孤立目录；数据库已提交的目录在提交前已完整发布。发布前对文件执行同步落盘，不把文件系统与 SQLite 声称为跨系统原子事务。

### 7.1.2 协议工程约束

- 包为 ZIP，扩展名 `.yanmew-game`；最大压缩包 64 MiB、展开 128 MiB、单文件 32 MiB、条目 4096。manifest 最大 64 KiB。
- 路径仅接受 ASCII 字母、数字、点、下划线、短横线及目录分隔 `/`，最大 240 字节；拒绝绝对/越界/编码路径、Windows 特殊名、符号链接、重解析点和大小写重名。资源格式由共用的 `package::mime` 定义；不能包含可执行文件。
- 版本使用 SemVer；宿主协议精确为 `1.0.0`。新增依赖已确认为 `zip` 与 `semver`，具体锁定版本在 Cargo.toml/lock。
- 设置最多 64 项，存档键最多 1024 个、每值 1 MiB、总计 10 MiB；键最大 128 字节。运行明细最多 64 KiB。金额和 SQLite ID 返回十进制字符串，钱包请求变化为 JS 安全整数。
- 网络请求 30 秒、每实例最多 4 个并行；正文及解压后响应各 1 MiB，头最多 32 项/16 KiB。只跳转 301/302/303/307/308，最多 3 次。跨来源移除自定义头；带正文的跨来源跳转除 303 外拒绝。
- SDK 类型、浏览器模拟器与作者说明在 `plugins/sdk/`；`plugins/template/` 仅验证连接和存档，不是小游戏。`yanmew-plugin pack/validate` 共用原生包校验，详见 `plugins/build/README.md`。
- 用户文件预览仅保存一份内存候选，10 分钟内确认；确认引用预览 token，不接受插件自行指定路径或身份。UI 放弃预览时调用取消接口释放候选。
- 使用目录 `data/plugins/versions/<sha256>/`，含 ZIP 原包及已展开资源；宿主重新校验 ZIP 并按实例读取其资源。浏览器数据目录 `data/plugins/webview-profiles/<实例>/` 不作为正式存档，不进入备份；作者必须通过 `storage.*` 保存长期进度。
- 游戏窗口不取得主程序 capabilities。统一命令入口仅放行插件桥接，资源协议核对可信窗口及路径实例前缀；CSP、导航拦截和弹窗拒绝共同限制直接联网及跨实例访问。不注入主题、人设或会话。

授权按版本保存的具体含义：用户确认安装更新后，宿主比较新旧 manifest 的权限及规范化 origin；未扩大的授权在版本切换事务中复制/更新为新版本对应决定，保留允许或拒绝状态；新增权限或 origin 为待确认。运行时只接受当前已安装版本对应的决定，不拿旧版本记录直接放行新版本。来源变化不能通过相同插件 ID 自动扩大授权。

### 7.2 `wallet.changeCoins()`

调用至少携带：

```text
request_id    本次钱包操作的唯一 ID
game_run_id   当前运行记录 ID
delta         整数；正数增加，负数扣除
reason        供用户查看的简短原因
details       可选的结构化游戏明细
```

主程序先验证调用来自对应插件宿主身份，并按 (plugin_id, request_id) 查询是否已提交。已提交且原运行记录、数量、原因一致时仅返回原账单，不执行新变化；关闭或升级后仍可核对原已提交请求，不一致则返回冲突。新请求再验证插件已启用、当前版本一致、运行记录仍运行、打开时具有钱包权限且当前仍授权、运行记录归属、合法整数变化及非负余额。本次纯玩运行不能因中途授权变成可结算运行。随后在同一 SQLite 事务中：

1. 写入或更新运行记录的喵币变化。
2. 插入带插件 ID、插件版本、运行记录 ID 和 `request_id` 的账单。
3. 更新全局余额。

任何一步失败都回滚。同一插件内的同一 `request_id` 携带相同业务内容重试时返回原结算结果，不能重复到账或扣款；同 ID 携带不同运行记录、变化数量或原因时返回冲突，不将它视为成功重试。数据库以 `(plugin_id, wallet_request_id)` 唯一约束兜底，避免不同插件的请求编号互相冲突。

成功返回包含账单 ID、已应用变化量、是否重复请求和查询时的当前余额；当前余额不冒充历史结算时余额。调用先完成钱包结算，再结束运行记录；关闭或完成后的新钱包请求拒绝，已提交请求仍可按幂等规则查证，不重复结算。

项目开源且钱包位于用户本机，这套机制用于保证数据一致、隔离插件和提供清楚账单，不承诺阻止电脑所有者主动修改程序或数据库。

### 7.3 `network.fetch()`

- 插件只有在 manifest 同时声明 `network.fetch` 和 `network_origins` 时才能申请联网；未声明、未授权或已撤销时，宿主直接拒绝请求。
- 安装与更新界面按 origin 分项展示，例如 `https://api.example.com`。用户可逐项允许或拒绝；新增 origin 必须重新确认，旧授权不能覆盖新来源。
- 插件 WebView 的内容安全策略禁止直接联网。请求只能通过宿主接口发出，宿主校验插件 ID、当前版本、权限、URL scheme、目标 origin、方法、超时和大小限制。
- V1 只允许 HTTPS，不允许 `file:`、`data:`、`javascript:`、本机回环地址或局域网私有地址。发生重定向时重新校验每一跳，跳到未授权来源立即停止。
- 宿主不会向插件附加颜喵的聊天/Embedding/天气 API Key、Cookie、Windows 凭据或其他插件数据。插件需要的公开服务凭据只能由插件自行向用户说明并保存在自己的全局私有存档中。
- 联网失败只影响该插件本次请求，不让桌宠进入休眠，也不影响主程序聊天与其他插件。

### 7.4 目标校验与解析绑定

以下为现有受限联网权限的实现要求，不扩大授权范围：宿主逐次校验 HTTPS 来源白名单、禁止 URL 用户名密码、检查所有 DNS A/AAAA 结果，并拒绝 loopback、私网、link-local、未指定、多播及其他非公网目标；IPv4-mapped IPv6 必须按内嵌 IPv4 一并检查。混合公网/私网解析结果拒绝，不能仅检查 URL 字符串。

实际连接必须使用此次已校验地址并保留原始主机名的 TLS 证书校验，防止校验后重新解析绕过。关闭 HTTP 客户端自动重定向；若支持跳转，最多 3 次，每一跳重新校验授权来源、DNS 和目标地址。禁止继承系统代理、应用聊天密钥、Cookie 或自动认证；限制响应体及解压后大小并遵守既有超时。该策略仅适用于插件代理，不套用到用户主动配置的本地/私网聊天或 Embedding 服务。

实施前核对 [OWASP SSRF 防护说明](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html)。插件宿主完成后做一次针对权限、桥接身份、DNS/重定向和钱包幂等的专项审查；不是每次小改都执行全项目测试。

## 8. 当前数据模型

以下结构已经加入完整 V1 `db/schema.sql`。阶段 13 接入仓储、宿主和界面，不再临时设计另一套表。是否需要旧库迁移必须核对真实历史 schema；不能因为进入阶段 13 就重复建已存在表，也不能根据当前 schema 构造的降版本样本断言旧库已完整。

- `game_plugins`：当前插件登记，保存插件 ID、名称、简介、作者、安装版本、API/存储版本、来源类型、相对包路径、包校验值、GitHub 仓库 `repository`、项目主页 `homepage`、Release 页面 `release_page`、manifest 声明的 HTTPS origin、是否随包提供、程序包状态、启用状态和安装/更新时间。程序包状态区分 `available` 与 `missing_package`，缺包时必须停用。
- `game_permissions`：插件 ID、权限名、权限作用域、`pending/allowed/denied` 状态、决定时间和对应插件版本。`wallet.modify` 的作用域为空；`network.fetch` 每个 HTTPS origin 保存一条状态。`pending` 没有决定时间且不能调用权限；新增权限、导入的独立插件数据或新增 origin 默认待确认，manifest 不能替用户授权。
- `game_runs`：不可因插件卸载而删除的全局历史运行记录，保存插件 ID、名称、版本、打开时钱包授权快照、状态、结果、JSON 明细、累计喵币变化、开始和结束时间。它不外键关联当前插件登记，也不保存人设或会话 ID。每次打开到关闭一条，玩法局次和长期进度由插件存档独立维护；石头剪刀布每日 20 局不得按打开次数统计。
- `game_plugin_settings`：插件 ID、设置键、JSON 值和更新时间。石头剪刀布的每日 20 局、胜 `+5`、负 `-4` 是第一版插件固定规则，不作为用户可改的全局设置。
- `game_plugin_data`：插件 ID、数据键、JSON 值、存储版本和更新时间。全部为应用全局的插件私有存档，只按插件 ID 隔离，不随人设或会话切换、删除。
- `currency_ledger`：插件钱包统一使用 `reason=plugin_game`，保存运行记录 ID、插件 ID、插件版本、给用户看的原因和钱包请求 ID。插件 ID 与版本是历史快照，运行记录使用 `RESTRICT` 外键保护。

### 8.1 插件键值与 JSON 字段约定

主程序全局 `settings.key/value` 的允许键和默认值统一登记在《数据库与持久化设计》第 2.7 节。插件不能写入该表，只能使用自己的设置和存档命名空间。

插件键使用稳定的小写英文标识，允许用点号划分用途，例如 `audio.volume`、`stats.overall`。发布后不能在没有迁移的情况下改变旧键含义。键不存在表示“没有用户覆盖值”或“尚无该项存档”，不能用空字符串混淆未设置状态。

`manifest.settings_schema` 中每个设置项可声明：

- `key`：稳定设置键，例如 `audio.volume`。
- `title`、`description`：设置页显示名称与说明。
- `type`：`boolean`、`integer`、`number`、`string` 或 `enum`。
- `default`：插件默认值；数据库没有覆盖行时使用该值。
- `required`：是否必须提供值。
- `minimum`、`maximum`：数字类型的可选范围。
- `options`：`enum` 的可选值及显示文字。

设置键不存在时才使用`default`。当`options`明确声明`null`、对象或数组为合法枚举值时，已保存的这些值必须原样展示和提交，不能把`null`当成缺失。管理页刷新后，保存值的JSON内容相同则保留未保存草稿，不因对象引用变化而重置选择；保存值实际变化时同步最新值。

常见的 `game_plugin_settings.setting_key → value_json` 可以是：

```text
audio.enabled                 → true
audio.volume                  → 80
game.difficulty               → "normal"
game.confirm_action           → false
accessibility.reduce_motion   → false
```

这些只是通用示例，不要求每个游戏都有这些设置。`value_json` 可以是 JSON 布尔、数字、字符串、数组或对象，但必须符合本插件 manifest 对该键的声明。宿主设置界面读取 schema 渲染控件，写入前由 Rust 校验键存在、类型、枚举和数值范围。

常见的 `game_plugin_data.data_key → value_json` 可以是：

```text
progress.main        → {"level":3,"checkpoint":"forest-2"}
stats.overall        → {"wins":12,"draws":3,"losses":8,"best_streak":4}
records.high_scores  → [{"mode":"classic","score":1200}]
unlocks.items        → ["blue_board","cat_badge"]
tutorial.state       → {"completed":true,"step":5}
state.current        → {"mode":"timed","remaining_seconds":42}
```

存档键不要求全部在 manifest 中预先列出，因为不同游戏的进度结构差异很大；插件负责其业务格式和 `storage_version` 迁移，主程序负责插件 ID 隔离、合法 JSON、容量限制与备份。插件不得把全局喵币余额、账单、权限决定或宿主强制规则写进私有存档后当作权威数据。

`game_runs.outcome` 保存插件定义的本次运行结果标识，例如 `finished` 或 `saved`；`details_json` 保存本次运行的汇总或最近一次操作明细，不承诺永久保留窗口内每一玩法局的过程。需要逐局战绩时由插件另存私有数据。运行汇总示例：

```json
{
  "schema_version": 1,
  "mode": "classic",
  "rounds_played": 5,
  "wins": 3,
  "draws": 1,
  "losses": 1,
  "duration_ms": 60000
}
```

`details_json` 可以因游戏不同增加得分、关卡、随机结果或回合统计，但不能直接决定喵币是否到账。钱包授权、实际 `coin_delta` 和账单以宿主验证后的 `game_runs`、`currency_ledger` 与 `user_state` 为准。石头剪刀布每日 20 局由该插件自己的私有存档按本地日期统计，纯玩和结算共用计数，不能按窗口打开次数统计。通用宿主不解释第三方游戏规则，也不把插件战绩当作钱包或授权事实。

插件登记、权限、设置、私有存档、运行记录、钱包和账单都是全局数据。当前插件登记、权限、设置和私有存档可以由用户明确清除；历史运行记录和账单始终保留。随包石头剪刀布由首次启动种子逻辑登记到 `game_plugins`，与本地安装插件走同一套权限、运行记录、存档和钱包结构。

## 9. 小游戏插件

设置只保留“小游戏插件”一个导航入口：同一套卡片显示全局余额、游戏摘要、打开、启停、卸载和清除数据并重载；点击卡片进入权限、设置、存档和历史详情。完整第一版职责如下：

- 展示随应用提供和用户本地安装的插件。
- 显示名称、作者、版本、来源、简介、源码链接、全局存档状态、喵币权限、申请的联网来源和逐项授权状态。
- 启动、停用、启用和卸载可卸载插件。
- 开启或撤销喵币权限。
- 按 HTTPS origin 开启或撤销联网权限。
- 查看战绩和插件产生的喵币账单。
- 阶段 17 接入单独备份或导入插件使用数据；导入摘要明确提示不会恢复历史账单或改变喵币余额，钱包和联网权限需要重新确认。
- 从本地 `.yanmew-game` 文件安装或更新插件。
- 对从备份恢复但尚未重新安装的插件显示“缺少插件包”数据卡片，列出插件名称、插件 ID、原版本、作者、存档是否存在，以及备份中保存的 GitHub 仓库或 Release 页面。
- “打开来源页面”只调用系统默认浏览器；颜喵第一版不请求 GitHub API、不检查更新，也不自动下载或安装。
- 缺少插件包时允许用户选择本地 `.yanmew-game` 重新安装，或删除保留的插件设置与私有存档。插件包安装成功且插件 ID 一致后，再按存储版本执行兼容检查并关联原数据。

四个随包小游戏允许停用和执行“清除数据并重载”，不允许永久卸载。该操作先关闭游戏，在同一事务中清空该插件的 `game_plugin_data`、`game_plugin_settings`，并将 `game_permissions` 的决定和时间重置为 `pending`、`NULL`；随后由用户重新确认权限，再打开全新进度。插件登记和程序包、全局喵币、历史运行记录与账单均保留。普通本地插件卸载并保留数据时，清空包路径、标为 `missing_package` 并停用，同时保留登记、授权、设置和私有存档；选择“同时清除插件私有数据”时删除当前登记及其级联数据。历史运行记录和喵币账单不能因卸载或清除当前数据而删除。

## 10. GitHub 人工分发

第一版不由颜喵直接连接 GitHub。用户通过浏览器下载，再从本地安装：

```text
项目维护者的小游戏
    主仓库源码 → 主仓库 Release → .yanmew-game

以后的第三方小游戏
    社区仓库 Pull Request → 自动检查 → 人工审查
    → 合并 → 社区仓库 Release → .yanmew-game

用户
    浏览器下载 → 颜喵“从本地安装” → 权限确认 → 小游戏插件
```

这一流程不需要插件网站、在线目录或 GitHub API，也不妨碍以后增加这些能力。

## 12. 备份与后续实施边界

已经确认：

- 全量备份只保存插件使用数据，以及识别这些数据来源所需的登记快照：授权、设置、私有存档、运行记录、相关喵币账单、插件 ID、名称、作者、原版本和来源链接。登记快照不代表插件已经安装。
- 小游戏插件支持单独导出“插件使用数据包”。包内只保存所选插件的登记快照、来源链接、manifest 声明的权限及联网 origin、设置和私有存档；不保存插件程序包、运行记录、插件账单或全局钱包余额。
- 独立插件数据导入按插件 ID 展示将恢复的设置和存档，用户确认后原子替换所选插件的现有设置与存档。它不导入插件账单、不导入运行记录、不修改当前喵币余额，也不重放任何历史喵币变化。
- 独立插件数据导入后，`wallet.modify` 与每个 `network.fetch` origin 都写为 `pending`；旧包中的允许或拒绝结果只用于说明曾申请过什么权限，不能恢复为有效授权。插件重新安装或打开时，由用户重新允许或拒绝。
- 全量备份不包含用户自行安装的 `.yanmew-game` 程序包；恢复后由用户自行重新下载并安装。
- 插件的本机包路径不进入备份；恢复后的第三方插件登记先标为 `missing_package`，重新安装相同插件 ID 且兼容检查通过后才写入新的本机路径。
- 插件登记同时备份名称、插件 ID、作者、原安装版本、来源类型、包校验值，以及 manifest 提供的 `repository`、`homepage` 和 `release_page`。这些链接用于帮助用户找回插件，不代表颜喵自动联网下载。
- 恢复时即使插件程序包缺失，也保留其登记、授权、设置、私有存档、运行记录和历史账单，并在小游戏插件中显示“缺少插件包”；重新安装相同插件 ID 后才允许继续运行。
- 来源链接缺失时，小游戏插件仍显示插件 ID、作者和原版本，并提示用户自行寻找安装包。
- 主程序 API Key 排除规则不等于扫描和删除插件自定义 JSON 中的未知凭据。插件自己的设置与存档按原数据备份，导出说明明确这一边界。
- 卸载或停用插件不能删除历史运行记录和喵币账单。
- 石头剪刀布程序包随应用提供，不依赖联网恢复。
- 插件数据全部属于全局，可以进入全量备份或独立插件使用数据包；人设资料包、人设完整包、会话包和用户设定包都不包含插件登记、授权、设置、存档、运行记录或插件账单。

进入插件开发阶段后，以下工程参数必须通过实现与安全测试定稿：

- 插件允许的资源格式、单包/解压/存档/网络响应大小限制、WebView 内容安全策略，以及 manifest、settings_schema 与桥接请求/响应的版本化 JSON Schema。SDK、模板与宿主共用，不能各自定义不兼容格式。

上述工程参数已在 13.5 固定于 7.1.2、plugins/sdk 的 Schema/类型和共用 Rust 校验器。JSON Schema 用于编辑辅助，安装仍以原生校验器为准。资源 fetch 只允许当前实例自己的包资源；直接外网、跨实例资源及主程序命令拒绝。原生 WebView 与真实迁移的实机验收仍待管理页面接入。

建立社区插件仓库时再确定正式名称、维护规则和 GitHub Actions 发布格式；这些发布流程不属于首版本地插件宿主的实现前提。

实施时按[实施接口与验收约定](实施接口与验收约定.md)第 4.6 节验证宿主身份、重复结算、权限撤销、插件更新与运行中导入的竞态。社区仓库尚未建立不阻塞首版本地插件机制。

## 自带经典游戏与管理界面

随源码清单提供六款：剪刀石头布、掷骰子比大小、接星星、我的家、扫雷、2048。当前源码扫雷及2048为1.0.2；其他插件版本见源码manifest和下方自带游戏说明，存档版本保持1。具体源码和复现入口见[自带游戏说明](../plugins/first-party/README.md)。

扫雷初级8×8／10雷，入场5币、胜利10币；中级16×16／40雷，20／40币；高级16×30／99雷，50／100币。首击安全，左键翻格、右键旗帜／问号／取消、双击数字按旗数展开，误标可踩雷。失败与放弃无奖励、不退入场费。

2048赚钱局花20币，按最终最高数字只结算一次：256得10、512得25、1024得50、2048及以上得200，不累加。允许达到2048后继续挑战或主动结束。无合法移动时自动结束，未到256无奖励。

两款各有独立的每日5次赚钱局额度，免费局不限次且无喵币变化。入场扣费和次数采用同一存档待核对流程，未结束棋盘逐步保存，关闭重开恢复、不重复扣费；余额不足或拒绝权限不消耗赚钱次数。沿用插件私有进度和日期规则，不新增宿主数据库额度表，清除插件数据的行为保持原协议。

管理入口位于全局设置。卡片按钮显示“打开”，详情中的运行历史、喵币账单默认折叠，每页5条；存档仅展示简短状态与最多3项玩家关心的指标，不向普通用户展示JSON封装、棋盘细节和结算请求。插件启用使用主题开关。

第三方作者可先保存实际进度，再通过既有 `storage.set("ui.summary", ...)` 提供版本1摘要，包含可选的saved／playing／completed状态与最多3项label／value文本。宿主统一排版，不渲染插件HTML，不增加权限、RPC、数据库字段或协议版本。无摘要或无效摘要回退默认显示，内置游戏保留原有进度解释；待核对结算状态优先。详见[SDK摘要约定](../plugins/sdk/README.md#管理页进度摘要可选)、`plugins/sdk/index.d.ts`的SaveSummary及`summary.schema.json`。

当前manifest仍指向颜喵主仓库与其Releases；不冒充已建立独立插件仓库。分发时应把实际`.yanmew-game`作为Release附件上传，GitHub自动生成的源码ZIP不是可安装插件包。独立仓库建立并发布后，再更新repository／release_page及重新打包。

## 经典游戏动效与帮助

扫雷胜利显示通关庆祝弹窗和短暂纸屑，踩雷显示失败反馈；帮助按钮打开原生模态教学，说明数字、左键、标旗/问号、双击、键盘、首击安全和赚钱规则。2048首次合成2048只庆祝，可以继续；无路可走时显示完成或失败反馈，仍按最高数字一次结算。用户主动结束未达目标时使用中性结果，展示层不扣币、不领奖。

2048先测量所有格子，再以完整方块图层沿transform移动180ms；旧位置显示中性棋格底板，不残留有色方块。存档与动画并行，提交完成后在同一显示阶段换成最终棋盘、清理移动图层，合并块轻弹、新块淡入；保留最后一次快速输入，弹窗期间不移动。动效统一缓动，支持prefers-reduced-motion，关闭动效仍能正常操作。

两款源码、共享展示资源及resources/plugins中的包同步到1.0.1，storage_version仍为1，保留旧存档与钱包规则。只更新这两款插件，其他四款不变。

## 窄窗与低高度布局（2026-10-27 源码）

共享窗口样式允许低高度下各子页滚动，操作区不被固定内容挤出；横向操作换行，选择弹窗限制在窗口内并可独立滚动。经典扫雷高级棋盘在窄窗保留可操作格子宽度，只让棋盘容器横向滚动，整页不横向溢出。2048及其他游戏控制区可换行。

“我的家”首页、田地、池塘、养殖、厨房、商城、仓库均适配窄/矮窗口。右上熟练度与喵币显示可悬停、可键盘聚焦的主题说明，名称明确。六个受影响插件递增补丁版本，storage_version保持1，玩法、数值、权限和存档不变；发布包须重新打包并校验。


## 我的家互动钓鱼（2026-10-27）

我的家1.0.4保持存档版本1、现有权限、鱼重范围与售价。熟练度30解锁，低/高级塘1/2喵币，每日20次、鱼竿80耐久和30币购竿规则不变。

抛竿先经既有钱包与存档流程保存入场费、当日次数、耐久及熟练度，再进入独立挑战。点按使鱼钩轻微上抬，按住持续抬升，松开自然下落；支持鼠标、触摸、空格和方向上键。鱼的活动区平滑随机移动，鱼越大活动区越短；鱼钩在区内增加收鱼进度，区外减少，攒满成功、耗尽失败。取消或关闭游戏保留本次消耗，不追加鱼获；不再额外随机判定逃跑。

成功后仅通过私有存档增加一次鱼获，出售仍走原钱包入口。保存失败可重试，不再次扣费；重复完成回调不重复加鱼。挑战过程只保存在内存，关闭后不恢复未完成挑战。模块不新增宿主API，不直接访问数据库，也不引入依赖。

独立响应式对话框限制在视口内，矮窗允许内部滚动，目标区和鱼钩以transform逐帧更新，收获结果在原水域内淡入以保持布局稳定；减少动态效果时取消装饰过渡，必要的游戏运动仍可操作。
