# 颜喵 Windows 安装与发布设计

> 当前实现基线（2026-11-09）：源码及备份v26，最新正式包20261109-143800为v26。本文中的阶段版本仅说明引入历史；实际交付范围与默认值见[当前实现与版本范围](当前实现与版本范围.md)。


日期：2026-11-09。适用版本：Windows x64首版。当前EXE与便携ZIP为20261109-143800、数据库v26，包含天气网格排版及此前预警等修复。资料已完整备份接续，ZIP不含个人data；未生成安装器，详见[发布记录](发布记录-20261109-143800.md)。

## 1. 两种发布形式

- 便携ZIP：完整解压后运行yanwenzi.exe，数据在exe旁data，资源在exe旁resources。保留现有发布流程。
- 安装包：使用Tauri 2的NSIS中文向导，安装当前用户版本，注册Windows卸载入口、开始菜单入口和可选桌面快捷方式。不是新增应用或另一套数据库。

安装版默认目录为`%LOCALAPPDATA%\Programs\YanMew`，可选择其他可写目录；默认不请求管理员权限。用户数据固定为当前用户已知文件夹`LocalAppData\YanMew\data`，包含数据库、背景/饰品图片、第三方插件程序、设置和存档及业务暂存。随包模型、第一方插件、运行DLL、许可证放在程序目录。资源路径与数据路径分别注入AppPaths，不再从安装版数据根推断程序资源。

安装包包含标记文件`yanmew-installed`，内容固定为`YanMew-installed-v1`。程序存在该有效标记时使用安装版数据根；没有标记时使用便携数据根。标记不可读或内容不支持时报告错误，不静默另建数据库。通过Windows已知文件夹API定位LocalAppData，不依赖启动工作目录，不把绝对目录保存到数据库或备份。

## 2. 安装流程

中文欢迎页→许可证→已有版本维护（仅检测到旧版时）→选择目录→快捷方式选项→安装→完成。开始菜单提供运行与卸载入口；桌面快捷方式默认勾选，可取消；完成页可选择立即启动。安装不自动开启开机自启，仍由现有设置管理。

安装包包含完整本地模型、六个第一方插件、运行DLL及许可文件。复用便携版的资源校验和组装服务，不复制开发数据、密钥、聊天、存档或开发工具。WebView2已安装时复用系统运行库，缺失时使用Tauri的下载引导进行补装；不承诺缺少该组件的电脑可以完全离线安装。应用卸载不移除系统共享WebView2或系统C++运行库。

应用正在运行时，安装和卸载提示用户先通过托盘或软件退出，再重试。安装器不强制杀进程，不在数据库仍使用时删除数据。

## 3. 升级和重新安装

新版本安装及同版本修复保留所有用户数据。更新程序、模型及第一方资源后，程序启动沿用既有数据库备份与迁移，不新增迁移或重置数据库。拒绝降级到旧版本。

必须区分安装器调用旧卸载程序与用户主动卸载：旧卸载程序收到`/UPDATE`时只替换程序资源，不清理用户数据、WebView缓存、快捷方式或自启。正常新版维护流程调用旧卸载程序时也明确追加该标记，不能只依赖自动更新模式。用户在同版本维护页选择“卸载”则属于主动卸载，应完整清空。

应用模式由标记判断，不能只通过命令行路径、是否位于Program Files或注册表里是否有同名项猜测。便携版与安装版的数据独立，通过既有备份导入转移；安装不自动搬走、覆盖或删除便携数据。

## 4. 主动卸载

卸载确认页明确写明：程序及全部人设、会话、聊天、记忆、喵币、设置、密钥、图片、插件和游戏存档将永久删除，无法恢复。不存在“保留数据”或“可选清空数据”选项。

主动卸载先确认应用已退出，再清理该安装版数据，随后移除程序文件、模型和插件资源、运行DLL、安装标记、快捷方式及卸载登记。清理路径固定在当前用户的`LocalAppData\YanMew\data`及该应用标识的框架缓存目录，不能从备份、插件或任意注册表值接收递归删除目标。数据目录清理失败时报告并停止，不宣称卸载成功。

现有开机自启项名为`YanMew`。只有值指向本次卸载的yanwenzi.exe时才删除对应Run项及StartupApproved/Run里的同名决定，不能按产品显示名删除或清空整个注册表键。升级不删除自启。

文件删除只处理安装器管理的文件和固定应用数据目录；用户自己放到安装目录的其他文件不递归清空。不删除另一个便携目录的数据，不删除用户导出到其他位置的备份。

## 5. 实现归属

- `platform/windows/paths.rs`：安装标记、已知文件夹及模式路径选择。
- `platform/contracts.rs`：AppPaths分别持有data_root和resource_root；业务继续接收平台提供的目录。
- `src-tauri/tauri.installer.conf.json`：独立NSIS配置，基础配置继续支持便携/no-bundle构建。
- `src-tauri/windows/installer.nsi`：基于当前Tauri CLI 2.11.4官方模板，定制上述页面、维护和退出行为。
- `src-tauri/windows/hooks.nsh`：安装版清理规则和卸载菜单；不承载聊天业务或SQL。
- `src-tauri/windows/yanmew-installed`：安装包专属模式标记，不进入便携包。
- `scripts/build-installer.ps1`：先复用便携组装，再用独立配置生成安装包、校验和及使用说明；生成的绝对资源映射只放本地发布目录。
- `scripts/build-portable.ps1`：保留原流程，提供PassThru输出供安装组装复用，不增加第二套资源复制逻辑。

官方模板来源固定为`https://github.com/tauri-apps/tauri/tree/tauri-cli-v2.11.4/crates/tauri-bundler/src/bundle/windows/nsis`。升级Tauri CLI后须重新核对维护参数和模板，不直接用dev分支模板覆盖。

## 6. 验收

定向验证模式标记、默认数据目录、改安装盘符后的资源定位及缺失目录失败，不执行无关全量测试。检查生成NSIS脚本的资源映射、更新参数、无保留数据复选框、中文文案和固定清理路径。

在独立Windows测试用户或隔离测试目录执行：首次安装、桌面与开始菜单启动、正常退出、同版本修复、升级保留数据库/存档、主动卸载清空数据和自启、卸载后重装恢复全新教程。不能用真实用户正在使用的数据做破坏性卸载验证。未实际执行的交互验收应记录为待测，不因为安装包生成成功就标记全部通过。

## 本机更新、数据接续与过期清理

本机交付不能只生成新目录而遗留用户旧资料。按本次要求构建EXE、完整便携ZIP或安装向导；安装向导生成对应卸载能力。分发ZIP/安装器始终不带个人data、聊天、密钥和存档。

1. 查明当前使用目录、程序是否退出、源数据库版本及基本记录统计；对旧data和目标已有资料先备份。运行中不复制或替换数据库，不强制杀进程。
2. 原便携目录更新时保留完整data，只替换程序资源；若生成新便携目录，先将旧完整data接入新版。目标已有真实新记录时不得直接覆盖，先与用户确定处理；只有初始化资料也先备份再替换。同机完整data接续保留受保护密钥，跨设备继续走既有逻辑备份协议。
3. 用新版正式启动入口执行内置一致性备份与数据库迁移，核对版本、完整性和旧记录是否保留。不手工临时改SQL，不只复制数据库而遗漏受管图片、插件及其他data文件。使用个人资料的正式程序须从用户正常运行环境启动，不继承构建工具的受限联网环境；受限环境中的DNS/连接失败不能直接判定为应用或提供商故障。数据库升级成功、资源初始化完成和实际联网业务成功应分别核对。
4. 新版及数据验证完成后，再清理已确认过期的EXE、ZIP、安装器、独立卸载构建产物及对应校验文件、安装资源清单。保留当前版本和数据备份，不把已安装软件的卸载入口当成构建垃圾，也不运行卸载程序来清理发布包。
5. 清理前逐一确认绝对路径位于指定旧发布/构建目录，按明确清单处理。Windows文件占用时保留旧数据与副本，待释放后继续。交付时说明新版路径、迁移结果以及未完成的安装/原生验收项目。

## 按data目录限制实例（增量J）

新版在打开SQLite和运行迁移前，先持有实际data/instance.lock的Windows文件写入权。相同目录再次启动仅唤出已有宠窗，不重建Runtime或重复启动后台任务；不同便携目录可独立同时运行，安装版仍固定自己的数据目录。锁文件可遗留，退出/崩溃由系统释放；不能用遗留PID或锁文件存在判断正在运行。启动尚未完成时第二进程短暂等待唤醒地址，无法唤出则明确失败，不另开同data实例。

旧构建没有此限制，不能追溯阻止已经运行的旧程序。更新程序仍先完全退出旧版，再保留/接续完整data；重新发布时沿用原构建与旧包清理规则，不修改安装/卸载数据策略。当前20261020-160457构建已包含J，旧094356目录已在完整备份、迁移核对后清理。
