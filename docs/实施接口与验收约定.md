## 1. 开发前需要具备什么

代码路径、模块责任、数据库写入归属和通信时序遵守[项目架构与代码职责](项目架构与代码职责.md)。本文件继续规定接口行为与验收，不用架构分层替代业务验证。

每个阶段先核对前置阶段产物，再实施、测试、联调，最后标记完成。后续阶段尚未提供的服务只能在测试中用替身，不向用户暴露“成功但没有实际效果”的按钮或工具。

每个功能交付须包含以下内容：

1. 输入字段、允许状态、返回结果及错误码；前端和 Rust 使用同一份契约。
2. 读取/修改的表、事务范围、版本校验和取消点。
3. 正常路径、重复操作、请求失败、应用重启、切换上下文的用例。
4. 所需资源、版本与打包路径；依赖模型或插件包的能力不能只在开发机验收。
5. 自动检查结果和涉及窗口/系统能力的人工记录。记录测试环境、操作、预期、实际结果；未做项写“未验证”。

schema 决定数据库字段与约束；专题文档决定业务规则；本文件决定实施接缝与验证方式。如果发现三者冲突，先解决文档冲突，不允许实现者挑选方便的一版。

## 2. 前后端接口约定

### 2.0 Windows 开机自启（Task 10.3）

- `get_autostart_status()` 和 `set_autostart({enabled:boolean})` 只允许 `settings` 窗口调用，返回 `{supported, enabled, needsRepair, blockedBySystem}` 四个布尔字段；其余窗口返回 `PERMISSION_DENIED`。非 Windows 查询返回 `supported=false`，设置返回 `UNSUPPORTED`，界面隐藏入口。
- `enabled` 仅在本应用有自启登记、命令精确匹配当前 exe 且未被 Windows 禁用时为 true。`needsRepair` 表示有登记但命令不匹配；`blockedBySystem` 表示有登记且 Windows 禁用。开关表达是否保留登记，状态文案必须区分这三种情况。
- 固定登记名 `YanMew`，位于当前用户 `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Run`；只读对应的 `Explorer\StartupApproved\Run` 标记。插件与 Windows API 限于桌面适配，不新增设置键，不进入备份。未来修改应用名不改登记名。
- 启用通过锁定插件写入，再将本应用命令改为带引号的当前 exe 完整路径（无额外启动参数），防止含空格目录失效。关闭仅删除本应用的 Run 登记。系统禁用时启用请求返回实际禁用状态并提示用户到系统设置恢复，不假报成功。关闭后再次明确开启属于新登记。
- 查询/设置在后台阻塞线程执行并串行；不自动登记、不自动修复、不申请管理员提权。任一步读写或校验失败返回 `AUTOSTART_ERROR` 和中文说明。设置后重新读取，结果不符不报成功；失败可能有部分系统变化，前端必须补查而不能回退假定旧值。
- 前端通过现有 `api.ts` 包装命令；无 JS 插件依赖，不给 main/chat/memory/小游戏授予 `autostart:*` capabilities。页面初始化及 focus 补查，读写忙时禁用操作，旧响应/卸载回执不得覆盖当前状态。
- 默认种子“电子小猫”在现有初始化事务中保证唯一；缺失补齐，已有活动普通人设不切换；多个内置项报错回滚。旧默认名称及提示词仅在值仍为旧种子原文时更新，用户改过的值保留。删除保护、当前非内置删除后的回退复用统一人设服务；未来导入副本不能携带内置身份。
- 自动验证覆盖状态/路径/权限判断、初始化种子和前端失败竞态；Windows 登录启动、真实目录移动与系统策略必须人工验收，未实测不得标记通过。

### 2.0.1 宠窗位置记忆（Task 10.5 已接通）

- 复用 `set_pet_dragging({dragging:boolean})`，仅 `main` 宠窗可调用；不新增前端坐标上传接口，不将坐标加入公开 `save_settings` 白名单。`config.rs` 内部读取/保存 `window_pos_x`、`window_pos_y`，两键以规范的带符号 i32 十进制字符串存储，同一 SQLite 事务更新；无初始行，不新增表、列或迁移。
- 首次或位置无效时，读取当前显示器工作区与实际窗口物理尺寸，放在工作区右下角；无当前显示器时优先主屏。合法保存位置与任一工作区相交时，选择交集最大的工作区并将窗口移回其中；完全不可见时回到默认位置。工作区小于窗口时放在其左上角。缺失、残缺、非整数、越界或非规范数值均视为无保存位置，保留原数据，不使其他设置读取失败。
- 拖动开始前读取原生起点；仅拖动期间的原生 `Moved` 记录待保存位置，250ms 节流写入，拖动结束再次读取最终位置并补存。同一写入锁保证写入顺序，保存期间发生的新移动不能被旧回执清除。不在位置状态锁内等待 SQLite，不为宠窗内部颜文字移动保存窗口坐标。
- 退出请求和退出事件停止接收新移动并补存最新待保存位置。保存失败保留待保存值，后续移动、结束或退出可重试；x/y 不允许部分提交。强制结束进程无法保证尚未落盘的最后一次移动。
- 启动恢复、重新显示、非拖动的窗口移动、尺寸/DPI 变化及重新获得焦点时按需要校正可见性；系统恢复和临时校正不写回首选位置。拖动期间不强制拉回窗口。最小化时不校正或记录 Windows 临时坐标，恢复后由窗口事件再次检查。
- 位置或存储失败使用现有 `pet-activity-error` 报告中文说明，并记日志；不将提供商标为失效，不触发桌宠休眠，不修改聊天和记忆。启动期事件未被前端监听时，以日志为准。
- 已有定向验证：5 项坐标存储用例、4 项工作区几何/待保存状态用例、1 项真实 SQLite 写入失败及退出重试用例；开发版构建通过。真实首次位置、拖动后重启、负坐标副屏、125%/150% 缩放、拔除副屏、任务栏位置变化、最小化与托盘恢复尚待人工验收，未实测不得标记完成。

### 2.0.2 用户设定与会话绑定（Task 10.6 已接通）

- `list_user_profiles() -> UserProfile[]`；`create_user_profile({name,content}) -> UserProfile`；`update_user_profile({id,name,content}) -> UserProfile`；`delete_user_profile({id}) -> void`。资料是全局数据，不接受人设归属参数；仍使用现有主程序窗口权限，插件不得调用。UserProfile 为 `{id,name,content,createdAt,updatedAt}`，ID 为正整数字符串。
- 两字段 trim 后非空；无手动正文长度硬限。校验失败返回带字段的 `VALIDATION_ERROR`，不存在返回 `NOT_FOUND`。公开命令复用 Runtime 短操作和现有数据库连接，不新增表、迁移或依赖。
- `create_session({personaId,contextRevision,userProfileId:null|string}) -> Session`：新建时可选绑定，在创建事务内验证设定存在；无效引用不会创建或切换会话。仓储保留既有无绑定创建函数，新增可选绑定入口。
- `set_session_user_profile({personaId,sessionId,contextRevision,userProfileId:null|string}) -> Session`：必须属于当前有效人设和会话；解除绑定为 null。过期目标返回 `CONTEXT_CHANGED`，无效资料返回 `NOT_FOUND`。校验及无变化判断先于取消。
- `set_session_pinned({personaId,sessionId,contextRevision,isPinned:boolean}) -> Session`：目标必须归属当前有效人设，校验当前上下文版本后在事务内更新目标is_pinned；支持非当前会话。Session DTO新增isPinned布尔值，列表按is_pinned DESC、updated_at DESC、id DESC排序。不改更新时间、当前选择、memory_revision或contextRevision，不取消请求，仅广播configuration_changed。用户可在侧栏右键取消置顶。
- 侧栏右键重命名和删除继续复用原命令，传点中的sessionId，不先切换；删除确认保存打开时的当前上下文与目标ID两份信息。仅目标为当前会话时调用当前取消入口；非当前删除保持聊天和记忆。确认上下文失效则关闭，写入失败保留目标/草稿及局部错误。
- 侧栏底部会话设置打开dialog、用户设定打开原卡片选择弹窗，设置/记事本使用现有导航窗口。紧凑轨道宽48，展开236；小于680宽为可收起抽屉；列表内部滚动，不挤掉底部操作。
- 编辑/删除设定或修改绑定时，在同一 store 锁内只取消受影响会话的 `chat:{sessionId}`。普通回复同步用原回合服务保存已有片段为 `interrupted/user_cancelled`，不增加完整回合奖励或短期记忆；重说只取消预览，原回复和记忆保留。取消信号阻止迟到正文、工具写入及重说替换，租约由原聊天工作器释放，不等待网络退出才保存资料。
- 若中断失败，不继续变更资料；若中断已成功但后续资料写入失败，中断不恢复，原资料/绑定保留，返回真实存储错误并允许重试。资料结果与需补查的会话 ID 分开返回给 commands；即使资料写入失败，仍通知补查已保存中断。无引用资料变更不影响当前聊天，无变化不取消。
- 删除依靠外键 `ON DELETE SET NULL` 解除全部引用，保留会话和历史。绑定正文仍由既有 `chat/context.rs` 完整读取，不新增拼装器，不重写已有记忆。绑定本身不改变选中会话、contextRevision、桌宠状态、旅行或回信；实际中断的内容版本依原回合事务递增。
- 提交或已保存中断后发 `configuration_changed`；按受影响会话发 `chat-messages-changed`。窗口先订阅再查询，聚焦补查；前端不能以通知失败回滚已提交数据。SettingsPage/UserProfilePanel 管理资料，ChatPage 提供新建选择和修改绑定，useCurrentContext 组合统一快照。
- 自动验证：仓储/引用 3 项、运行时/完整上下文 7 项 Rust 用例通过；当前相关前端 46 项及开发版构建通过。实际 Windows 双窗口变更、重说取消、重启恢复、窄窗口和 DPI 尚待人工验收。

### 2.0.3 人设聊天背景（Task 12.4 已接通）

- `get_chat_background({id, contextRevision})`：返回`{record:{personaId,file,opacity,blur,appearance},imageDataUrl,imageError}`；appearance为`{bubbleStyle,userTextColor,assistantTextColor}`，bubbleStyle枚举solid/transparent/outline/frosted，颜色为NULL或#RRGGBB，默认solid/NULL/NULL。file只为受管相对文件名；无图时URL和错误均为空。图片缺失/损坏时保留record（包括样式）、URL为空、提供局部imageError，允许恢复默认，不使桌宠休眠。
- `save_chat_background({id, contextRevision, input})`：input为`{expected,opacity,blur,image,reset,appearance?}`；expected是读取到的完整record（包含appearance），所有字段参与冲突校验。image为空或`{fileName,base64}`；返回已保存record。reset=true不允许携带image，并清空文件、恢复85/0；appearance未提交时保留原样式，提交时校验枚举/颜色并同事务更新。前端恢复背景时不提交appearance；普通保存提交完整样式，image=null保留旧文件。样式不接受任意CSS或HTML。
- 仅 settings/chat 窗口可调用。settings 可操作任意现存人设且版本参数忽略；chat 必须提供有效 contextRevision、id 为当前人设，切换后旧读取/提交返回 CONTEXT_CHANGED。插件、宠窗及其他窗口均拒绝调用。
- jpg/jpeg/png/webp、最大 10MiB（界面显示 10MB）。Rust 限制 Base64 长度、解码字节数，校验真实格式匹配扩展名并完整解码；用户路径不得作为 fileName。使用批准的 image 0.25.10，仅启用 jpeg/png/webp，保留默认解码资源限制。
- 文件操作在后台执行器完成，耗时读取/解码释放数据库锁；提交前锁内重核 expected 与版本，冲突返回 CONFLICT。唯一文件完整写入并 sync_all 后才提交引用，失败保留旧数据，清理本次无人引用的新文件；提交成功才清理无人引用的旧图。启动清理程序生成的孤立图，其他用户文件不处理。
- 成功保存只发 configuration_changed，不改变 contextRevision，不取消聊天，不改人设正文和自调时间。聊天页沿用 useCurrentContext 的原位刷新，不通过 onRefresh 重建。设置表单有草稿时收到冲突配置则要求用户明确重新读取，不静默丢弃。
- 自动验证覆盖三种真实图片、假扩展名/坏文件/路径/超限、提交失败、旧快照/切换、重启持久化、共享引用、默认恢复、局部错误及回复中保存；原生亮暗主题、缩放与多窗口视觉验收待完成。

### 2.0.4 钱包与亲密度查询（Task 13.1 已接通）

- `get_wallet()` 返回 `{coins:string,updatedAt:string}`，只读全局 id=1 钱包。余额用十进制字符串避免 SQLite i64 到 JavaScript number 的精度丢失；前端只展示，不进行钱包运算。未初始化报告 WALLET_UNAVAILABLE，不自动创建或清空。
- `get_session_intimacy({personaId,sessionId,contextRevision})` 返回 `{personaId,sessionId,contextRevision,intimacy,maximum:999}`。后台同锁校验当前人设、当前会话、版本和归属，旧选择返回 CONTEXT_CHANGED；不结算计时、不奖励、不增加版本。没有会话时不调用。
- 两命令复用应用窗口白名单和 storage 后台数据库入口；插件不能直接调用。前端 walletApi 只提供上述读取，不暴露 apply_delta。
- 后端 `apply_delta` 独立 IMMEDIATE 事务；`apply_delta_in_tx(&mut tx, change, now)` 接受调用方事务，保存点仅保护余额/账单，不提交父事务。余额 checked_add、非负检查、账单字段验证和写入共同成功；错误须由业务入口处理，关联业务失败应回滚父事务，成功通知必须在父事务提交后发出。
- 五种 reason 与 schema 一致。签到无 ref_id、制作/卖出必须正整数饰品历史引用；插件完整快照须来自可信宿主。该函数不代替插件授权、业务资格或请求幂等；13.4 必须先验证并查询重复请求，再调用记账，重复一致请求返回旧账单而不是再次写入。零价/零奖励/平局保留 0 流水。
- `count_today_reason` 接受固定 now 和 TimeZone；正式入口使用电脑当前时区，UTC 候选经本地日期过滤。签到在一个业务事务中同时查 daily_sign_in 和 sign_in_festival，避免不同原因各签一次；奖励规则由 13.3/18 接入。
- 数据服务专项验证包含 13 项 Rust 与 1 项前端查询。设置 → 桌宠状态与普通签到已由 Task 13.3 接通，契约见下节；插件桥接与账单列表已由13.4–13.6接通，逐来源授权与钱包幂等验收见4.6；通用记账函数本身不代替插件权限检查。

### 2.0.5 全局每日签到与状态页面（Task 13.2/13.3 已完成）

- `get_sign_in_status()` → `{wallet:Wallet,localDate:string,signedIn:boolean,rewardMin:string,rewardMax:string,intimacyThresholds:[number,number,number,number],festivals:[{id:string,scope:"catalog"|"session",name:string,blessing:string,isMemorial:boolean}]}`。localDate 为后端按电脑当前时区计算的 `YYYY-MM-DD`；纯读取不发奖。奖励上下限来自已有 sign_in 设置，档位来自 intimacy_threshold_1–4，不新增持久化副本。
- `daily_sign_in()` → `{status:SignInStatus,grantedCoins:string|null}`，只允许设置窗口调用，无入参，不接受前端日期、数量、会话或插件身份。grantedCoins=null 表示同日已经领过；"0" 表示本次成功领取 0，仍消耗本日资格。无当前会话、无可用提供商均可签到。
- Runtime 持有数据库锁后采样时钟，再使用当前系统时区。IMMEDIATE 事务内同时查普通/节日签到流水；未领取时按全局上下限均包含的范围抽数（默认 1–10），通过已有 apply_delta_in_tx 保存余额和 daily_sign_in 流水，整体成功后返回。已有领取则返回最新快照不写账、不再次抽数。无签到表、无额外迁移。18.4已在此事务内接入当天系统母表及全局自定义日期查询，命中任意记录则固定10、原因sign_in_festival且不调用随机源；多个命中只写一条账单，festivals合并返回所有祝福。不命中沿用普通范围，不在普通签到后另发节日币。
- 余额/账单写入失败、COIN_OVERFLOW、无效设置或 RANDOM_SOURCE_ERROR 不消耗本日资格；返回中文局部错误，不触发桌宠休眠。用户可重试，已成功但响应丢失的请求重试会返回已领取。多连接由 SQLite 写锁串行去重。
- 新签到提交后发送空载荷 `wallet_changed`（0 奖励也发）；重复签到不发。接收端重新读取权威余额；事件失败不撤销已提交签到，聚焦/重开页补查。
- 桌宠状态页显示当前会话亲密度及生活状态；全局喵币与签到使用独立全局入口。亲密度查询必须携带固定上下文并丢弃旧结果，999 显示上限、下一档位单独显示。无会话不发送空 ID 查询。余额按十进制字符串完整展示，签到过程中禁用按钮、不提前加余额。
- 页面监听钱包/配置/日期变动、当前会话互动、聊天完成及消息变化；窗口聚焦补读。午夜及至多一分钟检查只触发只读查询，后端返回的日期和 signedIn 是最终依据，不能由 JS 时间自动发奖。卸载清理监听/定时器，提交前发起的旧查询不能覆盖签到结果。日切换只恢复领取按钮，不补发过去日期奖励。

### 2.2 两类版本不能混用

- contextRevision：当前窗口上下文的运行期版本。切换人设/会话、删除当前项、导入使当前项变化时递增，防止旧窗口响应进入新页面。
- `sessions.memory_revision`：数据库内的会话内容版本。消息、回合、记忆写入与删除在事务内递增，用于拒绝过期生成结果。拒绝只解决旧结果污染，不能替代补偿：工作器必须立即按最新内容重排，启动时还要扫描 `completed` 且缺少短期记忆的回合；长期整合冲突则保持来源为 `pending`。
- 长任务保存目标 ID 与相应快照；完成时重验，不重新取“此刻当前会话”后把旧结果写进去。
- 不相关的其他会话变化不使本会话任务失效；本会话版本变化导致结果被丢弃后，仍未完成的后台任务需重新读取并排队，不能永久遗漏。

### 2.2.2 历史消息操作（Task 10.2 已接通）

- `update_chat_message({context,messageId,expectedContent,content}) -> Message`：context 同 ChatContextInput，ID 为十进制字符串；目标属当前会话，旧正文与 expectedContent 不同返回 MESSAGE_CONFLICT，空正文 VALIDATION_ERROR。聊天请求活动时 REQUEST_BUSY，不隐式取消。只更新原文与 memory_revision；已有记忆不联动，缺失短期后续用新原文；编辑 length_limit 回合改为 user_cancelled，取消原前缀续写资格。

### 2.3 聊天请求与事件

1. 发送入口只接收本次输入与目标上下文，不信任前端上传的人设、历史和记忆。
2. Rust 验证可聊天、提供商可用、同会话没有运行请求；建立 requestId，在事务中建立 pending 回合并保存用户消息。
3. 返回包含 requestId、sessionId、roundId 的回执；事件统一携带这些字段、单调递增 seq、type 和对应 payload。前端先订阅再发送；回执到达前暂存关联事件，不能因时序丢首段正文。
4. 表情、正文增量和终态均属于同一请求。完成与取消使用同一终态控制：一次请求最多提交一次 completed 或 interrupted，不允许完成和取消各插入一条回复。
5. 正常完成先提交数据库，再发完成事件。中断保存已收到的部分正文一次；无正文不插空 AI 消息。长度截断或异常断流不能误记为完整回合。
6. 前端刷新、关闭窗口或丢事件后，从后端查询当前请求和已保存消息恢复；事件不是历史记录。应用被强制终止时未落盘的流式片段不保证恢复，界面不得把它们标为已保存。
7. 启动时没有运行请求与之对应的 pending 回合转为 interrupted；保留已落盘消息，不自动重发、不生成短期记忆。
8. 中断已完成请求应返回其终态，不重复写入；取消后迟到的模型输出不能恢复已删除回合。

涉及钱包或其他副作用的工具不能因重新连接、重说或重放事件再次执行。工具循环检查取消信号、轮数上限和目标归属；只读回忆与写入记事本等能力也受同一上限约束。

`read_notebook` 与 `update_notebook` 的结果统一携带 `limit_chars`、`current_chars`、`remaining_chars` 和 `over_limit`；默认建议上限为 4000 个 Unicode 字符。该值是 AI 维护软限制：更新不得截断、丢弃或仅保存部分正文，超限结果仍完整提交并返回 `over_limit=true`，后续工具提示要求 AI 先合并重复内容和精简旧段落。用户手动编辑或导入的超限内容同样可读取和保存。

#### 阶段 3 已实现的传输边界

`chat.rs` 保留内部生成服务；`chat/coordinator.rs` 已接入阶段 5 仓储，提供阶段 8.4 的统一提交与持久化。内部生成终态不能直接作为已保存回执；对外 `chat-reply` 事件在终态事务成功后才携带 `saved`。

阶段 8.4 已实现接口：

- `submit_chat({personaId, sessionId, contextRevision, input})`：Rust 分配 requestId；在数据库锁内校验当前上下文、旅行/休眠、提供商和互斥，读取人设与最近消息快照，再建立 pending 回合。返回 `ChatRequestSnapshot`，包含 requestId、personaId、sessionId、contextRevision、roundId、seq、partialContent、expression、round；初始 round 中只有已保存的用户消息。前端不传任意角色或整份上下文。
- `get_chat_request({personaId, sessionId, contextRevision})`：返回当前活动请求快照或 null；partialContent 是未落盘流式片段，不能标为已保存。终态后通过消息查询恢复历史。
- `cancel_chat({personaId, sessionId, requestId, roundId})`：仅取消身份和回合都匹配的活动请求，返回数据库回合快照；返回 pending 表示取消已发出但尚未收束，窗口等待终态事件或重新查询。已结束回合直接返回 completed/interrupted，不重复写消息。旧请求 ID 不能取消后来的请求。
- `chat-reply`：携带 requestId、personaId、sessionId、contextRevision、roundId、seq，type 为 expression/text/finished/cancelled/failed；增量的 saved=null，成功保存终态后 saved 为 RoundSnapshot。finished 的 length/content_filter 仍保存为 interrupted，不能按事件名称判断完整；持久化错误发送 failed 且 saved=null。显示状态以 saved.round.status 为准。
- 窗口先订阅再查询/提交，按请求与上下文过滤、按 seq 去重；回执到达前暂存事件，发现序号缺口重新查询活动快照。Task 8.5 已接入页面发送、流式展示和暂停；发送失败保留草稿。
- 关闭聊天窗及正常退出会同步收束已收到片段；后续网络终态复用幂等回合保存，不重复插入。强制结束进程只保证此前已提交数据，启动复用 pending 恢复逻辑。

当前生成已在 9.6 接入完整会话上下文、混合 RAG 和有限回忆工具；9.3 的短期记忆调度沿用完整回复保存后的入口。9.7 管理小窗已接通，9.8 已接通完整回合一次性亲密度及流式异常守卫，仍使用同一协调流程。正常完成只在 pending 首次转为 completed 时与消息/回合/memory_revision 同事务奖励 +1，复用 `pet::rewarded_intimacy` 封顶 999；重复完成及中断不加，成功提交后才唤醒记忆任务。

默认首个有效响应 30 秒、有效进展间隔 30 秒，整轮聊天总时长 300 秒，包含表情、检索及工具。仅正文、字符串 `reasoning_content` / `reasoning` 或工具参数的非空增量推进，心跳、role 和空 delta 不推进；推理不展示、不落库、不备份；服务返回的 `reasoning_content` 仅在本轮内存中用于工具协议续请求，原样回传。DeepSeek 官方工具请求为无推理的历史 assistant 显式补空串，其他服务保持原消息扩展边界，不关闭思考模式。`CHAT_REPETITION` 映射 repetition，`CHAT_INVALID_ENCODING` 映射 invalid_encoding，`CHAT_NO_PROGRESS` / `CHAT_FIRST_RESPONSE_TIMEOUT` / `CHAT_TOTAL_TIMEOUT` 映射 timeout，`CHAT_TOOL_NO_PROGRESS` 映射 tool_limit。错误经原取消信号和唯一终态保存部分正文及原因，不进入提供商休眠，不生成本轮记忆或奖励；已成功工具操作保留。文本/工具守卫的局部阈值与保守范围见记忆设计 6.5，不新增设置或迁移。

#### 阶段 6.2 已实现的聊天提醒处理器

`reminder_extract.rs` 提供 `create_reminder` 的工具定义、当前本地时间提示和真实写入处理器。不另发一次 AI 提取请求，不通过前端扫描消息猜测提醒，也不注册绕过聊天请求校验的工具执行 command。Task 9.2 已向普通聊天模型开放，保存后发送既有 reminders-changed 通知。

参数固定为 `name`、`content`、`fireAt`、`schedule`，四个字段均须存在。名称和详情不能为空白，不允许附带人设 ID、会话 ID、来源、规则 ID 或后端日历游标：

- 一次性：`{"name":"复诊","content":"带检查报告","fireAt":"2030-10-02T09:00:00+08:00","schedule":null}`。日期必须有效、包含时区且在执行时仍属于未来。
- 每天：`{"name":"喝水","content":"喝一杯水","fireAt":null,"schedule":{"version":1,"repeat":"daily","time":"09:00"}}`。
- 每周：schedule 使用 `repeat="weekly"` 并填写非空、无重复的 `weekdays`（1=周一，7=周日）。
- 每月：schedule 使用 `repeat="monthly"` 并填写非空、无重复的 `days`（1–31）。日期、时区及夏令时计算全部复用提醒规则服务。

循环不接受非空 fireAt；一次性不接受空时间。缺少明确时间时模型应询问用户，后端返回 `VALIDATION_ERROR` 且不创建记录；格式校验不能证明模型正确理解自然语言，真实供应商的语言理解仍需聊天联调验收。

执行上下文由 Rust 固定：原请求凭据、persona/session/context revision 和取消信号。每次写入在同一存储锁内检查该凭据属于当前 runtime 的活动聊天请求、目标会话仍为当前项且没有出门，再调用 `reminders::save_rule`，固定 `source=chat`。不持有数据库锁等待模型响应。

成功结果为 `{requestId, toolCallId, reminder, alreadyApplied}`，`reminder` 是已提交记录，ID 为字符串。提交成功后才发 `reminders-changed`。错误沿用 `{code,message,field?}`；日期/参数错误用 `VALIDATION_ERROR`，旧作用域用 `CONTEXT_CHANGED`，取消用 `CANCELLED`，存储失败用 `STORAGE_ERROR`。不能把失败结果叙述成“已创建”。

每个普通聊天请求只创建一个 `ReminderCreation`，跨工具轮保留；处理器持有同一请求凭据，可交给后台阻塞执行器。同一 toolCallId 与相同参数重试只返回本请求首次提交结果，`alreadyApplied=true`；同 ID 参数不同返回 `TOOL_CALL_CONFLICT`，不再次写入。失败未提交时可以重试。重说不注册此写入工具，正文中断不撤销已提交提醒。进程重启不恢复并重放旧工具请求；当前去重记录仅服务活动请求，不宣称跨请求或跨重启的通用幂等账本。

验证覆盖现有 SSE 解析器到提醒保存的假服务链路，不消耗真实 API 配额。设置页和 9.2 工具循环已接入同一提醒服务；真实模型的自然语言理解仍需人工验收。

#### 阶段 9.2 记事本、游记查询与聊天工具循环

`notebook.rs` 保存会话记事本全文；`notebook_tools.rs` 提供 `read_notebook` / `update_notebook` 定义和请求级处理器，已接入 `chat/tools.rs` 的聊天工具循环，不注册通用前端工具执行命令。

- `read_notebook` 参数为 `{}`，返回完整 content、从 1 开始的 sections，以及 `limit_chars/current_chars/remaining_chars/over_limit`。剩余建议字数最小为 0，字数按 Unicode 字符计算。
- `update_notebook` 必须包含 `operation/section_index/content`：append 使用空编号及非空正文，replace 使用有效编号及非空正文，delete 使用有效编号及 null 正文。拒绝其他字段，特别是模型指定的 session_id。
- 修改前先读取；后端保留读取快照，事务内比较旧正文与更新时间。其他操作已改动时返回 `NOTEBOOK_CONFLICT`，需要重新读取。索引无效、参数错误、上下文过期或取消均不写入。
- 段落以空行分隔，兼容 CRLF 和含空格的空行；单换行属于段落正文。未修改段落和分隔符保留，不对整份内容进行无提示格式化。每次成功返回新的编号。
- 同一请求重复成功写调用只返回原回执；同一调用 ID 换参数或换工具名拒绝执行。只读调用可以重新读取最新状态。请求处理器绑定后台的 persona/session/contextRevision 和租约，切换会话、取消或出门后不能继续操作。
- 超限完整提交并返回标记，写工具说明集中要求后续整理；已提交改动不因聊天正文中断回滚。

公共工具循环与只读游记接口：

- 主模型请求注册实际已实现的记事本、提醒和游记工具。同一工具轮含多个调用时顺序执行，整轮只占 `tool_call_rounds` 的一次额度；默认30，可在全局通用设置调整。到达额度后再发一次不携带 tools 的正文收束请求；模型仍要求工具时返回 `TOOL_LIMIT_REACHED`，回合为 interrupted，不能伪造操作成功。
- assistant 的 tool_calls 使用 OpenAI-compatible 结构，arguments 为 JSON 字符串；每个结果使用 role=tool 和对应 tool_call_id，正文为 `{ok:true,result:...}` 或 `{ok:false,error:{code,message,...}}`。未知工具、非法参数和业务冲突作为失败结果交给模型；取消或上下文改变直接停止循环。
- 同一请求的处理器跨轮保存，成功写调用按 ID 去重；同一 ID 换名称或参数返回冲突。网络层不自动重试。中间自然语言与最终回复一起保存，工具协议消息只留在本次请求中，不伪装成用户聊天消息。
- `list_travel_journals({limit?,offset?})`：默认 limit=20、offset=0，limit 为 1–50；按 created_at、id 降序返回 journal_id、title、created_at，不携带正文。
- `search_travel_journals({query,limit?,offset?})`：非空关键词最多 200 个 Unicode 字符，匹配标题或正文中的原样子串；分页规则相同。关键词不是 SQL 表达式或通配符。
- `open_travel_journal({journal_id})`：ID 为正整数十进制字符串，返回当前会话该游记完整标题、正文及时间；不存在、已删除或属于其他会话均返回 NOT_FOUND。只读工具不创建旅行、游记或记忆，列表为空就返回空数组。
- 所有查询由后端固定会话作用域，每次读取前检查活动请求、取消信号和当前上下文。参数中不允许 session_id、SQL 或路径。

记事本管理接口与窗口：

- `get_notebook({personaId,sessionId,contextRevision})` 返回 `{notebook,limitChars}`；notebook 为 null 或 `{sessionId,content,updatedAt}`。
- `save_notebook({personaId,sessionId,contextRevision,expected,content})` 使用读取时完整快照 expected 比较保存，空正文与超限正文均允许；旧快照返回 NOTEBOOK_CONFLICT，不覆盖新内容。上下文变化返回 CONTEXT_CHANGED。
- 用户保存及 AI 更新成功后发送 notebook-changed 查询通知。记事本窗先订阅再读取，聚焦时补查；编辑中的草稿不被后台刷新覆盖。冲突保留草稿，用户明确重新加载最新内容后再编辑。计数使用 Unicode 字符，与 Rust 一致。
- 聊天窗“查看记事本”打开 memory 窗口，重复点击聚焦已有窗口，当前已展示记事本和 Task 9.7 短期/长期管理页签。关闭只关闭该窗口，切换人设或会话重新读取目标上下文。

#### Task 9.7 记忆管理命令

这些命令只向授权主程序窗口开放；`context={personaId,sessionId,contextRevision}` 中 sessionId 必须是当前非空会话，ID 都使用十进制字符串。前端不上传 SQL、提供商或任意来源。

- `list_memories({context,kind,afterId?,limit?}) -> MemoryPage`：kind 为 `short/long`，默认每页 30、范围 1–100；返回 `{items,nextAfterId}`。按短期 roundId / 长期 activatedByRoundId 降序，afterId 是上页最后记录 ID，后端校验归属并推导排序游标。
- `get_memory({context,kind,id}) -> MemoryDetail`：返回目标、会话内容版本、来源和关联长期；无权读取的 ID 返回 NOT_FOUND。
- `save_memory({context,expected,title,content}) -> MemoryDetail`：expected 为上次读取的完整详情。事务内比较目标、来源及 memoryRevision；不一致返回 MEMORY_CONFLICT，草稿由前端保留。短期 title=null；长期标题非空单行，正文非空；手动内容不受生成字数范围限制，不截断。
- `preview_memory({context,kind,id}) -> MemoryPreview`：返回 `{previewId,detail,title,content}`，只生成可编辑预览、不保存记忆。同 Runtime 只有一个预览生成请求；REQUEST_BUSY 不创建并发任务。有效记忆提供商及生成字数校验复用已有实现，不设另一种 AI 引擎。
- `confirm_memory_preview({context,previewId,title,content}) -> MemoryDetail`：只依据后端保存的预览快照核验原文、来源、配置及 memoryRevision，再原位覆盖。失效返回 MEMORY_PREVIEW_EXPIRED；成功消耗预览，重复确认拒绝。人工修改可超过字数范围，原 ID、来源、创建时间和触发回合不变。
- `cancel_memory_preview({context}) -> void`：取消未完成生成并丢弃未确认预览；不改数据库。原生 memory 窗口关闭及上下文切换也走此取消路径，不依赖前端一定执行卸载回调。
- 成功保存/确认后广播已有 `memory-generation-changed`；长期改动另发 `embedding-state-changed`。失败不广播保存成功，不使桌宠休眠。先订阅再查，焦点补查、请求代次与上下文核对沿用现有页面规范。

DTO：

- `MemoryRecord`：`id/sessionId/kind/roundId/integrationState/title/content/sourceCount/activatedByRoundId/coveredThroughRoundId/coveredThroughMessageId/createdAt/updatedAt`。短期无标题、来源数量及长期边界；长期无 roundId/integrationState，相应值为 null。覆盖末轮和消息由最大 source_order 的短期来源与其原 AI 消息推导。
- `MemorySource`：`shortMemoryId/roundId/sourceOrder/content/updatedAt`，按 sourceOrder 正序。
- `MemoryDetail`：`record/memoryRevision/sources/relatedLongMemories`；relatedLongMemories 为 `{id,title}[]`。长期 sources 包含全部原始来源，短期 sources 为空、通过关联长期提供按需重新整合入口。
- `MemoryPage`：`items/nextAfterId`，无下一页时游标为 null。
- `MemoryPreview`：`previewId/detail/title/content`；detail 是生成时基线，界面不得用更早详情代替。预览对比旧新内容，确认/取消始终可见；关闭或放弃不保存。

## 3. 启动、退出与恢复顺序

平台接缝遵守《项目架构与代码职责》第 5.1.1、7.4 和 9.1 节：共享服务不接收窗口或 Activity，原生入口与 Tauri commands 共用 runtime 和事务；界面先查询实际能力，后端每次重新校验。Windows 首版用假平台验收以下边界，Android 原生能力以后单独验证：

- 主窗口与悬浮服务重复连接只初始化一个 runtime；初始化完成前不接受业务写入，不重复迁移、调度或结算。
- 暂停不等于切换会话。没有运行许可的时间不累计旅行有效在线秒数；已出发旅行按 UTC 恢复，先返回再检查回信。
- 重复恢复、权限撤销、时钟跳变及无退出回调的进程终止均有用例；未完成聊天不自动重发，副作用不重放。
- 平台能力区分“不支持/待授权/可用/资源缺失”；系统授权不能由跨设备备份赋予。Windows 窗口关闭与 Android 页面返回由各自外壳处理，共享页面不直接操纵原生窗口。
- Android 系统服务、通知精度、文件 URI、Keystore 和模型 ABI 在后续专项验收后才算支持。

启动依次执行：

1. 检查数据目录，打开数据库，开启外键，执行已支持迁移和幂等种子；失败停止业务调度。
2. 校验当前提供商、人设与会话引用，恢复唯一当前上下文。
3. 将无运行请求的 pending 回合收束为 interrupted；不伪造成功回复。
4. 恢复旅行状态：到期先返回，取消对应待回信，然后才处理仍有效的回信；cancelled 任务不恢复。
5. 提醒离线补偿与在线循环串行交接，先恢复已有 queued/missed，再启动普通调度，避免重入。
6. 开启窗口查询和事件服务；后台恢复缺失短期记忆、长期整合、有效旅行生成和失效向量。按目标去重，同一任务不能被多个入口并发提交。

正常退出先阻止新任务、取消活动请求，短事务保存允许保存的回合终态及当前会话在线累计，再释放窗口和数据库。强制终止按启动恢复路径处理，不承诺补回未落盘数据。

后台 AI/网络工作始终在事务外；重试读取保存的目标与状态，不重新抽旅行奖励类型、回信期限等已经确定的随机值。结果与对应 done 状态必须在同一事务落盘。

### 4.2.1 阶段 7：天气与定位接口

阶段 7 天气后端接口已实现，阶段 8 设置页面已接入；Task 9.6 已消费缓存作为聊天环境资料：

- `get_weather()`：只读取运行期缓存，不申请定位、不联网；返回当前 `contextRevision`。
- `refresh_weather(contextRevision)`：只允许主程序窗口调用；前台窗口发起系统定位授权。后端注册全局 `weather` 请求，重复刷新返回 `REQUEST_BUSY`；切换上下文、退出或取消后不提交旧结果。
- `cancel_weather_refresh()`：取消当前刷新及原生定位/HTTP 等待；取消不覆盖已有缓存。
- `WeatherView`：`contextRevision`、`availability`、`data`、`error`。`data` 可为 null；非空时包含 `position { latitude, longitude, locatedAt }`、`observation { observedAt, description, temperatureCelsius, source }`、`fetchedAt`。所有时间为带时区 ISO 字符串，温度为摄氏度或 null，`source` 枚举 `openMeteo | qweather`。
- `availability` 枚举：`available` 有效成功观测；`cached` 刷新失败但尚未过期的缓存；`stale` 接收超过 30 分钟、观测超过 60 分钟或时间回拨；`unavailable` 无有效历史结果。cached/stale 必须显示观测时间和来源，不描述为刚刚取得的事实。刷新失败保留原坐标，不能给旧天气贴上新位置。
- 定位错误：`LOCATION_DENIED`、`LOCATION_UNAVAILABLE`、`LOCATION_TIMEOUT`、`LOCATION_FOREGROUND_REQUIRED`。天气错误：`WEATHER_NETWORK`、`WEATHER_TIMEOUT`、`WEATHER_SERVICE_ERROR`、`WEATHER_INVALID_RESPONSE`、`WEATHER_CONFIGURATION`、`WEATHER_UNAVAILABLE`。业务返回状态时保留可展示错误；取消及旧上下文直接拒绝请求。所有错误不改变聊天提供商健康状态、钱包或聊天回合。
- 定位和授权共 30 秒；单家天气 10 秒、连接 5 秒；优先 Open-Meteo，解析失败也可进入和风兜底。天气配置修改成功后取消旧请求并清空缓存；Key 解密失败只影响兜底，不阻止主服务返回成功。
- 天气缓存仅为内存中的外部资料，不随备份迁移；每次进入天气页先展示已有缓存，再自动调用一次 `refresh_weather` 定位查询，保留手动刷新和取消。聚焦及时效检查只读缓存，不形成定时联网刷新；初始化晚返回不得在离页或用户操作之后启动旧刷新。配置仍用 SQLite/DPAPI。前端离开天气页调用取消，Rust 同时在设置窗原生 CloseRequested 时取消 `weather` 请求，不依赖页面卸载回调；切换后按 revision 丢弃旧回执；聊天读取缓存而非等待刷新。

以上接口验收覆盖固定天气响应、Gzip、可空温度、错误时保留缓存、跨会话和取消，不以离线测试替代 Windows 权限弹窗及真实联网验收。

设置页面接入约定：`WeatherPanel` 接收当前 `contextRevision`，页面初次进入只调用 `get_weather_settings` 和 `get_weather`；主动刷新才调用 `refresh_weather`。保存配置使用 `SecretUpdate` 的 keep/set/clear，成功后读取清空后的缓存；失败保留输入。配置保存与刷新互斥，离开页面取消其进行中的请求，过期回执不写入当前页面。聚焦和定期读取缓存只更新展示时效，不触发定位和 HTTP。刷新结果按后端 availability 显示，不将 cached 一律标成 stale。前端定向验收覆盖入口、无自动定位、密钥处理、缓存错误展示及异步取消。

Task 9.3/9.4 的实际接口：

使用小样本 `k=2`，每轮均正常完成且成功生成短期记忆：

1. 第 1、2 轮后：两条 pending 短期记忆，无长期记忆。
2. 第 3 轮后：长期 A 来源为第 1、2 轮，触发回合为 3；从最后一条来源可推导覆盖边界为第 2 轮 AI 消息，第 3 轮短期仍 pending。
3. 第 5 轮后：长期 B 来源为第 3、4 轮，触发回合为 5；A 保留，第 5 轮短期 pending。
4. 删除底部第 5 轮：删除 B 与第 5 轮及其短期记忆，第 3、4 轮短期恢复 pending；A 及其来源不变。任一步注入数据库错误，所有上述变化回滚。
5. B 删除后重新完成新一轮：按实际来源回合顺序重新生成，不依赖自增 ID 连续，也不使用生成完成时间排序。

- 缺少较早短期记忆时不跳过缺口整合；重启只补 completed 且无短期的回合。

- 底部中断回合：用户消息和部分 AI 一起删，已有记忆不变；底部主动消息：只删该条，前面完整回合和记忆不变。

- 只读工具尝试打开其他会话 ID：拒绝；同一记忆在最近区和 RAG 区不会重复注入。

- Rust `memory_search::search(&Runtime, session_id, query, recent_m, &Cancellation) -> SearchResult`：query 最多 4096 字符，调用者必须使用已验证请求快照的 session_id/m，不能信任 AI 提供的会话 ID。返回 `hits[{id,title,content,matchedBy}]` 与 `fallbackError`；空候选不调用 Embedding。服务排除最近 m、只查该会话、校验向量身份/哈希、取消和提供商快照，最多 6 条/2400 字符，完整正文不截断。9.6 已将其放入上下文/只读工具，标题搜索复用 search_metadata 而不携带正文；最终模型容量预算仍由 context 模块负责。
- 模型配置/失败等待与诊断属于 Runtime；缺失/过期缓存是可恢复持久化待办。后台一条一条处理，关闭后从实际数据库继续，不重写长期记忆正文。
- 向量提交同时需要数据库与索引状态时，固定先取得Runtime的store锁，再取得memory_index状态锁，与长期记忆编辑及预览确认中的索引重置一致。不得持有索引状态锁等待store；版本、模型、内容哈希和取消检查仍在提交锁内执行。并发验收覆盖编辑器占用store时，等待中的向量提交不占住索引状态；重置后旧向量不落库。

- FTS 插入、编辑、删除、重建得到一致结果；中文二字词走短词补充匹配；用户输入的引号或 FTS 运算符不能导致未处理异常。
- 向量只使用当前 model_key、正确维度、有限数值、非零范数和当前内容哈希。旧模型或旧内容向量不参与相似度计算。

- 联网 Embedding 超时、无效响应或限流：本次降级 FTS，主聊天不休眠。
- 本地模型可行性验证先于 UI：固定模型文件版本、校验值、tokenizer、输入上限、池化、归一化、查询前缀与推理库版本，记录打包体积及 Windows CPU 实测。长正文超出模型输入长度时，必须明确被编码范围；不能默默截断却宣称索引了全文。需要多块向量而改变现有一记忆一向量结构时，先更新数据库设计并确认。

Letter={id,sessionId,travelId:String|null,sender:user|ai,content,replyToId:String|null,hasBeenReplied:bool,replyDueAt:String|null,replyState:none|pending|completed|cancelled,letterKind:user|midway|return|reply,isFavorite:bool,isRead:bool,createdAt}。其余 ID 也为 String，时间为 UTC RFC3339。hasBeenReplied 是永久历史资格，不由 replyToId 是否还能关联判断；删除回复不使原信可再回。

letters-changed 事件只含 {sessionId:String}，发送/标记/删除提交后及生成状态改变时通知。14.4页面已订阅并在打开、聚焦、切换后主动查询，详情成功加载再标已读。CONTEXT_CHANGED 应刷新目标上下文；LETTER_NOT_AWAY/LETTER_ALREADY_REPLIED 应禁用失效按钮但保留未发送草稿供复制；NOT_FOUND 关闭已删详情。失败不创建半封信、不改变旅行资格，也不使桌宠休眠。

生成输入复用完整会话资料的可选部分与预算，固定本次出行事实和原信作为任务资料，已发生活动才入输入；使用聊天提供商，后台仅开放当前人设绑定Skill的只读检索与读取，不开放聊天写工具和联网搜索；基础Skill始终读取。最终生成JSON内容并按要求使用颜文字。模型容量超限按已有策略裁旧一次重试，status.notice 说明历史仍保留。回来信读取真实 gift_snapshot_json，只有 gift_kind 时保持 pending。成功插入与状态更新同事务，提交前复验快照和取消；同刻返回优先。

#### 4.7.3 生图与图片饰品接口（当前版本已确认，阶段15实施）

15.1已开放list_accessories、get_accessory_image、wear_accessory、unwear_accessory、sell_accessory和delete_accessory；15.2已开放下述提供商与制作预览接口；15.3已接通预览卡片、管理页面与佩戴层。所有调用经既有可信宿主窗口/插件拦截；生图配置写操作只允许settings。图片生成是饰品业务的内部服务，不提供任意路径读取或任意付费生图的公共工具。

**提供商配置**

- `get_image_generation_config() -> ImageGenerationConfig`：只读全局配置，provider公开DTO为{id,name,protocol,baseUrl,model,hasApiKey}；version/revision/nextId/enabled/activeId与数据库设计一致，不返回密钥明文或密文。
- `save_image_generation_provider({id:String|null,expectedRevision,input:{name,protocol,baseUrl,model,apiKey:{action:keep|set|clear,value?}}}) -> ImageGenerationConfig`：新增时分配nextId，配置和密钥同事务；旧revision返回CONFIG_CONFLICT。set须非空，keep不写旧Key，clear删除。更换根地址须显式重新设置或清除Key，不能把旧服务凭据发送给新地址。
- `select_image_generation_provider({id:String|null,expectedRevision}) -> ImageGenerationConfig`：选择当前项，空选择关闭生图；切换到缺Key项保持关闭，不能自动取聊天Key。
- `set_image_generation_enabled({enabled:bool,expectedRevision}) -> ImageGenerationConfig`：唯一全局开关；true必须有有效当前项/Key，否则验证失败并保持false。false取消未完成图片请求，新候选直接使用图标、Emoji、颜文字或符号组合；已保存饰品不变。
- `delete_image_generation_provider({id,expectedRevision}) -> ImageGenerationConfig`：当前项拒绝删除，先切换或清除选择；其余只删此配置和对应密钥，不改聊天/Embedding/已保存图片。
- 配置提交后`image-generation-config-changed`无正文通知，页面主动再读并在聚焦时补查。配置检查本地完成，不暗中调用付费images/generations；字段齐备不等于已证明模型支持透明输出。

**唯一生图服务与本地处理**

请求从全局开启项捕获id/model/baseUrl/Key/revision，应用内所有生图都经此入口。首版OpenAI-compatible POST `<baseUrl>/images/generations`：model、prompt、n=1、size="1024x1024"、background="transparent"、output_format="png"；不支持参数或透明输出时如实图标、Emoji、颜文字或符号组合兜底，不自动改模型/端点、不偷偷调用其他Key。提示词由已验证name/description构造单一饰品、透明背景、无文字/水印/宠物整脸；不额外调用聊天AI写生图提示词。协议依据[官方图像接口](https://developers.openai.com/api/reference/resources/images/methods/generate)，真正接入时对所选模型做一次有授权的资源/透明性验证，不仅凭“OpenAI兼容”标签推断能力。

只解析第一项`data[0].b64_json`或`data[0].url`，无有效图像返回IMAGE_GENERATION_FAILED；图片URL由后端读取，HTTPS、不附带API Key或Cookie，复用公开网页读取的DNS/逐跳重定向/私网拒绝规则，最多3跳，不能信任模型提供的任意本地URL。前端不直接访问外部图片地址。单次请求含资源读取默认最多120秒，遵循取消信号，响应/解码/归一化上限与数据库设计11.2统一；生图POST无自动重试，不能把超时当作一定未产生费用。请求锁外完成，旧配置revision或上下文失效时丢弃图片结果。仅配置关闭/切换时，原会话仍有效的文本候选转ready图标/Emoji/颜文字预览并提示原因，不自动对新提供商重发；上下文失效/用户取消则整个候选丢弃。

**制作与读取**

`displayText`/`display_text`必须是实际可显示的图标字符、Emoji、颜文字或符号组合，不是普通名称/说明。`appearance=text`只是技术枚举：表示用字符渲染上述视觉饰品，与`image`的透明PNG渲染区分；界面不显示“文字饰品”或把“蝴蝶结”等名称当作兜底。工具提示词须明确此要求，校验不能仅判断非空，只有名称/描述而没有视觉内容时拒绝候选。

- `request_accessory_craft(name,display_text,description)`为已有计划中的聊天工具，目标由宿主注入完整context，不接受图片路径、币数或自报会话。按尚未使用的最低已解锁档位（前三档用完后才进入第四档）和文本校验先通过才创建运行态候选；返回{previewId,status:preparing|ready}表示正在准备或已就绪，不宣称已经购买。工具不等待生图完成，后台使用同一候选准备图片或图标、Emoji、颜文字或符号组合；同一tool_call重放返回原候选，不再次生成。
- `get_current_accessory_craft_preview({context}) -> AccessoryCraftPreview|null`：窗口首次打开/聚焦及漏事件恢复时查当前候选；没有候选返回null，已过期报价清理后返回null。不能恢复旧会话候选或自动重生成。
- `get_accessory_craft_preview({context,previewId}) -> AccessoryCraftPreview`：{previewId,context,tier,cost,name,displayText,description,status:preparing|ready,appearance:image|text,imageDataUrl:String|null,notice:String|null}。cost/ID统一十进制字符串，tier是后端匹配档位，preparing禁确认；imageDataUrl只为已校验受管PNG，不对外暴露候选绝对路径。ready且appearance=text（图标/Emoji/颜文字渲染）并由notice解释未开/无Key/失败原因；无效文本等必填内容失败不创建可购买预览。手动输入保护为name最多80字符、display_text最多40字符、description最多1000字符；外观有符号/图标/颜文字特征，拒绝普通中英文名称及控制字符。上下文/报价过期用ACCESSORY_PREVIEW_EXPIRED，不新增数据库状态枚举。
- `confirm_accessory_craft({context,previewId}) -> Accessory`：后端依据原预览检查当前会话、档位、价格、余额、候选文件，成功扣款/流水/饰品/档位同事务；不接受客户端传入image_file、金额或档位来覆盖。确认一次，重复确认拒绝；准备中返回REQUEST_BUSY。预览查询先发现缺图时同样标记需重新确认，不能通过后台查询静默绕过缺图保护。确认前文件损坏/丢失先改成图标/Emoji/颜文字预览并返回ACCESSORY_IMAGE_UNAVAILABLE，要求查看并重新确认，不能静默换外观后扣钱。
- `cancel_accessory_craft({context,previewId}) -> void`：取消图片请求/丢弃候选，不扣币；用户拒绝沿原1小时或下次启动冷却规则，不把图片失败当用户拒绝。拒绝冷却保存在本进程的单调时钟状态，不进入数据库/备份；切换/退出不视为用户拒绝。切换/退出走同一取消路径，迟到结果不可复活。
- `list_accessories({context,beforeId:String|null,limit:i64}) -> Accessory[]`：默认30、范围1–200、ID倒序、当前会话；`get_accessory_image({context,id}) -> {dataUrl:String|null,notice:String|null}`只按已验证饰品ID读取，失败图标/Emoji/颜文字回退。列表不返回任意外部图URL或整批图片二进制。
- `wear_accessory({context,id})`、`unwear_accessory({context,id})`、`sell_accessory({context,id})`、`delete_accessory({context,id})`：换装同事务，卖出/删除仅未佩戴；卖出固定10币和流水同事务，重复不再到账，不清档位。wear/unwear返回更新后的Accessory；sell返回{deletedId,wallet}（wallet复用既有WalletDTO），delete返回{deletedId}，页面再按事件补查。数据库提交后清理确定未引用的文件。
- Accessory={id,sessionId,name,displayText,imageFile:String|null,description,cost,source:crafted|travel,travelId:String|null,isWorn:bool,createdAt}；ID/cost为String，imageFile为受管相对路径，仅用专用读取接口，不由页面自行拼任意文件请求。

`accessories-changed`仅{sessionId:String}，购买/旅行发放/佩戴/卸载/卖出/删除提交后通知；`accessory-craft-preview-changed`仅{sessionId,previewId}，预览准备状态变化时通知。先订阅后查，聚焦补查，切换隔离及迟到防护沿既有窗口规范。生图错误只影响局部预览，不使桌宠休眠或撤销已保存聊天。普通聊天不携带图片内容，不给插件开放这些接口。

必要验收：无Key/关闭直接显示图标/Emoji/颜文字；有Key同一开启项生成真透明PNG；超时/不透明/全透明/超限/坏图图标、Emoji、颜文字或符号组合兜底且POST不自动重试；关闭/切换配置/上下文取消迟到结果；预览确认一次、价格变化/余额不足/文件丢失/SQL失败不误扣；图片先发布后提交引用；图片丢失可继续佩戴图标/Emoji/颜文字；旅行可选图片失败仍完成唯一发放；备份包含已保存图片而不含Key/候选。只针对变更测试，图片API验证须用户自己的有效配置与明确授权，不能用全量反复测试代替。

## 5. 产品边界与实施前置条件

第 5.1 节是已确认规则；第 5.2 节是对应阶段必须通过实测定稿的工程契约，不表示所有细节已经可直接编码；第 5.3 节补充跨阶段都必须遵守的出行事实约束。工程实测项不等同于仍需用户决定的产品规则，也不阻塞其他独立任务。

### 5.1 已确认的产品边界

- 无聊／睡觉共同触发阈值默认45分钟，只能统一修改；60–120 分钟仍指每次睡眠持续时间，两个设置独立。
- 上下文超限自动减少本次携带的较旧内容并提示，不删除数据库内容；具体步骤见《记忆与旅行游记设计》第 6.2 节。
- 出行记录表就是 travels，游记、信件、伴手礼和旅行饰品是同次出行的并列子项，不因某个子项删除而互相删除。
- 游记允许单独删除，小游戏仍为全局功能，与出行无关。默认无聊与入睡共用45分钟阈值，到点随机二选一，每次只抽一次；睡眠持续时间仍为 60–120 分钟。

### 5.2 实施阶段必须定稿的契约

- 阶段 6 已确认：循环提醒跟随电脑当前时区，夏令时不存在时刻跳过，重复时刻只采用第一次；一次性按绝对时间触发。`schedule` 版本 1 的 JSON、后端当地游标及兼容规则见《数据库与持久化设计》第 9 节。
- 阶段 9：各模型有效上下文上限的配置来源、token 估算与输出预留；本地 Embedding 的具体运行库、模型文件及长文本编码策略，通过 CPU 实测后锁定。检索阈值和候选上限记录测试依据。
- 阶段 13：manifest JSON Schema、settings_schema 支持类型、桥接请求/返回 schema、包体/解压/存档/响应大小上限与 CSP；SDK、模板、宿主使用同一版本，不各自猜字段。
- 阶段 17：format_version/schema_version 的兼容范围、合并追加的人设映射与历史饰品引用映射。内置默认人设复用目标唯一内置项并保留其设定，不删除或制造第二个内置默认人设。
- 阶段 18：内置农历/节气表的数据来源、再分发许可、覆盖范围和边界样本；完成后重跑阶段 17 的节日导入导出。

涉及用户可见行为变化的选择先确认；纯工程参数经测试定稿并写回专题设计后才进入联调。尚未定稿的契约不算阶段完成。

## 单实例、原生拖动与手动颜文字（增量J）

- Windows启动先取得data/instance.lock独占写入权，再执行Runtime::initialize。第二个写入者被系统拒绝，读取PID/HWND后验证GetWindowThreadProcessId，通知该窗口并退出，不打开SQLite、不迁移、不启动jobs。文件允许读取但不允许并发写入/删除；遗留文件在下一次成功取得使用权时重写。不同目录独立。
- 主宠窗注册固定原生唤醒消息；处理时复用show_pet_window（恢复隐藏/最小化并聚焦）。窗口子类钩子重复调用不叠加、不替换既有无边框处理，WM_NCDESTROY释放引用；唤醒失败不偷偷新开同data实例。
- WM_EXITSIZEMOVE触发后台finish_pet_drag，再发main专用pet-drag-finished空载荷事件。startDragging回包不代表释放鼠标，前端正常路径不得在finally里提交dragging=false。原生最终坐标用于检测、回收与保存，不能保存吸附前坐标。
- settings专用save_persona_expressions参数{id,expected,library}：expected为编辑开始时原始expressions JSON或null，不是effectiveExpressions。library为ExpressionLibrary，点击仍是click.happy/surprised/shy，新增可选normal、walk_left/right、peek_left/right、rest_sit/lie数组，旧包可缺。每项复用validate_expression（显示宽度最多14格、非空、无控制/双向控制符），分类最多8项；UI要求所有已展示分类至少1项。
- 后端同一事务比较当前JSON与expected；不一致返回CONFLICT，不存在NOT_FOUND，非法输入VALIDATION_ERROR，均不覆盖现有库。仅更新expressions和updated_at，返回Persona并广播configuration_changed；不改当前选择、设定、会话或context_revision，不调用provider。原生成任务已有previous条件更新会拒绝覆盖手动新值。
- 保存/读取与已有备份共用expressions字段，不另建表、列或迁移。验收需覆盖无Key手动保存、符号保留、冲突留草稿、姿态重读、旧JSON兼容、重复启动不增加后台任务、实际松手后整个画布可见。尚未构建的源码不能按旧EXE操作记为通过。

## 全局聊天表情包接口（v26）

本节是当前源码契约，尚未随20261027-153724/v25正式包发布。表情包用于聊天消息，独立于桌宠图片动作和生成图片。所有业务ID为十进制字符串，管理命令仅授权settings窗口。

- `query_chat_stickers({input:{entity,query?,page?,libraryId?,personaId?,tagIds?}})`：entity为libraries、stickers或tags；返回`{items,page,pages,total}`，固定每页12项、ID倒序，页码校正到有效范围。标签筛选为AND，必须同时符合所有选中标签；查询先筛选再分页。
- `mutate_chat_stickers({input})`：input以op区分saveLibrary、saveTag、saveSticker、delete和bind。库保存title/description；标签保存name；表情包保存title/description/tagIds；bind保存libraryId/personaId/bound。编辑和删除携带当前revision，旧版本返回CONFLICT，不覆盖用户新值；绑定可重复提交而不重复建关系。同名标签按不区分大小写规则复用。
- `import_chat_sticker({libraryId,input:{filename,dataUrl}})`与`get_chat_sticker_image({id})`：接收PNG、JPEG、WebP、GIF，校验后保存受管资源，GIF保留原动画。文件上限16MiB，静态解码像素最多1600万；GIF累计解码像素另有1亿保护。库图片不要求透明，DTO不暴露磁盘路径。
- 变更提交后广播`chat-stickers-changed`；列表及人设绑定视图重新读取，丢弃已切换目标的迟到结果。库、表情包、标签均有搜索与分页，翻页在列表下方。弹窗正文独立滚动，关闭操作在底部；不增加用户聊天输入区的表情包发送入口。

发送把图片作为独立消息附件保存在本次AI回合；复制后的资源不因删除库图片而失效。`message_images.source_kind`区分image与sticker，旧消息默认为image；生成图片查看/透明检测/抠图工具不误操作表情包。全量备份包含全局库及全部关系，部分人设/会话包携带绑定库、相关标签和图片并重映射ID；合并到现有人设时保留其原绑定。旧v6–25包补缺省字段且不补发表情包。
