# 颜喵实施接口与验收约定

- 日期：2026-09-19
- 范围：首版阶段 0–18 的实施接缝、恢复顺序与验收；不表示对应代码已实现。
- 配套：[实现计划](superpowers/plans/2026-09-04-yanwenzi-desktop-pet.md)、[产品规格](superpowers/specs/2026-09-04-yanwenzi-desktop-pet-design.md)、[数据库设计](数据库与持久化设计.md)。

## 1. 开发前需要具备什么

代码路径、模块责任、数据库写入归属和通信时序遵守[项目架构与代码职责](项目架构与代码职责.md)。本文件继续规定接口行为与验收，不用架构分层替代业务验证。

每个阶段先核对前置阶段产物，再实施、测试、联调，最后标记完成。后续阶段尚未提供的服务只能在测试中用替身，不向用户暴露“成功但没有实际效果”的按钮或工具。

每个功能交付须包含以下内容：

1. 输入字段、允许状态、返回结果及错误码；前端和 Rust 使用同一份契约。
2. 读取/修改的表、事务范围、版本校验和取消点。
3. 正常路径、重复操作、请求失败、应用重启、切换上下文的用例。
4. 所需资源、版本与打包路径；依赖模型或插件包的能力不能只在开发机验收。
5. 自动检查结果和涉及窗口/系统能力的人工记录。记录测试环境、操作、预期、实际结果；未做项写“未验证”。

schema 决定数据库字段与约束；专题文档决定业务规则；本文件决定实施接缝与验证方式。如果发现三者冲突，先解决文档冲突，不允许实现者挑选方便的一版。

## 2. 前后端接口约定

### 2.1 命名、身份与错误

- Tauri command 名使用现有文档中的 snake_case，前端 DTO 字段统一 camelCase，Rust 用序列化映射；数据库列名保持 snake_case。不要求 SQL 列名与 TypeScript 属性拼写相同。
- 数据库整数 ID 跨前后端 IPC 统一序列化为十进制字符串，Rust 入口解析并校验；数据库仍保留整数类型。运行期 revision/seq 使用可安全表示的整数，不允许不同业务模块混用 ID 表示。
- 通用错误至少为 `{code, message, field?}`；message 是中文，code 是稳定机器标识。常见类型：`VALIDATION_ERROR`、`NOT_FOUND`、`CONTEXT_CHANGED`、`REQUEST_BUSY`、`CANCELLED`、`PERMISSION_DENIED`、`PROVIDER_UNAVAILABLE`、`STORAGE_ERROR`。
- 返回值不得包含 DPAPI 密文或主程序 API Key；日志可记录请求 ID、阶段和耗时，不能直接打印完整请求上下文、密钥或插件私有存档。
- 会话级入口接收 personaId、sessionId、contextRevision，并由 Rust 验证归属和有效性；插件入口不接受客户端提供的 pluginId 作为身份依据。

### 2.2 两类版本不能混用

- contextRevision：当前窗口上下文的运行期版本。切换人设/会话、删除当前项、导入使当前项变化时递增，防止旧窗口响应进入新页面。
- `sessions.memory_revision`：数据库内的会话内容版本。消息、回合、记忆写入与删除在事务内递增，用于拒绝过期生成结果。拒绝只解决旧结果污染，不能替代补偿：工作器必须立即按最新内容重排，启动时还要扫描 `completed` 且缺少短期记忆的回合；长期整合冲突则保持来源为 `pending`。
- 长任务保存目标 ID 与相应快照；完成时重验，不重新取“此刻当前会话”后把旧结果写进去。
- 不相关的其他会话变化不使本会话任务失效；本会话版本变化导致结果被丢弃后，仍未完成的后台任务需重新读取并排队，不能永久遗漏。

### 2.3 聊天请求与事件

1. 发送入口只接收本次输入与目标上下文，不信任前端上传的人设、历史和记忆。
2. Rust 验证可聊天、提供商可用、同会话没有运行请求；建立 requestId，在事务中建立 pending 回合并保存用户消息。
3. 返回包含 requestId、sessionId、roundId 的回执；事件统一携带这些字段、单调递增 seq、type 和对应 payload。前端先订阅再发送；回执到达前暂存关联事件，不能因时序丢首段正文。
4. 表情、正文增量和终态均属于同一请求。完成与取消使用同一终态控制：一次请求最多提交一次 completed 或 interrupted，不允许完成和取消各插入一条回复。
5. 正常完成先提交数据库，再发完成事件。中断保存已收到的部分正文一次；无正文不插空 AI 消息。长度截断或异常断流不能误记为完整回合。
6. 前端刷新、关闭窗口或丢事件后，从后端查询当前请求和已保存消息恢复；事件不是历史记录。应用被强制终止时未落盘的流式片段不保证恢复，界面不得把它们标为已保存。
7. 启动时没有运行请求与之对应的 pending 回合转为 interrupted；保留已落盘消息，不自动重发、不生成短期记忆。
8. 中断已完成请求应返回其终态，不重复写入；取消后迟到的模型输出不能恢复已删除回合。

涉及钱包或其他副作用的工具不能因重新连接、重说或重放事件再次执行。工具循环检查取消信号、轮数上限和目标归属；只读回忆与写入记事本等能力也受同一上限约束。

`read_notebook` 与 `update_notebook` 的结果统一携带 `limit_chars`、`current_chars`、`remaining_chars` 和 `over_limit`；默认建议上限为 4000 个 Unicode 字符。该值是 AI 维护软限制：更新不得截断、丢弃或仅保存部分正文，超限结果仍完整提交并返回 `over_limit=true`，后续工具提示要求 AI 先合并重复内容和精简旧段落。用户手动编辑或导入的超限内容同样可读取和保存。

### 2.4 窗口与工具边界

- 窗口先订阅变化事件，再读取当前上下文；用 revision 排除乱序旧数据。重复点击入口聚焦既有窗口，关闭二级窗口不退出应用。
- 插件 WebView 不继承主程序窗口的 commands/capabilities。身份由宿主窗口与安装登记绑定，工具层再次检查权限。
- AI 工具参数中不开放任意 SQL、文件路径或会话 ID。查询来源时使用发起请求的会话快照，分页及结果长度必须有界。
- 工具注册清单与已实现服务一致；阶段 9 不提前暴露阶段 16/18 尚未可用的写入工具。

## 3. 启动、退出与恢复顺序

平台接缝遵守《项目架构与代码职责》第 5.1.1、7.4 和 9.1 节：共享服务不接收窗口或 Activity，原生入口与 Tauri commands 共用 runtime 和事务；界面先查询实际能力，后端每次重新校验。Windows 首版用假平台验收以下边界，Android 原生能力以后单独验证：

- 主窗口与悬浮服务重复连接只初始化一个 runtime；初始化完成前不接受业务写入，不重复迁移、调度或结算。
- 暂停不等于切换会话。没有运行许可的时间不累计旅行有效在线秒数；已出发旅行按 UTC 恢复，先返回再检查回信。
- 重复恢复、权限撤销、时钟跳变及无退出回调的进程终止均有用例；未完成聊天不自动重发，副作用不重放。
- 平台能力区分“不支持/待授权/可用/资源缺失”；系统授权不能由跨设备备份赋予。Windows 窗口关闭与 Android 页面返回由各自外壳处理，共享页面不直接操纵原生窗口。
- Android 系统服务、通知精度、文件 URI、Keystore 和模型 ABI 在后续专项验收后才算支持。

启动依次执行：

1. 检查数据目录，打开数据库，开启外键，执行已支持迁移和幂等种子；失败停止业务调度。
2. 校验当前提供商、人设与会话引用，恢复唯一当前上下文。
3. 将无运行请求的 pending 回合收束为 interrupted；不伪造成功回复。
4. 恢复旅行状态：到期先返回，取消对应待回信，然后才处理仍有效的回信；cancelled 任务不恢复。
5. 提醒离线补偿与在线循环串行交接，先恢复已有 queued/missed，再启动普通调度，避免重入。
6. 开启窗口查询和事件服务；后台恢复缺失短期记忆、长期整合、有效旅行生成和失效向量。按目标去重，同一任务不能被多个入口并发提交。

正常退出先阻止新任务、取消活动请求，短事务保存允许保存的回合终态及当前会话在线累计，再释放窗口和数据库。强制终止按启动恢复路径处理，不承诺补回未落盘数据。

后台 AI/网络工作始终在事务外；重试读取保存的目标与状态，不重新抽旅行奖励类型、回信期限等已经确定的随机值。结果与对应 done 状态必须在同一事务落盘。

## 4. 各阶段的行为验收

以下用例与实现计划中的 Task 一起执行。纯逻辑用临时 SQLite、假时钟、可控随机源和假 HTTP 服务测试；UI 与 Windows 能力另外人工验证。

### 4.1 阶段 2–3：配置与传输

- 新库初始化两次：只有一个全局钱包、一个内置默认人设和一个内置 Embedding 配置；当前项有效。
- 删除当前使用提供商：被拒绝；删除默认人设：被拒绝；删除当前非默认人设：目标子树删除、切回默认、全局钱包与插件不变。
- 更新名称但不输入密钥：密钥仍可用；明确清除才清除。列表与备份不返回主程序密钥。
- SSE 任意分块：最终中文文本与原样本一致；工具参数未完整前调用次数为 0，完整且有效后只执行一次。
- 正常结束、异常断流、用户取消分别得到正确终态；数据库不可写时不向 UI 报“保存成功”。

### 4.2 阶段 4–8：状态、回合、提醒、天气和窗口

- 只点击不喂食：无聊计时重置，饥饿仍按上次喂食计算。休眠期间推进时钟不会恢复 Normal。
- 一轮完成：一个 round、一个用户消息、一个 AI 消息；同时发第二个请求被拒绝。中断后没有完成奖励或短期记忆。
- 回合进行中切换会话：原请求取消，新会话不出现原来的增量或结果。
- 到期提醒入队后立即退出、尚未显示：重启后仍能投递原 occurrence，不新增第二条。展示确认只改 delivery_state，不等于完成。
- 离线错过三个一次性提醒、同一循环五次：汇总三个一次性及一个循环提醒名；再次启动不重复创建记录。
- 月度 31 日遇二月：跳过不存在日期；重复提醒点击完成仍有下一次计划，删除才停止。
- 天气缺失/拒绝定位：显示不可用，聊天继续；不得注入假温度或假位置。
- 两次打开相同二级窗口：只有一个实例；关闭再打开从后端恢复。窄窗口、长文字和不同 DPI 下按钮可操作，颜文字不裁切。
- 切换亮色/暗色/跟随系统：主程序所有窗口更新，小游戏不注入主程序主题。

无聊/睡眠实现与验收统一遵守产品规格“无聊与睡眠的随机分支”：默认同时到 45 分钟时各 50% 二选一，每段空闲只抽一次；不同阈值先到先进入，互动或睡眠结束开启下一周期。测试使用固定随机源分别覆盖两个分支，不能只等待真实随机结果。

### 4.3 阶段 9–10：记忆与消息操作

使用小样本 `k=2`，每轮均正常完成且成功生成短期记忆：

1. 第 1、2 轮后：两条 pending 短期记忆，无长期记忆。
2. 第 3 轮后：长期 A 来源为第 1、2 轮，触发回合为 3；从最后一条来源可推导覆盖边界为第 2 轮 AI 消息，第 3 轮短期仍 pending。
3. 第 5 轮后：长期 B 来源为第 3、4 轮，触发回合为 5；A 保留，第 5 轮短期 pending。
4. 删除底部第 5 轮：删除 B 与第 5 轮及其短期记忆，第 3、4 轮短期恢复 pending；A 及其来源不变。任一步注入数据库错误，所有上述变化回滚。
5. B 删除后重新完成新一轮：按实际来源回合顺序重新生成，不依赖自增 ID 连续，也不使用生成完成时间排序。

补充用例：

- 缺少较早短期记忆时不跳过缺口整合；重启只补 completed 且无短期的回合。
- 修改 k 不重算旧来源；生成期间修改 k 或消息使旧快照失效，重排任务后不能漏掉该组。
- 使用可控的延迟 AI 验证：短期记忆生成期间编辑来源消息，旧响应被拒绝，工作器用新正文重排，最终只有一条基于新正文的短期记忆；在拒绝后、重排前模拟退出，重启扫描仍须补齐。长期整合发生同类冲突时，来源保持 `pending` 并可重试。
- 编辑历史原文不自动改记忆；手动改记忆、重新生成预览及确认按各自规则执行。
- 底部中断回合：用户消息和部分 AI 一起删，已有记忆不变；底部主动消息：只删该条，前面完整回合和记忆不变。
- 重说全部新内容准备成功后一次替换；任何依赖记忆生成失败保留整套旧结果，ID 不变，亲密度不重复增加。
- 生成预览期间用户又编辑：确认不能覆盖较新版本，应提示预览已失效。
- 只读工具尝试打开其他会话 ID：拒绝；同一记忆在最近区和 RAG 区不会重复注入。

### 4.4 阶段 9：检索与模型资源专项

- FTS 插入、编辑、删除、重建得到一致结果；中文二字词走短词补充匹配；用户输入的引号或 FTS 运算符不能导致未处理异常。
- 向量只使用当前 model_key、正确维度、有限数值、非零范数和当前内容哈希。旧模型或旧内容向量不参与相似度计算。
- 向量返回期间长期记忆被改或删除：拒绝写入旧结果；切模型后可恢复重建，FTS 仍然工作。
- 联网 Embedding 超时、无效响应或限流：本次降级 FTS，主聊天不休眠。
- 本地模型可行性验证先于 UI：固定模型文件版本、校验值、tokenizer、输入上限、池化、归一化、查询前缀与推理库版本，记录打包体积及 Windows CPU 实测。长正文超出模型输入长度时，必须明确被编码范围；不能默默截断却宣称索引了全文。需要多块向量而改变现有一记忆一向量结构时，先更新数据库设计并确认。
- 用中文样本验证同义表述、人名/书名、时间变化、不相关话题、明确线索追溯及跨会话隔离。记录命中与未命中，不把融合排名分数直接当成概率。

### 4.5 阶段 11–12：主动消息与人设

- 主动消息先保存后展示，round_id 为空；没有当前会话、隐藏、出门、休眠或正在聊天时不生成。
- 同一段无聊状态最多发一条；取消或切换后的迟到结果不进入新会话。用固定随机源验证触发与不触发，无需等待真实时间。
- 人设自调只在完整回复后的允许阶段发生；中断、关闭开关或用户编辑人设使旧快照失效。不得覆盖 initial_prompt。
- 人设差异视图只比较当前 `prompt` 与 `initial_prompt`，在前端本地计算，不调用 AI、不写入数据库。新增必须同时具有绿色样式和“新增”标记，删除必须同时具有红色样式、删除线和“删除”标记；使用键盘和屏幕阅读器时也能区分，亮色、暗色及窄屏布局均需验收。
- 验证当前文本与初始文本一致、纯新增、纯删除、中文句内替换及多段混合变化。保存当前内容为初始设定或从初始设定恢复成功后，差异立即显示为一致；用户手动编辑的变化也计入累计差异，界面不得称其为 AI 修改历史。
- 标题生成期间用户手动改名：手动名称保留。背景文件保存失败：旧背景仍可读取。

### 4.6 阶段 13：钱包与插件

- 同一天重复签到：余额只增加一次，流水只有一条；普通签到与节日签到不能各领一次。
- 同插件同 request_id 同内容重试：返回原已提交结果，不再次改币；同 ID 不同游戏局/数量/原因：返回冲突。禁止把其他内容当成成功重试。
- 两个并发扣款余额不足：只有可支付事务成功，余额不为负；账单、游戏局累计和余额一致。
- 插件伪造另一个 pluginId 或 game_run_id：拒绝；停用、缺包、版本不匹配或权限待确认：禁止钱包与联网调用。
- 纯玩局中途授权：本局仍不结算；有权限局撤销权限：之后的新钱包操作被拒绝，已成功账单不回滚。
- 游戏完成/关闭与钱包请求并发：宿主按局串行裁决，结束后的新结算被拒绝；已提交请求的幂等查询不产生新结算。游戏完成不能自动重复调用一次奖励接口。
- 联网请求直接从 WebView 发出被阻止；重定向到未授权来源、回环/私网地址被拒绝，包含 DNS 解析后的目标校验。
- 更新/卸载/导入该插件数据前停止其活动局和新请求，再改变包及授权。失败不能留下已启用但文件不完整的登记。
- 随包石头剪刀布离线可打开，首次询问喵币权限，20 局限制覆盖纯玩与结算模式，胜 +5、负 -4、平 0。

### 4.7 阶段 14–16：旅行、信件与饰品

- 当前会话在家空闲才递减 `travel_trigger_remaining_seconds`；默认每轮从 2–4 小时抽取一次。聊天、互动、睡眠、休眠、隐藏和出门均暂停；非当前会话及应用关闭期间暂停并保留剩余值。
- 旅行倒计时与无聊/睡眠无互动计时独立；互动重置后者但不得重抽前者。设置范围变化只影响下一次抽取。
- 切换取消旅行和待回信，不发礼物/回来信/游记。退出重启不等于切换；已到期按计划时间返回。
- 返回与回信同时发生：返回优先，过期回信不落盘。删除回复后原信仍不可再回复。
- 重复触发返回/重启补偿：只有一个固定礼物类型与一件结果，done 不因用户删除结果而变回 pending。
- 旅行正常返回完整链路依赖饰品和游记实现，阶段 14 单独完成不能算旅行功能交付。
- 饰品 AI 生成失败或用户取消预览：不扣币、不占档位；确认时复核会话、档位、价格、余额，结果与扣费同事务。
- 单会话最多一件佩戴饰品；卖出/制作失败不留下余额和物品不一致。
- 游记使用人设口吻，聊天只注入最近五篇仍存在的标题，正文按需读取；不参与短期/长期整合。
- 删除游记后保留出行和全部其他子项；journal_state 仍为 done，重启不补生成，迟到编辑/生成不能复活该行。删除后备份恢复维持无游记；删除前的旧备份则按快照正常恢复。

### 4.8 阶段 17–18：备份、日期与发布

- 六类包分别在空库和已有数据上往返，检查映射后的关系、当前项、状态与记录数；不只比较 JSON 文件能否解析。
- 全量导入替换全局钱包/账单/设置；部分人设或会话包不改变全局数据；独立插件包不改变钱包/账单/游戏局，授权全部 pending。
- 缺包插件保留数据卡片与来源链接；程序文件不在备份中，重新安装兼容包后才可运行。
- 导入中注入文件写入错误、数据库错误、版本不兼容、孤儿引用和路径越界：旧数据库保持完整，不留下指向缺失文件的已提交记录。
- 全量流水中的饰品 ref_id 属于历史业务引用：来源饰品可能早已卖出或删除，不能要求每条历史账单都存在当前饰品；具体映射不能猜到另一个现存对象。插件账单的 game_run_id 则必须满足外键闭合。
- 农历腊月跨公历年、闰月、节气、跨年运行、系统日期变化、超出内置表范围分别测试；未知日期不沿用旧值。
- 同一天同时命中母表/子表：合并祝福、总额固定 10，不重复签到；没有联网日历请求。
- 干净目录离线验收便携包，包括本地模型、第一方插件与许可证；不依赖开发机缓存、node_modules 或旧 data。WebView2 缺失时应明确提示运行环境问题。

## 5. 产品边界与实施前置条件

第 5.1 节是已确认规则；第 5.2 节是对应阶段必须通过实测定稿的工程契约，不表示所有细节已经可直接编码；第 5.3 节补充跨阶段都必须遵守的出行事实约束。工程实测项不等同于仍需用户决定的产品规则，也不阻塞其他独立任务。

### 5.1 已确认的产品边界

- 无互动入睡阈值默认 45 分钟，允许用户修改；60–120 分钟仍指每次睡眠持续时间，两个设置独立。
- 上下文超限自动减少本次携带的较旧内容并提示，不删除数据库内容；具体步骤见《记忆与旅行游记设计》第 6.1 节。
- 出行记录表就是 travels，游记、信件、伴手礼和旅行饰品是同次出行的并列子项，不因某个子项删除而互相删除。
- 游记允许单独删除，小游戏仍为全局功能，与出行无关。默认无聊与入睡阈值均为 45 分钟，到点随机二选一，每次只抽一次；睡眠持续时间仍为 60–120 分钟。

### 5.2 实施阶段必须定稿的契约

- 阶段 6：提醒 schedule 的版本化 JSON 字段、时区变化和夏令时重复/不存在时刻的处理，写出样本后前后端共用。
- 阶段 9：各模型有效上下文上限的配置来源、token 估算与输出预留；本地 Embedding 的具体运行库、模型文件及长文本编码策略，通过 CPU 实测后锁定。检索阈值和候选上限记录测试依据。
- 阶段 13：manifest JSON Schema、settings_schema 支持类型、桥接请求/返回 schema、包体/解压/存档/响应大小上限与 CSP；SDK、模板、宿主使用同一版本，不各自猜字段。
- 阶段 17：format_version/schema_version 的兼容范围、覆盖内置默认人设的限制和历史饰品引用映射。新建副本不得制造第二个内置默认人设。
- 阶段 18：内置农历/节气表的数据来源、再分发许可、覆盖范围和边界样本；完成后重跑阶段 17 的节日导入导出。

涉及用户可见行为变化的选择先确认；纯工程参数经测试定稿并写回专题设计后才进入联调。尚未定稿的契约不算阶段完成。


### 5.3 出行事实已纳入结构

出行事实与礼物快照已经纳入 travels，字段、状态和提交顺序以《数据库与持久化设计》第 6.1 节为准。阶段 14–16 必须先保存同一份事实，再生成各子项。验证事实失败重试、取消期间迟到结果、礼物与快照原子提交，以及删除所有展示子项后基础事实仍存在。字段不依赖子项 ID，不因导入 ID 重映射损坏。
