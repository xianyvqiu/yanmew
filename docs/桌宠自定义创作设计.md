# 桌宠自定义创作与饰品定位

## 产品范围

此功能属于当前版本的可选图片模式，按人设保存，默认关闭。关闭后保留创作内容并恢复既有颜文字路径；聊天、记忆、养成、出行与钱包继续复用现有业务。设置增加“桌宠自定义创作”，显示当前人设。第一阶段支持静态透明 PNG/WebP。

## 创作条目与交互

每个人设有一个初始形象条目和多个表情条目。表情保存名称、自由填写的生成要求、使用说明、类别、启用状态、正式图片和待确认预览。类别为 normal、click、hungry、eating、sleepy、bored、thinking、chat。初始形象接受后才能开启图片模式；只有初始形象也可使用。

用户可以连续新建多条要求，逐项或批量生成。批量逐项执行并分别显示结果，一项失败不撤销其他项。每张预览可以接受、重新生成、修改要求、放弃；重新生成期间保留旧预览，成功才替换。重新接受前不覆盖正式图片。页面切换或取消不自动重试付费请求；已保存条目、正式图片和预览重启仍可读取。单次生成绑定条目版本、初始参考图与生图配置版本，迟到结果不覆盖用户新修改。

所有图片必须有真实透明区域和可见像素，拒绝动画、不透明底图及完全透明图片。沿用受管图片服务的解码限制、PNG发布和引用校验，使用统一256×256透明画布，保留用户图片的构图和比例，不按单张内容裁剪。透明通道检查不保证能自动识别所有画在图中的棋盘格或角色差异，用户仍需预览确认。

## AI与显示

聊天图片模式在既有表情阶段选择已接受且启用的表情ID，输入仅包含ID、名称及使用说明，不输入图片数据，不生成新的颜文字。非法选择回到初始形象。状态及点击互动按现有事件选择对应分类，缺项回到初始形象；睡眠、出行、提醒优先级保持。关闭模式继续原有实时颜文字生成。

参考图生成使用当前统一生图提供商，对支持OpenAI-compatible图像编辑的服务调用images/edits，携带初始形象和用户要求。没有初始图、未配置/关闭生图、接口不支持、透明校验失败时明确失败，不能以纯文字生图伪装参考图生成。生成是用户主动操作，说明参考图将发送给所选服务、可能计费；无自动付费重试。不改现有饰品images/generations请求。

## 饰品统一定位

颜文字与图片模式统一使用每件饰品的相对位置与缩放。饰品仍归属会话，一次最多佩戴一件。饰品详情新增组合预览，可拖动、调整大小、保存、取消及恢复默认。相对位置以桌宠稳定展示区域中心为基准，X/Y以该区域宽高的千分比保存，允许负值；缩放以默认饰品大小的千分比保存。位置不绑定屏幕或窗口。缺省X/Y为NULL表示沿用旧头顶布局，scale默认为1000。

已保存位置随宠物移动、游走和整体缩放，统一应用于所有表情，不实现逐表情校准。图片统一画布可避免留白导致的跳动，但站姿/躺姿等本身构图不同仍需用户选用合适表情。饰品范围计入命中与气泡避让，不能扩大整个窗口的鼠标拦截范围。制作、金币、卖出、档位等规则保持。

## 数据与备份

数据库以正式012迁移增加personas.pet_image_enabled（0/1）、pet_image_revision（非负版本），新增pet_artworks人设子表；accessories增加position_x、position_y、scale。旧库先生成一致性备份，再同事务迁移；新schema同步。创作表的枚举、字段用途、外键及约束写入SQL注释。

图片复用assets/accessories受管透明PNG服务，清理同时检查创作正式图及预览引用，不能误删。相关人设资料包、完整包、带人设的会话包及全量备份携带创作条目及图片；正式图与预览均为用户内容。导入映射persona_id和条目ID，复用目标人设时保持其原创作配置。旧包默认关闭图片模式、没有创作条目，饰品沿用旧默认定位。无密钥或生图模型进入人设包。

## 实施与验收顺序

1. 012迁移、新库schema、强类型仓储、版本校验及图片引用保护。
2. 创作CRUD、上传与预览接受/放弃、参考图生成与取消、可信设置窗口命令。
3. 设置入口、当前人设绑定、卡片搜索分页、批量要求及逐张重生成。
4. 既有表情阶段分支与状态选择、图片显示及失败回退；模式关闭路径保持。
5. 饰品定位命令、拖动预览及统一显示，保持原默认布局。
6. 备份导入导出、旧包兼容、数据库图及基础文档同步。
7. 定向检查迁移、模式隔离、透明图片、旧预览保留、上下文/配置过期、饰品保存和备份往返；前端类型构建。真实生图服务、透明窗口拖动和视觉待实机确认。

## 已接入的代码与命令

- `pet_creation.rs`：人设归属、版本校验、CRUD、透明图归一化、预览接受/放弃、参考图生成与图片选择；`pet_creation/tests.rs`为针对性业务验证。
- `get_pet_creation(personaId)`读库；`save_pet_artwork(personaId,id?,revision?,input)`新建/编辑；`set_pet_creation_enabled(personaId,enabled,revision)`切换模式。没有正式初始图不能开启。
- `upload_pet_artwork(personaId,id,revision,data)`将用户图片存为预览；`get_pet_artwork_image(personaId,id,preview)`只读取条目所引用的受管图片；`finish_pet_artwork(...,action)`的action仅accept/discard/delete，删除初始条目会关闭模式但保留表情条目。
- `generate_pet_artwork(personaId,id,revision)`单次生成；`cancel_pet_artwork(personaId,id)`取消当前条目任务。批量由设置页串行调用，每项独立结果；关闭页面停止后续项并取消正在生成的一项。取消请求不代表服务商没有计费。
- 所有写命令只允许可信设置窗口调用，图片只读接口不暴露任意文件路径。网络请求与解码不占存储锁；最终保存复核条目、创作库、生图配置版本和取消信号，拒绝迟到结果并清理无引用文件。
- `PetCreationPanel`复用卡片搜索/排序/分页；`PetArtworkDisplay`读取正式图，读取失败回到初始图；关闭模式走原颜文字路径。聊天只在既有表情阶段返回`@pet-image:<id>`内部引用，不追加一次判断请求。
- `save_accessory_placement(context,id,x,y,scale)`复用当前会话校验，只保存位置，不改变佩戴/制作/钱包。X/Y须同时为空或同时为-1500～1500的整数，缩放200～3000，默认1000；界面提供拖动及方向键辅助调整。
- 颜文字定位参考区域为中心周围120×56逻辑像素，图片定位参考区域为其实际正方形显示区域。位置按千分比换算；显示受透明宠窗边界约束，游走及命中区域包含饰品，气泡按可见上边界避让。
- 模型请求参考：[OpenAI图像编辑接口](https://developers.openai.com/api/reference/python/resources/images/methods/edit)。兼容服务是否支持由真实请求结果决定；未进行真实付费生图验收。

## 文件与备份的细节

图片复用已有16MB输入和4096边长解码约束，明确拒绝动画；桌宠原图可以接触边界，但必须有真实全透明区域及可见内容。归一化时保留整张原构图，等比缩入254×254并居中放入256×256透明PNG，以便沿用已有PNG资源验证与发布服务。不会自动抠图。

备份schema版本为12，接受旧6–11版本。旧包补全图片模式关闭、版本0、饰品NULL坐标与1000缩放，并允许没有pet_artworks表；新包包含表中条目及两个图片引用。人设资料包也包含创作条目。缺失创作图片时继续导出并提示，仅在备份副本清空失效引用；初始图缺失时关闭副本中的图片模式，保留条目要求和其他图片，原库不修改。导入发布图片后追加条目并重映射ID；复用目标人设时不覆盖其库，来源旧消息无法关联到目标库的图片引用置空，不伪造图片。

警示气泡打开时优先保留阅读区，图片本体临时缩小，饰品按剩余区域约束显示；只调整运行态，关闭警示恢复，数据库坐标与缩放不变。

## 读取与部分失败恢复

图片库先订阅事件再补查，按请求先后与库版本淘汰迟到数据，跨人设不沿用旧库。每个库版本内，同一正式图片加载失败后不重复读取；当前图与初始图都不可用时停止回退尝试并显示颜文字。库更新后允许重新读取，不额外请求AI。

批量新建要求逐条确认保存，每保存一条即从待提交文本移除并选中对应条目；部分失败后仍刷新真实库，保留未完成要求，重试不重复提交已确认条目。饰品首次从默认位置用键盘调整时，先将当前显示位置转换为相对坐标，避免位置跳变。画布无可用空间时不输出负尺寸。

透明PNG解码在锁外完成；文件发布和数据库引用写入共用存储锁，避免清理服务在发布与引用之间误删新图片。提交失败后清理无引用的新文件，原正式图和预览保留。
