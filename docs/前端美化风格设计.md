# 颜喵 YanMew 前端美化风格设计

- 日期：2026-09-20
- 状态：视觉方向与实现规范已确定，具体页面结构和业务交互仍以《前端设计文档》为准
- 适用范围：主宠窗、聊天窗、设置窗、记忆窗、出行与信件窗口、主程序弹窗和气泡
- 不适用范围：小游戏插件。插件拥有独立视觉，不读取颜喵主题变量

当前落地：主宠窗已接入本文件的亮暗色 Token、等宽字体、主题色窄描边、胶囊控件、错误气泡和待机呼吸；主题读取全局设置、人设颜色读取当前项，保存与切换后刷新。拖动和错误期间暂停呼吸，系统减少动效时禁用动画。聊天与设置二级窗口已接入暖灰/炭黑表面、响应式外壳、卡片、表单和消息记录样式；设置导航在窄窗口变为顶部选择器。聊天发送、记事本及记忆管理已接通，其余未完成设置与业务按后续任务实现，实际 Windows DPI 与窗口缩放仍待人工验收。

亮暗色 Token、字体层级、卡片和状态样式可由未来 Android 页面复用；当前窗口尺寸与拖动规则针对 Windows。共享组件不依赖鼠标悬停才能发现主要操作，手机外壳另行适配触摸尺寸、安全区和软键盘，不能把桌面界面整体缩小视为移动端完成。

## 1. 设计目标

颜喵的界面采用“暖灰纸感、墨色结构、樱粉点缀、颜文字为主角”的轻量桌面风格。界面应像一个安静、柔软、长期陪伴用户的小物件，而不是网页后台、手机应用放大版或堆满装饰的游戏面板。

核心印象：

- 温和：背景偏暖，避免冷白大面积铺满；暗色主题使用柔和的炭黑，不使用纯黑。
- 清楚：信息层级主要由留白、字重、表面层级和细边框构成，不靠高饱和色块区分所有内容。
- 有生命：颜文字、气泡和少量状态动效带来陪伴感，普通表单和数据页保持安静。
- 克制可爱：樱粉作为点缀，不让全部按钮、卡片和标题同时变粉；不大量使用渐变、玻璃拟态和发光描边。
- 可长期使用：亮暗主题都适合长时间阅读，正文、输入框和焦点状态清晰，动画可关闭或随系统减少。

## 2. 从参考设计中采用什么

采用以下视觉方法：

- 暖灰页面背景、白色主表面和略深一级的次表面，形成柔和纸张层次。
- 墨色作为主要结构色，樱粉用于当前状态、用户消息和少量强调。
- 大圆角卡片配细边框和中性阴影，营造轻盈浮层感。
- 颜文字使用独立等宽字体，并加主题色窄描边保证在桌面壁纸上可读。
- 主宠窗保持透明，不给整个窗口套背景卡片；宠窗按钮、菜单、气泡、快捷输入区和弹出提示均透明无填充，仅保留描边及文字/图标，不使用卡片阴影或毛玻璃底。此规则只限宠窗，其他窗口保持各自表面。
- 主宠气泡、聊天气泡、提醒气泡和错误气泡拥有不同语义外观。
- 使用柔和缩放、位移和呼吸动效表达桌宠生命感，并支持 `prefers-reduced-motion`。
- 输入框聚焦以清晰描边表示，不使用强烈霓虹发光。

不采用以下内容：

- 不照搬参考页面的顶栏、锚点导航、展示卡片排布或单页网站结构。
- 不把 `12px` 左右作为二级窗口的主要正文。颜喵正文默认提高到 `14px`，小字只用于辅助信息。
- 不让所有可点击元素都持续上浮和弹跳。频繁使用的列表行、输入框和危险操作保持稳定。
- 不对长段文字使用模糊滤镜。聊天外观可由用户主动选择毛玻璃气泡，使用backdrop-filter只模糊背景，正文保持清晰；不支持时回退主题表面。其他内容不增加整页模糊效果。
- 不在每层容器上同时添加圆角、描边和阴影。一个区域只保留必要的一层主表面。
- 不用颜色作为唯一状态提示；成功、危险、当前、待确认等状态必须同时有文字或图标。

## 3. 视觉层级

二级窗口最多使用三层表面：

1. `canvas`：窗口背景，承载全页内容。
2. `surface`：主要卡片、侧栏、弹窗和固定输入区。
3. `surface-muted`：卡片内部的输入框、列表行、代码片段和次级区域。

不再继续嵌套第四层“卡片里的卡片里的卡片”。需要分组时优先使用间距、细分隔线和小标题。阴影只用于真正浮起的对象，例如弹窗、菜单、主宠气泡和最外层重点卡片；普通列表项只用背景或边框。

主宠窗是例外：窗口本身完全透明，不属于上述三层。桌面上只显示颜文字、饰品、气泡和必要控件。

### 4.3 人设颜色

- `--ym-pet-color` 来自当前人设，只应用于基础颜文字。
- 用户选择的颜色必须分别在亮色和暗色桌面背景预览；可读性不足时显示提示，但保留用户选择权。
- 颜文字光晕使用主题中性颜色，不跟随人设颜色，避免形成彩色发光效果。
- 人设卡片可以用一条 `4px` 色条或小圆点显示本体颜色，不把整张卡片染成人设颜色。

### 4.4 聊天背景保护层

聊天背景图片放在最底层。亮色主题默认叠加低强度暖白遮罩，暗色主题叠加低强度炭黑遮罩；输入区和侧栏使用独立主题表面。消息气泡支持默认、透明、仅描边、毛玻璃四种人设级外观，默认沿用原主题底色；透明与描边不铺底色，毛玻璃使用主题色35%混合透明、8px背景模糊及主题描边，unsupported时回退主题表面。用户/AI正文分别可选颜色，默认跟随主题；自选颜色不被主题切换覆盖，可单独恢复跟随主题。复杂背景下通过预览选取合适颜色，正文不得跟随气泡整体透明或被模糊。时间、按钮、焦点环和错误提示继续使用主题token。具体保存与恢复规则见《前端设计文档》5.6。

## 5. 字体与文字

### 5.1 字体栈

```css
--ym-font-ui: "Segoe UI", "Microsoft YaHei UI", "Microsoft YaHei", sans-serif;
--ym-font-kaomoji: "Cascadia Mono", "Segoe UI Symbol", "Meiryo", Consolas, monospace;
```

界面使用 Windows 系统无衬线字体。颜文字优先使用等宽且符号覆盖完整的字体，关闭连字，保持空格和符号位置。若某个颜文字包含当前首选字体没有的字符，允许系统回退，但必须在实际 Windows 环境验收是否错位或被裁切。

### 5.2 字号层级

```css
--ym-font-title-lg: 20px;
--ym-font-title: 17px;
--ym-font-heading: 15px;
--ym-font-body: 14px;
--ym-font-control: 13px;
--ym-font-caption: 12px;
--ym-font-micro: 11px;

--ym-font-pet: 28px;
--ym-font-kaomoji-lg: 22px;
--ym-font-kaomoji-md: 17px;
```

- 普通正文使用 `14px / 1.65`，聊天消息可根据窗口缩放到 `14–15px`。
- 输入框和按钮使用 `13–14px`，不能用微型文字承载主要操作。
- `12px` 用于时间、状态补充和字段提示；`11px` 只用于极短标签，不用于长段说明。
- 标题以 `600` 或 `650` 字重区分，正文保持 `400`；避免满屏粗体。
- 数字 ID、时间、模型名和文件格式可以使用等宽字体，普通中文说明不使用等宽字体。

## 6. 间距、尺寸、圆角与阴影

基础间距使用 `4px` 网格：

```css
--ym-space-1: 4px;
--ym-space-2: 8px;
--ym-space-3: 12px;
--ym-space-4: 16px;
--ym-space-5: 20px;
--ym-space-6: 24px;
--ym-space-8: 32px;
```

正文与说明间距通常为 `4–8px`，同一表单项之间为 `12–16px`，页面分组之间为 `24–32px`。响应式缩窄时优先减少外边距，不压缩文字行高和可点击区域。

圆角：

```css
--ym-radius-sm: 8px;    /* 小标签、迷你控件 */
--ym-radius-md: 12px;   /* 按钮、输入框、列表行 */
--ym-radius-lg: 16px;   /* 气泡、普通卡片 */
--ym-radius-xl: 20px;   /* 弹窗、重点外层卡片 */
--ym-radius-pill: 999px;
```

主宠透明窗口没有圆角背景。聊天气泡、提醒气泡和弹窗允许使用较大圆角；表格单元格、设置分组和长列表不要逐项使用 `20px` 圆角。

阴影：

```css
--ym-shadow-sm: 0 3px 12px -6px rgba(22, 18, 24, 0.20);
--ym-shadow-md: 0 12px 30px -12px rgba(22, 18, 24, 0.24),
                0 2px 8px -4px rgba(22, 18, 24, 0.12);
--ym-shadow-lg: 0 24px 56px -18px rgba(22, 18, 24, 0.34),
                0 6px 18px -10px rgba(22, 18, 24, 0.18);
```

阴影始终使用中性黑，不使用粉色或人设色发光。暗色主题主要依靠表面明度和边框分层，阴影只做辅助。

## 7. 图标与装饰

- 操作图标统一使用简洁的线性 SVG，默认 `16px`，线宽和圆角一致。
- 同一功能在所有窗口使用同一图标，不混用文字字符、彩色 Emoji 和不同风格图标。
- Emoji 可以出现在饰品、礼物和内容展示中，不作为关闭、删除、设置等基础操作图标。
- 图标按钮必须有可访问名称和悬停提示；不能只凭图形猜用途。
- 可爱感主要来自颜文字、文案和动效，不靠大量猫爪、爱心、星光背景纹理堆叠。

## 8. 组件视觉规范

### 8.1 按钮

主要按钮每个操作区域通常只有一个。亮色主题使用墨色底和浅色文字；暗色主题使用浅色文字对应的高对比表面。樱粉用于选中、开启和温和强调，不把所有主要按钮都染粉。

- 主按钮：高 `36px`，左右内边距 `16px`，`12px` 圆角。
- 次按钮：透明或次表面背景，细边框。
- 文字按钮：用于低优先级操作，仍保留完整焦点区域。
- 危险按钮：默认描边或文字危险色；只有最终确认弹窗中的主危险操作使用实色危险背景。
- 图标按钮：普通窗口至少 `32×32px`；主宠窗受固定画布限制可以使用 `28×28px`，但命中区域不得更小。
- 禁用：降低对比并取消悬停变化，同时保留原因提示；不能只通过变灰让用户猜测。
- 处理中：保持原宽度，显示轻量进度标识和“保存中…”等明确文字，阻止重复提交。

按下反馈以 `scale(0.97)` 或背景变化为主。频繁使用按钮的悬停位移不超过 `1px`；危险按钮不使用弹跳动画。

### 8.2 输入框与表单

- 输入框使用 `surface-muted` 背景、细边框和 `12px` 圆角，默认高度至少 `36px`。
- 标签位于输入框上方；必填、单位、范围和默认值用正常中文表达。
- 聚焦同时显示较深边框和 `2px` 外焦点环，不能仅靠边框轻微变色。
- 校验错误紧邻字段显示危险色文字，并保留用户输入；不弹全局错误代替字段提示。
- API Key 默认以密码形式显示，查看和清除是独立操作。
- 开关用于即时布尔设置；需要填写多个字段或可能失败的修改仍使用“保存”。
- 数值滑块必须同时提供可输入的数字和值域说明，不能只显示滑块位置。

### 8.3 卡片、列表与状态标签

- 卡片承担完整对象或设置分组；列表行承担高密度浏览。数据很多时优先列表，不把每条历史记录做成巨大卡片。
- 当前项使用左侧 `3px` 樱粉指示条、选中背景和“当前”文字；不能只改变边框颜色。
- 状态标签使用柔和背景、深色文字和简短枚举文案，例如“已整合”“待确认”“出门中”。
- 插件、人设和提供商卡片在窄窗口为单列，宽窗口最多按内容需要形成多列；卡片高度不强制完全一致。
- 空状态使用短标题、原因说明和一个直接操作，不加入无关插画。

### 8.4 导航与窗口标题区

- 设置窗宽屏使用左侧导航，当前项以柔和背景和指示条表示；窄屏折叠为顶部选择器或抽屉。
- 标题区保持轻量，只显示窗口标题、当前上下文和少量高频操作。
- 同一标题栏不放超过一个高强调按钮；次要操作可进入菜单。
- 内容滚动时标题区和关键上下文保持可见，避免用户忘记当前编辑的是哪个人设或会话。
- 关闭按钮关闭当前二级窗口；视觉上使用普通图标按钮，不做醒目的危险按钮。

### 8.5 弹窗与菜单

- 模态弹窗使用 `surface-raised`、`20px` 圆角、`shadow-lg` 和中性遮罩。
- 标题直接说明动作，例如“删除人设？”；正文列出会被删除的对象和不能恢复的结果。
- 普通确认按钮在右，取消在左；危险动作使用危险色并写出具体动词。
- 弹窗最大高度不超过当前窗口可用高度，长内容内部滚动，底部操作始终可见。
- 菜单使用 `12px` 圆角、细边框和 `shadow-md`，选项高度至少 `32px`；菜单不承载长表单。

### 8.6 加载、进度与提示

- 首次加载使用与内容形状接近的低对比骨架，避免整个窗口只显示旋转图标。
- 短操作在按钮内显示进度；模型下载、备份导入、索引重建等长操作显示具体阶段和可理解的进度。
- 成功提示短暂出现，不遮挡当前输入；失败提示保留足够时间，并提供重试或查看详情。
- 聊天流式输出直接追加正文，不显示覆盖消息区的全局 loading。
- 上下文缩减、索引重建和资源缺失属于非阻断说明，使用 `info-soft` 横幅，不伪装成错误。

## 9. 气泡系统

四类气泡共享圆角、边框和阴影语言，但必须一眼可区分。

### 9.1 主宠气泡

- 主宠气泡透明底、细边框和指向颜文字的小尾巴，不绘制面板填充或阴影；文字与描边跟随亮暗主题。
- 最大宽度随 `320×280` 基础画布计算，不能超过画布安全边界；正文自动换行。快捷输入展开后的画布为 `320×400`，气泡仍保留在宠物上方。
- 警示气泡采用紧凑标题、可滚动的两行高说明和操作行，内边距8×10逻辑像素，最大高度112；额外按宠物行高、内边距和底部入口限制可用高度，不能覆盖颜文字。刷新、查看记忆等操作同排，超长原因只在说明区滚动。
- 日常话语保持轻量，不显示头像和复杂工具栏。
- 需要点击的确认气泡允许按钮，但按钮不超过两个；复杂流程转到二级窗口。

### 9.2 聊天气泡

- 用户消息使用 `accent-soft` 背景和高对比文字，靠右排列。
- AI 消息使用 `surface-muted` 背景和普通正文色，靠左排列。
- 两者都保留细微边框；长代码、工具结果或引用使用气泡内部独立块。
- 时间、编辑标记和回合操作使用 `caption`，默认弱化，聚焦或悬停时清楚可见。
- 流式光标低调闪烁，不让整个气泡持续跳动。

### 9.3 提醒气泡

- 使用 `warning-soft` 暖黄色表面，包含提醒图标、提醒名、详情、原定时间和“完成”。
- 视觉上不能像 AI 消息，避免用户误以为是聊天内容。
- 离线过期汇总使用同一提醒体系，但采用列表式弹窗承载多个名称。

### 9.4 错误与休眠气泡

- 使用普通表面配危险边框和危险色标题，不使用整块高饱和红色。
- 显示中文原因、可执行的恢复方式和“打开设置”等入口。
- 红色感叹号只在错误或休眠时显示；允许低频脉冲，但不能持续快速闪烁。

## 10. 主宠窗美化

主宠窗必须保持透明、无边框、无整窗投影。正式产品中不显示画布边界或调试虚线。

宠窗采用统一透明描边控件：感叹号、“...”、隐藏/显示宠窗、聊天入口以及其菜单内按钮，包含发送/暂停等操作，背景始终transparent；hover、active、focus、展开/选中和disabled都不恢复填充。悬浮和展开通过主题强调文字/边框表示，焦点环保留；禁用用次要文字色和禁用光标区分，错误/危险保持红色文字与描边。主题只控制文字、图标、描边与状态色，不增加底板。宠窗普通文字使用实心玫瑰色：亮色主题主文字#8e4e65、次文字#96536a，暗色主题主文字#a05d77、次文字#aa6881；仅在宠窗覆盖文字变量，不改变其他页面。采用单层0.3px主题色轮廓，并用paint-order先画轮廓再填实心字；禁止多方向text-shadow叠影及SVG的叠加drop-shadow。输入正文、占位文字、按钮和悬浮/展开状态均保持实心主题字，禁用使用次文字色。按钮外沿保留1px深浅樱粉系窄轮廓，不使用黑白描边、不铺底色。键盘焦点环和危险状态色保留。颜文字本体沿用人设颜色，单层轮廓为1.25px，亮色轮廓#7b3f52、暗色#4a2d37；真实图片不加文字描边或矩形边框。

同一规则覆盖错误提示、更多/右键菜单、聊天标签、普通状态/出发提示、聊天回复、主动消息、提醒、饰品制作提示、快捷输入面板及文本框。移除面板阴影，聊天气泡尾部也透明；真实饰品图片保持原始透明度和原色。所有覆盖限定`.pet-window`，不得改变聊天详情、设置和小游戏的背景或主题规则。

- 颜文字在默认状态下位于画布视觉中心偏下，给上方气泡留下空间。
- 颜文字使用等宽字体、`nowrap` 和完整安全宽度，任何状态切换都不能裁掉右侧符号。
- 颜文字轮廓用于抵抗复杂桌面壁纸，先描单层轮廓再填人设本体颜色，不做模糊外发光或多层叠影。
- 饰品相对颜文字锚点定位，与颜文字一起移动；饰品不得改变文本排版宽度。
- 当前版本饰品支持真实透明PNG贴纸，建议单一物件、简洁轮廓、细节在小尺寸仍可辨；禁止附带宠物整脸、文字、水印、白色底板或伪透明棋盘格。图片保持原色，不随主题或人设本体颜色重新着色；主题切换不重新生图。
- 头顶槽按前端设计12.3的尺寸约束等比contain，随颜文字移动；预览使用页面已有表面色检查边缘，佩戴不加不透明外框或整窗背景。无图/损坏用已有emoji/颜图标、Emoji、颜文字或符号组合兜底，不能露出浏览器破图符号。
- 生图准备使用局部加载状态；关闭/失败提示使用轻量说明，不冒充聊天连接故障。提供商生图模块沿用现有表单、开关和密钥操作样式，不加入独立主题。
- 右上角工具常态使用细描边，悬浮/焦点增强边框与文字，错误等重要状态保持明确状态色；不使用实色填充或整体降低透明度来弱化。
- 隐藏后只保留清楚可点击的“显示宠窗”胶囊，不保留空白透明大区域。

桌宠动效：

- 待机呼吸只使用 `translateY(2px)` 左右的轻微起伏和不超过 `1.01` 的缩放，周期约 `3.6s`。
- 点击/摸摸使用一次短弹跳并显示亲密度反馈；出门中不播放获得亲密度的反馈。
- 拖动期间暂停呼吸和自主移动，释放后平滑恢复。
- 表情切换可以使用淡入、轻缩放和垂直位移；同一个表情重复触发不重新播放。
- 睡觉状态动画频率降低，错误状态不与可爱弹跳同时播放。

## 11. 二级窗口风格

### 11.1 聊天窗

- 会话区和消息区以背景明度区分，不使用粗分隔线。
- 输入区固定在底部，使用轻浮起表面；发送按钮是该区域唯一主要按钮。
- 消息区保持较大留白，气泡宽度不铺满窗口；超长正文限制行宽以便阅读。
- 背景图片存在时，侧栏和输入区保持稳定表面，消息气泡提高不透明度。
- “暂停”沿用发送按钮位置，避免布局跳动；使用状态文字和图标共同表达。

### 11.2 设置窗

- 使用稳定的左侧导航和内容页标题，内容区按照设置主题分组。
- 同类配置用列表或卡片，表单字段对齐；说明文字放在字段附近，不集中堆在页面顶部。
- 提供商、人设和插件等对象的“新建”位于列表标题处；编辑在对象详情内完成。
- 删除和清除密钥等危险操作放在卡片底部的危险区域，不与普通保存按钮并排抢夺注意力。

### 11.3 记忆窗

- 短期记忆和长期记忆使用清楚的分区或标签页；“待整合/已整合”使用状态标签和文字。
- 长期记忆首先展示标题和正文摘要，展开后查看来源；来源链条使用垂直时间线或顺序列表。
- 重新生成/重新整合先显示预览，旧内容与新内容使用左右或上下对比，确认替换按钮保持明确。
- 记忆是中性事实，视觉上保持文档感，不使用人设颜色和对话气泡样式。

### 11.4 出行、信件与游记

- 出行记录用时间线表达开始、写信、活动、返回和取消；游记、信件、礼物作为同次出行的并列内容入口。
- 游记详情具有轻量纸张感，可使用更宽松行距；删除游记入口不放在信件或礼物操作旁。
- 出门中状态使用 `info-soft` 或暖色状态卡，不制造高强度警告感。

当前14.4落地：TravelPanel使用既有暖灰/炭黑卡片、樱粉胶囊和语义token，出行历史显示状态与时间，邮箱双栏在599以下转单栏；信件正文保留换行、宽松行距，写信文本区随容器缩放。独立TravelWindow/LetterWindow复用ResponsiveWindowShell及当前人设颜色；详情删除使用既有确认对话框。主宠窗继续透明，出发气泡沿用提醒优先槽位，不更改背景或原生命中区域。完整活动时间线、伴手礼/游记展示在16阶段补齐，原生主题/DPI视觉体验待人工确认。

### 11.5 小游戏插件

- 游戏卡片只使用颜喵外壳风格展示名称、作者、版本、权限和启动入口；启动后的插件 WebView 使用插件自身视觉。
- 权限标签清楚区分“允许”“拒绝”“待确认”，联网来源使用可换行的等宽文本。
- 缺包数据卡片使用 `warning-soft`，突出来源链接和重新安装，不把保留数据误画成错误损坏。


### 11.1 聊天详情左侧会话栏

沿用颜喵的亮暗主题、圆角、细描边和强调色。展开栏宽236逻辑像素，收起轨道宽48，内容间隔12；小于680可用宽度时变成抽屉与遮罩，不增加横向滚动。列表平铺为轻量按钮，标题单行省略、次行显示绑定资料，当前项用accent-soft和边框区分；置顶分组轻量显示，不增加大卡片。底部操作固定、图标与文字同排；收起时只显示图标并保留悬浮名称。右键菜单采用surface-raised、细边框和小阴影，危险删除用danger色；窗口边界内显示。管理表单使用既有dialog，头部与关闭保持可见、正文独立滚动，不再在聊天上方展开大面板。

## 12. 动效规则

界面动效需要快于参考展示页，保证桌面应用操作利落；只有桌宠本身允许更有弹性。

```css
--ym-ease-standard: cubic-bezier(0.2, 0, 0, 1);
--ym-ease-emphasized: cubic-bezier(0.22, 1, 0.36, 1);
--ym-ease-spring: cubic-bezier(0.34, 1.42, 0.64, 1);

--ym-duration-fast: 100ms;
--ym-duration-normal: 160ms;
--ym-duration-slow: 240ms;
--ym-duration-pet: 360ms;
```

- 按钮悬停和颜色：`100–160ms`。
- 菜单、提示、字段错误：`160–200ms`。
- 弹窗、气泡、面板切换：`200–280ms`。
- 颜文字表情切换：`280–420ms`。
- 主题切换：`180–240ms`，防止整个窗口长时间颜色漂移。
- 呼吸、等待和睡眠属于循环动画，幅度小且不改变布局。

动画只改变 `transform`、`opacity` 和必要的颜色，避免频繁动画宽高、阴影模糊和大面积 `filter`。窗口缩放与消息流式更新期间不触发无关转场。

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    scroll-behavior: auto !important;
    animation-duration: 1ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 1ms !important;
  }
}
```

以后如增加应用内“减少动效”，其优先级与系统设置共同生效；任意一方要求减少，就使用减少动效模式。

## 13. 响应式与缩放

二级窗口按照内容容器宽度重排，不仅根据显示器宽度。建议以以下容器范围实现：

- 窄：小于 `520px`。单列；设置导航变为顶部选择器或抽屉；按钮允许换行。
- 中：`520–839px`。侧栏可收窄；表单以一列为主，短字段可两列。
- 宽：不小于 `840px`。侧栏与内容并排，卡片可按需要两列或三列。

规则：

- 用户拖动窗口边缘时即时重排，不显示横向滚动条承载主要内容。
- 页面外边距在窄窗口降到 `12–16px`，正文行高和控件命中区域不缩小。
- 表格在窄窗口转换为带字段名的纵向记录；确实需要横向对比的数据才允许局部横向滚动。
- 固定底部操作区不得遮挡最后一项内容，滚动区域预留相应内边距。
- 在 Windows 100%、125%、150%、175% 和 200% 缩放下验收文字、气泡、菜单、弹窗与颜文字边界。
- 主宠窗使用 `320×280` 基础逻辑画布，快捷输入展开为 `320×400`；通过 DPI 换算保持物理命中区域正确，不使用普通页面断点。

## 14. 无障碍与可读性

- 普通正文与背景目标对比度至少达到 `4.5:1`；大号文字和非文本控件至少达到相应最低要求。
- 所有交互元素支持键盘操作，焦点顺序符合视觉顺序；焦点环不能被 `overflow: hidden` 裁掉。
- `:focus-visible` 使用 `2px` 清晰焦点环和 `2px` 间隔，不能完全移除 outline。
- 红绿差异视图同时显示“新增”“删除”文字；提醒、成功、危险和待确认都不能只靠颜色。
- 图标按钮有 `aria-label`，动态状态使用适当 live region，但流式正文不逐 token 打断屏幕阅读器。
- 正文支持 Windows 文本缩放和浏览器缩放，不把容器高度锁死导致文字被裁切。
- 点击目标通常不小于 `32×32px`，主要操作优先 `36px` 高；紧凑主宠控件也要扩大透明命中区域。

## 15. CSS 与组件实现约定

不引入新的 CSS 框架来实现这套视觉。沿用 React 组件和普通 CSS：

```text
src/styles/
├─ theme.css       亮色、暗色和语义颜色变量
├─ base.css        字体、重置、焦点、滚动条和基础排版
├─ components.css  按钮、输入、卡片、标签、弹窗等公共样式
└─ motion.css      动效变量、关键帧和减少动效规则
```

窗口独有布局保留在对应 `*.css` 中，例如 `PetWindow.css`；公共视觉只在上述文件定义一次。现有计划中的 `theme.css` 作为主题入口导入其余公共样式，不同时维护另一套颜色常量。

命名原则：

- 主题变量使用 `--ym-*`，避免与插件或第三方页面冲突。
- 组件通过明确的 variant/state 属性选择外观，例如 `data-variant="danger"`、`data-state="loading"`。
- 禁止在 JSX 中散写主题色；人设颜色和聊天背景等真正运行时数据除外。
- 组件状态来自业务数据，CSS 不通过文案内容猜状态。
- 插件 WebView 不加载这些样式文件，也不能读取 `--ym-*`。

建议公共视觉组件：

- `Button`、`IconButton`
- `Card`、`ListRow`、`StatusBadge`
- `TextField`、`TextArea`、`SelectField`、`SwitchField`
- `Dialog`、`PopoverMenu`、`InlineNotice`
- `WindowHeader`、`ResponsiveWindowShell`
- `PetBubble`、`ChatBubble`、`ReminderBubble`、`ErrorBubble`
- `EmptyState`、`ProgressState`

公共组件只负责外观、基本状态和无障碍属性；保存、删除、钱包、旅行和记忆规则仍由各功能页面与 Rust 服务负责。

## 16. 页面验收标准

每个窗口完成美化后至少检查：

1. 亮色、暗色和跟随系统三种主题模式；主题切换不闪出另一主题的底色。
2. 默认宽度、最小宽度和用户放大后的布局；无主要内容被横向裁切。
3. 100%–200% DPI；颜文字右侧符号、按钮文字和弹窗操作完整可见。
4. 键盘遍历、焦点环、屏幕阅读器标签和只用颜色表达状态的问题。
5. 默认、悬停、按下、聚焦、禁用、加载、成功和失败状态。
6. 长中文、长英文模型名、长路径、长插件来源和多行错误信息。
7. `prefers-reduced-motion` 下无持续呼吸、脉冲和弹跳，功能仍然清楚。
8. 聊天背景、人设极亮/极暗颜色和复杂桌面壁纸下的文字可读性。
9. 小游戏插件未被注入颜喵主题或公共 CSS。

## 17. 最终视觉判断

看到界面时，首先应注意到当前颜文字、当前对话或当前任务，而不是卡片阴影和装饰。拿掉颜文字后，界面仍然应是一套清楚、克制、可长期使用的 Windows 桌面应用；加入颜文字、樱粉点缀和柔和动效后，才形成颜喵独有的陪伴感。
## 14. 管理卡片、日历与昼夜天气

管理页使用摘要卡片和独立详情，普通卡片不嵌套全部表单。当前人设以边框/柔和底色、使用中文字及强调按钮共同标识。卡片右側的切换与管理操作不触发详情；交互按钮始终可见，不依赖悬停。搜索、排序和分页控件允许换行。
月历公历日期16px、农历12px；窄窗口农历可11px。今天圆形描边，选择日期格使用樱粉次表面，周末和节日不能仅靠颜色识别。七列始终保持，对长节日缩略并在日期详情完整显示。
天气卡片白天暖灰金色、晚上炭蓝，分别适配亮暗应用主题；时间、天气图标和温度形成主视觉，不使用复杂背景动画。实际天气内容及刷新规则独立于外观。
插件卡片的卸载/启停/清除重载使用统一按钮；自带卸载变灰并有禁用说明。小游戏内部仍使用各自原型视觉，不注入主程序主题。
