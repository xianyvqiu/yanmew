# 关于颜喵与程序更新

适用范围：Windows x64主程序、完整便携包和旧版更新助手。应用版本保持`0.1.0`，构建编号单独比较。不使用GitHub Actions，不自动发布Release，不改变数据库结构。

## 设置入口

“关于颜喵”是设置侧栏和窄窗下拉列表中的独立入口，不依赖当前会话加载成功。显示运行程序的版本、构建编号、便携/安装模式、资料目录，以及主仓库、社区仓库、反馈和Release链接。资料目录来自平台路径规则，不接受前端提供任意路径。

更新检查由后端应用启动时执行一次，之后只在用户点击“检查更新”时联网；打开多个窗口或反复进入页面只读取本进程缓存。页面轮询本地状态用于展示检查和下载进度，不是轮询GitHub。检查失败不阻塞启动，不自动下载或退出应用。

## Release协议

固定仓库：`https://github.com/xianyvqiu/yanmew`。匿名查询GitHub REST的`releases/latest`，只接受该仓库正式Release，不读取开发分支、draft或prerelease。HTTP 404说明暂无可公开访问的正式发布，不能区分尚未发布和仓库私有；403/429单独说明限流，网络/格式错误不能当作“已是最新版”。

每个正式Release需上传同一次构建生成的：

1. `颜喵 YanMew-portable.zip`：完整干净包，包含主程序、资源、运行库、`yanmew-update.exe`和`yanmew-package.json`。
2. `yanmew-update.json`：`schemaVersion:1`、`version`、`buildId`、`assetName`、`size`和ZIP的`sha256`。
3. `颜喵一键更新.exe`及其SHA-256文件：供没有应用内更新入口的旧版用户单独下载。它与包内`yanmew-update.exe`内容相同。

`yanmew-package.json`包含`schemaVersion:1`、`product:com.yanmew.pet`、版本/构建编号，以及每个受管文件的相对路径、长度、SHA-256；清单自身不列入自己的哈希表。包中不得有`data`、未登记文件、重复/大小写冲突路径、链接、Windows设备别名、路径穿越或安装模式标记。大小、文件数量及解压总量均有限制。

清单附件和ZIP均核对GitHub Release API返回的`digest:sha256:…`；ZIP还需与更新清单的大小和哈希一致，解包后逐文件验证。不接受缺少digest的附件。下载只允许固定仓库发布地址和GitHub官方附件重定向域名，保留HTTPS验证，不使用用户API Key、GitHub Token或私有仓库凭据。

这是对GitHub官方HTTPS来源、附件摘要和包内清单的校验，没有额外引入独立发布私钥或声称已完成代码签名。参考：[GitHub Releases API](https://docs.github.com/en/rest/releases/releases#get-the-latest-release)、[Release附件API](https://docs.github.com/en/rest/releases/assets#get-a-release-asset)。

更新比较先用语义版本，版本相同再比较固定格式`yyyyMMdd-HHmmss`构建编号；同版同构建及降级拒绝覆盖。无清单的旧便携包由助手识别，首次升级不能推断历史构建，但会验证目标程序和资源目录。

## 应用内更新

用户点击“更新并重新启动”后，下载和解包校验先在系统临时工作目录完成；下载失败、校验失败或准备助手失败时不替换旧程序，不动个人资料。

主程序校验当前受管助手的哈希，复制到独立临时目录运行；现有`Runtime.shutdown`成功保存及取消任务后写入交接信号，再正常退出。未成功交接时助手超时取消，不强制结束进程。助手重新核对当前正式Release和下载包，检查目标完整路径、等待对应程序退出并独占实际data实例锁，再执行更新。

## 兼容旧版的更新助手

双击`颜喵一键更新.exe`，选择旧版`yanwenzi.exe`所在文件夹。助手自动查询正式Release、下载完整包并显示进度；旧版仍运行时提示从托盘正常退出，退出后继续，无需用户手动复制data。

助手与应用内更新共用网络、解包和文件事务代码。正式Release尚未发布或不可公开访问时只说明状态，不假报更新成功。首次公开Release前，真实公网下载升级链路仍需在发布后验收。

## 资料、备份与失败恢复

程序和资料目录继续遵守[安装与发布设计](安装与发布设计.md)。便携资料在EXE旁data；安装资料通过Windows已知文件夹API定位。安装标记无效时停止，不猜另一份数据库。

替换前将旧受管程序及完整data复制到程序目录上一级`YanMew-backups/update-构建编号-唯一编号/`，逐文件核对。只跳过data根目录运行锁，嵌套插件中同名文件仍备份。备份失败不进入替换。更新不使用新包覆盖data，数据库仍由正式启动入口进行已有一致性备份和迁移；跨电脑密钥不属于本流程。

有旧清单时，只清理明确登记且新版不再提供的文件；无旧清单时保守保留未能确认归属的历史资源。目录中的其他文件、外部导出备份及其他便携版本不删除。

替换前持久保存事务标记与旧文件哈希；替换失败恢复旧程序，资料不回写。替换期间进程/系统异常退出时，主程序拒绝直接启动数据库，更新助手在联网检查前恢复未完成事务。备份损坏则停止并保留现场，不删除剩余文件。

成功替换后移除事务标记并重新启动程序，更新前完整备份保留。程序启动后的模型兼容、数据库迁移或后来产生的新记录不属于文件替换自动回滚；不能在已经运行新版后直接启动旧版或自动覆盖当前data，需要按对应升级前备份处理。

## 卸载

卸载与更新使用不同命令，不通过普通卸载执行更新。设置弹窗必须明确确认永久删除全部资料，取消不会请求后端；后端仅接受settings窗口和主动确认。

主程序正常保存并交接退出后，便携助手检查程序和data目录，按包清单清理程序文件、清理自己的data，只在自启项精确指向本程序时移除该项和对应StartupApproved记录；不递归删除整个程序目录，不动外部备份或其他文件。安装版调用当前目录正式`uninstall.exe`，沿用原安装器清理规则。占用、权限或清理失败均报告未完成，不宣称成功。

## 实现位置与验收

- `src/components/settings/AppInfoPanel.tsx`、CSS、`SettingsNavigation.tsx`、`src/pages/SettingsPage.tsx`：独立页面、状态展示、更新和卸载确认。
- `src/api.ts`、`src-tauri/src/update_commands.rs`：受限命令、进程内状态、启动检查与退出交接。
- `src-tauri/src/updates/`：版本/清单、固定Release网络、解包、备份/替换/恢复及Windows进程、目录、锁和助手窗口。
- `src-tauri/src/bin/yanmew-update.rs`：独立助手入口；`main.rs`阻止未完成事务直接启动；`build.rs`注入构建编号。
- `scripts/build-portable.ps1`：同次构建编译助手、组装干净包、生成受管文件清单及未来Release附件，绝不自动发布。

自动检查覆盖版本比较、来源/摘要拒绝、受管路径边界、完整资料保留、替换失败恢复、事务恢复、ZIP损坏和未登记数据、界面防连点/失败重试、卸载确认及无会话入口。只在隔离目录检查破坏性操作。真实Release公布后的检查/下载/升级、杀进程/断电恢复、安装版NSIS、跨用户权限、亮暗/窄窗/DPI及正常卸载仍需人工验收，不因编译通过就代填通过。
